# AI 能力选型：Prompt、RAG、Tool、Agent、Skill 与 MCP

团队准备自动检查一批 Markdown 文章。第一版只在本地运行，后面可能接入编辑器和 CI。这个需求同时包含文本判断、确定性检查和跨工具复用，很适合用来解释 AI 能力怎样组合。

选型前先写清四件事：输入从哪里来，哪些事实会变化，程序是否产生副作用，结果怎样验收。能力名称排在后面。缺少这些约束，Prompt、RAG、Tool、Agent、Skill 与 MCP 很容易被误当成六种互斥产品。

## 六种能力处在不同层

| 能力 | 解决的问题 | 控制权在哪里 | 常见边界 |
| --- | --- | --- | --- |
| Prompt | 怎样描述任务和输出形状 | 一次模型调用 | 不能提供新事实，也不能授予权限 |
| RAG | 怎样把外部资料送入本轮生成 | 检索器与上下文装配器 | 相似结果不等于正确、最新或可见 |
| Tool | 怎样执行一个确定动作 | 工具实现与策略层 | 模型只提出参数候选，程序负责校验 |
| Agent | 观察结果后怎样动态选择下一步 | 受限行动循环 | 需要预算、终止条件、状态和恢复 |
| Skill | 怎样复用一类任务的说明、脚本和资源 | Host 的触发与加载机制 | 不负责跨进程协议，也不增加权限 |
| MCP | Host 与外部能力怎样发现和调用彼此 | Client、Server 与传输层 | 统一交互协议，不替代领域校验 |

Workflow 也应放进比较。它把已知步骤和分支固化成程序，适合顺序稳定、失败处理能够提前枚举的任务。只有下一步必须依据本轮观察才能决定时，Agent 才提供额外能力。

## 先从没有模型的版本开始

文章的 frontmatter 是否存在、内部链接是否指向文件、代码围栏是否闭合，都可以由确定性程序判断。模型更适合处理“这段解释是否缺少边界条件”一类语义问题。两者混进一个 Prompt，模型可能把明确的语法错误判成风格建议，也可能为了润色改坏链接。

最小链路可以写成：

```text
读取文件 -> 结构检查 -> 链接检查 -> 语义审阅 -> 汇总报告
```

前三步是普通函数，第四步才需要模型。步骤固定时，脚本或 Workflow 足够。语义审阅产生的建议仍是候选，自动写回正文前要经过差异检查和人工确认。

## RAG 只在资料不随请求一起提供时出现

规范已经随任务传入，模型可以直接对照，不需要额外检索。规范很多、版本频繁变化，或者不同栏目使用不同规则时，RAG 才负责找出当前适用的条款。

检索请求至少绑定栏目、规范版本和可见范围。只按“文章检查”做向量相似搜索，可能把旧规范与新规范同时取回。检索无结果应暴露为资料缺口，不能让模型凭常识补出一条规则。

## Tool 与 Agent 的分界看下一步由谁决定

“检查这个文件的链接”可以直接调用一个 Tool。程序知道调用时机，也知道拿到结果后继续做什么。任务变成“定位构建失败，读取相关文件，选择检查命令，根据输出继续缩小范围”时，路径依赖中间观察，可以使用有限 Agent Loop。

有限循环需要硬约束：允许读取的目录、工具白名单、最大步骤数、总 Deadline、重复动作检测和取消信号。模型返回的工具名和参数通过 Schema 只说明形状正确，路径范围、当前权限和副作用仍由执行器检查。

## Skill 与 MCP 解决两种复用

Skill 适合把“怎样完成文章检查”封装为可按需加载的任务知识。入口文件说明触发条件、处理流程和停止规则，脚本目录保存可重复检查，参考资料只在命中相应问题时读取。它复用的是做事方法。

MCP 适合多个 Host 调用同一个外部能力。编辑器、桌面客户端和 CI 都要查询统一的链接索引时，可以把查询能力放进 MCP Server。它复用的是跨进程能力与发现协议。

只有一个本地脚本、调用方也只有一处时，包装 MCP 会增加初始化、传输、版本协商和运维成本。先证明第二个真实客户端存在，再决定是否建立 Server。

## 用文章检查任务做一次完整选择

当前需求是本地批量审阅，规则文件随仓库提供，执行路径固定。合理的第一版由脚本、一次语义模型调用和人工确认组成。为了让不同项目复用，可以再封装 Skill。编辑器与 CI 确实需要共享同一远程索引后，才增加 MCP Server。

此时没有引入 Agent。排障路径无法提前列出，并且每次检查结果会改变下一步文件和命令时，才把那一段升级成受限循环。升级范围只覆盖动态部分，文件遍历、链接解析和最终门禁继续由确定性程序负责。

## 选型结果怎样验收

同一组样本要同时跑直接实现和候选方案。正常文章、断链、过期规范、模型超时、权限拒绝和取消都应有明确结果。记录每种方案调用了多少外部能力、哪些错误能定位、是否会自动改正文，以及失败后需要清理什么。

选型成立的证据是更小方案无法满足某个已确认约束。以后新增客户端、资料版本或动态分支时，再用同一组样本比较升级前后的正确性、延迟、成本和故障面。
