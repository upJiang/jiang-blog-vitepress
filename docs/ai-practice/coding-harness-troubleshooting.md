# Coding Harness 排障：上下文、工具、环境与反馈

编码 Agent “没有反应”可能对应完全不同的状态：请求没有进入运行时，模型正在等待，工具进程卡住，命令已经结束但事件没有交付，或者验证失败后系统仍在重试。只盯着聊天窗口会把这些故障压成同一种现象。

Harness 把模型、工具、上下文、工作区、权限、事件和验证连接起来。排障要沿控制链找到最后一个有证据的阶段。

## 保存可复现输入

记录任务 ID、开始时间、仓库修订、工作区状态、Harness 与模型版本、允许工具和 Deadline。不要把完整 Prompt、凭证或用户文件复制进公开日志，保留哈希、大小和受控引用即可。

同一句请求在不同工作区上可能得到不同结果。复现时固定代码与依赖，先确认故障仍存在，再注入更详细的诊断事件。

## 一次执行经过哪些阶段

```text
accepted -> context_ready -> model_waiting -> tool_running
         -> verifying -> completed / failed / cancelled
```

每次迁移写入递增事件序号和阶段开始时间。UI 断线后可以按游标重放，不需要重新启动任务。日志只有自然语言“正在思考”时，无法判断模型、工具还是验证器拥有当前状态。

## 从最后一个事件向下检查

停在 `accepted`，检查队列投递、Worker 准入和任务 Lease。停在 `context_ready`，检查模型请求是否真正发出。停在 `model_waiting`，区分供应商超时、流式空闲和正常长推理。停在 `tool_running`，查看进程、命令摘要、输出心跳和取消状态。

命令已经退出却没有进入验证，通常是结果解析或事件写入失败。验证完成但 UI 仍显示运行，检查终态持久化与 SSE 重放。每层先查它拥有的状态，不用修改 Prompt 掩盖交付故障。

## 工具卡住需要进程证据

工具调用保存 `call_id`、工作目录、参数摘要、开始时间、子进程身份和输出字节数。长时间没有新输出不一定卡死，测试或构建可能在安静计算；同时观察 CPU、子进程和 Deadline 才能裁决。

取消时向进程组传播信号，等待有限宽限期，再记录强制结束。只终止父 Shell 可能留下测试服务器或编译进程。清理结果也要进入终态，避免下次任务撞上旧端口。

## 上下文问题表现为错误决策

Agent 反复读取同一文件、忽略最新修正或修改范围外内容，通常要检查上下文装配和任务合同。确认规则是否在裁剪中丢失，历史摘要是否包含过期假设，文件内容是否来自当前修订。

上下文过长不是唯一原因。规则顺序、冲突指令和旧工具结果也会污染当前决策。诊断记录应说明本轮真正送入了哪些材料及其版本，不只保存 Token 总数。

## 模型、工具和验证器分开统计

模型错误包括无合法动作、结构化输出失败和供应商拒绝；工具错误包括进程退出、权限拒绝和外部服务超时；验证错误包括测试失败、类型错误和构建失败。三类错误使用不同重试策略。

结构输出失败可以有限修复，权限拒绝不能重试升权，测试失败应回到代码差异。所有问题都“再问一次模型”，会消耗预算并隐藏责任层。

## 检查点只保存可恢复状态

每轮模型输出、工具调用和工作区变化都生成事件，但检查点不需要复制全部日志。它保存当前 Turn、已确认观察、未完成调用、工作区修订、剩余预算和允许继续的动作集合。大输出放进对象存储，检查点只保存带哈希的引用。

```json
{
  "turn": 7,
  "workspaceRevision": "ws-18",
  "pendingCall": null,
  "lastObservation": "artifact://tool/call-42",
  "remainingSteps": 5,
  "state": "verifying"
}
```

工具调用前先写 `prepared` 事件，执行后写带回执的 `observed` 事件。恢复时发现 prepared 没有 observed，读取工具类别：纯读可在同一版本重试；带幂等键的写入先查回执；无法查询的写入进入 unknown。把所有未完成调用一律重放，会把一次 Harness 故障变成重复副作用。

工作区恢复还要比较修订号。用户在任务暂停期间修改了目标文件，旧补丁只能作为候选差异展示，不能直接应用。恢复能力的验收应包含进程在每个事件缝隙退出，而不只是主动点击“继续”按钮。

## Watchdog 不能只看心跳

进程定期心跳只能证明它还活着。卡循环中的 Agent 可能持续调用工具，看起来活跃却没有状态变化。Watchdog 同时观察阶段时长、重复动作签名、结果是否新增证据和剩余预算。

达到软阈值时记录诊断并允许一次受控纠正，达到硬 Deadline 后停止创建新动作。已经发出的写操作查询回执，未知结果保持 unknown，不能直接重放。

## 用故障注入验证排障链

主动注入模型超时、工具无输出、子进程遗留、事件存储失败、客户端断线和验证失败。每个样本都应落到预期阶段，给出稳定错误码，并能在重连后读取相同终态。

Fake Tool 可以验证调用顺序，不能证明真实 Shell、容器或外部 API 行为。排障报告注明证据层级。根据任务 ID 能还原事件顺序、当前所有者和清理结果后，“没有反应”就变成了可以定位的阶段故障。
