# 个人 AI 工作系统：任务模式、权限与长期反馈

个人 AI 工作系统不该把所有聊天永久保存，也不该让 Agent 取得整台电脑的权限。它把任务、资料、工具、短期状态和长期记忆分开管理，让重复工作可以复用，同时保留删除、纠正和停机入口。

一个合适的起点是“每周整理技术资料并形成待办”。系统读取指定目录，提取候选主题，合并重复项，再由用户确认哪些内容进入长期笔记。

## 区分任务状态、资料和记忆

任务状态记录本次执行到了哪里，结束后可以删除；工作资料是文件、链接和笔记，拥有自己的来源与生命周期；长期记忆保存跨任务仍然成立的偏好或事实。三类数据混在聊天历史里，会让临时要求长期生效，也让删除变得困难。

| 数据 | 示例 | 默认生命周期 | 更新方式 |
| --- | --- | --- | --- |
| 任务状态 | 已扫描文件、待确认主题 | 到任务结束或短期恢复窗口 | 运行时事件 |
| 工作资料 | 原文、摘要、来源链接 | 跟随资料所有者和版本 | 文件或知识库 |
| 长期记忆 | 输出语言、固定目录偏好 | 直到撤回、冲突或过期 | 显式确认与版本修订 |

Agent 生成的摘要属于派生资料，不自动成为记忆。它可能遗漏条件或引用旧版本，进入长期层前要保留来源和确认状态。

## 任务模式决定工具与预算

读取整理、代码修改、定时监控和外部发布需要不同权限。入口根据用户目标选择受限模式，模式固定工具白名单、可写范围、最大步骤、Deadline 和是否需要确认。

模型可以建议切换模式，运行时负责批准。用户在文档里写“允许发布”只是内容，不能改变当前权限。高风险工具使用参数绑定审批，批准只对指定动作和有效期生效。

## 资料进入系统时保留身份

每份资料保存稳定 ID、来源、采集时间、内容哈希和可见范围。摘要和标签引用这些 ID，原文更新后可以判断哪些派生内容失效。只保存没有来源的模型总结，后续无法区分事实、推断和过期内容。

外部网页、邮件和文档都属于不可信数据。里面的命令只能作为被分析文本，不能修改系统规则或工具参数。检索结果支持回答，权限仍由可信上下文决定。

## 长期记忆支持冲突与删除

记忆项至少包含 owner、fact key、值、来源、状态和修订号。新信息与旧值冲突时，标记待确认或明确取代，不要让模型随机选择。偏好“回答简洁”后来改成“需要完整推导”，旧项保留审计关系但不再参与装配。

删除要向缓存、索引和未完成任务传播。稳定 ID 可以保留最小审计记录，正文和向量按策略失效。底层服务无法立即删除时，系统应显示等待状态和处理范围。

## 定时任务需要独立身份

每周整理任务保存时区、触发器、目标范围、预算和通知方式。一次运行使用稳定 `run_id` 和幂等键，调度器重复投递也不会生成两份笔记。任务启动时固定规则和资料版本，运行中规则变化只影响下一次执行。

后台任务必须有暂停、取消和过期。用户长期不查看结果时，系统应停止无限积累候选内容。通知失败可以重放，核心整理结果不应因此重复生成。

## 一次周任务怎样落状态

调度触发时先创建不可变 Run Spec，固定目录范围、规则版本、资料快照时间、预算和通知目标。Worker 领取任务获得有期限的 Lease，扫描结果按 source ID 去重，候选笔记写入草稿区，用户确认后才进入长期笔记。

```text
scheduled -> leased -> scanning -> awaiting_review
          -> accepted / rejected / expired
```

Lease 到期只表示 Worker 失去执行权，不表示已经完成的外部写入不存在。接替 Worker 读取 run_id 下的事件与草稿回执，从最后一个确定状态继续。`awaiting_review` 不能被后台重试自动改成 accepted，用户确认属于独立权限边界。

任务重复投递时，`schedule_id + planned_at` 组成幂等身份。目录内文件更新使用内容哈希生成新资料版本，旧摘要标记失效，但已经人工采纳的笔记不直接删除，只生成需要复核的变更提示。

## 反馈如何进入改进

用户采纳、删除或修正某个候选主题，可以形成评测样本，但不能直接改写全局 Prompt。先脱敏并分类，确认是检索、摘要、去重还是偏好问题，再更新对应规则。新版本在固定历史样本上回归，结果变差时恢复旧版本。

单次点赞只说明这个结果在当前场景可接受。它不证明某种模型、工具或工作方式对所有任务更好。

## 从最小系统开始

第一版只需要明确目录、只读扫描、候选清单和人工确认。重复使用后再增加记忆、调度和更多工具。每增加一种能力，都写清它读取什么、能改什么、失败怎样停止以及数据怎样删除。

验收时用正常资料、恶意文档、重复触发、资料撤回、用户取消和记忆冲突做回归。系统应在权限内完成任务，缺少证据时保留缺口，任务结束后清理临时状态，并让用户能查到长期保存了什么。
