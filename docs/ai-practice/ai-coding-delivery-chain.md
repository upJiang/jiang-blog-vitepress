# AI Coding 交付链：从需求到候选发布

AI 能快速生成补丁，交付仍要经过仓库约束、差异审查、测试、制品和发布决策。模型输出只是候选修改；通过本地测试也只证明当前环境中的一组行为，没有自动获得提交、推送或上线权限。

本文用“给现有 API 增加一个可选过滤参数”贯穿说明。这个改动会影响协议、业务查询、测试和客户端兼容，适合观察一条完整交付链。

## 入口固定任务和权限

开始前读取仓库规则、当前分支、工作区差异和相关实现。用户已有改动应当保留；无法区分归属时，缩小修改范围。任务合同写清允许改哪些模块、是否能新增迁移、需要哪些验证，以及是否授权提交或部署。

需求中的业务事实要找到来源。参数名称来自接口约定，权限范围来自认证和服务逻辑，数据库字段来自 Schema。模型可以提出实现方案，不能凭标题猜表结构或生产配置。
## 代码定位从调用链开始

沿路由、请求模型、Service、Repository 和测试找到状态所有者。只搜索相似字段名，容易在旧模块或另一个协议版本中修改错误位置。

```text
HTTP 参数 -> 请求校验 -> 业务范围求交 -> 仓储查询 -> 响应映射
```

每层只承担自己的判断。请求校验负责形状，业务层确认范围，仓储层构建参数化查询。把权限判断放进模型生成的查询文本，会让协议输入越过可信边界。
## 候选补丁保持小而可解释

修改前保留当前测试结果。先写或更新失败测试，再实现最小改动。补丁同时重命名文件、升级依赖和格式化全仓时，评审很难判断哪项变化修复了需求，也难以安全回滚。

差异审查至少回答：是否改到任务外文件，错误合同是否变化，日志是否泄露输入，迁移能否回退，旧客户端是否仍可调用。生成代码中的注释和类型也要逐行检查，模型可能引用不存在的 API 或过期版本。
## 验证按责任层拆开

单元测试检查纯业务分支，集成测试确认数据库和协议，类型与 lint 检查静态合同，生产构建检查打包边界。涉及页面交互还要在真实浏览器里走关键路径。

失败要保留原始命令、退出码和关键日志。不能为了变绿删除断言、扩大忽略规则或把失败测试改成跳过。环境缺失与代码回归分开记录，前者不证明补丁正确。
## 从源码到制品还有供应链

候选发布绑定代码修订、依赖锁文件、构建环境和制品摘要。相同版本号却对应不同文件，会让回滚和漏洞追踪失去依据。制品经过扫描后进入候选环境，再做健康检查和业务验证。

数据库变化先创建可验证的回滚点，并确认旧版本是否能读取新状态。旁路、灰度或滚动发布的切流条件和回滚阈值要在开始前写清。模型不能根据一段成功日志自行决定扩大流量。
## 用交付状态机阻止跳步

交付记录不要只保存一个 `status` 字符串。它至少绑定源码修订、工作区摘要、测试报告、制品摘要、候选环境和审批记录。每次转换检查前置证据：没有通过构建的修订不能创建候选，没有候选业务验证不能进入切流，已经回滚的制品不能被迟到事件重新标成已发布。

```ts
type DeliveryState =
  | { type: 'working'; revision: string }
  | { type: 'verified'; revision: string; reportId: string }
  | { type: 'candidate'; artifactDigest: string; reportId: string }
  | { type: 'released'; artifactDigest: string; releaseId: string }
  | { type: 'rolled_back'; releaseId: string; rollbackId: string }
```

状态对象使用稳定 ID 引用大日志，数据库用版本号做条件更新。两个 Worker 同时处理同一候选时，只有读取到当前版本的一方能迁移成功；另一方重新读取终态，不能覆盖。这个约束由存储层实现，不能靠模型在文本里承诺“不会重复发布”。

恢复测试要在每个边界杀掉进程：测试刚结束但报告未写入、制品已上传但候选未创建、代理已切换但回执丢失。重启后先读取外部事实，再决定继续或补偿。若无法确认写操作结果，进入 `unknown` 并要求人工裁决，禁止直接重放。
## 失败要回到拥有状态的组件

请求校验测试失败，检查协议实现；查询结果越权，回到业务范围和仓储条件；构建失败，检查依赖与环境；候选健康但业务错误，停止切流并保留旧版本。把所有失败重新交给模型生成补丁，会累积与根因无关的修改。

已经产生外部副作用时先查回执。重复迁移、重复消息或重复发布可能扩大影响，重试需要稳定操作 ID 和幂等规则。取消只阻止后续动作，不能自动撤销已经提交的事务。
## 交付报告只陈述已验证事实

报告列出修改文件、行为变化、运行过的命令、失败与修复、未验证项和回滚入口。内存仓库通过单元测试，不能写成真实数据库已验证；本地构建成功，也不能写成生产发布成功。

提交、推送和部署属于独立授权。没有授权时保留工作区差异，让用户可以审查。AI Coding 缩短定位和实现时间，交付可信度仍来自可复查的证据链。
