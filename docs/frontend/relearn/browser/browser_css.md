# 浏览器样式与布局过程

浏览器把 DOM 和样式表交给 style engine。它先判断哪些规则匹配，再做级联、继承和自定义属性解析，得到用于布局的样式结果。布局、绘制和合成是后续阶段，修改一条 CSS 的影响范围取决于属性类型与所在结构。

## 规则匹配关注选择器右侧

选择器决定元素是否匹配一条规则。实现通常从最右侧的 key selector 开始寻找候选，再验证祖先或兄弟关系；这是引擎优化策略，不是开发者可以依赖的规范执行顺序。

~~~css
main .card > h2 {
  color: #333;
}
~~~

候选 h2 必须有满足 `.card` 的直接父元素，且这个父元素还要处在 main 后代关系中。选择器写得很长不一定慢，真正的成本取决于候选数量、失效范围和页面结构。用 Performance 面板测量，比背“后代选择器一定慢”可靠。

## 级联决定胜出的声明

同一属性有多条声明时，浏览器按来源、重要性、级联层、specificity 和出现顺序做比较。specificity 只在前面条件相同时参与，`!important` 也不能无条件解决设计冲突。

级联层可以把基础样式、组件样式和覆盖层分开，避免通过不断增加选择器权重解决问题。自定义属性参与值计算，但它们保存的是 Token 流，直到使用位置才按目标属性语法解析。

~~~css
:root {
  --gap: 8px;
}

.panel {
  gap: var(--gap);
}
~~~

如果 `--gap` 的值不符合 `gap` 语法，声明会在使用处变成无效。可以为变量提供回退值，但回退只在变量未定义或无效时生效，不能修复任意语法错误。

## 继承和初始值补齐样式

继承属性在父元素计算后传给子元素，非继承属性使用初始值、指定值或自动值。CSS 的 `inherit`、`initial`、`unset` 和 `revert` 分别表达不同的回退策略。

~~~css
.panel {
  color: #222;
}

.panel button {
  color: inherit;
  all: unset;
}
~~~

`all: unset` 会重置大量属性，使用时要明确恢复按钮的交互、焦点和可访问性样式。浏览器默认样式属于 user-agent origin，重置它们并不会自动提供一套可用控件。

## 何时触发布局失效

改变 `color` 通常只需要重新绘制受影响内容。改变 `width`、`font-size` 或字体加载状态可能影响当前节点、祖先和兄弟的几何关系，触发布局。改变 `transform` 通常可以在合成阶段处理，但它仍可能影响命中测试、层创建和内存。

这些分类是优化线索，不是固定 API 合同。阴影、滤镜、contain、滚动容器和 SVG 会改变失效边界。把读写混在循环里还可能强迫浏览器立刻完成尚未处理的样式和布局。

## 从样式到布局的输入契约

样式计算给布局提供 display、尺寸、边距、字体、书写模式和定位信息。布局根据可用空间建立 formatting context，计算每个盒的 border box、padding box 和内容位置。布局结果再交给绘制和合成。

`display: none` 的子树不参加布局；`visibility: hidden` 仍保留几何空间；`content-visibility: auto` 可能让屏外子树延迟布局。区分“没有盒”“有盒但不画”和“暂时跳过计算”，才能解释尺寸读取结果。

## 用证据判断规则成本

准备三个只改一个因素的样本：继承属性、颜色属性、几何属性。用 DevTools 的 Computed、Layout、Rendering 和 Performance 面板记录样式失效、布局、绘制和脚本时间，再改变 DOM 深度和选择器候选数量。

文章里的复杂度直觉只能作为假设。浏览器版本、页面规模、字体、contain 和硬件都会改变结果，报告性能结论时要写清输入和观察工具。
