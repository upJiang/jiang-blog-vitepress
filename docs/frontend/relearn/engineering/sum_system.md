# 前端工程系统设计

工程系统把组件、模板、数据、构建、发布和观测连成一条可回滚链路。页面搭建或低代码只是其中一种入口，它没有消除业务规则，只是把部分变更从源码转移到 Schema、运行时和发布平台。

## Schema 是公开协议

搭建页面通常由组件树、属性、数据绑定、动作和版本组成。Schema 一旦保存到数据库，就成为长期协议，组件重命名、属性删除和默认值变化都需要兼容旧文档。

~~~json
{
  "version": 3,
  "type": "Banner",
  "props": {
    "title": "Release",
    "tone": "info"
  }
}
~~~

运行时不能信任 Schema。读取时先校验版本和字段，再迁移到当前模型；未知组件、无效属性和权限不足要有明确降级。允许任意表达式或脚本会扩大注入和数据访问风险，动作应由白名单协议描述。
## 组件注册表连接编辑器与运行时

注册表保存组件名称、属性 schema、默认值、编辑器控件、运行时实现和兼容版本。编辑器使用它生成配置面板，预览和生产运行时使用同一解析合同。

组件发布要区分“新增兼容属性”和“破坏性变化”。旧版本需要保留到所有页面完成迁移，不能只升级编辑器然后假设线上 Schema 会自动变化。
## 数据绑定要有来源和权限

页面可以读取静态数据、上下文、接口结果和用户输入。每种来源要声明类型、刷新时机、错误状态和权限。服务端字段变化时，数据适配层负责把外部响应转换为稳定的页面模型。

客户端隐藏字段不能形成权限边界。编辑器能选择某个接口，也不代表当前访问者有权读取。发布前在服务端或可信网关校验身份、资源范围和动作参数。
## 发布版本要可预览和回滚

编辑状态、审核状态和线上状态使用不同版本。发布时把 Schema、组件运行时版本、资源摘要和依赖配置固化为一个制品，预览与生产使用同一份内容。

回滚需要能恢复上一 Schema 和相容的运行时。只回滚 JSON 而组件代码已经删除，页面仍会失败。保留策略应覆盖两边，并在清理旧资源前检查引用。
## 运行时要处理局部故障

单个组件数据失败时，页面可以展示该区域错误并继续其他内容；解析器崩溃或权限校验失败时，应停止危险动作。错误边界、超时、取消和重试要按组件职责设置，避免全页无限重试。

观测数据至少包含页面版本、组件类型、解析错误、接口错误和渲染耗时。上报前删除敏感字段并控制采样，不能把完整用户 Schema 和接口响应直接发送到日志。
## 工程系统用全链路样本验收

准备一个带数据、交互和权限的页面，从编辑、预览、审核、发布、观测到回滚走完整链路。再用旧 Schema、新组件、无权限用户和接口超时验证兼容性。

搭建效率和页面数量只能描述使用规模。真正的质量指标包括发布失败、回滚成功率、旧版本兼容、错误隔离和人工恢复时间。
