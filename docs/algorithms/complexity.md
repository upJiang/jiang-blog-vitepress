# 复杂度分析

两段程序在 10 个元素时都不到一毫秒，一段只扫描一次，另一段比较所有数对。输入扩大到一万后，前者约增加一千倍操作，后者可能增加一百万倍。复杂度描述这种增长关系，不预测某台电脑的精确耗时。

本篇从一次扫描、双循环和二分缩小三个例子理解 `O(n)`、`O(n²)` 与 `O(log n)`，再补充空间、递归、均摊和 JavaScript 隐藏成本。

## 第一步永远是定义 n

`n` 可以是数组长度，图算法还会使用节点数 `V` 与边数 `E`，矩阵使用行 `r` 与列 `c`。数值算法要区分数值大小和输入位数。没有定义规模，`O(n)` 没有可审查含义。

| 增长阶 | n 翻倍时 | 常见例子 |
| --- | --- | --- |
| `O(1)` | 基本不变 | 数组按下标读取 |
| `O(log n)` | 多常数步 | 二分查找 |
| `O(n)` | 约两倍 | 一次扫描 |
| `O(n log n)` | 略多于两倍 | 比较排序 |
| `O(n²)` | 约四倍 | 比较所有数对 |
| `O(2^n)` | 指数增加 | 子集搜索 |

严格说，O 是渐近上界，Ω 是下界，Θ 表示上下同阶。工程沟通常把 O 当作“复杂度”，仍应注明最坏、平均、期望或摊还情况。

## 步骤一：数总操作，不数缩进

两层循环不一定都是平方复杂度。双指针即使写在 while 中，只要 left 和 right 总共各移动不超过 n 次，整体仍是 `O(n)`。顺序执行的 `O(n) + O(n²)` 保留高阶为 `O(n²)`。

下面的函数比较每一对不同下标。输入 n 个元素时，次数是 `n(n-1)/2`，因此时间为 `Θ(n²)`，额外空间为 `O(1)`。

```ts
function countIncreasingPairs(values: readonly number[]): number {
  let count = 0
  for (let left = 0; left < values.length; left += 1) {
    for (let right = left + 1; right < values.length; right += 1) {
      if (values[left]! < values[right]!) count += 1
    }
  }
  return count
}
```

去掉常数 `1/2` 只用于描述增长阶。同阶方案在真实运行中仍会受到常数、缓存、分支、数据分布和引擎优化影响，所以理论分析之后还需要基准。

## 步骤二：递归写成递推关系

线性递归满足 `T(n)=T(n-1)+O(1)`，时间 `O(n)`，调用栈 `O(n)`。归并排序满足 `T(n)=2T(n/2)+O(n)`，得到 `O(n log n)`。朴素 Fibonacci 重复计算相同子问题，呈指数增长；记忆化后每个状态只算一次。

回溯还要包含输出成本。生成 n 个不同元素的所有排列有 `n!` 个结果，仅写出结果就需要 `Ω(n · n!)`，不能用剪枝承诺变成多项式。

## 步骤三：理解摊还与空间口径

动态数组扩容时某一次 push 可能复制 O(n) 个元素，但若容量倍增，一系列 n 次 push 的总复制量仍是 O(n)，所以单次摊还 O(1)。摊还是对操作序列的分析，不是随机输入平均值。

空间分析包括哈希表、临时数组和递归栈。输出本身不可避免时，文章应区分输出空间和辅助空间。JavaScript 的 `slice`、展开运算符和字符串拼接可能产生隐藏复制；`Array.shift()` 作为高频队列操作也可能反复移动后续元素。

## 步骤四：用基准检查常数和假设

基准固定输入，分别测冷启动与预热，运行多次看分布，并验证输出没有被优化掉。改变多个 n，观察增长斜率而不是一个时间点。性能测试同时记录内存和 GC，防止用空间换时间后只报告更快的平均值。

完整复杂度结论包括：规模定义、产生该阶的原因、最坏或摊还口径、额外空间以及语言实现假设。做到这些，复杂度才是论证，而不是背诵。
