# 数据结构基础

数据结构把数据组织方式和允许操作绑在一起。选择时先写访问模式：按下标读、按键查、两端进出、取最小值、维护顺序还是表达关系。名称相同的结构，在不同运行时中也可能有不同常数和内存布局。

## 用操作矩阵开始选择

| 结构 | 擅长的操作 | 主要边界 |
|---|---|---|
| Array | 下标访问、顺序扫描、尾部追加 | 头部插删和中间移动成本高 |
| Map / Set | 按键查找、去重 | 不提供排序与优先级 |
| Linked List | 已知节点处插删 | 随机访问要沿链移动 |
| Stack | 最近进入者先离开 | 只能直接操作栈顶 |
| Queue / Deque | 按顺序或两端进出 | 需要维护头尾不变量 |
| Heap | 反复取得最小或最大值 | 任意元素查找不快 |
| Tree | 层级、范围和有序关系 | 平衡策略影响高度 |
| Graph | 任意关系与路径 | 边数和遍历状态可能很大 |

复杂度表只是第一轮筛选。键类型、排序、迭代顺序、内存局部性、序列化和并发模型都会影响工程选择。
## 数组用连续编号表达顺序

数组适合按位置访问和线性扫描。JavaScript Array 还能稀疏、混合类型并动态扩容，不能把它与固定连续内存的 C 数组完全等同。TypedArray 才有固定元素类型和长度，适合二进制协议与数值缓冲区。

中间插入需要移动后续元素的逻辑位置。若业务经常按 ID 查任务，再用 `find` 扫描数组，规模增长后应增加 Map 索引，而不是等待换数据库才处理。
## Map 与 Set 保存键关系

Map 保存 key 到 value 的映射，Set 保存唯一键。对象也能当字符串键字典，但原型、属性描述符和键转换会增加边界；Map 能直接使用对象键，并有明确迭代顺序。

~~~ts
type Task = { id: string; priority: number }

const byId = new Map<string, Task>()
const seen = new Set<string>()

function register(task: Task): void {
  if (seen.has(task.id)) throw new Error('duplicate task')
  seen.add(task.id)
  byId.set(task.id, task)
}
~~~

Map 只保证键唯一，不能保证 Task 对象内容不可变。删除、更新和另一个索引必须在同一操作中同步，否则组合结构会失去一致性。
## 栈和队列限制访问顺序

栈维持 LIFO，适合调用、撤销、括号和 DFS。队列维持 FIFO，适合任务到达顺序和 BFS。限制访问能力让不变量更容易证明。

JavaScript 用数组尾部 `push/pop` 实现栈很直接。队列若频繁 `shift`，可使用头指针或环形缓冲区，避免每次移动剩余元素。
## 堆维护局部有序

二叉堆只保证父节点优先级不劣于子节点，因此根是最小值或最大值。插入和删除根沿一条树高路径调整，时间为 `O(log n)`；查看根是 `O(1)`。

堆不适合按 ID 删除任意任务，除非再维护 id 到堆下标的索引。优先队列常是“堆加 Map”的组合，而不是单一结构。
## 树和图表达关系

搜索树把小值放一侧、大值放另一侧，若不平衡会退化成链。Trie 按字符路径组织前缀，空间取决于分支表示。图由顶点和边组成，邻接表适合稀疏图，邻接矩阵适合快速判断任意两点是否有边但占 `O(V²)` 空间。

关系方向、重复边、自环和权重都要进入数据模型。忽略这些条件，遍历算法会在 visited、入度或最短路上给出错误结果。
## 组合结构要写同步不变量

一个带优先级且支持按 ID 取消的调度器，可以使用 Map 保存实体、Heap 保存优先顺序。两边都必须满足：

- 每个活跃 ID 在 Map 中恰好出现一次。
- Heap 中的活跃节点能找到同一任务。
- 更新优先级后恢复堆序。
- 删除后没有可被再次消费的旧节点。

可以使用惰性删除，让 Heap 暂时保留旧节点，弹出时再与 Map 当前版本核对。这样降低任意删除成本，也增加内存和清理逻辑。
## 验证从操作序列开始

为每个结构生成随机操作序列，与简单参考实现对比。每次操作后检查大小、顺序、键集合和结构不变量。再用接近真实分布的数据测量时间和峰值内存。

“选对数据结构”意味着常用操作成本可接受、边界可证明、失败能恢复。复杂度只是其中一个条件。
