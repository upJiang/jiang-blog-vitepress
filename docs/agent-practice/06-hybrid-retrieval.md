# 06｜从关键词检索扩展到混合召回

用户问“编号 DOC-2026-042 的负责人是谁”。向量检索擅长找语义相近内容，却可能把编号当普通字符；全文检索擅长词面匹配，又可能漏掉“凭证过期”和“Token 失效”这种不同表达。

本篇用同一个检索器组合多条通道。每条通道解决一种问题，最后把结果去重、融合、重排，并在某条服务失败时保留可解释的降级结果。

## 先理解召回和重排

**召回**是从大量片段中快速找出候选，宁可稍多，也不要过早漏掉正确答案。**重排**是对较小候选集做更精细的相关性排序。

```mermaid
flowchart LR
  A[用户问题] --> B[选择检索通道]
  B --> C[精确/全文/向量/表格召回]
  C --> D[按片段去重与融合]
  D --> E[重排]
  E --> F[受预算约束的证据集]
```

## 第一步：精确检索负责编号和别名

包含字母、数字和分隔符的业务编号，适合在标题、别名、精确词和结构化字段中查询。精确编号无结果时，系统不应找一篇“看起来类似”的文档冒充答案。

同样逻辑可以处理稳定别名和标题。它不是字符串包含的万能通道，仍要限制知识版本和访问范围。

## 第二步：全文与向量解决不同表达

全文通道保留重要业务词，适度移除“请问、如何、当前”等问题框架词。首次严格查询无结果时，才做有限降级，不退化为无范围的全库模糊搜索。

向量通道处理语义改写，例如“登录凭证过期后怎么恢复”和“Token 失效处理”。嵌入服务失败时，这条通道返回空并记录降级，精确与全文仍继续运行。

## 第三步：表格需要字段语境

第 04 篇已经把表格行保存为结构字段。查询“request_timeout 是多少”时，候选不能只包含 `30s`，还要带表头、章节路径和行文本。

```text
标题：服务配置
路径：运行参数 / 超时
字段：参数=request_timeout；值=30s
正文：参数 request_timeout 的值为 30s
```

这份输入帮助重排器和回答模型理解 `30s` 到底描述什么。

## 第四步：融合时先去重，再限制来源占比

同一片段可能被精确、全文和向量同时命中。融合以稳定片段 ID 去重，并记录它来自哪些通道。多路命中可以增加可信度，但不会重复占用三份上下文。

长文档可能命中大量相邻片段，因此还要限制单文档占比，为其他来源留出证据空间。具体上限由策略和 Eval 校准，不写成通用最佳数字。

## 第五步：重排输入要可解释

重排不仅看正文，还结合标题、章节路径、片段类型和结构字段。最终排序可以组合召回名次、词法覆盖和模型重排结果。

精确编号的词法命中通常应高于泛化语义相似；开放式问题则可能更多依赖向量和全文。这就是多路检索比“只选最先进的向量库”更稳健的原因。

## 正常结果和失败结果

| 问题 | 主要通道 | 正常结果 | 失败时怎样处理 |
| --- | --- | --- | --- |
| 查询明确编号 | 精确 | 返回目标记录 | 无命中就明确不足 |
| 同义问题 | 向量 + 全文 | 找到语义相近片段 | 向量失败时保留全文 |
| 查询表格字段 | 表格 + 精确 | 带表头和值 | 不返回孤立数值 |
| 多主题问题 | 多分支 | 保留多个来源 | 单文档不能占满预算 |

测试会让嵌入客户端抛出异常，确认全文结果仍然返回，并在 Trace 中标记向量降级；精确编号测试则确认目标片段优先于通用文本。

## 当前实现的边界

通道权重、候选数和重排阈值都需要评测集校准。降级能保持可用性，却可能降低召回质量，客户端不应把降级静默当成完整结果。

下一篇把用户身份和显式文档范围应用到每一条召回、缓存和最终引用。

## 为不同问题选择召回通道

用四类问题做最小实验：精确编号“DOC-104”、标题“访问权限申请”、同义表达“怎样开通系统使用资格”、表格查询“访客账号有效期”。每类问题先单独跑通道，再观察融合结果。这样能知道某条结果为什么出现，而不是只盯最终十条候选。

| 查询类型 | 优先通道 | 补充通道 |
| --- | --- | --- |
| 编号、固定术语 | Exact、Title、Alias | 全文 |
| 词语基本一致 | 全文检索 | 向量 |
| 表达差异较大 | 向量检索 | 全文、Alias |
| 明确字段和值 | 表格或结构化查询 | 全文 |

融合前先用稳定证据 ID 去重，再用 RRF 等名次方法合并不同分数体系。随后限制单一来源占比，恢复父级或相邻片段，最后才交给重排器判断问题与完整语境的相关性。重排器失败时可退回融合名次，但权限过滤和版本过滤不能降级。

测试报告记录每路候选、融合名次、重排名次和最终引用。若目标证据没进候选，改召回；进了候选却被压低，查融合与重排；最终证据正确而答案错误，再进入生成和验证层。把阶段拆开，调优才不会靠反复改一个权重碰运气。
