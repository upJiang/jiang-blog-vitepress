# 工程问题与学习资源索引

“React 并发调度就是 `requestIdleCallback` 吗？”搜索结果里可以找到很多肯定答案，但 React 当前调度实现与浏览器这个 API 不能简单画等号。学习的产物不应是一条最流行的回答，而是一条标注版本、前提、证据和反例的结论。

本篇用同一方法组织前端、后端、Agent、运维和安全资料。资源链接只是入口，能够复现和定期复审的结论才是产物。

## 证据从哪里来

优先顺序通常是：现行语言或协议规范，框架当前官方文档与 Changelog，源码与测试，能复现的论文或技术文章。搜索与 AI 输出适合寻找线索，不直接充当事实来源。

官方资料也有版本和简化。冲突时先核对版本、运行环境和术语，再读规范或源码，并设计最小实验。

```mermaid
flowchart LR
  Q[具体问题] --> S[候选资料]
  S --> V[版本与前提]
  V --> X[源码或最小实验]
  X --> C[带边界结论]
  C --> T[测试或文章]
  T --> R[版本变化后复审]
```

## 步骤一：把问题写窄

不要问“Vue 响应式原理是什么”，改成“某版本中 computed 在依赖变化后何时标脏，消费者何时得到调度通知”。具体问题决定该看公共文档、测试还是实现源码，也能设计反例。

一条知识记录包含：结论、适用版本、已知反例、来源、最小实验、工程影响和复审触发。性能结论还记录硬件、数据、冷暖状态与分布，不从一次本机计时推断所有环境。

## 步骤二：按领域选择一手入口

| 领域 | 优先入口 |
| --- | --- |
| HTML 与 DOM | WHATWG HTML、HTML AAM、Web Platform Tests |
| JavaScript | ECMA-262、TC39、test262 |
| CSS 与可访问性 | CSSWG、WCAG、WAI-ARIA、APG |
| React/Vue/Vite | 官方文档、RFC、源码测试与 Changelog |
| Node/Python/Go | 语言标准库与框架官方文档 |
| 数据库 | PostgreSQL/Redis 文档、执行计划和隔离实验 |
| Agent | 官方 API、协议规范、框架文档、Eval 与源码测试 |
| 运维安全 | OCI/Docker/Nginx、OpenTelemetry、OWASP、SRE |

MDN 适合快速入口和兼容说明，精确语义回到规范与浏览器测试。数据库优化先查看执行计划、锁和数据分布，不从“加缓存、分库”开始。

## 步骤三：做能推翻结论的实验

实验只改变一个变量，固定版本、配置和数据，并包含正常与边界输入。事件循环实验记录执行顺序，缓存实验制造乱序失效，并发实验用同步屏障放大竞态。若实验失败，修正结论，而不是继续寻找支持原判断的文章。

阅读源码从公共入口和测试开始，沿核心数据结构、调度与错误路径追踪。教学版 mini 实现要明确省略了什么，不能把几十行 Demo 描述成框架完整实现。

## 步骤四：把面试题和项目经验转成知识

面试“标准答案”按主题拆成概念、现行规范、反例和验证。HappyPack、DLLPlugin 等历史技术保留演进背景，不作为当前默认方案。重复问题合并，错误答案直接纠正。

私有项目只用于验证工程行为。公开文章抽取跨系统共性，用中性名称重新写示例；不公开项目、组织、路径、接口、表字段、真实数据、提示词、密钥或截图。无法从代码和测试证明的能力标为设计目标或可选演进。

## 学习完成的标准

| 检查 | 合格表现 |
| --- | --- |
| 版本 | 明确适用标准、框架或运行时 |
| 来源 | 至少有可追溯的一手资料 |
| 实验 | 能复现并包含反例或边界 |
| 工程性 | 说明失败、安全、并发或恢复 |
| 匿名化 | 无法反推私有项目和真实数据 |
| 维护 | 写明何时需要重新核对 |

收藏数量、文章字数和 `updated` 日期都不能证明掌握。一个专题在能画出模型、解释来源、运行反例、写出测试并说明限制后，才形成可复用知识。

## 把一个陌生问题查成可复用知识

假设问题是“浏览器为什么没有发送 Cookie”。先把范围写窄：浏览器版本、请求来源与目标、Cookie 属性、是否跨站、实际请求头。然后按“规范/官方文档、框架源码与测试、最小实验、社区讨论”顺序找证据，后者用于发现线索，不替代前者。

| 记录项 | 需要留下什么 |
| --- | --- |
| 问题 | 可复现环境和预期/实际行为 |
| 一手结论 | 规范或官方行为，带版本和链接 |
| 实验 | 最小代码、输入、输出和反证条件 |
| 工程限制 | 框架、代理、安全策略带来的额外边界 |
| 适用范围 | 哪些浏览器/版本/场景成立 |
| 后续复审 | 哪个变化会让结论过期 |

面试题也用同一方法处理。把“GET 比 POST 安全”拆成传输加密、缓存、日志、副作用与幂等几个问题，就会发现方法名本身不是安全等级。正确知识合并进对应主题，重复题不保留成孤立答案。

每周选择一个实际问题完成一页证据笔记，并让另一位读者只靠笔记复现实验。能解释结论、边界和验证方式，才算学习完成；收藏链接和复制答案只是材料收集。资源索引应优先维护高质量入口，而不是不断增加无人复审的链接数量。
