# 单元、集成、契约与端到端测试

一个创建回合接口失败了。单元测试都绿，但真实 PostgreSQL 的唯一约束报错；端到端测试又要启动整套服务，十分钟后才告诉你 HTTP 字段写错。测试分层不是把测试越多越好，而是让每层验证自己最擅长的事实。

本文用“创建一个只读问答回合”贯穿四层测试，给出选择依据和一张可迁移的测试策略表。

## 先看四层边界

~~~mermaid
flowchart TB
  A[规则与状态转换] --> B[单元测试]
  C[数据库/Redis/队列适配] --> D[集成测试]
  E[服务间请求与事件契约] --> F[契约测试]
  G[真实入口到终态] --> H[端到端测试]
~~~

越靠下环境越真实、执行越慢、诊断越宽。底层测试不能替代上层路径，上层失败也不应承担所有边界组合。

## 第一步：单元测试保护规则

把“无证据不能完成”“重复幂等返回原结果”“取消不再写入”放在应用服务单元测试。替换数据库、模型和队列，只记录调用参数与顺序。

测试输入应覆盖正常、缺范围、无证据、依赖超时、重复键和非法状态。断言结果与副作用：不仅断言返回值，还要确认越权的 Repository 没被调用、终态只写一次。

单元测试快的原因是没有网络和磁盘。它不能证明 SQL、序列化、连接取消或真实模型格式，但能快速阻止规则回归。

## 第二步：集成测试验证适配器

Repository 集成测试连接隔离 PostgreSQL，验证迁移、唯一索引、事务回滚、锁与查询。Redis 集成测试验证序列化、TTL、缓存失效和断连降级。队列集成测试验证 ACK、重试、重复消息与 Worker 恢复。

每个测试准备自己的数据，结束时回滚事务或删除明确目标。不要把开发数据库当成隔离数据库，也不要用全局清空命令清理未知数据。

集成测试应断言数据库状态和事件事实，而不是只断言 API 返回 200。客户端超时测试要确认下游收到取消或任务进入可恢复状态。

## 第三步：契约测试保护跨服务变化

HTTP/OpenAPI 契约验证字段、状态码、错误结构和版本兼容；Protobuf 契约检查字段编号、保留字段和旧客户端解析；事件契约检查版本、必填字段和消费者未知字段行为。

契约测试回答“提供者和消费者对形状的理解是否一致”，不回答业务数据是否正确。提供者构建时验证自己能生成契约，消费者用契约样例验证解析；关键生产者/消费者组合再做少量集成测试。

向后兼容常见策略：新增可选字段、不复用已发布编号、不突然改变枚举语义、保留旧错误类别一段兼容窗口。删除字段需要先停止使用，再经过版本升级。

## 第四步：端到端只覆盖关键路径

E2E 从真实入口开始，经过鉴权、数据库、队列、Agent Runtime 和事件终态。它适合验证部署配置、路由、迁移、代理、SSE 重放和一条核心用户路径。

不要把每个边界情况都写成 E2E。端到端失败时可能是任一依赖、时间、并发或测试数据导致，定位慢且容易抖动。对外部模型使用固定替身或录制响应，另行做少量真实供应商 smoke，并控制成本。

异步 E2E 要等待可观察条件：终态事件、任务状态或数据库断言，而不是固定 sleep。测试超时应包含诊断信息和 Trace ID。

## 用同一个需求做策略表

| 行为 | 单元 | 集成 | 契约 | E2E |
| --- | --- | --- | --- | --- |
| 无范围拒绝 | 详细分支 | 可选 | 错误结构 | 一条回归 |
| PostgreSQL 事务回滚 | 不适合 | 重点 | 不适合 | 关键路径 |
| 事件字段兼容 | 不适合 | 消费者适配 | 重点 | 一条端到端 |
| 客户端断开 | 模拟取消 | 真实 ASGI/队列 | 流协议 | 代表路径 |
| 重复消息 | 状态规则 | Broker/Worker | 事件幂等 | 少量回归 |

这张表是工作产物。新增需求时先填“哪层能证明”，再写测试，避免测试数量先行。

## 测试失败后的观察顺序

1. 单元失败：看输入、期望状态和副作用调用。
2. 集成失败：看迁移版本、连接、隔离数据、SQL 和真实错误。
3. 契约失败：比较版本、字段、状态码和生成样例。
4. E2E 失败：先保存日志/Trace，再判断是测试数据、环境还是产品路径。

不要通过增加重试和 sleep 掩盖竞态。先找等待条件、所有权和清理遗漏。

## 可以带回工作的检查清单

1. 每个关键业务规则是否有快速单元测试？
2. 事务、锁、缓存和队列是否在隔离依赖上验证？
3. 服务间 HTTP、RPC 和事件是否有契约门禁？
4. E2E 是否只覆盖关键路径且等待可观察终态？
5. 测试数据是否可追踪、可清理、不会污染共享环境？
6. 失败是否能通过日志和 Trace 诊断，而不是只说超时？
7. 代码、迁移、契约和测试是否在同一变更中演进？

迁移练习：为一次“用户取消流式问答”分别写单元、集成、契约和 E2E 的最小断言，说明每层不负责验证什么。
