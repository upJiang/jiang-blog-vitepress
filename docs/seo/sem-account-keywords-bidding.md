# SEM 账户结构、关键词、出价与预算

搜索广告优化的起点是需求和测量，不是“把预算加到表现最好的词”。账户结构要让搜索词、广告承诺、落地页和业务价值可以互相解释；品牌、非品牌、竞品、地域和不同业务线应在需要时拆分，避免高意图品牌词掩盖非品牌没有增量。出价自动化只有在转化定义稳定、样本和延迟可接受时才值得使用。

## 竞价链路和账户六层

一次展示通常经历查询匹配、资格判断、竞价、广告质量/相关性、位置和最终点击。平台具体公式会变化，不能把一个简化的质量分数当作完整排名解释。账户中至少要能区分：账户、广告系列、广告组、关键词/匹配、创意和落地页/转化。

```mermaid
flowchart LR
  Q[搜索词] --> M[匹配与否定]
  M --> G[广告组与创意]
  G --> L[落地页]
  L --> C[主要转化]
  C --> V[有效业务价值]
  V --> B[出价与预算调整]
```

每层只承担一个决策维度：系列控制地域、预算和目标；广告组控制紧密主题；关键词表达匹配意图；创意兑现承诺；落地页提供证据和行动；转化回传最终业务状态。多个层级重复放同一个词，容易造成报告混乱和否定词冲突。

## 品牌、非品牌和竞品分层

品牌词常有较高相关性和较低成本，但未必带来增量；非品牌词更能验证新需求，却通常需要更高教育成本；竞品词要考虑商标、平台政策和用户误认风险。分层后分别查看展示、点击、有效业务、毛利和新客比例，不能把三者混成一个平均 CPA。

| 系列 | 目标 | 预算判断 | 护栏 |
| --- | --- | --- | --- |
| 品牌 | 防守和承接导航需求 | 观察增量和自然替代 | 蚕食自然点击 |
| 非品牌 | 验证新需求 | 依据有效业务边际价值 | 无效查询、低质量线索 |
| 竞品 | 小规模比较实验 | 单独设上限和合规审查 | 商标与误导风险 |

## 匹配模式与否定词

广泛、词组和完全匹配的具体行为由平台定义并持续变化，不应凭旧经验推断。启动时用高意图样本和严格否定词建立边界，定期查看真实搜索词报告，识别同义表达、无关需求和重复系列。否定词要有负责人和变更记录，避免一个系列的否定误伤另一个系列。

```text
搜索词审核：
1. 是否满足产品/服务对象和地域？
2. 是了解、比较、交易还是支持/招聘/免费需求？
3. 是否已经有现有页面或广告系列承接？
4. 需要加入、降价、否定还是继续观察？
```

## 出价和预算用边际回报

平均 CPA 或 ROAS 会掩盖增加一元预算带来的边际变化。可承受成本应从有效业务毛利和成交延迟倒推，扣除退款、销售成本和归因误差预留。长成交周期要区分即时线索、资格通过、成交和回款，不能让平台只优化最容易发生但价值最低的点击。

```text
可承受 CPA = 单次有效业务毛利 × 可分配比例
边际价值 = 新增有效业务毛利 / 新增广告成本
```

示例是决策框架，不是固定比例。预算调整应设置变化幅度和观察窗口；频繁每天改出价会让自动策略一直处于学习状态，也难以区分季节和真实改动效果。小样本时先控制曝光和查询质量，等转化信号稳定再扩大自动化范围。

## 上线前基线

记录账户/系列/广告组/关键词/创意/落地页/主要转化的版本、预算、地域、时间、匹配和否定词。用测试查询验证广告承诺与落地页一致、UTM 或平台参数保留、服务端事件去重、隐私同意和离线回传可用。广告上线前就写停止条件：无效查询比例超过阈值、业务质量持续低于底线、追踪中断、价格或库存变化等。

## 验证和复盘

每周按搜索词、系列、落地页和有效业务查看数据，先排除追踪异常，再调整查询、创意、页面和预算。报告要区分事实、假设和缺口：例如“点击增加”是事实，“标题导致质量提高”是待验证假设。只有固定时间、归因窗口和业务状态后，才能比较不同预算策略。

## 实施记录：从问题到动作

预算决策应建立在搜索词和有效业务样本上。自动出价前固定转化定义与回传延迟，保留人工上限和否定词审核；当无效查询、成本或业务质量越过护栏时，先收紧匹配和预算，再调查落地页和产品承接。

执行记录需要保留四类信息：基线快照、改动版本、观察条件和业务对账。基线至少包含 URL、模板、查询/搜索词、状态码、索引资格、事件口径和时间范围；改动要能定位到内容、路由、缓存、创意或出价的具体版本；观察条件要记录设备、地域、语言、模型或平台版本；业务对账要以服务端的资格、成交、退款和回款为准。这样在结果变差时可以回到上一个可用版本，而不是凭记忆争论。

## 故障演练与回滚

| 演练场景 | 预期信号 | 保护动作 | 恢复证据 |
| --- | --- | --- | --- |
| robots 或 WAF 误拦截 | 抓取 4xx 上升、核心 URL 失败 | 恢复规则并限制变更面 | GET、日志、覆盖报告 |
| 模板发布错误 | title/canonical/正文异常 | 回滚模板或内容版本 | 原始 HTML 对比 |
| 追踪重复或丢失 | 客户端与服务端数量不一致 | 停止自动化学习，修复去重 | 事件 ID 对账 |
| 业务质量下降 | 有效率、退款或毛利越过护栏 | 收紧查询/预算或下线页 | CRM/订单状态 |

演练使用模拟场景和最小流量，不改变真实生产预算或数据。回滚后再次检查公开页面、缓存、站点地图、广告参数、事件队列和业务状态；只有所有关键证据恢复，才允许继续实验。

## 结果判定与后续动作

把结论分为事实、假设和缺口。事实必须能由页面、日志、平台、实验或业务记录直接复核；假设写出可证伪的预测；缺口说明缺少哪项数据以及它会影响哪项判断。观察周期内不要连续叠加多个主变量，也不要把平台评分、平均排名或单次引用当作有效业务的替代。

```text
基线 -> 小范围变更 -> 技术验收 -> 搜索/广告观察 -> 业务对账 -> 继续、调整、合并或停止
```

## 操作清单与决策记录

自动出价必须有稳定的主要转化、预算上限和无效查询护栏，学习异常时回到人工边界。

发布或投放前按顺序记录：

1. **范围**：目标用户、语言、地域、页面类型和明确不覆盖的需求。
2. **证据**：查询样本、页面版本、规范/源码/实验来源、数据时间和负责人。
3. **技术**：状态码、抓取规则、canonical、sitemap、内链、缓存、脚本失败和移动端表现。
4. **业务**：主转化、资格条件、去重键、成交/退款状态和归因窗口。
5. **保护**：预算或发布范围、护栏指标、观察周期、回滚版本和停止条件。

## 指标与停止条件

| 信号 | 可继续的证据 | 应暂停或回滚 |
| --- | --- | --- |
| 技术 | 公开 URL 状态稳定，规范页和索引目标一致 | 5xx、误拦截、canonical 冲突或空壳正文 |
| 搜索 | 相关查询、页面和点击方向一致 | 查询意图偏移、重复页面或无效展现激增 |
| 用户 | 到站后完成主要任务，错误反馈可解释 | 跳转、表单、脚本失败导致任务中断 |
| 业务 | 有效率、毛利和退款符合护栏 | 低质量线索、退款上升或归因无法对账 |

停止不是失败，而是保护样本和现金流的工程动作。停止后保留原始事件、页面快照和决策日志；需要恢复时先回到最后一个可验证版本，再单独改变一个变量。

### 预算变更记录

每次预算、匹配模式、否定词或出价策略变更都记录原因、预期、上限和观察窗口。若搜索词质量下降，先查看真实查询和落地页承接；若转化突然下降，先核对追踪和业务延迟，再决定是否调整出价，避免用竞价动作掩盖数据故障。

预算分配要同时考虑新客比例、成交延迟、毛利和现金流，而不是只看平台当日回报。品牌系列可能保护导航需求，非品牌系列负责验证增量，竞品系列应设置独立上限；三个系列的结果不能直接平均。

对小样本采用保守决策：先扩大查询质量和测量覆盖，再逐步提高预算。没有足够有效业务时，自动策略的精细数值只是噪声，不应被包装成确定性结论。

上线前还要检查系列之间的预算共享、地域和时段设置、广告排期、品牌排除、否定词继承以及落地页状态。配置变更通过评审和小范围发布，保留旧版本快照，避免在高峰期一次修改全部系列。发现成本突变时先冻结扩大动作，保存搜索词和平台日志，再按匹配、创意、页面、追踪、业务五层定位。

平台建议不等于业务决策。任何自动建议先在模拟或小预算系列验证，明确是否改变查询覆盖、边际成本和新客质量，再决定是否应用。

每次策略变更后保留旧配置、搜索词快照和业务对账，观察足够的成交延迟再做下一步动作。预算上限是风险控制，不是预期花完的指标；没有增量证据时，继续投放并不能证明需求存在。

```text
事实（页面/日志/业务记录） -> 假设（可证伪预测） -> 动作（单一变量） -> 观察（固定口径） -> 决策（继续/调整/停止）
```
