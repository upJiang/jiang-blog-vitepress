# SEO 内容生产、AI 辅助与 GEO 质量控制

生成式搜索改变了用户获取答案的入口，但没有改变内容质量的基本约束：页面要解决真实问题，事实要有来源，作者要承担责任，机器和人都能理解结构。GEO（Generative Engine Optimization）不等于给模型塞一段“请引用我”的提示，也不等于批量生成同义文章。更可行的做法是把内容当作一个带证据、版本和验收门禁的工程资产。

## 内容类型有不同职责

先区分内容在用户旅程中的职责，再决定格式和指标：

| 类型 | 主要任务 | 证据要求 | 主要指标 |
| --- | --- | --- | --- |
| 概念解释 | 建立共同语言 | 规范、教材、定义 | 阅读完成、后续查询 |
| 实现指南 | 让读者完成操作 | 可运行代码、版本、实验 | 复制、运行、问题解决 |
| 决策比较 | 说明取舍 | 可重复条件、限制 | 试用、咨询、选择 |
| 参考文档 | 快速查值 | 完整字段、版本、变更记录 | 回访、搜索定位 |
| 研究/报告 | 支撑判断 | 原始数据、方法、时间 | 引用、外部链接 |

一页只应有一个主任务。把概念、产品推销和教程强行塞进同一页，既难以衡量也难以被生成式系统准确摘取。对于需要转化的页面，交易事实和操作路径必须显著可见，而不是藏在结构化数据里。

## 内容简报不是标题列表

发布前简报至少包含读者、问题、适用范围、反例、主查询簇、页面类型、证据清单、内部链接、作者和更新条件。简报还要记录“不能声称什么”，例如没有实验就不能说性能提升多少，没有合规审查就不能说满足某项法规。

```yaml
brief:
  task: 解释如何为 SSE 设计可重放事件流
  audience: 需要上线实时通知的后端工程师
  scope: Last-Event-ID、事件序列、权限、背压
  out_of_scope: 具体供应商价格和未验证的吞吐指标
  evidence:
    - WHATWG EventSource 规范
    - 可复现实验与测试代码
  success: 读者能在隔离环境复现断线重放
  review_when: 协议或实现发生兼容性变化
```

## AI 适合参与哪里

模型可以用于整理访谈原文、生成大纲候选、发现术语冲突、把代码示例改写成不同语言、提出可能的反例和摘要版本；它不应成为事实来源、作者责任主体或最终发布门禁。生成内容必须回到一手文档、源码、实验和产品记录核对。对于引用、数字、版本、兼容性和安全结论，宁可暂时降低表达强度，也不要让流畅句子替代证据。

```mermaid
flowchart LR
  B[内容简报] --> R[资料检索]
  R --> D[AI 起草/改写]
  D --> H[人工事实核验]
  H --> T[技术/安全审查]
  T --> P[发布与内链]
  P --> M[搜索与业务指标]
  M --> U[更新/合并/下线]
```

如果使用检索增强生成，应保留每条关键断言与来源的映射；如果使用模型做内容质量评分，评分只能作为排序信号，不能代替领域审阅。禁止用隐藏文本、不可见关键词、伪造作者、批量低价值页面或诱导模型引用等方式操纵结果。

## 让页面更容易被引用

生成式系统通常需要从页面识别实体、主张、条件和来源。可引用性来自清晰结构而不是神秘技巧：首段直接回答页面主问题；每个小节有明确标题；代码、表格和示例说明前提；数字带单位、时间和方法；引用链接指向原始资料；作者和更新时间可验证。一个页面还应明确哪些结论是经验、哪些是规范要求、哪些是模拟场景。

```text
断言：启用断线重放后，客户端可以从上次收到的序号继续请求事件。
条件：服务端持久化事件序列，客户端发送 Last-Event-ID，事件仍在保留窗口内。
证据：协议规范 + 示例实现 + 断网/恢复测试。
边界：超过保留窗口时只能返回“需要重新同步”，不能补造历史事件。
```

不要承诺“被 AI 搜索引用”。可观察的替代指标包括：带引用链接的外部访问、品牌/主题实体提及、生成式结果中的页面出现样本、引用后的停留和业务质量。生成式结果具有随机性，采样时固定查询、语言、地区、时间和模型版本，并记录没有出现的样本。

## 内容质量门禁

质量检查应区分硬门禁和软评分。硬门禁包括：没有来源的关键事实、代码无法运行、涉及安全/法律的结论没有审查、作者和更新时间缺失、标题承诺与正文不一致、与现有页面重复。软评分可以评估任务完整度、示例清晰度、内链价值和语言质量，但低分应进入人工队列，不自动发布。

```ts
type ContentGate = {
  hasPrimarySources: boolean
  claimsHaveEvidence: boolean
  examplesReproducible: boolean
  authorReview: boolean
  duplicateRisk: 'low' | 'medium' | 'high'
}

function publishable(gate: ContentGate) {
  return gate.hasPrimarySources && gate.claimsHaveEvidence
    && gate.examplesReproducible && gate.authorReview
    && gate.duplicateRisk !== 'high'
}
```

门禁结果要保存内容版本、来源版本和审阅人。内容改写后，至少重新检查受影响的断言、代码和内部链接。不要把“AI 检测分数”当作事实质量指标；它无法证明内容真实，也无法证明页面对用户有帮助。

## 更新和淘汰

设置更新触发器比设置固定发布数量重要：规范版本变化、依赖 API 变化、实验数据过期、查询意图变化、排名页格式变化、产品功能下线和用户反馈集中出现时进入复审。复审可选择改写、拆分、合并或下线。下线时保留决策记录和替代链接，避免旧 URL 继续被内链和 sitemap 引用。

## 验证与指标

技术指标包括索引资格、抓取状态、规范 URL、结构化数据错误；内容指标包括查询覆盖、阅读完成、返回搜索、引用和纠错反馈；业务指标包括有效线索、订单质量、退款和留存。不要用页面数、字数、模型生成量或单一排名作为质量代理。每次内容实验只改变一个主要变量，并至少覆盖一个完整搜索与业务观察周期。

## 实施记录：从问题到动作

生成式搜索观察应保存采样条件和原始结果，并把错误引用、主体混淆和过期事实当作内容缺陷回流。不能通过增加重复段落或隐藏指令提高出现概率；应补足原始证据、作者责任和页面结构。

执行记录需要保留四类信息：基线快照、改动版本、观察条件和业务对账。基线至少包含 URL、模板、查询/搜索词、状态码、索引资格、事件口径和时间范围；改动要能定位到内容、路由、缓存、创意或出价的具体版本；观察条件要记录设备、地域、语言、模型或平台版本；业务对账要以服务端的资格、成交、退款和回款为准。这样在结果变差时可以回到上一个可用版本，而不是凭记忆争论。

## 故障演练与回滚

| 演练场景 | 预期信号 | 保护动作 | 恢复证据 |
| --- | --- | --- | --- |
| robots 或 WAF 误拦截 | 抓取 4xx 上升、核心 URL 失败 | 恢复规则并限制变更面 | GET、日志、覆盖报告 |
| 模板发布错误 | title/canonical/正文异常 | 回滚模板或内容版本 | 原始 HTML 对比 |
| 追踪重复或丢失 | 客户端与服务端数量不一致 | 停止自动化学习，修复去重 | 事件 ID 对账 |
| 业务质量下降 | 有效率、退款或毛利越过护栏 | 收紧查询/预算或下线页 | CRM/订单状态 |

演练使用模拟场景和最小流量，不改变真实生产预算或数据。回滚后再次检查公开页面、缓存、站点地图、广告参数、事件队列和业务状态；只有所有关键证据恢复，才允许继续实验。

## 结果判定与后续动作

把结论分为事实、假设和缺口。事实必须能由页面、日志、平台、实验或业务记录直接复核；假设写出可证伪的预测；缺口说明缺少哪项数据以及它会影响哪项判断。观察周期内不要连续叠加多个主变量，也不要把平台评分、平均排名或单次引用当作有效业务的替代。

```text
基线 -> 小范围变更 -> 技术验收 -> 搜索/广告观察 -> 业务对账 -> 继续、调整、合并或停止
```

## 操作清单与决策记录

固定查询、语言、地区和模型版本采样，记录引用是否准确，把错误回流到来源和页面结构。

发布或投放前按顺序记录：

1. **范围**：目标用户、语言、地域、页面类型和明确不覆盖的需求。
2. **证据**：查询样本、页面版本、规范/源码/实验来源、数据时间和负责人。
3. **技术**：状态码、抓取规则、canonical、sitemap、内链、缓存、脚本失败和移动端表现。
4. **业务**：主转化、资格条件、去重键、成交/退款状态和归因窗口。
5. **保护**：预算或发布范围、护栏指标、观察周期、回滚版本和停止条件。

## 指标与停止条件

| 信号 | 可继续的证据 | 应暂停或回滚 |
| --- | --- | --- |
| 技术 | 公开 URL 状态稳定，规范页和索引目标一致 | 5xx、误拦截、canonical 冲突或空壳正文 |
| 搜索 | 相关查询、页面和点击方向一致 | 查询意图偏移、重复页面或无效展现激增 |
| 用户 | 到站后完成主要任务，错误反馈可解释 | 跳转、表单、脚本失败导致任务中断 |
| 业务 | 有效率、毛利和退款符合护栏 | 低质量线索、退款上升或归因无法对账 |

停止不是失败，而是保护样本和现金流的工程动作。停止后保留原始事件、页面快照和决策日志；需要恢复时先回到最后一个可验证版本，再单独改变一个变量。

```text
事实（页面/日志/业务记录） -> 假设（可证伪预测） -> 动作（单一变量） -> 观察（固定口径） -> 决策（继续/调整/停止）
```
