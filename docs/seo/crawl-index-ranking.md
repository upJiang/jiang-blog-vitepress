# 搜索引擎怎样发现、收录和排序网页

一篇文章发布后，在浏览器能打开，却搜不到标题。此时改标题、增加字数还是提交站点地图？回答这个问题前，要先知道网页从发布到出现在搜索结果中经历了哪些阶段。

本篇依次解释发现、抓取、渲染、索引、排序和点击。每个阶段都有自己的证据，前一层没有通过时，不应该跳到后一层猜原因。

## 先看六个阶段

```mermaid
flowchart LR
  A[发现 URL] --> B[抓取响应]
  B --> C[渲染页面]
  C --> D[建立索引]
  D --> E[针对查询排序]
  E --> F[展示与点击]
```

**发现**表示搜索引擎知道这个 URL；**抓取**表示爬虫请求了页面；**渲染**表示系统处理 HTML、CSS 和 JavaScript；**索引**表示页面有资格进入搜索数据库；**排序**针对某个查询判断结果顺序；最后用户才会看到并决定是否点击。

“已抓取”不等于“已收录”，“已收录”也不等于每个关键词都有排名。

## 第一步：搜索引擎怎样发现 URL

常见入口有站内链接、站点地图、外部链接和历史抓取记录。只有站点地图而没有站内入口的页面，用户难以访问，搜索引擎也很难理解它与网站主题的关系。

检查新页面时，先确认栏目页或相关文章能通过普通链接到达它，站点地图包含规范 URL，并且 URL 没有只存在于登录后或点击脚本中。

## 第二步：抓取时先看 HTTP

爬虫请求 URL 后，服务器返回状态码、响应头和正文。`200` 表示请求成功，`301/308` 表示永久跳转，`404` 表示资源不存在，`5xx` 表示服务端故障。

一个实际故障是：站内点击无后缀文章正常，刷新 `/docs/example` 却返回 404，而 `/docs/example.html` 返回 200。页面内容没有问题，错误发生在 Nginx 将公开 URL 映射到构建文件的阶段。修复顺序应先调整静态文件规则，再谈标题或正文。

可以用真实 GET 记录证据：

```bash
curl -sS -L -o /tmp/page.html \
  -w 'status=%{http_code}\nurl=%{url_effective}\nredirects=%{num_redirects}\n' \
  'https://example.com/docs/topic'
```

输入是要检查的公开 URL，输出包括最终状态、最终地址和跳转次数。不要只使用 HEAD，因为代理和应用可能对 HEAD 与 GET 采用不同处理。

## 第三步：渲染决定搜索引擎能看到什么

服务器返回 200 后，正文仍可能依赖 JavaScript 才出现。现代搜索引擎能够执行 JavaScript，但渲染需要额外资源和时间，脚本失败、接口鉴权或浏览器存储依赖都会造成空壳页面。

公开文章的主标题、正文和重要链接应尽量存在于初始 HTML。排查时对比原始 HTML、关闭脚本后的页面和完整浏览器结果。如果只有完整浏览器能看到正文，就继续检查脚本和资源，而不是用“本地可以打开”结束排查。

## 第四步：索引不是自动结果

搜索引擎会处理重复内容、规范 URL、索引指令和页面价值。`robots.txt` 控制抓取许可，`noindex` 表示不希望页面进入索引，`canonical` 提示重复页面中的首选版本，三者职责不同。

站点地图也只是发现清单，不是收录保证。它应包含希望被索引的规范 URL，不应混入重定向、noindex、软 404 或大量筛选参数。

## 第五步：排名必须针对查询分析

同一页面可能在一个具体问题上排名靠前，在另一个宽泛词上完全没有展示。排名会受到查询意图、内容相关性、质量、语言、地域、新鲜度和结果形态影响，因此“全站平均排名”很难直接指导修改。

分析时至少同时记录查询、页面、地域、设备和日期。若排名页主要是官方文档或百科，用户可能在寻找解释；若结果页主要是产品和广告，意图更接近购买。页面类型与意图不一致时，继续增加字数通常无效。

## 第六步：展示后才有点击

页面进入结果不代表用户会点击。标题和摘要需要准确说明页面能解决什么，品牌和结果形态也会影响选择。CTR 下降可能来自排名变化、查询意图变化或结果页新增模块，不一定只是标题写得差。

## 一张表完成分层排查

| 阶段 | 主要证据 | 常见故障 | 下一步 |
| --- | --- | --- | --- |
| 发现 | 内链、站点地图 | 新 URL 无入口 | 增加真实导航关系 |
| 抓取 | GET 状态、日志 | 404、5xx、误拦截 | 修服务器或规则 |
| 渲染 | 原始 HTML、资源请求 | 空壳、脚本失败 | 改渲染与资源 |
| 索引 | URL 检查、canonical | 重复、noindex | 统一索引目标 |
| 排序 | 查询与页面数据 | 意图不匹配 | 调整页面职责 |
| 点击 | 展示、CTR、SERP | 承诺不清 | 对照查询改表达 |

## 正常结果和失败结果

正常页面应该返回稳定的 200，原始 HTML 包含主内容，canonical 与站点地图指向同一 URL，并通过站内链接可达。不存在页面应返回真实 404 或 410。

失败时不要把所有旧 URL 统一跳转首页，这会形成软 404。只有存在明确替代页面才做永久跳转；没有替代内容就保留正确的不存在状态。
