# 搜索引擎如何发现、抓取、收录和排序

“页面在浏览器能打开”只证明一次用户请求成功，不证明搜索引擎已经发现、抓取、渲染、索引或愿意在某个查询下展示。排查搜索问题必须沿阶段顺序收集证据，否则会把抓取失败误诊成内容质量问题，把排名波动误诊成服务器故障。

## 六个阶段

```mermaid
flowchart LR
  A[链接/站点地图/外部提及] --> B[发现 URL]
  B --> C[抓取 HTTP 与资源]
  C --> D[渲染脚本与样式]
  D --> E[建立索引与规范页]
  E --> F[查询相关性与排序]
  F --> G[结果展现与点击]
```

发现依赖可访问的链接、站点地图和外部信号；抓取需要 DNS、TLS、robots、HTTP 状态和稳定响应；渲染需要脚本、资源和合理的执行预算；索引会处理重复页、规范 URL、内容质量和索引指令；排序是针对某个查询的相关性、质量、地域和新鲜度判断；展现还受到结果形态、标题改写和用户设备影响。

| 阶段 | 证据 | 典型故障 | 检查顺序 |
| --- | --- | --- | --- |
| 发现 | sitemap、内链、外链、日志 | 新 URL 没有入口 | 看 sitemap 和可爬链接 |
| 抓取 | 状态码、响应头、robots、耗时 | 403、5xx、超时、误拦截 | 用真实 GET 检查 |
| 渲染 | HTML、脚本、资源请求 | 内容只在客户端生成 | 比较原始 HTML 与渲染结果 |
| 索引 | URL 检查、canonical、noindex | 重复、低价值、指令冲突 | 确认主 URL 和索引资格 |
| 排名 | 查询、位置、竞品页面 | 意图不匹配、竞争太强 | 以查询为单位抽样 |
| 点击 | 展现、CTR、标题、结果形态 | 标题承诺与正文不一致 | 对照 SERP 和落地页 |

## 用 HTTP 证据开始排查

不要只使用 HEAD：部分代理对 HEAD 和 GET 的缓存、压缩、跳转处理不同。真实排查至少记录最终地址、跳转链、状态码、内容类型、缓存策略和响应时间。

```bash
curl -sS -L -D /tmp/headers.txt -o /tmp/page.html \
  -w 'status=%{http_code}\nurl=%{url_effective}\nredirects=%{num_redirects}\ntime=%{time_total}\n' \
  'https://example.com/docs/topic'

rg -n 'canonical|noindex|<h1|application/ld\+json' /tmp/page.html
```

示例域名和路径只用于说明方法。检查结果应保存时间、区域和 User-Agent，避免把一次 CDN 或 WAF 波动当成长期事实。搜索爬虫的 User-Agent 可以帮助筛选日志，但不是身份凭证；重要控制仍然是网络层规则、访问日志和验证过的来源地址。

## robots、noindex 与 canonical 不同

`robots.txt` 表达抓取许可，不能保证 URL 不被发现，也不能代替 `noindex`；如果完全禁止抓取，爬虫可能看不到页面里的 noindex。`noindex` 是页面级索引指令，前提是爬虫能够读取响应；`canonical` 是重复页面的首选提示，不是强制重定向。三者冲突时，应先确定希望搜索引擎看到哪个 URL，再统一生成链接、站点地图和响应头。

```text
User-agent: *
Disallow: /admin/
Disallow: /preview/
Sitemap: https://example.com/sitemap.xml
```

不要把整个站点、CSS、关键脚本或公开正文目录误写进 Disallow。查询参数、登录后页面和内部搜索结果要根据是否承担公开搜索需求分别治理，不能用一条通配规则覆盖全部。

## 站点地图是发现清单，不是收录保证

站点地图只放希望被索引的规范 URL，使用绝对地址，返回 200，并保持 `<lastmod>` 与真实重要更新一致。分页、过滤参数、重定向 URL、noindex 页面和软 404 不应混入。大型站点按目录和更新时间拆分，并检查索引文件与子地图的大小限制。

## 渲染与客户端内容

现代搜索引擎可以执行 JavaScript，但执行是额外阶段，资源失败、鉴权、长任务或依赖浏览器存储都可能导致空壳页面。公开内容应尽量在服务器返回可读 HTML，关键标题、正文、链接和结构化信息不能只在点击后才产生。客户端增强可以继续存在，但不能把 SEO 关键事实藏在不可抓取的交互路径里。

判断渲染问题时对比三份材料：原始响应 HTML、无脚本浏览器结果和完整渲染后的 DOM。若原始 HTML 没有正文，但完整浏览器有正文，要进一步检查脚本失败、资源状态、执行时间和是否依赖用户状态；不能因为本地开发环境能看到就下结论。

## 404、软 404 与跳转

不存在资源必须返回真实 404 或 410，不要返回 200 的“未找到”模板。自定义错误页面可以友好，但状态码必须保留。只有存在明确替代内容时才建立 301/308；将大量失效页统一跳转首页会制造软 404，掩盖真实内容缺口。改版前应导出旧 URL、状态、外部链接和业务价值，建立可审计的迁移表。

## 诊断记录和验证

每次故障记录 URL、查询、区域、时间、请求头、响应证据和变化版本。按 P0 到 P3 分级：全站不可抓取是阻断；核心目录大量错误是高影响；单页标题或内链是增长项；无证据的排名波动先观察。修复后用同一批 URL 做对照，检查 200/3xx/4xx、canonical、sitemap、日志和搜索覆盖，不要只看首页是否能打开。

```text
验收顺序：
1. 公开 URL 返回预期状态，关键资源不被误拦截
2. robots 和 sitemap 与索引目标一致
3. 原始 HTML 包含主标题、正文、内链和必要元信息
4. 不存在 URL 返回真实 404，替代页才使用永久跳转
5. 在观察周期内对照抓取、索引、查询和业务指标
```

## 实施记录：从问题到动作

抓取排障必须区分一次性故障和系统性故障：按状态码、模板、区域、User-Agent 与发布时间聚合，检查是否只有某个 CDN 节点或 WAF 规则异常。恢复后观察抓取日志和索引覆盖，不要用短期排名恢复替代技术验收。

执行记录需要保留四类信息：基线快照、改动版本、观察条件和业务对账。基线至少包含 URL、模板、查询/搜索词、状态码、索引资格、事件口径和时间范围；改动要能定位到内容、路由、缓存、创意或出价的具体版本；观察条件要记录设备、地域、语言、模型或平台版本；业务对账要以服务端的资格、成交、退款和回款为准。这样在结果变差时可以回到上一个可用版本，而不是凭记忆争论。

## 故障演练与回滚

| 演练场景 | 预期信号 | 保护动作 | 恢复证据 |
| --- | --- | --- | --- |
| robots 或 WAF 误拦截 | 抓取 4xx 上升、核心 URL 失败 | 恢复规则并限制变更面 | GET、日志、覆盖报告 |
| 模板发布错误 | title/canonical/正文异常 | 回滚模板或内容版本 | 原始 HTML 对比 |
| 追踪重复或丢失 | 客户端与服务端数量不一致 | 停止自动化学习，修复去重 | 事件 ID 对账 |
| 业务质量下降 | 有效率、退款或毛利越过护栏 | 收紧查询/预算或下线页 | CRM/订单状态 |

演练使用模拟场景和最小流量，不改变真实生产预算或数据。回滚后再次检查公开页面、缓存、站点地图、广告参数、事件队列和业务状态；只有所有关键证据恢复，才允许继续实验。

## 结果判定与后续动作

把结论分为事实、假设和缺口。事实必须能由页面、日志、平台、实验或业务记录直接复核；假设写出可证伪的预测；缺口说明缺少哪项数据以及它会影响哪项判断。观察周期内不要连续叠加多个主变量，也不要把平台评分、平均排名或单次引用当作有效业务的替代。

```text
基线 -> 小范围变更 -> 技术验收 -> 搜索/广告观察 -> 业务对账 -> 继续、调整、合并或停止
```

## 操作清单与决策记录

用同一批 URL 对照原始 HTML、日志、覆盖报告和真实浏览器结果，确认修复发生在正确阶段。

发布或投放前按顺序记录：

1. **范围**：目标用户、语言、地域、页面类型和明确不覆盖的需求。
2. **证据**：查询样本、页面版本、规范/源码/实验来源、数据时间和负责人。
3. **技术**：状态码、抓取规则、canonical、sitemap、内链、缓存、脚本失败和移动端表现。
4. **业务**：主转化、资格条件、去重键、成交/退款状态和归因窗口。
5. **保护**：预算或发布范围、护栏指标、观察周期、回滚版本和停止条件。

## 指标与停止条件

| 信号 | 可继续的证据 | 应暂停或回滚 |
| --- | --- | --- |
| 技术 | 公开 URL 状态稳定，规范页和索引目标一致 | 5xx、误拦截、canonical 冲突或空壳正文 |
| 搜索 | 相关查询、页面和点击方向一致 | 查询意图偏移、重复页面或无效展现激增 |
| 用户 | 到站后完成主要任务，错误反馈可解释 | 跳转、表单、脚本失败导致任务中断 |
| 业务 | 有效率、毛利和退款符合护栏 | 低质量线索、退款上升或归因无法对账 |

停止不是失败，而是保护样本和现金流的工程动作。停止后保留原始事件、页面快照和决策日志；需要恢复时先回到最后一个可验证版本，再单独改变一个变量。

```text
事实（页面/日志/业务记录） -> 假设（可证伪预测） -> 动作（单一变量） -> 观察（固定口径） -> 决策（继续/调整/停止）
```
