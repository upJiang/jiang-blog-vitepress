# 搜索引擎怎样发现、抓取、索引和排名

搜索引擎处理网页是一条从发现 URL 到为具体查询排序的处理链。发现是知道 URL 存在，抓取是通过 HTTP 获取内容，渲染是执行页面所需的资源，索引是保存并理解可参与检索的版本，排名则是在查询发生时决定展示顺序。这条链位于网站发布与用户看到搜索结果之间，用来判断页面究竟卡在哪个阶段。

例如，一篇文章在浏览器能打开，却搜不到标题。此时改标题、增加字数还是提交站点地图，不能凭感觉决定：抓取失败要先看 HTTP 和日志，未索引要看规范化与内容条件，有展示但无点击才轮到标题和摘要。

下文依次检查发现、抓取、渲染、索引、排名和点击。每个阶段都有自己的证据，前一层没有通过时，不跳到后一层猜原因。

[SEO 诊断的证据与评分边界](/docs/seo/seo-evidence-scoring-boundaries)提供记录方法。对每个阶段只写当前证据能证明的事实；没有服务器日志时，不得把“没有看到抓取”写成“搜索引擎从未访问”。

## 搜索链路的六个阶段

```mermaid
flowchart LR
  A[发现 URL] --> B[抓取响应]
  B --> C[渲染页面]
  C --> D[建立索引]
  D --> E[针对查询排序]
  E --> F[展示与点击]
```

**Discovery（发现）**表示搜索系统知道这个 URL。**Crawl（抓取）**是爬虫通过 HTTP 请求 URL。**Rendering（渲染）**是解析 HTML、样式和脚本，形成可理解的页面。**Indexing（索引处理）**是判断是否保存内容以及把哪个 URL 作为主版本。**Ranking（排序）**则针对一次具体查询选择结果顺序。最后才是展示和点击。

这些词描述不同状态，而不是一条自动流水线。已发现的地址可能长期不抓取；抓取成功的页面可能不进入索引；已索引页面也可能因查询不匹配而没有展示。

“已抓取”不等于“已收录”，“已收录”也不等于每个关键词都有排名。

## URL 发现与入口信号

常见入口有站内链接、站点地图、外部链接和历史抓取记录。只有站点地图而没有站内入口的页面，用户难以访问，搜索引擎也很难理解它与网站主题的关系。

检查新页面时，先确认栏目页或相关文章能通过普通链接到达它，站点地图包含规范 URL，并且 URL 没有只存在于登录后或点击脚本中。

## HTTP 抓取与响应状态

爬虫请求 URL 后，服务器返回状态码、响应头和正文。`200` 表示请求成功，`301/308` 表示永久跳转，`404` 表示资源不存在，`5xx` 表示服务端故障。

一个实际故障是：站内点击无后缀文章正常，刷新 `/docs/example` 却返回 404，而 `/docs/example.html` 返回 200。页面内容没有问题，错误发生在 Nginx 将公开 URL 映射到构建文件的阶段。修复顺序应先调整静态文件规则，再谈标题或正文。

可以用真实 GET 记录证据：

```bash
curl -sS -L -o /tmp/page.html \
  -w 'status=%{http_code}\nurl=%{url_effective}\nredirects=%{num_redirects}\n' \
  'https://example.com/docs/topic'
```

输入是要检查的公开 URL，关键逻辑是跟随跳转并让服务器完成一次真实 GET，输出包括最终状态、最终地址和跳转次数；终端的 `/tmp/page.html` 只是临时证据，不会进入博客。不要只使用 HEAD，因为代理和应用可能对 HEAD 与 GET 采用不同处理。

`GET` 的输入是 URL 与请求头，服务器依次经过 DNS、CDN、代理、路由和应用，输出状态码、响应头与正文。任一层都可能失败：DNS 无法解析、TLS 连接错误、CDN 误拦截、路由返回 404、应用超时为 5xx，或服务器用 200 返回一张“内容不存在”的错误页。

| 最终状态 | 页面真实状态 | 正确处理 |
| --- | --- | --- |
| 200 | 内容真实存在 | 核对正文、索引目标和规范地址 |
| 301/308 | 地址永久迁移 | 直接到最相关最终 URL，并更新内链 |
| 302/307 | 确实临时变化 | 保留原地址语义，避免长期滥用 |
| 404/410 | 内容不存在且无替代 | 从内链和 Sitemap 清理 |
| 429 | 请求过多 | 检查限流是否误伤正常访问 |
| 500/502/503 | 服务异常或维护 | 优先恢复服务，分析错误和耗时日志 |

状态码必须和正文含义一致。`200 + 内容不存在` 是 **Soft 404（软 404）** 候选；它让监控以为成功，却让用户和搜索系统拿到无效内容。

## 渲染与可读取内容

服务器返回 200 后，正文仍可能依赖 JavaScript 才出现。现代搜索引擎能够执行 JavaScript，但渲染需要额外资源和时间，脚本失败、接口鉴权或浏览器存储依赖都会造成空壳页面。

公开文章的主标题、正文和重要链接应尽量存在于初始 HTML。排查时对比原始 HTML、关闭脚本后的页面和完整浏览器结果。如果只有完整浏览器能看到正文，就继续检查脚本和资源，而不是用“本地可以打开”结束排查。

## 索引资格与规范页面选择

搜索引擎会处理重复内容、规范 URL、索引指令和页面价值。`robots.txt` 控制抓取许可，`noindex` 表示不希望页面进入索引，`canonical` 提示重复页面中的首选版本，三者职责不同。

站点地图也只是发现清单，不是收录保证。它应包含希望被索引的规范 URL，不应混入重定向、noindex、软 404 或大量筛选参数。

## 查询相关性与排名

同一页面可能在一个具体问题上排名靠前，在另一个宽泛词上完全没有展示。排名会受到查询意图、内容相关性、质量、语言、地域、新鲜度和结果形态影响，因此“全站平均排名”很难直接指导修改。

分析时至少同时记录查询、页面、地域、设备和日期。若排名页主要是官方文档或百科，用户可能在寻找解释；若结果页主要是产品和广告，意图更接近购买。页面类型与意图不一致时，继续增加字数通常无效。

## 搜索展示与点击

页面进入结果不代表用户会点击。**SERP（Search Engine Results Page，搜索结果页）**上的标题、摘要、品牌、日期和结果形态都会影响选择。**CTR（Click-through Rate，点击率）**按 `点击次数 / 展示次数 x 100%` 计算，它适合比较同一查询、位置和周期下的点击表现，不能脱离排名和结果形态横向下结论。

CTR 下降可能来自排名变化、查询意图变化、品牌构成变化或结果页新增模块，不一定只是标题写得差。没有展示时 CTR 没有可解释分母，更不能通过改标题解决“尚未被索引”的问题。

## 服务器日志能补上什么证据

页面检查只能看到“现在请求一次”的结果，服务器访问日志可以回答一段时间内哪些 URL 被请求、状态如何、耗时多长。先确认日志格式，再按 URL、状态、日期和耗时聚合：

- 4xx/5xx 集中在哪些目录或模板；
- 哪些重要 URL 长期响应慢；
- 参数、筛选和站内搜索地址是否消耗大量请求；
- Sitemap 中的重要 URL 是否在样本周期内出现过疑似爬虫请求。

**User-Agent（用户代理字符串）**只是请求方自报身份，任何客户端都可以写 `Googlebot`。因此日志只能先标“疑似爬虫”，需要结合 Google、Bing 或百度公开的验证机制以及反向/正向 DNS、平台日志说明进一步确认。不要通过改 User-Agent 把自己的请求称为真实搜索爬虫。

日志处理还要最小化隐私：分析抓取时通常只需路径、状态、时间、耗时和归一化爬虫类别；无需长期保存 IP、完整 Referer、查询中的个人信息或原始 User-Agent。

## 一张表完成分层排查

| 阶段 | 主要证据 | 常见故障 | 下一步 |
| --- | --- | --- | --- |
| 发现 | 内链、站点地图 | 新 URL 无入口 | 增加真实导航关系 |
| 抓取 | GET 状态、日志 | 404、5xx、误拦截 | 修服务器或规则 |
| 渲染 | 原始 HTML、资源请求 | 空壳、脚本失败 | 改渲染与资源 |
| 索引 | URL 检查、canonical | 重复、noindex | 统一索引目标 |
| 排序 | 查询与页面数据 | 意图不匹配 | 调整页面职责 |
| 点击 | 展示、CTR、SERP | 承诺不清 | 对照查询改表达 |

## 正常结果和失败结果

正常页面应该返回稳定的 200，原始 HTML 包含主内容，canonical 与站点地图指向同一 URL，并通过站内链接可达。不存在页面应返回真实 404 或 410。

失败时不要把所有旧 URL 统一跳转首页，这会形成软 404。只有存在明确替代页面才做永久跳转；没有替代内容就保留正确的不存在状态。

## 用五个 URL 练习逐层诊断

从网站挑选五个地址：正常详情页、永久跳转页、不存在页、依赖脚本渲染的页和一个带追踪参数的重复页。对每个地址同时记录 GET 最终状态、最终 URL、原始 HTML 是否有主要内容、规范地址、robots 指令、站内入口和站点地图状态。

| 样本 | 应确认的真实行为 |
| --- | --- |
| 正常页 | 200，正文与标题存在，允许索引 |
| 跳转页 | 单跳到最相关稳定地址，内链已更新 |
| 不存在页 | 返回 404/410，不用 200 展示错误模板 |
| 脚本页 | 最终渲染可用；关键公开内容尽量直接输出 |
| 参数页 | 首选地址一致，参数不会无限进入发现路径 |

发现问题时只在当前层下结论。没有站内链接属于“发现”问题；服务器日志显示爬虫持续 5xx 属于“抓取”问题；HTML 为空但渲染后有内容属于“渲染”问题；页面已抓取却未进入索引，需要继续核对重复、规范地址与内容价值；进入索引但某查询无展现，才进入查询意图和排序分析。

一次检查完成后留下证据表，而不是“网站权重低”的判断。若没有服务器日志，只能确认外部响应，不能声称搜索引擎从未抓取。若站长平台数据有延迟，也要记录观测日期和数据缺口。

## 诊断结果怎样进入页面规划
为五个 URL 增加“查询需求”列：页面原本想承接什么问题，当前是否已经产生相关展示。抓取正常但查询不匹配的页面应进入搜索意图与页面映射；状态或索引仍异常的页面留在技术队列，不要用关键词改写掩盖。

职责上，开发/运维提供 HTTP、渲染和日志证据，SEO 负责人确认索引目标与查询，内容负责人判断页面是否有独立价值，创业者只在影响业务和资源排序时介入。任何角色都不应跨过缺失证据直接宣称“算法降权”。
