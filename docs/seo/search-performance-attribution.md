# 搜索表现分析与 SEO 归因

一份月报显示自然点击从 1,000 增至 1,400。继续拆分后发现，新增点击大多来自品牌名；非品牌商业页几乎不变；网站注册增加，但有效激活没有增加。40% 是正确计算，却没有回答新增需求、有效业务和收入。

搜索表现分析的任务不是证明团队做了很多，而是定位变化发生在需求、展示、点击、页面还是业务层。[站外增长记录](/docs/seo/links-brand-analytics-attribution)提供品牌活动和引荐时间线，搜索平台 CSV 再把 Google、Bing 和百度的查询数据映射到页面与业务结果。

## 三类数据不能直接混成一个数

| 数据层 | 典型来源 | 主要回答 | 不能单独回答 |
| --- | --- | --- | --- |
| 搜索平台 | Google Search Console（Google 搜索控制台，GSC）、Bing Webmaster Tools（Bing 网站管理员工具）、百度搜索资源平台 | 查询、页面、展示、点击、位置 | 用户是否完整到站、是否成交 |
| 站内分析 | 自建事件、合规分析工具 | 落地页、会话、交互、前端转化 | 线索是否有效、订单是否退款 |
| 业务系统 | CRM、订单、退款、毛利 | 有效业务与价值 | 首次搜索触点一定完整 |

平台、时区、日期、国家/地区、设备、搜索类型、归因窗口和隐私阈值都可能不同。导入前保留原始文件和口径，规范化后再汇总；不要把不同平台“位置”或点击简单相加后当全市场份额。

## 基础指标先从公式理解

**Impression（展示）**表示页面在搜索结果中获得一次可见机会，具体计数按平台定义。**Click（点击）**是用户从结果进入页面的动作。**CTR（Click-through Rate，点击率）**为：

```text
CTR = 点击 / 展示 x 100%
```

若 2,000 次展示带来 80 次点击，CTR 为 4%。分母为零时不能计算；不同位置、查询和结果形态的 CTR 不可直接比较。

**Average Position（平均位置）**是平台对展示位置的聚合统计。合并多行时应按展示量加权：

```text
加权平均位置 = sum(每行位置 x 每行展示) / sum(有位置的展示)
```

位置 5 有 1,000 展示、位置 50 有 10 展示，不能简单平均为 27.5。即使加权正确，平均位置也会混合国家、设备、查询和结果功能，应作为趋势线索而不是固定排名。

## CSV 导入先解决字段和数据质量

Google、Bing 和百度导出的列名、语言与格式不同。标准解析器应处理 BOM、引号、字段内逗号和中英文表头；自动识别失败时由用户确认映射。最小规范字段是：

```text
platform｜date｜query｜page｜impressions｜clicks｜ctr｜position｜device｜country
```

导入流程要验证：

1. 日期能解析且时区明确；
2. 展示和点击非负，CTR 可由原始数重新计算；
3. URL 去掉 fragment、规范尾斜杠，但不要误合并不同页面；
4. 位置缺失保留 null，不填 0；
5. 品牌规则来自项目配置，不按单一字符串粗暴判断；
6. 大文件在受控内存或 Worker 中解析，不把原始搜索词发送给无关服务。

平台可能因隐私或低量查询隐藏部分行，因此查询明细之和不一定等于总计。报告应保留这个限制，不通过补造“其他查询”来假装精确。

## 品牌与非品牌必须分开

**Branded Query（品牌查询）**包含品牌、产品、域名、创始人或明确拼写变体；**Non-branded Query（非品牌查询）**表达问题、品类、比较或场景，但尚未明确寻找你的品牌。

品牌词通常 CTR 和位置更高，也可能来自广告、公关、线下、老用户导航。把它与非品牌混合，会让总 CTR、平均位置和增长看起来更好，却无法说明网站是否覆盖新需求。

品牌规则至少支持多个词、常见空格/连字符和拼写变体，并人工抽查误判。竞品名不自动属于自己的品牌；包含行业通用词的品牌尤其容易误分类。

报告分别展示品牌/非品牌的展示、点击、CTR、页面和业务结果。品牌增长可以是好事，只是需要诚实说明它回答的是品牌需求，不是全部 SEO 增量。

## CTR 要和本站同位置基线比较

“CTR 低于行业平均”往往缺少可比条件。更稳妥的方法是按本站数据把平均位置分桶，例如 1 至 3、4 至 10、11 至 20、21+，计算每个桶的展示加权 CTR，再找同位置下明显偏低的查询与页面组合。

假设某查询位于 4 至 10 桶，有 800 展示、16 点击，CTR 2%；本站该位置桶基线为 5%。它是摘要优化候选，但还要检查：

- 查询意图与页面是否匹配；
- SERP 是否出现广告、图片、视频或即时答案；
- 品牌与非品牌构成是否相同；
- Title/Description 是否兑现首屏内容；
- 样本是否足够、位置是否在周期中剧烈变化。

可以用“低于同位置基线 30%”作为内部复核阈值，但它不是搜索引擎规则，也不是所有网站通用标准。修改后保留排名和转化作为保护指标，避免夸张标题换来无效点击。

## 平均位置 4 至 20 的机会页面

平均位置 4 至 20 且有真实展示的页面，常被称为 **Near Win（接近突破的机会）**：搜索系统已经让页面进入前两页附近，小幅改善意图匹配、证据、内链或摘要可能比从零竞争宽泛大词更可验证。

候选不等于必然增长。位置 18 的低价值查询可能不值得投入，位置 2 的页面也可能因摘要差错过大量点击。按展示、商业价值、页面质量和实施成本共同排序。

行动顺序是先核对页面任务，再补缺失证据和相关内链，最后用等长周期观察位置与点击。不要在同一周期同时改 URL、Title、正文和导航。

## Query-Page Conflict 怎样判断

**Query-Page Conflict（查询与页面冲突）**指同一查询在多个站内 URL 产生展示，可能表示页面职责不清。工具可以按规范化 URL 统计页面数和展示量，输出候选清单。

但多个 URL 不自动等于内耗：品牌查询可能合理展示首页、登录和帮助；同一宽泛查询也可能对应不同结果形态。二次判断要比较页面任务、展示份额、周期变化和实际 SERP。

确认冲突后选择主页面，其他页面按情况合并、迁移、转向不同意图或调整内链/Canonical。不要把同一关键词继续复制到所有页面。

## 等长周期比较避免时间偏差

**Equal-period Comparison（等长周期比较）**用相同天数的当前期与前一期比较。例如最近 28 天对前 28 天，而不是 31 天对 7 天。

计算展示、点击和 CTR 变化时：

```text
变化率 = 当前值 / 前期值 - 1
```

前期为零时变化率不可计算，应报告新增而不是无穷增长。还要记录星期构成、季节、节假日、发布、站点故障和平台口径变化。SEO 数据常有延迟，最近几天可能尚未完整。

样本置信度可按项目设定。例如累计展示不少于 5,000 且点击不少于 100 才标高置信度，展示不少于 1,000 且点击不少于 30 标中等，其他为低。这只是内部规则；长尾高价值查询即使低量，也可能值得业务人工判断。

## 从点击连接到有效业务

搜索平台点击、站内会话和 CRM 数字可能不同：页面加载失败、拦截、跨域、重复点击、Cookie 与隐私选择都会影响。建立统一数据字典：

```text
search_click -> landing_session -> primary_conversion -> valid_lead/order
             -> revenue -> refund -> gross_profit
```

**Primary Conversion（主要转化）**应接近核心业务，例如完成试用激活或提交合格咨询；下载资料、滚动和按钮点击可作为观察事件，不应与收入等价。用合法的内部 lead/order ID 连接业务状态，不把邮箱、电话放进 URL 或分析参数。

**Attribution（归因）**是把结果分配给触点的规则。首次、末次、线性、时间衰减各回答不同问题；关联键缺失时降低置信度。品牌词 SEM、自然品牌点击和直接访问可能共享同一需求，不能重复把一笔收入全额记给多个渠道。

自然 SEO 很难做严格封闭实验，可以通过发布时间线、相似页面、地区或查询组做对照，并保留需求和排名变化。结论写“与假设一致但仍受哪些因素影响”，不承诺单项改动创造全部收入。

## 一张诊断树把数据变成行动

```text
自然点击下降
├─ 展示下降
│  ├─ 需求/品牌构成变化
│  ├─ 页面退出索引或抓取异常
│  └─ 查询排名或结果形态变化
├─ 展示稳定、点击下降
│  ├─ 位置变化
│  ├─ 同位置 CTR 候选
│  └─ SERP/品牌/摘要变化
└─ 点击稳定、有效业务下降
   ├─ 到站或性能失败
   ├─ 查询意图与页面变化
   ├─ 产品/表单/销售变化
   └─ 追踪、去重或归因异常
```

先排除数据和技术故障，再改内容。仅看到点击下降 20% 不足以直接重写全站 Title。

## 查询页面分析表与数据字典

分析表至少包含：

```text
平台｜日期与时区｜品牌分类｜查询｜规范页面｜页面类型｜
展示｜点击｜CTR｜平均位置｜位置桶｜本站桶基线｜
本期/前期变化｜样本置信度｜页面任务｜候选动作
```

数据字典继续定义点击、会话、主要转化、有效业务、收入、退款和毛利的来源、去重与关联键。SEO 负责人解释查询与页面，数据负责人维护导入和归因，开发负责人保证 URL/事件稳定，业务负责人确认有效结果，创业者按毛利和资源选机会。

验收时至少找出一个同位置低 CTR 候选、一个 4 至 20 位机会、一个查询页面冲突候选和一个不能下结论的数据缺口。验证过的需求和页面结构可以继续用于搜索广告账户设计。
