# SEO 与 SEM 的协同验证周期

一家刚上线的预约管理 SaaS 同时发布了 60 篇文章、重写首页、开启三种自动广告系列，还把“提交表单”设成主要转化。三个月后，自然流量上涨，广告平台报告 140 次转化，销售却只确认 9 条有效线索。因为技术、内容、投放和追踪同时变化，团队无法回答哪项工作创造了结果，也不知道下一季度该扩大什么。

90 天计划的目标不是承诺排名或流量，而是建立一个可复查的搜索增长系统：用小规模实验确认需求，先解除技术与测量阻断，再让 SEO（Search Engine Optimization，搜索引擎优化）沉淀长期页面，让 SEM（Search Engine Marketing，搜索引擎营销）加快市场反馈，最后用有效业务和毛利决定去留。

[多平台诊断与止损](/docs/seo/sem-platform-diagnostics)补齐协同周期需要的广告输入。这里不再增加新的“增长技巧”，而是把已有结论排进依赖、负责人、工作量、观察周期和回滚条件，形成创业团队可以执行的路线图。

## 开工前先收齐 21 章留下的资产

若前面的实践产物仍散落在聊天记录或个人脑中，先不要排日期。将它们合并成六个启动包，每项注明版本、证据日期、负责人和缺口。

| 启动包 | 来自哪些章节 | 必须包含什么 | 缺失时的风险 |
| --- | --- | --- | --- |
| 商业与需求 | 第 1-5 章 | 搜索增长漏斗、项目评估卡、查询-意图-页面映射 | 把流量当目标，页面承接错误需求 |
| 页面与内容 | 第 6-9 章 | 页面树、内链图、模板验收表、主题集群、媒体规格 | 重复建页，内容没有独有价值或维护人 |
| 索引与交付 | 第 10-15 章 | 索引治理矩阵、原始/渲染对照、性能诊断、单页与全站报告 | 批量发布在不可抓取、不可渲染或低质量模板上 |
| 站外与自然搜索数据 | 第 16-17 章 | 链接品牌台账、搜索数据字典、查询页面分析表 | 看见点击变化却无法区分品牌、页面和查询 |
| SEM 执行 | 第 18-21 章 | 账户结构、搜索词规则、预算边界、转化验收、多平台止损表 | 平台自动化学习错误目标并放大无效消耗 |
| 证据与治理 | 第 3 章贯穿全系列 | 事实/假设/缺口、覆盖率、P0-P3、验证与回滚模板 | 工具分数代替业务判断，问题无法复查 |

每个启动包都可以不完整，但不能假装完整。缺少 Search Console、日志或 CRM 关联时，路线图应该安排“补证据”，而不是先写一个确定结论。

## 一张任务卡必须能回答九个问题

路线图不是“写文章、做外链、投广告”的愿望清单。每项工作至少使用以下字段：

```text
任务｜业务目标｜已确认事实｜待验证假设｜证据来源与日期｜
P0-P3｜负责人｜依赖｜预计工作量｜修改动作｜验收指标｜
观察周期｜停止条件｜回滚动作｜复盘结论
```

这里的 **Owner（负责人）** 是对结果和证据闭环负责的人，不只是执行人；**Dependency（依赖）** 是任务开始前必须满足的条件；**Workload（工作量）** 建议用半天、1-2 天、3-5 天或跨周期描述，避免伪精确工时。

观察周期必须与机制匹配。404 修复和转化代码可以发布后立即验证，搜索引擎重新抓取、索引和查询表现需要更长时间，低频成交业务还要等待销售和退款成熟。没有成熟窗口就下结论，容易把延迟误判成增长或衰退。

### P0-P3 决定先后，不代表搜索价值大小

| 级别 | 本计划中的含义 | 示例 | 默认动作 |
| --- | --- | --- | --- |
| P0 阻断 | 服务、索引、追踪或预算正在发生严重损失 | 全站 5xx、生产误 `noindex`、主要转化完全重复、广告异常失控 | 立即止损并恢复已知正常状态 |
| P1 高影响 | 核心目录或主要业务链路持续受损 | 核心模板空白、错误 Canonical、有效线索无法关联、预算流向明显无效需求 | 本周期优先，完成前限制扩量 |
| P2 增长 | 基础可用后有证据支持的改善机会 | 4-20 位查询页增强、已验证主题扩展、落地页承诺优化 | 受控实验，保留对照和观察窗口 |
| P3 观察 | 影响有限、证据不足或暂不适用 | 低流量页面轻微提示、待补样本的候选问题 | 记录、抽查，不抢占阻断资源 |

工具提示只能提供问题候选。预期索引状态、页面业务价值、影响范围和真实证据共同决定优先级。例如登录页存在 `noindex` 通常是正确治理，不能因为页面审计出现这个信号就自动升级为 P0。

## 第 1-14 天：选市场、定口径、先止损

第一阶段的目标不是发布，而是证明“谁在搜索什么、什么结果算成功、当前链路是否能被测量”。

创业者先确定一个产品、一个主要客群、一个核心地区和一个主要业务结果。若产品仍服务多个差异很大的场景，先选毛利、交付能力和需求证据最清楚的一条，不要让一个 90 天实验承担整个公司的定位问题。

SEO/内容负责人从客户访谈、销售记录、客服问题、站内搜索和已有搜索词中整理原始问法，建立第一版查询-意图-页面映射。此时搜索量是参考，不应覆盖真实客户语言和交付边界。

开发/运维负责人做最小技术基线：关键 URL 的状态、跳转、原始 HTML、渲染后主体、robots、Sitemap、Canonical、移动端和主要转化请求。数据负责人定义主要转化、有效线索、订单、退款和毛利字段，并验证点击或受控归因键能否连接业务系统。

SEM 投手只准备小范围结构、否定词、地区、时段、落地页和测试预算，不因急于“积累数据”跳过追踪验收。

阶段交付物：

- 一张可交付市场的项目评估卡，含资源上限与停止条件；
- 第一版搜索增长漏斗和 20-50 条高相关需求，不追求数量；
- 查询-意图-页面映射，标出已有、待建、合并和不承接；
- 技术与测量基线，所有 P0/P1 有负责人和回滚；
- 数据字典，明确平台转化不等于有效业务。

进入下一阶段的条件是：主要页面可用，主要转化可复测，异常消耗有暂停权限。若核心产品尚无可交付价值、毛利无法覆盖获客成本，或追踪完全不可用，停止扩量，先回到产品和测量层。

## 第 15-30 天：建页面结构与测量地基

第二阶段把需求映射转成少量可工作的页面和账户结构。先处理会批量影响后续工作的模板问题，再生产内容。

开发侧完成 URL 收敛、站点结构、内链入口、索引治理和关键模板的原始 HTML 输出。根据第 12、13 章的诊断，只修与当前样本有因果关系的性能根因，并为部署保留基线、监控和回滚版本。

非代码侧由 SEO/内容负责人维护 robots、Sitemap、Canonical 目标、页面清单和更新责任。robots.txt 负责抓取规则，`noindex` 负责索引意图，Canonical 表达规范网址，Sitemap 提交希望搜索系统发现的规范 URL；四者不能互相替代。

内容侧先完成核心产品页、场景页和少量决策支持内容。每页只有一个主要任务，Title、Description、H1、正文、媒体和结构化数据都服务于真实可见内容。未验证主题不批量扩写，AI 只辅助整理与编辑，关键事实由责任人核对。

SEM 侧按品牌/非品牌、意图、地区和页面任务建立可解释的 Campaign（广告系列）与 Ad Group（广告组）。上线前用真实点击参数完成一次测试转化，确认广告平台、分析系统和业务系统没有重复计数。

阶段验收不看排名承诺，而看地基是否闭环：

| 检查对象 | 验收证据 | 失败处理 |
| --- | --- | --- |
| 核心 URL | 真实 GET、原始 HTML、渲染 DOM、页面清单 | 恢复模板或路由，不继续批量发布 |
| 索引信号 | robots、meta/X-Robots-Tag、Canonical、Sitemap 对照 | 修正冲突并重新抽查代表页 |
| 主要转化 | 调试记录、去重键、CRM/订单关联 | 暂停自动出价和业务结论 |
| 广告落地页 | 搜索词、创意承诺、实际最终 URL、事件回传 | 排除错误 URL 或暂停广告组 |
| 发布质量 | 单页审计、模板抽样、性能基线 | 回滚造成 P0/P1 的版本 |

## 第 31-50 天：用小规模 SEM 验证需求

到这一阶段才让付费搜索承担它最擅长的工作：快速取得真实查询、承诺点击和业务结果反馈。预算的目的不是买来一个漂亮流量曲线，而是降低需求和页面判断的不确定性。

优先选择高意图、产品能交付、落地页已验收的查询簇。控制地区、设备、时段和日预算，品牌与非品牌分开。广泛匹配或自动出价只有在主要转化可信、否定词有人维护、预算有上限时才进入受控实验。

每天检查 P0：落地页失效、地域错误、追踪中断、政策问题和异常消耗。普通 CTR、CPC 或 CPA 波动不要每天调价；等待约定的点击、转化和业务成熟窗口，再比较等长周期。

每周把 Search Term（搜索词，用户真实输入）按“相关且有效、相关待成熟、信息型、不相关、风险”分类。否定词先由人工判断意图和词组影响，避免一个宽泛否定误伤有价值长尾。

数据负责人把平台转化连接到有效线索、订单、退款和毛利。建议同时看：

```text
平台 CPA = 广告成本 / 平台归因转化数
有效 CPA = 广告成本 / 有效业务数
退款后 ROAS = （收入 - 退款）/ 广告成本
毛利回报 = 归因毛利 / 广告成本
```

这些指标只能在口径、窗口和关联率可解释时使用。样本很少时写实际分子分母，不用一个剧烈波动的比率假装稳定规律。

阶段输出是一份需求验证表：查询簇、实际搜索词、页面、成本、主要转化、有效业务、毛利、证据成熟度、继续/调整/停止结论。下一阶段只把反复出现、产品能交付且有业务证据的问题沉淀为长期页面。

## 第 51-70 天：让 SEO 沉淀已验证需求

SEO 不是把广告搜索词逐条改成文章标题。先回到用户任务，合并同义表达，判断应由产品页、场景页、比较页、教程还是支持页承接，再更新查询-意图-页面映射。

内容负责人为每个通过验证的主题准备 Brief（内容简报）：目标读者、主要任务、必须回答的问题、第一手材料、可核对来源、独有信息、页面下一步、维护人与退出规则。开发负责人只在页面类型需要时增加模板、结构化数据或媒体能力，避免每篇文章出现一次性实现。

发布后先验证状态、索引信号、原始/渲染主体、内部链接和分析事件，再提交 Sitemap 或使用平台检查工具。页面被抓取或收录，不代表会获得目标查询排名；未出现展示前，不因 CTR 为零就改标题。

同时把自然搜索的新查询反馈给 SEM：

- 高价值非品牌查询可加入精确监测或广告测试；
- 明显不相关的查询可成为否定词候选，但仍需人工复核；
- 自然页面与广告落地页任务冲突时，先统一承诺，不抢着提高出价；
- 品牌自然与品牌广告分别报告，避免双方重复宣称全部转化。

阶段验收看页面是否有明确职责、独有证据、可发现入口和维护人，也看投放是否因更好的页面与否定词变得更可控。不要用“发布篇数”代替这些结果。

## 第 71-90 天：比较成熟结果并做资源决策

最后 20 天不是冲刺堆量，而是等待足够成熟的数据并复盘。建立当前周期与前一等长周期，注明季节、活动、品牌事件、站点改版和广告学习期；自然与付费分别分析，再汇总到同一个业务漏斗。

SEO 侧至少拆查询、页面、品牌/非品牌、展示、点击、CTR、平均排名、索引状态和有效业务。SEM 侧拆平台、系列、搜索词、实际最终 URL、成本、平台转化、有效业务、退款和毛利。两者都不能越过关联缺口宣称收入归因。

### 四类资源结论

| 决策 | 证据特征 | 下一步 |
| --- | --- | --- |
| 扩大 | 需求、交付、追踪和毛利均通过；新增资源仍带来边际业务 | 小步增加页面簇或预算，保留上限与对照 |
| 维持 | 方向成立但样本不足，或渠道处于合理成熟期 | 保持主要变量稳定，补足观察窗口 |
| 调整 | 有需求但页面、产品、搜索词或追踪存在明确断点 | 一次改一个主要变量，重新定义验收 |
| 停止 | 持续无有效需求、单位经济不成立、风险不可接受或无法交付 | 停止消耗，保存证据，明确重启前提 |

“停止”不是失败报告，而是创业资源管理。已经证明不适合的主题、页面和投放，应从 Sitemap、内容计划和预算中退出；需要保留的历史页面则按用户价值选择更新、合并、重定向或下线，不能机械删除。

## SEO 与 SEM 共享数据，但不重复归因

两个渠道应共享需求语言、页面职责、否定词候选、转化口径和业务结果，却保留各自的展示、点击、成本和归因链。推荐维护一张共享事实表，而不是把两个平台报表直接相加。

```text
日期｜查询或主题簇｜品牌分类｜目标页面｜渠道｜展示｜点击｜成本｜
平台转化｜有效业务｜订单收入｜退款｜毛利｜归因键｜关联状态｜证据置信度
```

同一用户可能先看到自然结果，后点击广告，再直接访问成交。没有实验或可靠多触点证据时，可以报告各渠道可观察贡献与重叠，不能让 SEO、SEM 和“直接访问”各领取一次完整收入。

SEM 的快速搜索词可以帮助 SEO 发现真实表达，但付费点击受出价、匹配和广告资格影响，不代表全部自然需求。SEO 的自然查询能帮助投放补充词表，但搜索平台会隐藏或聚合部分数据，也不能当作完整市场样本。

## 每周运行一次小团队搜索增长会议

会议控制在 45-60 分钟，围绕证据和决策，不逐项汇报忙碌程度。

1. 前 10 分钟检查 P0/P1、站点可用性、追踪健康和预算异常。
2. 接着核对上周任务的验收、观察期和回滚是否完成。
3. SEO/内容展示新增查询、页面和索引证据；SEM 展示搜索词、成本与实际最终 URL；数据负责人展示有效业务与关联率。
4. 创业者基于现金流、交付和毛利只确定本周最重要的 1-3 项任务。
5. 记录继续、调整、暂停或回滚，以及结论仍缺什么证据。

日常看板要有版本历史。算法、页面、广告系列和转化口径变化时记录日期，避免三周后拿新口径与旧口径直接比较。

## 五类角色怎样交接

| 角色 | 90 天内的主要责任 | 必须交给下一角色的证据 |
| --- | --- | --- |
| 创业者 | 市场选择、业务结果、毛利、资源上限、停止条件 | 明确优先客群和可接受获客边界 |
| SEO/内容 | 查询映射、页面职责、索引治理、内容证据、搜索表现 | 页面清单、内容简报、查询页面变化 |
| 开发/运维 | HTTP、渲染、性能、事件、日志、发布与回滚 | 可复测版本、监控、变更和失败路径 |
| SEM 投手 | 结构、搜索词、匹配、创意、出价、预算与止损 | 实际搜索词、最终 URL、成本和实验条件 |
| 数据负责人 | 口径、去重、归因键、有效业务、退款与毛利 | 数据字典、关联率、成熟窗口和质量异常 |

一人可以兼任多个角色，但不能省略交接证据。创业者亲自投广告时，仍需区分“我设置的转化”和“销售确认的客户”；开发者负责 SEO 时，也不能独自决定哪些业务页面应被索引。

## 90 天搜索增长路线图

为五个阶段各建一组任务，并至少选择一个代表 URL、一个查询簇和一个广告组贯穿 90 天。路线图首页写清：业务目标、现金上限、主要转化、有效业务、毛利口径、目标市场、明确不做的范围。

验收时让未参与制定的人随机抽一项任务，回答以下问题：

- 为什么现在做，前置依赖是否已经满足？
- 这是事实、假设还是数据缺口，证据日期是什么？
- 谁负责，预计工作量和影响范围多大？
- 怎样证明完成，观察多久才作业务判断？
- 什么情况立即停止，怎样恢复到已知正常状态？
- SEO 与 SEM 是否共享了需求证据，又是否避免重复领取结果？

能完整回答，路线图才是经营工具。只能回答“为了提高 SEO 分数”或“平台建议增加预算”，说明任务仍未连接到业务。
