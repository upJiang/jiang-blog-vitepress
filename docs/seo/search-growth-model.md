# SEO、SEM、GEO：用户怎样找到一个网站

假设你刚上线一个提供技术审计服务的网站。页面能打开，标题也写了“专业技术审计”，但一个月后几乎没有有效咨询。你应该继续写文章、投搜索广告，还是优化页面让 AI 搜索引用？

先不要急着选渠道。一个网站获得搜索增长，要先有人产生需求，再让正确页面被发现、理解、展示、点击，最后完成真实业务转化。SEO、SEM 和 GEO 只是在这条链上介入的位置不同。

这篇文章不承诺“做完多少天就有排名”。我们会建立一个可以实际使用的诊断模型：看到流量不足或转化不佳时，知道先检查哪一层证据，而不是把所有问题都归因于“权重低”。

## 先看三个用户怎样来到网站

同一个人想找“网站性能审计服务”，可能走三条路径：

1. 在搜索引擎输入问题，点击自然结果。
2. 点击带有“赞助”标记的搜索广告。
3. 向生成式搜索或 AI 助手提问，从回答中的引用进入网站。

对应的三类工作分别是：

| 渠道 | 全称 | 主要工作对象 | 是否直接购买展示机会 |
| --- | --- | --- | --- |
| SEO | Search Engine Optimization | 网站、页面、内容、技术可访问性和站外信号 | 否 |
| SEM | Search Engine Marketing，本系列特指搜索广告 | 关键词、匹配、出价、创意、落地页和转化追踪 | 是 |
| GEO | Generative Engine Optimization | 可验证内容、实体关系、来源表达和机器可理解性 | 否，但结果不可承诺 |

三者不是三套互不相干的技巧。搜索广告里表现好的真实搜索词，可以帮助发现 SEO 页面需求；SEO 中解释清楚、可引用的内容，也更适合作为 GEO 的事实来源；无论哪条渠道，落地页和真实转化都要共用同一业务口径。

## SEO 到底在优化什么

SEO 的目标不是让爬虫“喜欢”网页，而是让搜索引擎能够发现、抓取、理解一张真正满足搜索需求的页面，并有足够理由在相关查询中展示它。

一张页面进入自然搜索结果，至少会经历：

```mermaid
flowchart LR
  A[市场需求] --> B[对应页面]
  B --> C[发现与抓取]
  C --> D[渲染与索引]
  D --> E[查询排序]
  E --> F[展示与点击]
  F --> G[站内转化]
```

每一层都可能失败。页面没有被索引，继续修改按钮颜色没有意义；页面有展现却没有点击，要检查标题和搜索意图；有点击没有有效咨询，则要回到页面任务、信任信息和业务承接能力。

### 一个容易混淆的例子

你发布了一篇“如何进行网站性能审计”的教程，但真正想获得的是企业客户的审计咨询。教程可能满足学习意图，服务页才承接购买意图。如果所有关键词都塞进同一页面，页面既不像完整教程，也不像能让客户做决策的服务页。

SEO 的第一步通常不是增加关键词密度，而是弄清用户问题应该由哪种页面回答：教程、产品页、服务页、案例页、工具页还是专题页。

## SEM 为什么能更快获得数据

搜索广告允许广告主针对查询参与竞价。用户搜索时，平台综合出价、广告质量、预期影响和竞争环境决定是否展示以及展示位置。广告主通常为点击或约定的结果付费。

它“快”的地方是可以较快获得展示、点击和搜索词数据，不代表可以跳过需求与页面。一个错误的关键词会更快消耗预算，一个不匹配的落地页会更快证明用户不愿转化。

一次 SEM 链路可以拆成：

```text
用户查询 -> 关键词匹配 -> 广告竞价 -> 创意展示 -> 点击
         -> 落地页 -> 平台转化 -> 有效线索/订单 -> 收入与毛利
```

“平台转化”与“有效业务”要分开。按钮点击、表单提交或拨号可能被平台记录为转化，但它们不自动等于有效客户。若自动出价只看到容易触发的中间事件，系统可能越来越擅长买到低价值流量。

### 先算清一笔最小账

假设模拟周期内发生：

| 数据 | 数值 |
| --- | ---: |
| 展示 | 1,000 |
| 点击 | 50 |
| 广告成本 | 500 元 |
| 平台表单 | 10 |
| 经人工确认的有效咨询 | 4 |
| 最终成交 | 1 |

那么点击率是 `50 / 1000 = 5%`，平均点击成本是 `500 / 50 = 10 元`。按平台表单计算的 CPA 是 50 元，但按有效咨询计算是 125 元。

两个 CPA 都能正确计算，却回答不同问题。优化广告账户时，如果只报告 50 元，就隐藏了线索质量。是否赚钱还需要订单收入、退款、交付成本和毛利，不能看到一笔成交就直接宣称广告有效。

## GEO 在解决什么问题

生成式搜索会把多个来源的信息组织成回答，有时附带引用。GEO 关注的是：当系统需要回答一个主题时，你的内容是否容易被识别、核实、抽取和正确引用。

它通常需要：

- 页面明确回答一个具体问题，而不是堆积空泛观点。
- 结论有来源、作者责任、更新时间和适用条件。
- 名称、实体、属性和上下文表达一致。
- 页面允许相应系统访问，并能稳定渲染核心内容。
- 原创数据或方法能够被第三方核对。

这些工作与高质量 SEO 内容高度重合，但 GEO 不是“在文章里多写几个问答”或“批量生成内容”。外部系统如何选择和引用来源不由站长控制，任何“保证被 AI 推荐”的承诺都缺乏可验证依据。

## 不要先选渠道，先画完整漏斗

把搜索增长拆成十二层，排查时从左到右：

```text
市场需求 -> 关键词与页面 -> 发现 -> 抓取 -> 渲染 -> 索引
-> 查询排名 -> 搜索展示 -> 点击 -> 到站行为 -> 有效业务 -> 收入
```

这条漏斗最重要的用法是避免跨层猜测。

### 场景一：页面没有自然搜索点击

先查搜索平台是否有展示，再查 URL 是否被索引。若根本没有抓取记录，优先检查链接入口、Sitemap、robots 和响应状态；若已索引但查询不相关，再检查页面和需求映射。

不能因为“点击为零”就直接得出“标题不吸引人”。没有展示时，用户根本没看见标题。

### 场景二：广告有很多平台转化，销售却说没有客户

先核对转化定义、去重、业务结果回传和归因键。然后拆分品牌与非品牌、搜索词和落地页。此时继续提高预算，可能只会放大错误信号。

### 场景三：AI 回答了相关问题，却没有引用网站

先确认页面是否可访问、核心结论是否清楚、有无原始证据，以及内容是否真的比现有来源增加了信息。没有平台级引用数据时，只能记录为待验证假设，不能用一次人工提问代表整体表现。

## 为模拟网站建立第一张诊断表

现在给“技术审计服务”做一张最小表。这里的数据全部是教学用模拟值，不代表真实项目：

| 层级 | 要回答的问题 | 证据来源 | 当前判断 |
| --- | --- | --- | --- |
| 需求 | 用户会怎样描述问题 | 客户访谈、搜索词、销售记录 | 待收集真实问法 |
| 页面 | 哪张页面负责回答 | URL 清单、页面模板 | 教程与服务页需分开 |
| 抓取 | 搜索引擎能否获得页面 | GET 响应、robots、日志 | 需要实际检查 |
| 索引 | 页面是否进入索引 | 搜索平台 URL 检查 | 当前无数据 |
| 展示 | 哪些查询产生曝光 | 搜索表现报表 | 当前无数据 |
| 点击 | 标题是否匹配意图 | CTR、查询与页面 | 需有展示后判断 |
| 转化 | 用户是否完成咨询 | 站内事件 | 只能作为中间信号 |
| 业务 | 咨询是否有效 | CRM 或人工确认 | 核心结果 |
| 收入 | 是否产生可持续价值 | 订单、退款、毛利 | 最终业务约束 |

表里允许写“无数据”。数据缺口本身就是结论，它能阻止团队在证据不足时编造原因。

## 第一次搜索增长检查怎样做

### 第一步：从真实问题建需求清单

找出用户在购买前、使用中和故障时会提出的问题。来源可以是销售记录、客服工单、站内搜索和广告搜索词。每条记录原始问法，不要先改成工具里看起来搜索量更高的词。

### 第二步：为每个问题指定页面任务

用一张映射表记录查询意图、目标页面、页面类型和希望用户完成的下一步。一个页面可以覆盖紧密相关的表达，但不同任务不要强行合并。

### 第三步：确认机器能获得和理解页面

使用真实 GET 检查状态码、跳转、响应头、原始 HTML 和渲染后内容。继续检查 robots、Sitemap、Canonical、标题、主标题、结构化数据和内部链接。

浏览器扩展或审计工具可以收集证据，但工具分数不是搜索引擎评分。每条问题都要展示检测依据、影响范围和复查方法。

### 第四步：建立搜索与业务数据连接

自然搜索至少记录查询、页面、展示、点击、日期和品牌分类。广告还要记录成本、匹配方式、搜索词、系列、落地页和平台转化。业务侧用点击 ID、UTM 或受控归因键关联有效线索、订单、退款和毛利。

关联不上时，应降低结论置信度，而不是把全部收入按最后一次点击强行分配。

### 第五步：一次只改变一个主要变量

如果同时改标题、页面正文、广告预算和转化目标，数据变化后无法判断原因。为每次修改记录日期、假设、影响页面、观察指标和停止条件，并等待与抓取、成交延迟相称的周期。

## SEO、SEM 和 GEO 怎样协同

可以用一个循环把三者连接起来：

1. SEM 小范围验证真实查询和落地页匹配，但不把短期点击当作需求真相。
2. 将反复出现且有业务价值的问题沉淀为 SEO 页面。
3. 页面使用可验证事实、清晰结构和原始证据，提高搜索和生成式系统理解的可能性。
4. SEO 页面获得的查询和站内行为继续修正广告关键词与创意。
5. 三个渠道最终都回到有效业务和收入，而不是各自汇报漂亮的中间指标。

品牌流量要单独看。用户已经知道品牌后再点击广告，平台可能获得一次转化，但不代表广告创造了全部需求。必要时通过地域、时间或受控停投实验估计增量价值。

## 带到工作中的搜索增长检查表

- 我们解决的是需求、抓取、索引、排名、点击还是转化问题？
- 每个重要查询是否有职责明确的页面？
- 页面是否通过真实 GET 返回正确状态和核心内容？
- 搜索数据是否区分品牌与非品牌？
- 平台转化是否与有效业务结果核对？
- SEO、SEM、GEO 是否使用同一页面任务和业务口径？
- 当前结论是事实、可验证假设还是数据缺口？
- 本次修改改变了几个主要变量，如何判断成功或回滚？

下一篇会先回答一个更现实的问题：一个项目到底值不值得投入 SEO。因为没有稳定需求、可交付产品或数据能力时，技术优化做得再完整，也不一定能形成增长。
