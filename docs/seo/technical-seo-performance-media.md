# 技术 SEO、性能与图片视频优化

技术 SEO 的目标不是把 Lighthouse 分数刷满，而是让公开页面可访问、可理解、可缓存、可测量，并在真实设备上快速完成用户任务。性能、渲染、媒体和索引相互影响：首屏脚本阻塞可能让正文延迟出现，错误缓存可能把旧 canonical 发给爬虫，大图和视频可能拖慢最大内容绘制；但单纯压缩图片也不能修复错误的 HTTP 状态或页面意图。

## 先选择渲染方案

静态生成适合变化频率低、内容公开且可在构建阶段获得的数据；服务端渲染适合需要请求时数据但仍要返回可读 HTML 的页面；客户端渲染适合强交互和登录后区域。混合方案通常更实际：公开标题、摘要、正文和内链先在 HTML 中返回，交互再渐进增强。

| 页面类型 | 首选策略 | 关键风险 | 验收 |
| --- | --- | --- | --- |
| 文档/文章 | 静态或增量生成 | 发布后缓存未失效 | HTML、内链、更新时间 |
| 目录/搜索 | 服务端或可分页 SSR | 参数组合膨胀 | 分页和索引规则 |
| 编辑器/控制台 | 客户端 | 无需公开索引 | 鉴权和性能预算 |
| 实时数据 | SSR 首屏 + 流式增强 | 连接和缓存冲突 | fallback 与超时 |

## JavaScript 和缓存边界

关键内容不要等到点击、滚动或第三方脚本完成后才插入。将非关键脚本 `defer`、按路由拆分、延迟加载；不在首屏加载不影响主任务的编辑器、图表和追踪 SDK。缓存键必须包含会改变响应的语言、用户范围和版本，私有响应不能被公共 CDN 复用。

```http
Cache-Control: public, max-age=60, stale-while-revalidate=300
ETag: "article-v42"
Vary: Accept-Encoding, Accept-Language
```

上面是公开文章的模拟策略；登录、权限或个性化数据应使用 `private` 或不缓存。发布新版本时用版本化静态资源和可控失效，避免一边更新 HTML、一边让旧脚本解析新数据结构。

## Core Web Vitals 要和任务一起看

LCP 关注主要内容出现的速度，INP 关注交互响应，CLS 关注布局稳定性。它们是用户体验信号，不是“通过/失败”开关。先按设备、网络、模板和页面类型分组，找到真实瓶颈，再决定优先级。常见原因包括服务端首字节慢、关键图片未预加载、字体阻塞、长任务、未设置媒体尺寸和第三方脚本过多。

```js
new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    console.log(entry.name, entry.startTime, entry.duration)
  }
}).observe({ type: 'longtask', buffered: true })
```

示例只用于本地诊断，不应把用户隐私或完整 URL 直接打到公开日志。线上采集要脱敏、采样并关联模板和版本。实验室分数只能说明某次设备和网络，最终要与真实用户数据、索引和业务事件一起判断。

## 图片交付规则

图片应有明确教学或产品价值，使用正确的格式、尺寸和替代文本。根据展示尺寸提供响应式资源，避免用一张超大图缩放到小卡片；首屏主图优先加载，屏外图片懒加载；不要用 CSS 背景图承载唯一信息。`alt` 要描述图片传达的内容，装饰图使用空 `alt`，不能把关键词塞进替代文本。

```html
<img
  src="/media/architecture-960.avif"
  srcset="/media/architecture-480.avif 480w, /media/architecture-960.avif 960w"
  sizes="(max-width: 768px) 100vw, 760px"
  width="960"
  height="540"
  loading="lazy"
  decoding="async"
  alt="请求、检索、验证和事件流之间的数据关系"
>
```

图片 CDN 的裁剪、质量和格式参数要固定白名单，避免任意 URL 代理造成 SSRF 或缓存爆炸。文件名、周围正文和页面标题可以帮助理解，但不替代可见内容和替代文本。

## 视频与专题页

视频首屏应提供标题、摘要、封面和文字转录，避免只有一个播放器。自托管或第三方播放器要处理懒加载、字幕、键盘操作、隐私同意和失败降级。专题页不应只是多个卡片堆叠：需要有主问题、分段导航、上下文链接、更新时间和每个模块的职责。

## 真实 404 和脚本失败

内容站的不存在路径必须返回真实 404，应用内部路由不能用 200 的空壳模板掩盖错误。关闭脚本后，公开页面仍应有标题、正文和内链；模拟慢网络、第三方脚本失败、图片失败和窄屏滚动，检查用户是否还能完成主要任务。

## 发布门禁

```text
构建前：检查静态资源尺寸、重复图片、生成的 canonical 和 sitemap
构建后：检查响应状态、原始 HTML、缓存头、压缩和资源依赖
浏览器：375/768/1440px，慢 4G，禁用脚本，键盘导航
线上观察：模板分组的 LCP/INP/CLS、抓取状态、错误率和业务事件
```

任何性能优化都要记录基线、改动、实验条件和回滚方式。把 HTTP/2 Server Push 当作主要优化或用多 CDN 并发“堆速度”都不可靠；浏览器协议和缓存行为变化很快，应优先减少关键路径和传输内容。

## 实施记录：从问题到动作

性能优化要建立模板预算：HTML 大小、关键 CSS、首屏图片、脚本长任务和第三方请求分别设上限。发布时做旁路构建与真实设备验证，发现图片 CDN、缓存或脚本失败影响正文时优先回滚，避免只修实验室分数。

执行记录需要保留四类信息：基线快照、改动版本、观察条件和业务对账。基线至少包含 URL、模板、查询/搜索词、状态码、索引资格、事件口径和时间范围；改动要能定位到内容、路由、缓存、创意或出价的具体版本；观察条件要记录设备、地域、语言、模型或平台版本；业务对账要以服务端的资格、成交、退款和回款为准。这样在结果变差时可以回到上一个可用版本，而不是凭记忆争论。

## 故障演练与回滚

| 演练场景 | 预期信号 | 保护动作 | 恢复证据 |
| --- | --- | --- | --- |
| robots 或 WAF 误拦截 | 抓取 4xx 上升、核心 URL 失败 | 恢复规则并限制变更面 | GET、日志、覆盖报告 |
| 模板发布错误 | title/canonical/正文异常 | 回滚模板或内容版本 | 原始 HTML 对比 |
| 追踪重复或丢失 | 客户端与服务端数量不一致 | 停止自动化学习，修复去重 | 事件 ID 对账 |
| 业务质量下降 | 有效率、退款或毛利越过护栏 | 收紧查询/预算或下线页 | CRM/订单状态 |

演练使用模拟场景和最小流量，不改变真实生产预算或数据。回滚后再次检查公开页面、缓存、站点地图、广告参数、事件队列和业务状态；只有所有关键证据恢复，才允许继续实验。

## 结果判定与后续动作

把结论分为事实、假设和缺口。事实必须能由页面、日志、平台、实验或业务记录直接复核；假设写出可证伪的预测；缺口说明缺少哪项数据以及它会影响哪项判断。观察周期内不要连续叠加多个主变量，也不要把平台评分、平均排名或单次引用当作有效业务的替代。

```text
基线 -> 小范围变更 -> 技术验收 -> 搜索/广告观察 -> 业务对账 -> 继续、调整、合并或停止
```

## 操作清单与决策记录

按模板设置 HTML、关键 CSS、图片、脚本和第三方请求预算，真实设备回归通过后再扩大。

发布或投放前按顺序记录：

1. **范围**：目标用户、语言、地域、页面类型和明确不覆盖的需求。
2. **证据**：查询样本、页面版本、规范/源码/实验来源、数据时间和负责人。
3. **技术**：状态码、抓取规则、canonical、sitemap、内链、缓存、脚本失败和移动端表现。
4. **业务**：主转化、资格条件、去重键、成交/退款状态和归因窗口。
5. **保护**：预算或发布范围、护栏指标、观察周期、回滚版本和停止条件。

## 指标与停止条件

| 信号 | 可继续的证据 | 应暂停或回滚 |
| --- | --- | --- |
| 技术 | 公开 URL 状态稳定，规范页和索引目标一致 | 5xx、误拦截、canonical 冲突或空壳正文 |
| 搜索 | 相关查询、页面和点击方向一致 | 查询意图偏移、重复页面或无效展现激增 |
| 用户 | 到站后完成主要任务，错误反馈可解释 | 跳转、表单、脚本失败导致任务中断 |
| 业务 | 有效率、毛利和退款符合护栏 | 低质量线索、退款上升或归因无法对账 |

停止不是失败，而是保护样本和现金流的工程动作。停止后保留原始事件、页面快照和决策日志；需要恢复时先回到最后一个可验证版本，再单独改变一个变量。

### 资源预算示例

把关键 HTML、CSS、字体、首屏媒体、脚本和第三方请求分别设预算，并按移动端慢网验证。预算超限时先删减非关键依赖或降低媒体尺寸，不能只把加载交给更强的服务器；服务器变快也不能修复脚本错误、布局跳动和空壳正文。

```text
事实（页面/日志/业务记录） -> 假设（可证伪预测） -> 动作（单一变量） -> 观察（固定口径） -> 决策（继续/调整/停止）
```
