# 平台 CPA 50 元，为什么销售说每条有效线索要 500 元

广告平台记录了 20 次“转化”，成本 1,000 元，因此平台 CPA 是 50 元。业务系统里只有 2 条通过资格审核的咨询，其中 1 条后来退款。两个团队都没有算错，只是“转化”定义不同。

如果自动出价优化的是任意表单成功，它会寻找更容易提交的人；若重复提交、垃圾线索和测试数据也被计入，算法会越来越擅长购买无效结果。SEM 的真实链路必须从搜索词和创意一直连接到有效业务、退款与毛利。

上一篇的[搜索词治理表](/docs/seo/sem-search-terms-bidding-budget)给出哪些查询值得保留。本篇把这些查询的广告承诺、实际落地页、事件和业务结果逐层对账，输出一份可供投手、开发、数据和销售共同验收的追踪表。

## 创意不是写得热闹，而是减少错误点击

一组搜索广告要回答：

1. **相关性**：是不是用户刚刚搜索的任务；
2. **价值**：页面能解决什么问题；
3. **差异**：适合哪些对象与场景；
4. **证据**：产品、案例、流程、价格或资质怎样核对；
5. **行动**：点击后能试用、咨询、购买还是继续比较。

**Ad Creative（广告创意）**的输入是广告组意图、真实产品事实和平台格式，处理是组合标题、描述与资产，输出是用户看到的承诺。标题组合每一条应承担不同信息，不能只是同一句话换顺序。

创意里出现的价格、库存、时效、地域和效果必须在落地页可见。页面不能兑现时先修改或暂停广告，不用小字免责声明掩盖主要承诺。

创意数据至少保存平台、系列、广告组、标题、描述、最终 URL、状态和日期。标题、描述或 URL 缺失，以及同一广告组无解释地对应多个不同任务页面，都应进入复核。

## Message Match 决定点击后是否“走错房间”

**Message Match（信息匹配）**是搜索词、广告承诺、落地页首屏和转化动作的一致程度。用户搜索“餐饮预约系统价格”，广告写“餐饮门店方案”，点击后应直接看到适用对象、价格/计费方式和试用路径，而不是通用公司首页。

信息匹配的输入是实际搜索词、最终展示创意与实际最终 URL，处理是人工比较页面任务，输出是通过、需调整或拆广告组。它不能只靠关键词重复次数判断。

落地页通常包含 **CTA（Call to Action，行动引导）**，即希望用户执行的试用、咨询或购买动作。完整信息顺序可以是：

```text
首屏确认需求、对象、价值和主 CTA
-> 问题与成本
-> 方案、适用条件和限制
-> 产品/案例/方法证据
-> 购买、试用或咨询流程
-> 价格、隐私、售后与常见疑虑
-> 再次行动
```

SEO 页面可能覆盖更完整主题，SEM 页面更聚焦一组意图；两者都需要真实内容、移动可用、性能和信任。广告专页不是制作空壳和隐藏信息的理由。

## URL 标记只能放渠道信息

**UTM Parameters（Urchin Tracking Module 参数）**常用来记录来源、媒介、系列和创意，例如：

```text
/demo?utm_source=google&utm_medium=cpc&utm_campaign=booking_core&utm_content=proof_a
```

名称应小写、稳定、可枚举。不要把邮箱、电话、姓名、合同或内部敏感信息放进 URL。跳转、跨域和注册后要在合法同意与第一方边界内保留首次来源；Canonical 仍指向没有追踪参数的规范页面。

平台点击 ID 往往提供更精确关联，但仍受同意、保存期限和归因窗口限制。缺失时可尝试 UTM Campaign 或受控系列键，候选不唯一时降低置信度，不把订单强行匹配。

## Conversion Tracking 的输入输出

**Conversion Tracking（转化追踪）**记录用户完成目标动作，并把事件与来源关联。它的输入是用户动作和业务状态，浏览器/服务器处理去重与关联，输出是分析事件、业务记录和可选的平台回传。

一条可靠链路至少有：

```text
点击标识/UTM -> 第一方会话 -> event_id -> lead_id/order_id
             -> 有效性 -> 成交/收入 -> 退款 -> 毛利
```

浏览器事件不是业务事实。前端显示“提交成功”后，后端仍应验证、持久化并返回唯一业务 ID；重复网络请求使用幂等键返回同一结果。分析事件只在业务成功并满足必要同意条件后触发。

事件中不发送姓名、邮箱、电话和地址。拒绝非必要分析后，业务表单应按合法目的继续工作；不能用指纹绕过用户选择。开发实现需按目标市场隐私要求和平台政策审核。

## Primary 与 Observation 转化怎样分开

| 类型 | 英文 | 示例 | 是否给自动出价学习 |
| --- | --- | --- | --- |
| 主要转化 | Primary Conversion | 有效咨询、激活试用、付款 | 通过业务验收后才是 |
| 观察转化 | Observation/Secondary Conversion | 查看价格、播放演示、开始填表 | 通常只诊断漏斗 |
| 诊断事件 | Diagnostic Event | 表单错误、支付失败、接口超时 | 不作为成功目标 |

平台设置只有观察事件、没有可识别主要转化时，自动策略可能缺少正确目标；把所有微动作都设主要转化，则会优化最容易发生的点击。变更主要目标属于核心实验，要记录时间、学习期和历史不可比范围。

## 四个成本/回报指标回答不同问题

假设周期内成本 1,000 元、平台转化 20、有效线索 2、收入 4,000、退款 1,000、毛利 1,200：

### Platform CPA

**Platform CPA（平台 CPA）**：

```text
平台 CPA = 成本 / 平台记录转化 = 1000 / 20 = 50 元
```

它适合检查平台学习目标和报表，不能代表真实获客成本。

### Valid CPA

**Valid CPA（有效 CPA）**：

```text
有效 CPA = 成本 / 有效业务 = 1000 / 2 = 500 元
```

“有效”必须由业务定义并去重。线索、订单和新客户的 CPA 仍是不同分母。

### Refund-adjusted ROAS

**ROAS（Return on Ad Spend，广告支出回报）**通常为归因收入/广告成本。为了反映退款：

```text
退款后 ROAS = (收入 - 退款) / 成本 = (4000 - 1000) / 1000 = 3.0
```

3.0 表示每 1 元广告成本对应 3 元退款后收入，不代表有 3 元利润。

### Gross Profit Return

**Gross Profit Return（毛利回报）**：

```text
毛利回报 = 可归因毛利 / 广告成本 = 1200 / 1000 = 1.2
```

它比收入 ROAS 更接近可持续性，但还可能未包含团队、软件、销售和固定成本。SaaS 还要结合续费和回收周期。

四个指标应并列，不能拿平台 CPA 掩盖有效 CPA，也不能用平台回传价值冒充退款后收入。

## Attribution Confidence 怎样标记

**Attribution Confidence（归因置信度）**描述业务结果与广告行之间的关联可靠程度：

- 点击 ID 精确唯一匹配，可记高置信度；
- UTM Campaign 只对应一行/一组，可记中；
- 仅靠系列名称或时间近似，可记低；
- 无法匹配，保留未知。

还要计算 **Link Rate（关联率）**：`已关联业务结果 / 全部业务结果`。只关联 2/20 条时，不能用这两条代表全部搜索词。平台归因窗口、跨设备、同意与离线延迟仍会造成缺失。

首次归因适合看最初获客，末次归因适合看成交前触点。品牌广告、自然搜索和直接访问常在一条路径出现，一笔收入不能在汇总时被每个渠道各算 100%。增量实验比选择一个“更漂亮”的归因模型更接近真实贡献。

## 数据对账先于页面实验

每周至少对比：平台转化、前端成功事件、后端业务记录、有效业务、收入和退款。平台 20、后端 10、有效 2 时，要定位重复、失败、垃圾和延迟发生在哪层。

平台转化与有效业务比值持续低于 50% 只是一个风险阈值示例，最终标准取决于业务。发现差距后，先检查事件去重、表单验证、业务审核和离线回传，再调整创意或出价。

数据稳定后才做落地页实验。一次测试一个核心假设，例如首屏对象表达、证据位置或表单字段；主要指标使用有效线索率或订单，保护指标包括页面错误、表单完成、销售质量和退款。样本不足时报告不确定。

## 验收所有失败分支

转化追踪至少测试：

- 桌面与移动、直接访问与带广告参数；
- 页面最终 URL 和 Canonical；
- 表单成功、前端校验失败、后端失败与超时；
- 重复点击和相同幂等键；
- 同意、拒绝和撤回非必要分析；
- 跨页面/允许的跨域流程；
- 线索判无效、订单取消和退款修正；
- 追踪脚本失败时业务流程仍可用。

每种场景记录浏览器事件、网络请求、后端记录、广告平台预期和最终业务结果。追踪回滚不能让业务表单一起失效。

## 本篇产物：转化与归因验收表

```text
搜索词/广告组｜创意承诺｜指定与实际最终 URL｜页面任务｜
event_id｜主要/观察/诊断事件｜触发条件｜同意条件｜去重｜
lead/order ID｜有效状态｜收入｜退款｜毛利｜转化延迟｜
点击ID/UTM/归因键｜关联置信度｜失败测试｜负责人
```

SEM 投手维护创意和平台目标，开发实现页面与幂等事件，数据负责人做关联、去重和回传，销售/业务确认有效性、退款和毛利，创业者决定可承受成本。SEO 负责人可复用页面证据，但自然与付费归因要分开。

验收必须能计算平台 CPA、有效 CPA、退款后 ROAS 和毛利回报，并说明关联率与缺口。下一篇会在这套可信数据上诊断 Google、Bing 和百度的自动化功能。
