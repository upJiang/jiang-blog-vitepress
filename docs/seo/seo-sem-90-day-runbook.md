# SEO 与 SEM 协同的 90 天执行手册

新网站最容易同时犯两个错误：先批量生产内容，又在追踪没验收时开启大量广告。三个月后有文章、有点击，也有平台转化，却说不清哪些需求真实、哪些页面有效、钱应该继续投在哪里。

这份手册把前 17 篇组织成 90 天顺序。目标不是承诺排名或回报，而是建立一套能够观察、验证、调整和停止的搜索增长系统。

## 开始前准备六份输入

1. 商业模型：服务谁、如何收费、毛利和交付边界；
2. 用户问题库：访谈、销售、客服和搜索词；
3. 竞争页面表：结果类型、价值和缺口；
4. 关键词与页面映射：意图、页面、状态和下一步；
5. 技术基线：URL、HTML、状态码、性能、日志和发布；
6. 数据字典：自然/付费、品牌/非品牌、转化、收入与退款。

信息缺失时先做能够观察的检查，并把缺口写出来。不要用估算值冒充后端业务事实。

## 90 天路线图

```mermaid
flowchart LR
  A[1-14 天 验证市场] --> B[15-30 天 建页面与测量]
  B --> C[31-50 天 发布核心内容]
  C --> D[51-70 天 小预算广告]
  D --> E[71-90 天 对账与决策]
```

每个阶段只有通过当前验收，才扩大下一阶段投入。生产环境误禁抓取或转化追踪错误时，先恢复基础，不继续扩内容和自动出价。

## 第 1–14 天：判断方向

明确目标用户、产品、核心转化和可承受成本。观察至少一组核心搜索结果，完成项目六维评分，并选择最需要反证的假设。

输出不是一份宏大关键词清单，而是“投入、先验证、暂缓”的初步结论，以及停止条件。例如用户问题真实，但产品激活尚未稳定，就先验证产品承接，不急着扩展自然页面。

## 第 15–30 天：搭结构和测量

完成页面类型、栏目、URL、内链和第一版页面映射。上线少量核心商业页与必要说明，检查真实 GET、原始 HTML、canonical、站点地图、移动体验和错误状态。

同时定义主要转化、辅助事件和业务对账。表单成功、重复提交、失败、拒绝非必要同意和退款都要有预期结果。

## 第 31–50 天：发布核心内容

围绕已验证问题发布少量支柱、教程、比较和帮助内容。每篇有明确承诺、来源、独特材料、前后内链和复查责任。

观察发现、抓取、索引和初始展现。新页面短期没有排名不等于立刻失败，但大量重复、空壳或技术错误应暂停扩量。

## 第 51–70 天：用小预算广告验证

建立精简账户，品牌、非品牌和探索需求分开。先投少量高意图词，查看真实搜索词、到站、主要转化、有效业务与可承受成本。

广告可以把新搜索词反馈给 SEO，也可以验证某个页面承诺是否有需求。它不能证明长期自然排名，也不能在追踪失真时指导自动出价。

## 第 71–90 天：对账并做决定

连接自然与付费的查询、页面、有效转化、收入和退款。检查品牌重复归因，比较新增预算与新增价值，找出最大瓶颈位于需求、页面、技术、产品还是销售。

第 90 天只做四类决定：

- **扩大**：需求和业务已验证，边际回报仍可接受；
- **维持**：稳定产生价值，但市场或交付接近上限；
- **调整**：存在明确瓶颈，只改一个主要假设；
- **停止**：多轮验证无需求、成本不可承受或风险不可接受。

停止错误方向是有效决策，不为沉没成本继续扩量。

## 每周怎样工作

| 时间 | 工作 | 输出 |
| --- | --- | --- |
| 周一 | 复核业务目标、异常与假设 | 本周优先级 |
| 周二至周三 | 页面、内容、技术或广告改动 | 可验收版本 |
| 周四 | 数据、质量和失败测试 | 验证记录 |
| 周五 | 复盘并记录继续/调整/停止 | 决策日志 |

普通排名波动不打乱整个节奏。P0 服务故障、生产误禁抓取、主要转化完全错误或广告异常花费则立即止损。

## 一个任务怎样才算可执行

每项任务都写：已确认事实、主要假设、影响范围、动作、负责人类型、工作量、验证指标、观察周期和回滚。像“加强内容”“提高权重”这样的描述没有验收标准。

正常计划会在第 30 天发现表单重复记录，于是先修幂等和对账，再启动广告。失败计划为了追赶日程照常投放，最终让自动系统学习了错误转化。

## 第 90 天只回答五个问题

1. 哪些搜索需求有真实证据？
2. 哪些页面能被发现、点击并产生业务？
3. SEO 与 SEM 是否存在重复归因？
4. 当前最大瓶颈在哪一层？
5. 下一季度只做哪三件事，又停止哪些工作？

这套节奏可以用于新站，也可以用于一次季度重构。规模会变化，先验证再扩大的原则不变。
