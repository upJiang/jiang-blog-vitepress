# SEO 与 SEM 协同的 90 天执行手册

90 天计划不是承诺 90 天排名，而是把市场假设、页面能力、技术可抓取性、内容证据、广告小预算实验和有效业务测量串成一轮可复盘周期。SEO 和 SEM 共享搜索需求与落地页，但不共享同一套成功指标：SEO 更关注可持续的相关发现和自然业务，SEM 更关注付费增量、边际成本和学习稳定性。

## 启动前的输入

开始前收集站点、产品、市场、用户、核心转化、数据源、当前发布/广告变化和操作权限。把事实、假设、缺口分开：例如“某目录返回 200”是事实，“因此已被索引”是假设；“平台有 20 个转化”不是业务事实，除非能在服务端找到去重和资格记录。缺少查询、日志或订单数据时，优先建立测量，不要直接扩内容或预算。

## 诊断主流程

```mermaid
flowchart LR
  A[目标和口径] --> B[需求与页面映射]
  B --> C[抓取/索引/性能]
  C --> D[内容与落地页]
  D --> E[小预算 SEM]
  E --> F[有效业务对账]
  F --> G[继续/调整/停止]
```

问题分级要可执行：P0 是全站不可访问、禁止抓取或计费/追踪失控；P1 是核心目录索引错误、严重错误页面或广告预算持续流向无效需求；P2 是内容缺口、内链、创意和落地页实验；P3 是证据不足或短期波动。每个问题写证据、影响、动作、工作量、验证指标、观察周期和回滚。

## 第 1-14 天：市场和测量

完成用户访谈、客服/销售问题归类、查询样本和结果页抽样；区分了解、排障、比较、交易、本地和导航意图；建立页面映射表和品牌/非品牌分组。同步校验真实 GET、robots、sitemap、canonical、404、原始 HTML、移动端和关键脚本。建立第一方事件、服务端业务状态、去重规则和数据字典。

交付物不是一堆关键词，而是优先查询簇、页面职责、证据缺口、业务事件、基线看板和停止条件。此阶段若发现产品匹配弱、市场无法触达或数据不可验证，应缩小实验或停止，不要用内容数量掩盖。

## 第 15-30 天：结构和核心页面

修复阻断抓取/索引的问题，统一 URL、内链和模板元信息；发布少量能完整解决核心任务的页面，包含方法、边界、作者、更新时间和来源。页面之间按知识前置和下一步任务建立链接，避免一个查询生产多个近似 URL。保留发布前快照，给每篇文章设置刷新/合并/下线条件。

```text
页面上线闸门：
□ 主意图和不覆盖范围清楚
□ 原始 HTML 有标题、正文、内链和必要元信息
□ 代码/数据/结构化信息可复核
□ canonical、sitemap、状态码一致
□ 移动端、禁脚本和错误路径可用
□ 作者、来源、更新时间和回滚版本已记录
```

## 第 31-50 天：内容和内链迭代

根据真实查询和用户问题补充案例、实验、反例与参考资料；不以固定字数或关键词密度为目标。人工审阅 AI 辅助草稿的事实、代码、安全和责任链，记录来源版本。观察抓取、索引、查询、CTR、回访、问题解决和有效业务，不要把短期排名变化当成文章质量证明。

## 第 51-70 天：小预算 SEM 验证

只为已经有明确页面和测量链路的查询建立小范围系列，分开品牌、非品牌和竞品；使用否定词、预算上限和合规审核。创意兑现落地页承诺，点击 ID 和服务端记录可对账，主转化使用经过资格校验的业务事件。优先查看搜索词和有效率，预算扩大必须以边际有效业务价值为依据。

## 第 71-90 天：复盘与决策

把自然和付费流量分开看，再按查询、页面、模板和版本对账有效业务、收入、退款和新客比例。对每个实验决定扩大、维持、调整或停止；写清证据、假设、未验证风险和下个观察周期。SEO 内容可以刷新、合并或淘汰，SEM 系列可以改查询、创意、页面、出价或预算，但不要同时改变所有变量。

## 每周决策日志

```yaml
week: 6
change: 调整非品牌系列的落地页首屏结构
fact:
  - qualified_lead_rate_by_page
  - tracking_reconciliation_status
hypothesis: 直接说明适用范围会减少无效申请
guardrails:
  - index_coverage
  - refund_rate
  - invalid_query_rate
decision: observe
owner: content-and-growth
next_review: 2026-09-16
rollback: restore-content-version-12
```

这个日志是模板示例，指标必须来自真实数据源。记录“不做什么”同样重要：没有证据时不扩大页面、不提高预算、不承诺排名；追踪失真时先暂停自动化；发现 P0/P1 时先恢复可用性和索引边界。

## 放大、调整和停止

可以放大的条件是：需求与业务匹配、数据链路稳定、有效业务边际价值为正、页面和广告承诺一致、质量护栏没有恶化。需要调整的信号包括查询意图偏移、有效率下降、重复页面、索引异常、创意吸引错误人群和内容事实过期。停止条件包括无法核验业务价值、持续产生安全/合规风险、预算流向无效需求或反证实验表明市场不成立。

## 实施记录：从问题到动作

90 天结束不代表项目自动扩大。复盘要给出继续、调整、合并、停止的明确结论，列出未验证缺口和下个周期的最小实验；没有稳定的有效业务和回滚点时，宁可缩小范围也不要用更多页面或预算掩盖不确定性。

执行记录需要保留四类信息：基线快照、改动版本、观察条件和业务对账。基线至少包含 URL、模板、查询/搜索词、状态码、索引资格、事件口径和时间范围；改动要能定位到内容、路由、缓存、创意或出价的具体版本；观察条件要记录设备、地域、语言、模型或平台版本；业务对账要以服务端的资格、成交、退款和回款为准。这样在结果变差时可以回到上一个可用版本，而不是凭记忆争论。

## 故障演练与回滚

| 演练场景 | 预期信号 | 保护动作 | 恢复证据 |
| --- | --- | --- | --- |
| robots 或 WAF 误拦截 | 抓取 4xx 上升、核心 URL 失败 | 恢复规则并限制变更面 | GET、日志、覆盖报告 |
| 模板发布错误 | title/canonical/正文异常 | 回滚模板或内容版本 | 原始 HTML 对比 |
| 追踪重复或丢失 | 客户端与服务端数量不一致 | 停止自动化学习，修复去重 | 事件 ID 对账 |
| 业务质量下降 | 有效率、退款或毛利越过护栏 | 收紧查询/预算或下线页 | CRM/订单状态 |

演练使用模拟场景和最小流量，不改变真实生产预算或数据。回滚后再次检查公开页面、缓存、站点地图、广告参数、事件队列和业务状态；只有所有关键证据恢复，才允许继续实验。

## 结果判定与后续动作

把结论分为事实、假设和缺口。事实必须能由页面、日志、平台、实验或业务记录直接复核；假设写出可证伪的预测；缺口说明缺少哪项数据以及它会影响哪项判断。观察周期内不要连续叠加多个主变量，也不要把平台评分、平均排名或单次引用当作有效业务的替代。

```text
基线 -> 小范围变更 -> 技术验收 -> 搜索/广告观察 -> 业务对账 -> 继续、调整、合并或停止
```

## 操作清单与决策记录

90 天复盘以继续、调整、合并或停止为结论，下一周期只保留一个最小可证伪实验。

发布或投放前按顺序记录：

1. **范围**：目标用户、语言、地域、页面类型和明确不覆盖的需求。
2. **证据**：查询样本、页面版本、规范/源码/实验来源、数据时间和负责人。
3. **技术**：状态码、抓取规则、canonical、sitemap、内链、缓存、脚本失败和移动端表现。
4. **业务**：主转化、资格条件、去重键、成交/退款状态和归因窗口。
5. **保护**：预算或发布范围、护栏指标、观察周期、回滚版本和停止条件。

## 指标与停止条件

| 信号 | 可继续的证据 | 应暂停或回滚 |
| --- | --- | --- |
| 技术 | 公开 URL 状态稳定，规范页和索引目标一致 | 5xx、误拦截、canonical 冲突或空壳正文 |
| 搜索 | 相关查询、页面和点击方向一致 | 查询意图偏移、重复页面或无效展现激增 |
| 用户 | 到站后完成主要任务，错误反馈可解释 | 跳转、表单、脚本失败导致任务中断 |
| 业务 | 有效率、毛利和退款符合护栏 | 低质量线索、退款上升或归因无法对账 |

停止不是失败，而是保护样本和现金流的工程动作。停止后保留原始事件、页面快照和决策日志；需要恢复时先回到最后一个可验证版本，再单独改变一个变量。

### 90 天复盘输出

复盘包应包括：查询与页面映射、技术问题清单、内容版本和来源、自然/付费数据口径、有效业务对账、实验结果、预算变化、已知缺口和下一周期决策。把“未做什么”和停止原因也写入版本库，避免下一轮重复同一条无效路径。

复盘会议按漏斗顺序进行：先确认网站和测量可用，再看需求和页面匹配，随后讨论抓取、索引、内容、广告和业务。每个结论后面必须有一项可执行动作或明确的观察任务；没有证据支持的机会放入待验证队列，而不是马上承诺资源。
每次会议只确定少量下一步动作，并为动作指定负责人、截止日期和回滚点。
这样下一周期才能比较决策，而不是比较记忆。
复盘结论应链接到对应的页面、日志和业务记录。

```text
事实（页面/日志/业务记录） -> 假设（可证伪预测） -> 动作（单一变量） -> 观察（固定口径） -> 决策（继续/调整/停止）
```
