# SEO 数据分析、归因与实验

SEO 报表最容易犯的错误是把平台指标当作业务事实：展现不是到站，点击不是线索，表单不是成交，最后一次来源也不等于唯一贡献。数据分析要先明确事件、主体、时间和口径，再沿“搜索 -> 到站 -> 行为 -> 有效业务 -> 收入”逐层对账。没有关键数据时，结论应标记为缺口，而不是用平均值补齐。

## 指标词典

| 指标 | 定义 | 不能直接推出 |
| --- | --- | --- |
| 展现 | 搜索结果中页面被展示的次数 | 用户看到了页面或愿意点击 |
| CTR | 点击/展现 | 页面质量或转化能力 |
| 平均位置 | 查询样本中的位置统计 | 所有人看到的固定排名 |
| 到站会话 | 分析系统记录的访问 | 有效用户或唯一真实访问 |
| 主要转化 | 预先定义的关键行为 | 订单、毛利或留存 |
| 有效业务 | 经过去重和资格校验的线索/订单 | 仍然没有退款和履约信息 |

指标需要按查询、页面、设备、语言、地域、品牌/非品牌、模板和版本分组。平均值会掩盖长尾和异常，尤其是多语言、多产品或改版后的站点。任何同比、环比都要写清时间范围、时区、归因窗口和数据延迟。

## 统一事件模型

第一方事件至少包含事件名、时间、匿名主体、页面 URL、查询/渠道标识、内容版本、同意状态和服务端关联 ID。敏感数据不要写入 URL、页面标题或日志；用户拒绝分析同意时，要按当地法规和产品策略减少采集。

```ts
type GrowthEvent = {
  eventId: string
  name: 'landing_view' | 'cta_click' | 'lead_created' | 'lead_qualified' | 'order_paid'
  occurredAt: string
  pageUrl: string
  contentVersion: string
  source: 'organic' | 'paid' | 'direct' | 'referral' | 'unknown'
  anonymousId?: string
  serverRecordId?: string
}
```

`lead_created` 和 `lead_qualified` 必须分开；前端点击和服务端成交也要分开。事件写入后通过服务端或数据仓库去重，不能仅凭浏览器事件判断收入。对于广告平台回传，要核对平台 ID、同意状态和最终业务状态，避免重复计数。

## 归因要保持谦逊

最后点击、首次接触、线性和时间衰减都是解释模型，不是因果证明。SEO 页面可能在广告、直接访问和销售跟进前多次被阅读；品牌词会吸收其他渠道创造的需求。报告中至少拆分品牌与非品牌、自然与付费、平台转化与有效业务，并说明归因窗口。要估计增量价值，需要地理/时间分组、暂停实验或其他能控制混杂的设计，而不是只比较平均 CPA。

## URL 级看板

看板应支持从目录到页面到查询的下钻：页面版本、抓取状态、索引资格、展现、点击、CTR、到站、关键行为、有效业务、收入和更新时间。为每个异常记录 P0/P1/P2/P3 分级、证据、假设、动作、验证指标和观察周期。

```sql
select page_url, content_version,
       sum(impressions) impressions,
       sum(clicks) clicks,
       sum(qualified_leads) qualified_leads,
       sum(revenue) revenue
from growth_daily
where day between :start_day and :end_day
group by page_url, content_version
order by qualified_leads desc;
```

示例查询不代表任何真实表结构。指标需按同一时区和去重规则聚合；如果收入要跨系统关联，使用不可变的服务端 ID，而不是从客户端传入金额。对于低流量页面，展示“样本不足”比显示一个精确到小数的 CTR 更诚实。

## GEO 观察不能伪装成排名

生成式搜索结果具有随机性、模型差异和地区差异。可以建立固定查询样本，按日期、语言、地区、模型版本保存结果中是否出现主体、引用链接、描述是否准确、是否存在错误归因。把样本作为观察信号，不承诺引用率，也不要通过操纵内容诱导模型输出。更可靠的长期指标仍然是相关自然访问、品牌查询、引用质量和有效业务。

## 实验设计

先定义假设和一个主要变量，例如只改标题表达，不同时改 URL、正文、内链和价格；保存对照版本；预设最小观察周期和停止条件；分析时区、季节、发布、算法或产品活动等外部变化。SEO 实验通常需要较长周期，不能根据两天波动宣称因果。

```text
假设：首屏直接给出任务边界会提高非品牌查询的有效到站率
变量：导语结构
不变：URL、正文主体、内链、转化表单
主要指标：符合资格的到站 -> lead_qualified
护栏指标：404、索引覆盖、跳出/返回搜索、退款
停止：出现索引异常、错误咨询上升或数据质量失败
```

## 数据故障优先于内容优化

如果追踪丢失、跨域重复、时区错误、同意状态缺失或服务端事件延迟，先修复测量。可以用一条模拟用户链路对账：搜索平台点击、入口会话、页面版本、事件 ID、服务端记录、最终状态是否一一对应。只有链路稳定后，才讨论页面、预算和文案的边际变化。

## 实施记录：从问题到动作

看板必须显示数据新鲜度、采样和归因窗口。业务系统拒绝或退款后，历史转化应按版本修正但保留原始事件；模型或渠道调整要有对照组与护栏，避免把季节、发布和跟进延迟归因给某个标题。

执行记录需要保留四类信息：基线快照、改动版本、观察条件和业务对账。基线至少包含 URL、模板、查询/搜索词、状态码、索引资格、事件口径和时间范围；改动要能定位到内容、路由、缓存、创意或出价的具体版本；观察条件要记录设备、地域、语言、模型或平台版本；业务对账要以服务端的资格、成交、退款和回款为准。这样在结果变差时可以回到上一个可用版本，而不是凭记忆争论。

## 故障演练与回滚

| 演练场景 | 预期信号 | 保护动作 | 恢复证据 |
| --- | --- | --- | --- |
| robots 或 WAF 误拦截 | 抓取 4xx 上升、核心 URL 失败 | 恢复规则并限制变更面 | GET、日志、覆盖报告 |
| 模板发布错误 | title/canonical/正文异常 | 回滚模板或内容版本 | 原始 HTML 对比 |
| 追踪重复或丢失 | 客户端与服务端数量不一致 | 停止自动化学习，修复去重 | 事件 ID 对账 |
| 业务质量下降 | 有效率、退款或毛利越过护栏 | 收紧查询/预算或下线页 | CRM/订单状态 |

演练使用模拟场景和最小流量，不改变真实生产预算或数据。回滚后再次检查公开页面、缓存、站点地图、广告参数、事件队列和业务状态；只有所有关键证据恢复，才允许继续实验。

## 结果判定与后续动作

把结论分为事实、假设和缺口。事实必须能由页面、日志、平台、实验或业务记录直接复核；假设写出可证伪的预测；缺口说明缺少哪项数据以及它会影响哪项判断。观察周期内不要连续叠加多个主变量，也不要把平台评分、平均排名或单次引用当作有效业务的替代。

```text
基线 -> 小范围变更 -> 技术验收 -> 搜索/广告观察 -> 业务对账 -> 继续、调整、合并或停止
```

## 操作清单与决策记录

先修复事件去重、时区和业务状态对账，再做标题、内链或预算实验；数据缺失时停止推断。

发布或投放前按顺序记录：

1. **范围**：目标用户、语言、地域、页面类型和明确不覆盖的需求。
2. **证据**：查询样本、页面版本、规范/源码/实验来源、数据时间和负责人。
3. **技术**：状态码、抓取规则、canonical、sitemap、内链、缓存、脚本失败和移动端表现。
4. **业务**：主转化、资格条件、去重键、成交/退款状态和归因窗口。
5. **保护**：预算或发布范围、护栏指标、观察周期、回滚版本和停止条件。

## 指标与停止条件

| 信号 | 可继续的证据 | 应暂停或回滚 |
| --- | --- | --- |
| 技术 | 公开 URL 状态稳定，规范页和索引目标一致 | 5xx、误拦截、canonical 冲突或空壳正文 |
| 搜索 | 相关查询、页面和点击方向一致 | 查询意图偏移、重复页面或无效展现激增 |
| 用户 | 到站后完成主要任务，错误反馈可解释 | 跳转、表单、脚本失败导致任务中断 |
| 业务 | 有效率、毛利和退款符合护栏 | 低质量线索、退款上升或归因无法对账 |

停止不是失败，而是保护样本和现金流的工程动作。停止后保留原始事件、页面快照和决策日志；需要恢复时先回到最后一个可验证版本，再单独改变一个变量。

### 对账例外

迟到事件、退款、重复提交和跨设备访问都应进入异常队列，而不是静默丢弃。看板同时显示原始事件量、去重后量、业务确认量和数据新鲜度；这样业务、内容和增长团队看到的是同一条可追溯链路。

复盘时还要检查模型或渠道改动是否改变了事件命名、归因窗口和过滤条件。指标定义随版本保存，旧数据不因新口径被覆盖；需要修正时保留原始层和修正层，报告中明确口径变化。
只有稳定口径才适合比较实验。
异常记录必须可回放。
口径变更要在图表上标注。

```text
事实（页面/日志/业务记录） -> 假设（可证伪预测） -> 动作（单一变量） -> 观察（固定口径） -> 决策（继续/调整/停止）
```
