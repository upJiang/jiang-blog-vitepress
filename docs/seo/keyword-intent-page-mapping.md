# 怎样从用户问题找到关键词

客户说“网站上线一个月了，为什么还是搜不到”，关键词工具里却只有“网站收录”“SEO 优化”这类标准词。应该按客户原话写，还是追逐工具显示的高搜索量？

关键词研究的目标不是收集尽可能多的词，而是还原用户在什么场景下、想完成什么任务。先理解需求，再决定页面和商业动作，词表才有用。

上一篇的[五个 URL 分层诊断表](/docs/seo/crawl-index-ranking)已经把技术正常但查询不匹配的页面筛了出来。本篇把真实用户问法作为输入，输出“查询—意图—页面”映射；下一篇再把映射变成栏目、URL 和内链。

## 关键词只是需求的表达

同一个需求可以有很多说法：“网站搜不到”“网页没收录”“搜索引擎找不到页面”。文字不同，背后的任务可能相同。反过来，“Agent”这个词既可能表示概念学习，也可能是在找开发框架，不能只因词面相同就放进一页。

**Keyword（关键词）**是团队用来归纳需求的词或短语；**Search Query（搜索查询）**是用户在某次搜索里真正输入的表达。一个关键词可以汇总许多查询，但不能反过来抹掉用户语境。

**Search Intent（搜索意图）**是用户输入查询时希望完成的任务。它解决“同一个词为什么需要不同页面”的问题，输入包括查询、地区、设备和结果页样本，处理是判断任务与所处阶段，输出才是页面类型。常见意图包括了解、操作、比较、商业调查、交易和导航。

```mermaid
flowchart LR
  A[收集用户原话] --> B[识别任务与阶段]
  B --> C[观察搜索结果]
  C --> D[合并相同意图]
  D --> E[评估价值与成本]
  E --> F[进入页面规划]
```

## 第一步：先去业务现场找问题

关键词工具适合估算和扩展，真实语义通常来自更靠近用户的地方：

- 销售咨询、客服工单和用户访谈；
- 站内搜索、没有结果的搜索和帮助中心反馈；
- 自然查询与广告搜索词；
- 产品使用障碍、购买疑虑和售后问题；
- 行业社区反复出现、现有答案又不完整的问题。

先保留用户原话，不急着翻译成术语。教程标题可以用用户语言进入，再在正文解释“索引”“幂等”等标准概念。

## 第二步：给问题标注意图

| 用户表达 | 所处阶段 | 更合适的页面 |
| --- | --- | --- |
| Agent 是什么 | 了解 | 入门教程 |
| Agent 怎样调用工具 | 操作 | 分步实践 |
| LangGraph 和 Agents SDK 区别 | 比较 | 选型指南 |
| Agent 开发服务价格 | 商业调查 | 服务或方案页 |
| 下载某个工具 | 交易 | 产品入口 |
| 某品牌登录 | 导航 | 官方入口 |

意图不能只靠“是什么”“价格”等词尾机械判断。要打开目标地区的搜索结果，观察主流结果是文章、产品、视频、工具还是官网。结果形态是当前需求的重要证据。

## 第三步：把相同任务放在一组

两个查询是否能由同一页面承载，可以问三个问题：搜索结果是否高度相似，用户最终任务是否一致，一篇页面能否自然完整回答。如果答案大多为是，就应合并，而不是一词一文。

自动聚类和向量相似度可以帮助处理大词库，但最后仍需人工检查。文字相似不等于意图相同，文字差异也不代表需要不同页面。

**Clustering（聚类）**是把相似查询分组。SEO 中最有用的不是单纯按文字相似，而是同时比较用户任务和 SERP：如果两个查询的高排名页面类型与核心结果高度重叠，通常可以先测试由同一页面承接；若一个结果偏教程、另一个偏产品，就应拆开。

实体和修饰词也要保留。**Entity（实体）**指可明确识别的人、产品、地点、组织或概念；“预约系统”是主题，“餐饮门店”“多员工”“价格”则分别改变对象、场景和决策阶段。只有修饰词造成真实任务差异时，才值得新建页面。

## 第四步：决定先做哪些需求

搜索量只是一个估算，还要结合商业价值、团队能否给出独特答案、竞争空间、可获得点击和实施成本。可以使用 1–5 分帮助排序，但每一分都要附证据。

季节性也要单独记录。一个词的月均值可能来自全年稳定需求，也可能集中在考试、节日或采购季。自然内容通常需要提前发布；广告则要为旺季竞争和预算上限做准备。

生成式摘要、地图、商品和视频可能直接满足部分查询，搜索量不等于都能获得网页点击。此时可以转向更深入的任务、工具、图片或视频结果，而不是假设所有展示都会进入网站。

## 正常词库与失败词库

正常词库至少记录原始问题、标准主题、意图、用户阶段、地区、结果类型、商业价值、目标页面和当前决策。随机抽一条，另一位成员能判断该写教程、建产品页、做广告实验还是暂不投入。

失败词库只有“关键词、搜索量、难度”三列，然后按搜索量从高到低排期。它无法判断页面类型，也会把品牌、教程、价格和售后问题混在一起。

## 一个查询应该映射到哪张页面

映射表至少需要这些字段：

| 字段 | 判断问题 |
| --- | --- |
| 原始查询与来源 | 用户实际怎么说，来自销售、自然还是广告 |
| 标准主题与实体 | 归属哪个业务问题、对象和场景 |
| 主意图与阶段 | 想理解、操作、比较还是购买 |
| 结果页类型 | 当前主要是文章、产品、工具、视频还是地图 |
| 页面承诺 | 进入页面后具体能得到什么 |
| 独特材料 | 数据、案例、工具、产品能力或专家判断 |
| 主页面与状态 | 更新、新建、合并、迁移、观察或暂不承接 |
| 下一步动作 | 阅读、试用、咨询、购买或解决故障 |

允许“暂不承接”非常重要。一个词有搜索量，但团队没有真实材料、产品不能兑现或结果页几乎没有网页点击空间时，不创建页面比发布空泛内容更节省抓取和维护成本。

## 识别 Keyword Cannibalization 候选

**Keyword Cannibalization（关键词内耗）**通常指站内多个页面竞争同一搜索任务，导致搜索系统难以稳定选择主页面。它不是“同一个词出现在多篇文章”这么简单。

有价值的证据包括：同一查询在多个 URL 产生大量展示、目标 URL 在周期间频繁变化、普通文章替代了更匹配的商业页。处理前先确认意图，再选择主页面；其他页面可以合并、转向不同任务、保留但减少竞争，或在确实重复时迁移。

仅凭查询对应两个页面不能自动合并。品牌首页、帮助页和产品页可能在同一品牌查询下同时出现，却承担不同导航需求。要比较页面任务、展示份额、点击和业务价值。

## 竞品词需要额外边界

竞品查询可以用于研究比较需求，但内容应依据公开、可验证的差异，说明适用条件，不冒充对方，也不制造无法证明的贬低结论。广告还要遵守平台政策和商标规则。

## 从十条用户原话建立需求表

先收集销售、客服、站内搜索、自然查询和广告搜索词中的原句，不急着改成行业术语。以预约工具为例，“怎么避免客户爽约”“预约软件价格”“某品牌替代方案”分别接近问题解决、商业选择和比较决策，页面承诺不能完全相同。

| 字段 | 为什么要记录 |
| --- | --- |
| 原始查询 | 保留用户真实语言，避免内部术语替代需求 |
| 任务与意图 | 用户想学习、比较、购买、导航还是处理问题 |
| 结果页形态 | 当前更常出现教程、产品、视频、地图还是即时答案 |
| 商业动作 | 阅读、试用、询价、购买或线下到店 |
| 目标页面 | 更新现有页、新建、合并或暂不承接 |
| 证据来源 | 查询来自哪个平台、日期、地区和设备 |

聚类时比较“同一页面能否自然完整回答”，而不只看词面相似。两个词字面接近但一个要教程、一个要产品报价，应拆开；两个词表达不同但任务和结果页高度一致，可以由同一页承接。

随机抽十条查询，让另一位执行者仅看字段就能判断应该做文章、商业页、广告验证还是暂不投入。若判断经常分歧，说明意图或页面承诺写得不清。搜索量只是估算，优先级还要结合可获得点击、商业价值、竞争与交付能力。

## 角色分工与交接

创业者确认哪些用户和商业动作值得服务；SEO/内容负责人收集查询、观察 SERP、定义页面承诺；SEM 投手提供真实搜索词但不把付费流量直接当自然需求；数据负责人标记来源、日期和品牌词；开发在下一篇根据映射设计可维护的页面类型。

本篇产物是一张至少包含 30 条查询的映射表。验收时随机抽十条，另一位执行者应能判断页面类型、状态、证据和下一步。下一篇只接收通过验收的页面任务，不接收没有意图和独特材料的关键词列表。
