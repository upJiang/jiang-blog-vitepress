# 证据驱动的 AI 系统

模型回答“申请访问需要主管审批”，但用户找不到这句话来自哪份文档，也不知道文档是否属于自己可见范围。答案即使听起来合理，也不能被核对、撤销或评测。

本篇把回答拆成 Claim（可验证的事实主张）和 Evidence（支撑主张的来源片段）。从检索开始，权限、版本和引用位置一直保留到最终输出。

## Evidence 不只是一段文本

一条证据至少包含来源版本、可见范围、标题路径、页码或字符位置、内容摘要和检索时的 Release。这样回答可以重现当时使用的知识，而不会随着在线文档更新失去含义。

Claim 则是一句可以判定“有支持、冲突或证据不足”的陈述。长答案先规划 Claim，再为每条绑定 Evidence，最后合成自然语言。

```mermaid
flowchart LR
  Q[问题与可见范围] --> R[检索候选]
  R --> E[Evidence 集合]
  E --> C[规划 Claims]
  C --> A[生成回答]
  A --> V[事实/引用/权限验证]
  V --> O[答案与可点击引用]
```

## 步骤一：权限先于召回

检索查询携带 tenant、Release 和 allowed scopes，每条通道都在数据层过滤。全库召回后再做 ACL 会让无权片段进入缓存、重排器和日志，也会挤掉真正可见候选。

缓存键包含范围摘要和策略版本。相邻 Chunk 扩展、表格补全和引用渲染也重复使用同一范围，避免从已授权命中跳到未授权邻居。

## 步骤二：固定知识版本

一次请求钉住一个已激活 Release。解析、切片、Embedding 和索引都是可重建投影；候选构建通过质量门禁后原子激活。回答记录实际使用的来源版本，后续文档更新不改变历史执行证据。

安全撤权例外：即使为了复现固定了历史版本，当前用户已失去权限时仍不继续展示正文。复现能力不能高于当前安全策略。

## 步骤三：把回答拆成 Claim

示例回答可以分成三条：谁可以申请、需要哪些步骤、失败时联系谁。每条 Claim 分别选择证据，而不是给整段答案挂一个模糊链接。若关键 Claim 没有证据，系统应删去该主张、继续有限检索或明确说资料不足。

引用编号不是装饰。验证器检查引用确实存在、属于当前范围、定位可打开，并且摘录与 Claim 相关。来源之间冲突时展示差异与版本，不让模型自行选择一个看起来顺耳的结论。

## 步骤四：确定性检查与模型检查分工

ACL、引用存在、版本、Schema、敏感字段和数量预算适合确定性代码检查。语义支持程度、矛盾和回答完整性可以由模型辅助，但需要固定输入、输出 Schema 和评测样本。模型不能审核自己没有看到的来源。

验证失败最多做有限修复，例如一次重新绑定引用或删除无证据 Claim。无限“让模型再想想”会增加成本，也可能掩盖系统性检索问题。

## 正常结果和失败结果

| 场景 | 系统输出 |
| --- | --- |
| 每条 Claim 有可见证据 | 回答并展示精确引用 |
| 资料只支持部分问题 | 只回答被支持部分 |
| 证据互相冲突 | 展示差异、来源与时间 |
| 指定范围无结果 | 安全拒答，不扩大到其他范围 |
| 引用在生成后被撤权 | 不再展示正文 |
| 模型生成额外事实 | 验证失败并有限修复 |

评测分开记录检索命中、Claim 支持率、引用定位、无答案正确率和权限泄露。只对最终文风打分，会掩盖召回失败与错误引用。

## 当前限制

证据链提高可核对性，却不能把不完整或错误来源变成真相。资料质量、版本冲突和现实世界变化仍需责任人治理。下一篇从单个证据系统扩展到模块化平台，讨论多个入口怎样复用同一 Runtime 而不复制规则。

## 把一个答案改造成证据对象

假设系统回答“访客账号有效期为七天”。Evidence 不只是这句话，还应包含稳定身份、来源版本、定位信息、访问范围和内容摘要；Claim 记录要发布的事实以及支持它的 Evidence ID。引用由两者关系生成，而不是模型临时拼接一个链接。

| 对象 | 负责保存什么 | 不负责什么 |
| --- | --- | --- |
| Source | 原始资料身份和版本 | 当前回合权限 |
| Evidence | 本轮可用片段、位置和快照 | 自动证明所有结论 |
| Claim | 一个可独立验证的事实 | 隐式共享整篇引用 |
| Citation | Claim 与公开定位的关系 | 绕过访问校验 |

检索前应用 ACL，回合创建时钉住知识和策略版本，生成时只提供本轮 Evidence，发布前逐 Claim 检查引用身份、范围和支持关系。这样同一个答案可以复现，也能解释某次更新后为什么变化。

练习时准备一条有直接支持的事实、一条需要两份证据组合的比较和一条证据不足的推断。前两条分别绑定来源，第三条标记未知或移除。证据驱动不保证模型永远正确，却能让错误定位到召回、版本、Claim 或验证阶段，并阻止无来源结论伪装成确定事实。
