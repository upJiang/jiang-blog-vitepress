### CSRF 攻击

什么是 csrf 攻击？

CSRF（Cross-site request forgery，跨站请求伪造）

它是指攻击者利用了用户的身份信息，执行了用户非本意的操作

CSRF 是跨站请求伪造，是一种挟制用户在当前已登录的 Web 应用上执行非本意的操作的攻
击方法

它首先引导用户访问一个危险网站，当用户访问网站后，网站会发送请求到被攻击的站点，
这次请求会携带用户的 cookie 发送，因此就利用了用户的身份信息完成攻击

比如，先登录了银行网站，此时浏览器携带了该网站的 cookie 信息，在未关闭该网站时访
问了危险网站，危险网站通过 get 图片，或者 post 表单请求到银行网站，自动携带了
cookie，导致信息泄露或者财务顺势

#### 防御方式

|                   |                 |                                       |
| ----------------- | --------------- | ------------------------------------- |
| 防御手段          | 防御力          | 问题                                  |
| 不使用 cookie     | ⭐️⭐️⭐️⭐️⭐️ | 兼容性略差 ssr 会遇到困难，但可解决   |
| 使用 sameSite     | ⭐️⭐️⭐️⭐️    | 兼容性差 容易挡住自己人               |
| 使用 csrf token   | ⭐️⭐️⭐️⭐️⭐️ | 获取到 token 后未进行操作仍然会被攻击 |
| 使用 referer 防护 | ⭐️⭐️          | 过去很常用，现在已经发现漏洞          |

### XSS 攻击

XSS（Cross Site Scripting，跨站脚本攻击），是指攻击者利用站点的漏洞，在表单提交
时，在表单内容中加入一些恶意脚本，当其他正常用户浏览页面，而页面中刚好出现攻击者
的恶意脚本时，脚本被执行，从而使得页面遭到破坏，或者用户信息被窃取。

**防御方式**

服务器端对用户提交的内容进行过滤或编码

- 过滤：去掉一些危险的标签，去掉一些危险的属性
- 编码：对危险的标签进行 HTML 实体编码

> 3. SSL 劫持攻击是指攻击者劫持了客户端和服务器之间的连接，将服务器的合法证书替
>    换为伪造的证书，从而获取客户端和服务器之间传递的信息。这种方式一般容易被用
>    户发现，浏览器会明确的提示证书错误，但某些用户安全意识不强，可能会点击继续
>    浏览，从而达到攻击目的。
> 4. SSL 剥离攻击是指攻击者劫持了客户端和服务器之间的连接，攻击者保持自己和服务
>    器之间的 HTTPS 连接，但发送给客户端普通的 HTTP 连接，由于 HTTP 连接是明文传
>    输的，即可获取客户端传输的所有明文数据。

### 安全防护措施

- 敏感信息通过单独接口拉取获取，比如身份证号，银行卡号等，支付令牌动态生成，加入
  时间限制等
- 剪切板禁止
  ```javascript
  // 禁止复制银行卡号
  document.addEventListener('copy', (e) => {
    if (e.target.matches('.card-number')) {
      e.preventDefault()
      alert('禁止复制敏感信息！')
    }
  })
  ```
- 用户行为监控
  - 异常行为检测
    ```javascript
    // 监控异常频繁操作
    let clickCount = 0
    paymentForm.addEventListener('submit', () => {
      clickCount++
      if (clickCount > 3) {
        triggerRiskControlCheck() // 触发风控验证
      }
    })

    // 鼠标轨迹分析
    document.addEventListener('mousemove', (e) => {
      analytics.track('user_movement', { x: e.clientX, y: e.clientY })
    })
    ```
  - 防自动化脚本
    ```javascript
    // 添加人机验证
    function initiatePayment() {
      grecaptcha
        .execute('reCAPTCHA_site_key', {
          action: 'payment'
        })
        .then((token) => {
          submitPaymentForm(token)
        })
    }
    ```
- **敏感信息存储**：
  - 禁用 `localStorage` 存储支付凭据
  - Cookie 设置 `Secure; HttpOnly; SameSite=Strict`
    ```javascript
    document.cookie = `token=${value}; Secure; HttpOnly; SameSite=Strict; Max-Age=3600`
    ```
- **加密传输**：全站 HTTPS + HSTS 头强制加密
- 禁用：eval
- **反调试**：禁用开发者工具（通过 `debugger` 语句干扰）
  ```javascript
  setInterval(() => {
    if (typeof console !== 'undefined') console.clear()
    window.open('', '_self')?.close() // 防窗口劫持
  }, 1000)
  ```
- 请求签名（防 API 篡改）

```javascript
// 支付请求添加时间戳和签名
const timestamp = Date.now()
const sign = CryptoJS.MD5(`amount=100&timestamp=${timestamp}&secretKey=xxx`)

fetch('/api/pay', {
  headers: {
    'X-Signature': sign,
    'X-Timestamp': timestamp
  }
})
```

- 内容安全策略（CSP）

```xml
<!-- 只允许加载本站资源 -->
<meta http-equiv="Content-Security-Policy"
      content="default-src 'self'; script-src 'self' 'unsafe-inline'">
```

### CSP

- **安全目标**：通过白名单机制限制页面可加载的资源类型及来源，主要防御 XSS 攻击
  、数据注入、非法资源加载
- **关键能力**：
  - 阻止未经授权的脚本执行（如被注入的恶意支付劫持代码）
  - 控制子资源（图片、字体等）加载来源
  - 禁止内联脚本/样式（`<script>alert(1)</script>`）

1. 违规报告配置

   ```javascript
   // 浏览器自动发送违规报告
   document.addEventListener('securitypolicyviolation', (e) => {
     console.error('CSP违规:', e.blockedURI)
   })
   ```

- 设置：
  ```xml
  location /payment {
      add_header Content-Security-Policy
          "default-src 'none';
           script-src 'self' 'wasm-unsafe-eval';
           style-src 'self' 'nonce-$request_id';
           img-src 'self' data:;
           connect-src 'self' https://payment-gateway.com;
           frame-src 'self';
           form-action 'self';
           report-uri /csp-report;";
  }
  ```

|             |                                                     |                                |
| ----------- | --------------------------------------------------- | ------------------------------ |
| 指令        | 示例值                                              | 作用                           |
| default-src | 'self'                                              | 所有未指定资源的默认策略       |
| script-src  | 'self' [https://apis.pay.com](https://apis.pay.com) | 控制 JS 脚本来源               |
| style-src   | 'self' 'unsafe-inline'                              | 控制 CSS 样式来源              |
| img-src     | data: https: blob:                                  | 控制图片加载源                 |
| connect-src | 'self' [https://api.pay.com](https://api.pay.com)   | 限制 AJAX 请求目标             |
| frame-src   | 'none'                                              | 禁用 iframe 嵌套（防点击劫持） |
| report-uri  | /csp-violation-report                               | 策略违规上报地址               |

### 对称加密，非对称加密，摘要

> 密钥
>
> 密钥是一种参数，它是在明文转换为密文或将密文转换为明文的算法中输入的参数。密钥
> 分为对称密钥与非对称密钥，分别应用在对称加密和非对称加密上。
>
> 对称加密
>
> 对称加密又叫做私钥加密，即信息的发送方和接收方使用同一个密钥去加密和解密数据。
> 对称加密的特点是算法公开、加密和解密速度快，适合于对大数据量进行加密，常见的对
> 称加密算法有 DES、3DES、TDEA、Blowfish、RC5 和 IDEA。
>
> 非对称加密
>
> 非对称加密也叫做公钥加密。非对称加密与对称加密相比，其安全性更好。对称加密的通
> 信双方使用相同的密钥，如果一方的密钥遭泄露，那么整个通信就会被破解。而非对称加
> 密使用一对密钥，即公钥和私钥，且二者成对出现。私钥被自己保存，不能对外泄露。公
> 钥指的是公共的密钥，任何人都可以获得该密钥。用公钥或私钥中的任何一个进行加密，
> 用另一个进行解密。比如 Github Action 通过 ssh 登录推送代码到服务器，本地生成
> RSA 非对称加密钥匙对，把私钥放到 action 的 Secrets 变量中，公钥放到服务器的授
> 权列表中 ~/.ssh/authorized_keys 。这样就能推送代码了，从而不需要密码。相同
> ，github 的在 clone 代码时，一个是 https，一个 ssh 方式，也是在本地生成密钥对
> ，然后把公钥放到 github 的 ssh key 列表中，自己本机保存有私钥，这要就能快速推
> 送代码了，避免了 github 网络问题。如果要用多个机子推送，使用相同方法即可。
>
> 摘要
>
> 摘要算法又称哈希/散列算法。它通过一个函数，把任意长度的数据转换为一个长度固定
> 的数据串（通常用 16 进制的字符串表示）。算法不可逆。

背景：在自己的项目中，有这么一个需求，就是有一个上传图片的接口，需要用在不需要登
录的界面上，但是这个接口一旦放开登录限制，很容易就会被别人滥用，拿去作图床，所以
要确保是在自己项目中调用。

于是，跟同事约定好做一个做一个先对称加密，再非对称加密的操作，原理是：

根据 一个 32 位随机数+当前时间戳+约定好的 clientId+请求接口地址 ，对这串字符串进
行 AES 对称加密，密钥约定好相同。然后再用 RSA （非对称加密）对这个字符串再加密一
次，最后结果放到 header 中，让后端做校验。
