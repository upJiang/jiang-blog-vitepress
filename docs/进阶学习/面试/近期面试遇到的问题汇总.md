## Cookie 有哪些属性

- **Name**=Value

- **Path**：允许哪些页面路由方法

- **Domain**： 允许哪些域名访问，

- **Expires**： 过期时间

- **Max-Age**： 存活时间，优先级高于 Expires

- **Secure**： 只能通过 https 访问

- **httpOnly**： 禁止 js 访问

- **SamsSite**： 控制跨站请求是否自动发送 cookie

  - Strict：仅同站点发送

  - Lax：允许部分安全跨站请求

  - None：允许所有跨站请求。但需要同时设置 Secure

- **Priority**： 当浏览器存储空间不足时，优先保留哪些 Cookie

  - High => Medium => Low

```JavaScript
Set-Cookie:
user_name=aaa
Domain=.example.com
Path=/
Expires=Web,21 Oct 2025 07:23:00 GMT
Max-Age=250000
Secure;
HttpOnly
SameSite=Lax
Priority=High
```

**函数柯里化**：是一种将**多参数函数转换为一系列单参数函数的技术**，具有参数复用、延迟执行和函数组合等优点

```Plaintext

        };
    };
}

```

## 去重

filter （arr.indexOf(item) === index，注意 filter 的第三个参数是当前本身的 arr）跟 reduce （第一个参数是当前结果数组。第二个参数是当前操作值）实现去重

reduce 的参数

- accumulator 累加器，当前执行的结果

- currentValue 当前执行的值

- currentIndex 当前执行的 index

- array 正在被执行的数组

- initialValue 初始值

```Plaintext
//ES6 提供的 Set 去重
function unique(arr) {
    const result = new Set(arr);
    return [...result];
    // return Array.from(result); //不兼容ie
    //使用扩展运算符将Set数据结构转为数组
}

// filter 配合 indexOf，
//使用 indexOf 获取当前内容的下标，这个下标必须跟当前 index 相等，不相等说明出现在别的地方，是重复的需过滤
function unique(arr) {
    return arr.filter(function (item, index, arr) {
        return arr.indexOf(item) === index;
    })
}

// reduce
let arr = [1, 2, 2, 4, null, null].reduce((accumulator, current) => {
    return accumulator.includes(current) ? accumulator : accumulator.concat(current);
}, []);
```

## 如何做响应式布局

- 通过 PostCSS 插件（如**`postcss-pxtorem`**或**`postcss-px-to-viewport`**）在构建阶段自动将代码中的`px`转换为响应式单位（rem/vw）。

- 开发者按设计稿尺寸直接书写`px`，插件根据配置文件（如基准屏幕宽度）动态计算目标单位值，实现"写 px 得适配"的无感转换，兼顾开发直观性与跨设备适配需求。

postcss.config.js

```JavaScript
module.exports = {
  plugins: {
    autoprefixer: {},
    'postcss-px-to-viewport': {
      // 视窗的宽度，对应的是我们设计稿的宽度，一般是750
      viewportWidth: 375,
      // 视窗的高度，根据750设备的宽度来指定，一般指定1334，也可以不配置
      // viewportHeight: 1334,
      // 指定`px`转换为视窗单位值的小数位数
      unitPrecision: 5,
      // 指定需要转换成的视窗单位，建议使用vw
      viewportUnit: 'vw',
      // 指定不转换为视窗单位的类，可以自定义，可以无限添加,建议定义一至两个通用的类名
      selectorBlackList: ['.ignore'],
      // 小于或等于`1px`不转换为视窗单位，你也可以设置为你想要的值
      minPixelValue: 1,
      // 允许在媒体查询中转换`px`
      mediaQuery: false
    }
  }
}
```

## **Monorepo**

> **Monorepo**（Monolithic Repository）是一种**代码管理架构模式**，指将多个独立项目/模块的代码存储在**同一个版本控制仓库**中。与传统的多仓库模式（Multi-repo）形成对比。

**核心特征**：

- **统一入口**：所有项目共享 `package.json` 或 `workspace` 配置

- **交叉引用**：模块间可直接引用（如 `import @shared/utils`）

- **原子提交**：跨项目的变更可单次提交（保证版本一致性）

**与传统模式的对比**

|              |                            |                             |
| ------------ | -------------------------- | --------------------------- |
| **对比维度** | **Monorepo**               | **Multi-repo**              |
| **代码组织** | 所有项目在单一仓库         | 每个项目独立仓库            |
| **依赖管理** | 共享依赖 + 内部软链接      | 各自安装依赖（可能重复）    |
| **版本控制** | 统一版本（或子包独立版本） | 各项目独立维护版本号        |
| **协作效率** | 跨项目修改原子化           | 需多仓库同步修改 + 版本协调 |
| **典型场景** | 中大型产品线、组件库生态   | 独立微服务、无关联项目      |

**典型技术栈**

- **包管理器**：`pnpm`（优先） / `Yarn Workspaces` / `npm Workspaces`

- **构建系统**：`Turborepo`（Vercel） / `Nx` / `Lerna`（逐步淘汰）

- **辅助工具**：

  - `Changesets`：管理多包版本与 CHANGELOG

  - `Rush`：微软系 Monorepo 全流程解决方案

## 异步错误，怎么监控

- 浏览器提供了 window.onerror 和 window.addEventListener('error')来捕获全局错误

- 对于 Promise，如果代码中没有.catch 处理错误，就会触发 unhandledrejection 事件

```javascript
// 常规JS错误（含异步）
window.addEventListener('error', (event) => {
  const { message, filename, lineno, colno, error } = event
  reportError({
    type: 'JS_ERROR',
    message,
    stack: error?.stack,
    location: `${filename}:${lineno}:${colno}`
  })
})

// Promise未处理的拒绝
window.addEventListener('unhandledrejection', (event) => {
  const reason = event.reason || 'Unknown rejection'
  reportError({
    type: 'PROMISE_REJECTION',
    message: reason instanceof Error ? reason.message : reason,
    stack: reason.stack
  })
})
```

## Vue 的渲染是异步还是同步的，为什么

优先使用 promise.resolve().then ，不支持 promise 的浏览器使用 MutationObserver 监听 Dom 变化，模拟微任务，如果还不支持就继续降级到 `setImmediate` `setTimeout`

- **Vue 2.x**： 使用 `Promise.then` > `MutationObserver` > `setImmediate` > `setTimeout` 的降级策略

- **Vue 3.x**： 采用 `queuePostFlushCb` 统一调度，优先使用 `Promise` 和 `MessageChannel`，其实实现基础也是 promise。如果对于不支持 Promise 的浏览器，也是按照 vue2 的实现方式依次寻找。**通过** **`queuePostFlushCb`** **注册的任务会在所有组件更新完成后执行，而直接使用** **`Promise`** **的任务可能在组件更新过程中触发**

简易版源码

```javascript
// Vue 3 源码中的降级检测逻辑（简化版）
let timerFunc: () => void

if (typeof Promise !== 'undefined') {
  // 现代浏览器：优先使用 Promise
  const p = Promise.resolve()
  timerFunc = () => p.then(flushJobs)
} else if (typeof MutationObserver !== 'undefined') {
  // 支持 MutationObserver 的浏览器（如 IE11）
  let counter = 1
  const textNode = document.createTextNode(String(counter))
  const observer = new MutationObserver(flushJobs)
  observer.observe(textNode, { characterData: true })
  timerFunc = () => {
    counter = (counter + 1) % 2
    textNode.data = String(counter) // 触发 DOM 变化
  }
} else if (typeof setImmediate !== 'undefined') {
  // IE 10+ 和 Node.js 环境
  timerFunc = () => setImmediate(flushJobs)
} else {
  // 最终降级到 setTimeout
  timerFunc = () => setTimeout(flushJobs, 0)
}
```

**批量更新队列，异步，\*\***，Vue 的视图更新发生在 当前执行栈清空后的首个微任务阶段\*\*

- 当数据变化时，Vue 不会立即更新 DOM，避免频繁的 dom 更新，合并多次数据更新

- 将变更推入异步队列，同一事件循环内的多次变更会被合并

- 类似于 react 的 setState，但 vue 是自动追踪依赖，react 需要手动更新

代码示例：

```javascript
// 测试执行顺序
console.log('同步任务开始')

Vue.nextTick(() => console.log('nextTick 回调'))

Promise.resolve().then(() => console.log('Promise 微任务'))

setTimeout(() => console.log('setTimeout 宏任务'), 0)

console.log('同步任务结束')


同步任务开始
同步任务结束
Promise 微任务  → 微任务队列优先执行
nextTick 回调   → 与 Promise 同属微任务队列，按注册顺序执行
setTimeout 宏任务
```

总结：`nextTick` 的核心原理是 **利用微任务队列实现异步批量更新**，其本质确实类似于 `Promise.resolve().then`

## 内存泄漏产生的方式，怎么进行垃圾清理机制

### **内存泄漏成因**

1. **全局变量失控**：未声明的变量持续占用内存
2. **事件未解绑**：页面元素移除后仍保留监听
3. **闭包残留**：长期持有外部作用域变量引用
4. **游离 DOM**：已移除节点仍被 JavaScript 引用
5. **定时器堆积**：未清理的 setInterval/setTimeout

### **垃圾回收机制**

**一、基础回收策略**

1. **标记-清除算法（Mark-Sweep）**

   1. **标记阶段**：从全局对象（Window/DOM）出发，标记所有可达对象
   2. **清除阶段**：回收未被标记的内存块
   3. **优势**：解决循环引用问题
   4. **局限**：产生内存碎片

2. **引用计数（Reference Counting）**

   1. 跟踪每个对象的引用次数
   2. 当引用归零时立即回收
   3. **缺陷**：无法处理循环引用（如：DOM 节点相互引用）

---

**二、V8 引擎优化方案**

3. **分代回收（Generational Collection）**

   1. **新生代**（占用 20%内存）

      - 使用`Scavenge算法`（复制式回收）

      - 对象存活周期短（临时变量）

      - 采用`From/To`双空间交替使用

   2. **老生代**（占用 80%内存）

      - 结合`标记-清除`与`标记-整理`（Mark-Compact）

      - 长期存活对象存放区（闭包/全局变量）

4. **增量标记（Incremental Marking）**

   1. 将标记过程拆分为多个 50ms 以下的小任务
   2. 避免主线程长时间阻塞（>100ms 会触发页面卡顿）

## 操作系统的进程是怎么管理的

操作系统通过**五大核心机制**管理进程：

1. **进程控制块（PCB）** 为每个进程建档存信息（状态、资源占用等），类似"身份证" 管理
2. **多队列调度** 使用就绪/阻塞队列轮转分配 CPU 时间片，类似叫号系统保证公平执行
3. **内存隔离** 为进程分配独立内存空间，防止相互干扰，类似浏览器多标签页隔离
4. **进程间通信（IPC）** 提供管道/共享内存等安全对话方式，类似 Web Worker 的消息传递
5. **资源回收** 进程结束后自动回收内存和文件句柄，类似关闭标签页释放浏览器资源

## Docker 的实现原理

> _"Docker 本质上是通过 Linux 的隔离机制（比如命名空间），给每个应用套了个『独立房间』，房间里的 CPU/内存用量有管家（Cgroups）盯着，不会影响其他应用。镜像就像预制好的装修方案，到哪里都能一键复制出相同的房间环境——这和我们前端用 Webpack 打包代码+环境变量的思路很像。"_

**前端常见场景**

- **本地/线上环境一致**：解决 "在我电脑能跑，服务器就报错" 的问题（类似 CSS 浏览器兼容问题）

- **微服务隔离**：不同服务像前端微前端应用，独立部署互不影响

- **快速回滚**：镜像版本号就像 `git tag`，随时切回旧版本

（三把刀：Namespaces 隔离、Cgroups 限流、UnionFS 分层）
