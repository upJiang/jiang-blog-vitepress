**LangChain 概述**

LangChain 是一个专为构建大型语言模型（LLMs）驱动的应用程序而设计的框架，其核心目标是简化从开发到生产的整个应用程序生命周期。

**主要特点**

- **模块化构建**：提供一套模块化的构建块和组件，便于集成到第三方服务中，帮助开发者快速构建应用程序。
- **生命周期支持**：涵盖应用程序的整个生命周期，从开发、生产化到部署，确保每个阶段的顺利进行。
- **开源与集成**：提供开源库和工具，支持与多种第三方服务的集成。
- **生产化工具**：LangSmith 是一个开发平台，用于调试、测试、评估和监控基于 LLM 的应用程序。
- **部署**：LangServe 允许将 LangChain 链作为 REST API 部署，方便应用程序的访问和使用。

```javascript
// 安装依赖：npm install langchain @langchain/community hnswlib-node
import { HNSWLib } from '@langchain/community/vectorstores/hnswlib'
import { OpenAIEmbeddings, ChatOpenAI } from '@langchain/openai'
import { TextLoader } from 'langchain/document_loaders/fs/text'
import { RecursiveCharacterTextSplitter } from 'langchain/text_splitter'
import {
  RunnableSequence,
  RunnablePassthrough
} from '@langchain/core/runnables'

// 1. 加载文档
const loader = new TextLoader('./state_of_union.txt')
const docs = await loader.load()

// 2. 分割文本
const splitter = new RecursiveCharacterTextSplitter({
  chunkSize: 500,
  chunkOverlap: 50
})
const splittedDocs = await splitter.splitDocuments(docs)

// 3. 创建向量存储
const vectorStore = await HNSWLib.fromDocuments(
  splittedDocs,
  new OpenAIEmbeddings({
    modelName: 'text-embedding-3-small'
  })
)

// 4. 构建RAG链
const model = new ChatOpenAI({
  modelName: 'gpt-3.5-turbo',
  temperature: 0.5
})

const chain = RunnableSequence.from([
  {
    context: async (input) => {
      // 检索相关文档
      const retriever = vectorStore.asRetriever(2)
      return retriever.getRelevantDocuments(input.question)
    },
    question: new RunnablePassthrough()
  },
  {
    result: (prev) =>
      model.invoke([
        [
          'system',
          '基于以下上下文回答：\n' +
            prev.context.map((d) => d.pageContent).join('\n')
        ],
        ['human', prev.question]
      ]),
    sources: (prev) => prev.context.map((d) => d.metadata.source)
  }
])

// 5. 执行查询
const response = await chain.invoke({
  question: '总统关于能源政策的主要观点是什么？'
})

console.log('回答：', response.result.content)
console.log('来源：', response.sources)
```

### Nestjs

- Jwt 怎么实现
  - **安装依赖**：使用 `@nestjs/jwt` 和 `passport-jwt` 处理 Token 生成与验证
  - **配置密钥**：通过 `JwtModule.register` 设置 secret 和过期时间
  - **策略创建**：继承 `PassportStrategy` 实现 `validate` 方法解析 Token
  - **全局守卫**：使用 `jwtAuthGuard` 拦截请求，配合 `@Public()` 装饰器放行特定路由
  - **登录签发**：用户验证成功后，用 `JwtService.sign()` 生成包含用户信息的 Token
  - **请求验证**：通过 `Authorization: Bearer <token>` 头传递凭证，守卫自动校验有效性并返回 401 错误

大白话：

- 首先创建一个 auth 的模块，里面包含一些用户字段，比如 userName password id
- 编写注册方法，在注册方法中将用户的密码使用 bcryptjs 进行加密，并存到 redis 中。登录的时候用 bcryptjs.**compareSync 自动对比密码。**

  - 注册全局守卫，对所有接口请求进行登录拦截，使用 `jwtAuthGuard` 拦截请求，配合 `@Public()` 装饰器放行特定路由

### Echarts 复杂数据大屏，如何优化

- 使用 webWork 加载数据

  ```javascript
  // 主线程
  const worker = new Worker('data-processor.js')
  worker.postMessage(rawData)
  worker.onmessage = (e) => {

  // worker.js
  self.onmessage = (e) => {
    // 获取接口数据
    const processed = e.data.map((item) => ({
      ...item,
      value: complexCalculation(item) // 耗时操作
    }))

  ```

- 间隔一分钟收集所有数据的更新，使用 promise.all 收集到所有数据，然后再一起赋值，在赋值时开启从左向右的一个更新动画，避免用户卡顿或者跳屏的感知。
- 在获取数据时，建立重试机制，以及异常上报
- 图片优化：WebP 格式 + CDN 加速 + 懒加载 =》提升页面加载性能
- 大数据量/高频更新 使用 **Canvas，复杂交互/矢量精度要求高 使用 SVG**

|                     |                          |                          |
| ------------------- | ------------------------ | ------------------------ |
| 特性                | Canvas                   | SVG                      |
| 渲染模式            | 像素绘图（指令式）       | DOM 对象（声明式）       |
| 内存占用            | 固定内存（画布尺寸决定） | 线性增长（元素数量决定） |
| 10,000 节点渲染耗时 | 120-180ms                | 800-1200ms               |
| 交互复杂度          | 需手动实现事件检测       | 原生支持 DOM 事件        |
| 动态更新性能        | 全量重绘效率高           | 局部更新效率高           |
| 适用场景            | 大数据量/高频更新        | 复杂交互/矢量精度要求高  |

const initHybridChart = () => {

  overlayChart.setOption({
    graphic: [

    ],
    aria: { enabled: false },
    backgroundColor: 'transparent'
  })
}
