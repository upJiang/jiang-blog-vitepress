## vite 的打包，生成跟测试不一致，有什么问题

- 开发环境可能使用不同的环境变量文件

- 路径解析问题，例如相对路径和绝对路径在构建后的处理方式不同

- 代码优化如 Tree Shaking 可能在生产环境中移除未使用的代码，影响功能

`Vite` 的基本实现原理，就是启动一个 `koa` 服务器拦截浏览器请求 ES 模块的请求。通过路径查找目录下对应文件的文件做一定的处理最终以 `ES` 模块格式返回给客户端

## webpack 中 loader 与 plugin 有什么区别，有没有写过 plugin

webpack

| | **Loader** | **Plugin** |

|----------------|--------------------------------|---------------------------------|

| **作用层级** | 处理单个文件 | 干预整个构建流程 |

| **触发时机** | 模块加载阶段 | 任意构建阶段（通过钩子监听） |

| **配置方式** | `module.rules` 中定义规则 | `plugins` 数组实例化插件 |

| **典型场景** | TS→JS、SASS→CSS、图片压缩 | 生成 HTML、代码拆分、环境变量注入|

问题回答

````JavaScript
1. **核心职责**
   - Loader 是"文件翻译官"：专门处理特定类型文件（如用 `babel-loader` 转译 ES6）

   - Plugin 是"流程操控者"：通过钩子干预构建全流程（如 `CleanWebpackPlugin` 清空旧构建文件）

2. **执行时机对比**
   - Loader 在文件解析阶段工作（模块转换流水线）

   - Plugin 可在任何构建阶段介入（如 `compilation` 阶段修改输出内容）

3. **代码配置差异**
   ```javascript
   // Loader 配置
   module.exports = {
     module: {
       rules: [{
         test: /\.css$/,
         use: ['style-loader', 'css-loader']
       }]
     }
   };

   // Plugin 配置
   const HtmlWebpackPlugin = require('html-webpack-plugin');
   module.exports = {
     plugins: [new HtmlWebpackPlugin({ template: './src/index.html' })]
   };
````

## **问题 2：是否写过 Plugin？**

**回答策略**：**承认经验不足 → 展示原理理解 → 伪代码演示**

````Markdown
1. **诚实回答**
   "实际项目中使用过常用插件，但自定义Plugin经验较少。不过了解其核心实现原理："

2. **原理说明**
   - Plugin本质是一个**包含 `apply` 方法的类**

   - 通过Webpack的[Tapable 钩子系统](https://webpack.js.org/api/compiler-hooks/)监听事件

   - 典型开发流程：
     ```javascript
     class MyPlugin {
       apply(compiler) {
         compiler.hooks.emit.tap('MyPlugin', compilation => {
           // 在生成资源到output目录前修改内容
           compilation.assets['version.txt'] = {
             source: () => 'v1.0.0',
             size: () => 7
           };
         });
       }
     }
     ```

3. **场景举例**
   "例如开发一个自动生成版本号的插件：
   - 监听 `emit` 钩子（资源生成前）

   - 向输出目录添加包含构建版本的 `version.txt`"
````

## 怎么实现热更新，不用打包工具

- 服务端用文件监控工具（如 `chokidar`）实时监听代码文件改动。

- 通过 WebSocket 向浏览器推送变更消息（JS/CSS/HTML 等类型）

- 浏览器按类型动态替换资源（JS/CSS）。

  - JS：删除旧脚本标签，插入新脚本（带时间戳防缓存）。

  - CSS：直接修改 的 href 强制浏览器重载。

  - 核心目标：不刷新页面，局部替换代码。

```Plaintext
[文件修改] → (服务端发现) → [WebSocket 通知] → (浏览器接收)
                ↓                        ↓
          [重新加载JS/CSS]        [不刷新页面]
```

服务端代码

```Plaintext
// ---------- 服务端 server.js ----------
const http = require('http');
const WebSocket = require('ws');
const chokidar = require('chokidar');

// 启动WebSocket服务
const wss = new WebSocket.Server({ port: 8080 });

// 监听文件变化
chokidar.watch('./client').on('change', (path) => {
  wss.clients.forEach(client => {
    if (client.readyState === WebSocket.OPEN) {
      client.send(JSON.stringify({
        type: path.endsWith('.css') ? 'css' : 'js',
        file: path.split('/').pop()
      }));
    }
  });
});

console.log('HMR服务已启动 ws://localhost:8080');
```

客户端代码

```Plaintext
<!-- ---------- 客户端 index.html ---------- -->
<!DOCTYPE html>
<html>
<body>
  <div id="app">初始内容</div>
  <script>
    const ws = new WebSocket('ws://localhost:8080');
    let version = 0;

    // 动态加载JS
    function loadScript() {
      const script = document.createElement('script');
      script.src = `./client/app.js?v=${version++}`;
      document.body.appendChild(script);
    }

    // 处理更新
    ws.onmessage = (e) => {
      const msg = JSON.parse(e.data);
      if (msg.type === 'js') {
        document.querySelectorAll('script').forEach(s => s.remove());
        loadScript(); // 重新加载脚本
      }
      if (msg.type === 'css') {
        document.querySelector('link').href = `./client/style.css?v=${Date.now()}`;
      }
    };

    // 初始加载
    loadScript();
  </script>
</body>
</html>
```
