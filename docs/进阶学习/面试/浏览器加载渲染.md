### 用户输入 url 过程

口述：

首先，浏览器打开一个页面，至少有一个浏览器进程，网络进程，gpu 进程，插件进程（如果装有插件），每个标签页都会有一个渲染主进程。从一个站点打开另一个相同站点或者相同协议，相同根域名，浏览器会复用一个渲染进程。

当用户在浏览器地址栏输入内容时，会根据内容分析是 url 地址还是搜索内容，在浏览器设置那里可以设置默认搜索引擎，如何复合 url 地址规范，会进行自动补全，检查 url 的合法性。

然后浏览器进程通过 ipc 通信，让网络进程去处理 url 请求，网络进程会先在本地找缓存，若没有则开始发起请求，这一步开始进行 dns 解析，利用 ip 地址与服务器建立 tcp 连接，如果是 https 还要进行 tls 连接，用于数据加密等。浏览器会构建请求行，请求头信息，跟域名相关的 cookie 信息等发送给服务器。服务器会接受到请求后，会相应返回响应行，响应头，状态码，如果状态码是 301 或者 302，则会根据相应头里面的 location 字段里面 url 地址进行重定向，重新来一遍前面的步骤。

根据响应头的 content-type 判断服务器返回的数据类型，比如 html，或者 stream 字节流下载，然后去做相应的处理。浏览器根据使用的协议版本，以及 Connection 字段的约定，决定是否要保留 TCP 连接。

这个时候这些信息仍然还在网络进程，这时候浏览器进程，会建立渲染进程与网络进程的传输通道，当渲染进程接收完文档数据后，会给浏览器进程一个确认提交的消息，然后浏览器进程就会结束标签页上方的加载，更新前进后退的页面历史。然后就交给渲染进程进行文档的解析渲染了！！

浏览器开始从上到下解析 HTML，若遇到外部资源链接，则进一步请求资源

解析过程中生成 DOM 树、CSSOM 树，然后一边生成，一边把二者合并为渲染树（rendering tree），随后对渲染树中的每个节点计算位置和大小（reflow），最后把每个节点利用 GPU 绘制到屏幕（repaint）

在解析过程中还会触发一系列的事件，当 DOM 树完成后会触发 DOMContentLoaded 事件，当所有资源加载完毕后会触发 load 事件

浏览器会进行自动补全或者搜索建议，检查 url 的合法性，拼写错误，检查 url 的安全性，是否是恶意网站

#### 1. DNS 查询

浏览器根据 URL（域名） 进行 DNS 查询，查询顺序：浏览器缓存、系统缓存、路由器缓存，以及递归查询到根域名服务器、顶级域名服务器和权威域名服务器的过程

优化：尽量使用同一域名,dns 预解析`dns-prefetch`

#### 2. 浏览器缓存

浏览器查找当前 URL 是否存在缓存，并比较缓存是否过期。

- 强缓存：不会发送请求
  - Expires: http1.0 的产物，指定什么时候会过期 `Expires: Wed, 22 Oct 2018 08:41:00 GMT`，受限于本地时间，如果本地时间更改，则缓存时间也会失效
  - canche-contorl：针对 EXpires 的时间限制，于是 http1.1 的产物诞生，也是 http 实现长连接的根本，当设置了这个，请求能够在设定的时间内共用一个 TCP 连 接
    - `Cache-control: max-age=30`,30 秒后过期 ![](https://r6kvtxijgm.feishu.cn/space/api/box/stream/download/asynccode/?code=M2E3NzhjNGJkNTAzYmVkODU4MjViYWNkZDhlMGRlMWNfTlVkSnc4dWk5clZ0MFNaYnpjQ1hER01jQnp4aDFzRnZfVG9rZW46SFlpbWJva05vb1lUNXp4S01xSGNuU015bkZnXzE3NDI2NDg5NTQ6MTc0MjY1MjU1NF9WNA)

![](https://r6kvtxijgm.feishu.cn/space/api/box/stream/download/asynccode/?code=ZDQwYTVkMzY2Yjg4MmJhY2YzYjA4YWFhNTFhNzNhMzNfTWIySXpOR1lRUWFXTHRxcDBJTmh5ZHd3dTJxdXFnckpfVG9rZW46RTRhMmJBdzFvb1pPdDB4eG1HbWM4UEk5bmNmXzE3NDI2NDg5NTQ6MTc0MjY1MjU1NF9WNA)

- 协商缓存，会发送请求，然后比较本地资源
  - Last-Modified：以修改时间为标准的 `Last-Modified`，http1.0 的产物客户端会 把 `If-Modified-Since`发送给服务端，服务端对比这个值跟当前的 `Last-Modified`,查看最后修改时间有没有变化，没有变化则返回 304，告知客户端 使用本地缓存，由于是以修改时间为标准，如果一个资源周期性的修改，改了又改回 来，那么也会被认为是修改了。
  - E-tag：基于 Last-Modified 的最后修改时间限制，一个针对于资源唯一性的产物 e-tag 诞生，http1.1 的产物，由文件内容 hash 生成，只有当资源改变才会被识别成改变

Expires 跟 Last-Modified 都是 1.0 的产物，都是以时间为维度，于是 1.1 在这个基 础做了优化，出现了更灵活的 canche-contorl 以及以资源为维度的 e-tag

#### 3.**建立 TCP 连接**

- 如果缓存未命中或无效，浏览器将建立与服务器的 **TCP 连接**。
- TCP 连接会经历 **三次握手**（SYN → SYN-ACK → ACK），确保可靠的通信通道。

#### **4.TLS 握手（如果是 HTTPS）**

- 如果请求使用 HTTPS 协议，在 TCP 连接建立后，还会进行 **TLS 握手**。这一步是为了加密通信、进行身份验证等。

#### 5.浏览器**发起 HTTP 请求**，服务器处理请求，浏览器接收 HTTP 响应

- 完成 TCP（和 TLS）连接后，浏览器才会发起实际的 **HTTP 请求**，请求服务器的资源。
- HTTP 请求包括方法（如 GET、POST）、头部信息（如 `User-Agent`、`Cookie` 等）以及可能的请求体。

#### 6.渲染

- 浏览器接收到响应后，开始渲染页面。渲染过程大致包括以下步骤：
  - **解析 HTML**：浏览器首先解析 HTML 文件，构建 DOM 树，遇到 javaScript 标签会暂停解析，执行完 js 后恢复
  - **解析 CSS**：解析样式表，构建 CSSOM 树。css 的解析不会影响 dom 树的生成，但是会影响渲染，js 也可能会操作 dom 样式，所以建议将 css 放头部，js 放尾部。但是非首屏的样式文通过 link 标签尽量放尾部。
  - **合成渲染树**：将 DOM 树和 CSSOM 树合并，形成渲染树。
  - **布局与绘制**：计算每个元素的位置信息，并绘制到屏幕上。
  - **JavaScript 执行**：浏览器执行 JavaScript 脚本，可能会修改 DOM 或触发其他操作。

      src: {
        type: String,
        required: true
      },
      placeholder: {
        type: String,

          if (entry.isIntersecting) {
            const img = entry.target
            img.src = props.src
            observer.unobserve(img)
          }
        })

      observer.observe(imgRef.value)
    })

    onUnmounted(() => {
      if (observer) {
        observer.disconnect()
      }
    })
    </script>

      <img
        ref="imgRef"
        :src="placeholder"
        :data-src="src"
        :alt="alt"
        class="lazy-image"
        @load="() => $emit('loaded')"
        @error="() => $emit('error')"
      />
    </template>

#### 分析评估

**FP (First Paint)**：指页面开始渲染任何内容的时间，即浏览器首次绘制任何像背景色或文字的内容。

**FCP (First Contentful Paint)**：是指页面首次绘制有内容（如文本、图像等）的时间，它代表页面已经开始显示实际内容，而不仅仅是背景色。

**FMP (First Meaningful Paint)**：指页面首次呈现出用户可以识别的主要内容的时间，通常是指文本或图像的渲染。这表示页面开始变得有意义，用户可以获取有价值的信息。

**LCP (Largest Contentful Paint)**：表示页面加载过程中最大的可视内容元素（如大块的图片、标题或文本）渲染完成的时间，它是衡量页面主要内容加载的关键指标。

**FID (First Input Delay)**：衡量用户首次与页面交互（如点击、输入等）到浏览器响应的延迟时间，主要反映了页面的交互性。

常见的性能优化需要关注以下几方面：

- **页面加载性能**（首屏渲染时间、白屏时间、资源加载速度）
- **交互响应性能**（用户操作的延迟、动画流畅度）
- **代码执行性能**（JavaScript 运行速度、计算密集型任务优化）
- **网络请求优化**（HTTP 请求数、请求大小、CDN 加速）
- **错误和异常监控**（JS 报错、网络请求失败）

现代浏览器如 Chrome 采用多进程架构，**每个标签页通常对应一个渲染进程，而网络请求、GPU、插件等有独立进程**。当页面请求多或卡顿，可能导致渲染进程的 CPU 和内存使用过高，甚至崩溃。

页面可能出现以下问题：

请求过多 | 渲染进程网络线程过载 | 标签页卡死/崩溃 | | JS 执行阻塞 | 渲染进程主线程堵塞 | 页面无响应/交互延迟 | | 内存泄漏 | 渲染进程内存持续增长 | 整体浏览器变慢/频繁崩溃 | | GPU 过载 | GPU 进程负载过高 | 动画卡顿/页面渲染异常 |
