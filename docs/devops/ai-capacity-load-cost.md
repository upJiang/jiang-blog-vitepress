# AI 容量：并发 100 不是一个完整负载模型

压测报告写着“支持 100 并发”，却没有输入长度、输出长度、到达率、模型、GPU、TTFT 和错误率。这个结论无法迁移到任何业务。100 个短分类请求与 100 个长文生成，对 KV Cache、Decode 时间和费用完全不同。

容量工程的输入是请求分布与 SLO，处理是受控负载和资源观测，输出是可解释容量区间、过载行为、成本与扩容条件。

## 先定义请求形状

至少记录输入 Token、最大/实际输出 Token、模型、流式、工具/RAG 次数、并发主体和 Deadline。用 P50/P90/P99 或业务档位表示分布，不用一个平均值代替长尾。

还要说明冷/热 Cache、候选模型 Revision、Serving 参数、硬件、实例数和入口限制。任何一项变化都可能让旧容量结论失效。

## TTFT、TPOT 与吞吐

TTFT 覆盖入口、排队、Tokenize、Prefill 和首事件；TPOT 描述 Decode 后续 Token 间隔；端到端时间还取决于输出 Token 数。吞吐可以是 Request/s、Input Token/s 或 Output Token/s，必须写单位。

单请求 Token/s 很高，不代表实例总吞吐高；总吞吐高，也可能以长 TTFT 为代价。在线服务通常同时约束 TTFT、TPOT、错误与队列年龄，而离线任务更偏向单位时间总 Token。

## Little's Law 用来做一致性检查

稳定系统中，平均在系统数量 `L`、平均到达率 `λ` 与平均停留时间 `W` 近似满足 `L = λW`。它不是模型专用公式，也不告诉你延迟分布，却能检查报告是否自洽。

例如到达率升高而服务时间不变，在途数量会增加；当服务能力饱和，队列增长使 `W` 上升。若压测只维持固定并发，客户端等待变慢后发送率会自动下降，可能隐藏系统无法承受真实开放流量的问题。

## Closed-loop 与 Open-loop

Closed-loop 客户端收到响应后才发下一请求，适合测固定并发下的服务行为，但会产生协调遗漏：系统变慢时到达率也下降。Open-loop 按计划到达率发送，更接近外部流量，可以暴露排队与拒绝，但必须设置上限，避免把测试变成失控攻击。

容量测试通常分层进行：单请求基线、固定形状阶梯负载、混合业务分布、突发、长稳、故障注入和恢复。每阶段有停止条件，例如错误、TTFT、队列、OOM 或资源超过安全阈值。

## 找到饱和点而不是跑到崩溃

逐步提高到达率，观察吞吐何时不再线性增长、延迟何时陡升、队列是否持续积累、抢占和 OOM 是否出现。安全容量应低于饱和点并保留故障、发布和流量波动余量。

过载行为和峰值同样重要：系统应按策略排队或拒绝，不能让所有请求一起超时。拒绝率、队列最大年龄和恢复到稳态的时间都进入结果。

## 托管模型成本

托管服务通常按输入、缓存输入、输出、工具或其他计量计费，具体价格和能力会变化。账本使用供应商最终 Usage 与价格版本，不在文章里固化容易过期的数字。

单请求成本可拆为模型 Attempt、Embedding、Rerank、工具和存储/网络。重试与 Failover 分别记 Attempt，不能只记录最终成功。预算准入使用估算，结算使用最终事实。

## 自托管成本

自托管不仅是 GPU 单价。还包含 CPU、主存、磁盘、网络、闲置、冗余、模型加载、平台运维和故障容量。单位成本可以按时间窗口内总基础设施成本除以有效请求或有效输出 Token，但要说明利用率和质量门槛。

更便宜的量化或小模型若导致质量不合格，不能称为单位成本降低。成本比较要让候选通过同一 Eval 和 SLO。

## 容量模板

| 字段 | 记录内容 |
| --- | --- |
| 版本 | 模型/Tokenizer/引擎/镜像/配置 |
| 环境 | GPU、CPU、内存、网络、实例数 |
| 流量 | 到达模型、并发、输入/输出分布、流式比例 |
| 结果 | Request/s、Token/s、TTFT、TPOT、完成、拒绝、错误 |
| 资源 | GPU、显存、KV、CPU、连接、队列、网络 |
| 成本 | Usage、价格版本、GPU 时间、闲置和冗余 |
| 边界 | 饱和点、安全容量、停止条件、已知限制 |

当前环境没有 GPU 和真实模型负载，因此模板不填示例数字，避免数字脱离版本和硬件被误用。

## 扩容决策

队列持续增长先确认到达率和下游瓶颈。增加 Serving 副本可能受模型冷启动、GPU 库存和 Gateway 路由影响；增加 Worker 可能打满数据库；提高 Batch 可能恶化 TTFT。扩容动作必须对应瓶颈。

容量结论要有有效期。模型、引擎、精度、上下文、Prompt、硬件、请求分布或 SLO 变化后重新验证。可复现的实验定义比某个漂亮峰值更有长期价值。
