# Python 文档处理流水线

一份 PDF 看起来有文字，程序却可能提取不到内容，因为页面只是扫描图片。另一份文件能提取文字，却把标题、表格和页码全部打乱。若这些结果直接进入检索，后面的模型再强也找不到可靠证据。

本篇处理一个同时包含普通文本页和扫描页的文档。目标不是“得到一长串字符串”，而是产出可追溯的结构块：每块知道来源版本、页码、标题路径和内容摘要，并且只有缺少文本层的页面才进入 OCR。

## 先认识流水线产物

原文件和加工结果需要不同身份。Document 是稳定业务对象，SourceRevision 是某次不可变来源快照，ParseArtifact 是特定解析器版本的结果，ChunkSet 是特定切片配置的结果，Release 则指向一组已通过检查的可查询产物。

这样设计后，解析器或 Embedding 升级时可以从同一来源重建，不会原地覆盖在线数据。引用也能指向回答当时使用的具体版本。

```mermaid
flowchart LR
  A[接收字节] --> V[识别与校验]
  V --> P[结构解析]
  P --> O[缺失页 OCR]
  O --> N[规范化]
  N --> C[结构切片]
  C --> Q[质量门禁]
  Q --> R[候选发布]
```

## 步骤一：把上传文件当作不可信输入

扩展名和客户端 MIME 只是提示。服务端还要读取文件签名，并限制总大小、页数、压缩展开大小、图片像素、嵌套深度和处理时间。压缩包解包必须确认目标仍位于任务临时目录，避免路径穿越。

解析器适合运行在低权限、无不必要网络、受 CPU 和内存限制的进程中。URL 导入还要防止请求环回、私网和云元数据地址，并在重定向后重新校验。失败或取消后只清理本次任务明确创建的临时文件。

来源快照保存内容摘要、媒体类型、字节数和解析配置版本。内部存储定位受保护，公开引用只展示中性标题和页码，不公开磁盘路径或私有下载地址。

## 步骤二：先解析，再按页决定 OCR

解析器输出页面或结构节点，而不是立即拼成一个字符串。每页记录文本量、字符质量、图片占比和解析警告。只有文本为空或质量低于门槛的页面进入 OCR；正常文本页继续使用原始文本层，避免 OCR 引入错字并浪费资源。

下面是根据该行为重写的最小控制流程。输入是已经通过安全校验的文档，输出是逐页结构。它省略具体 PDF/OCR 库，只展示“普通解析优先、缺失页失败关闭”的决策。

```py
async def parse_document(source: SafeSource) -> list[PageBlock]:
    pages = await parser.extract_pages(source)
    result: list[PageBlock] = []

    for page in pages:
        if page.text_quality >= TEXT_THRESHOLD:
            result.append(PageBlock.from_text_layer(page))
            continue

        if not settings.ocr_enabled:
            raise OcrRequired(page.number)

        ocr = await ocr_client.recognize(
            page.image,
            timeout=settings.ocr_page_timeout,
        )
        if not ocr.text.strip():
            raise OcrProducedNoText(page.number)
        result.append(PageBlock.from_ocr(page, ocr))

    return result
```

OCR 未启用、超时或返回空文本时，本页不能伪装成成功。任务应记录可行动错误，并保留已完成的稳定中间产物供诊断或重试。OCR 结果还需保留置信信息和来源页，不能与原生文本混在一起而失去追踪。

## 步骤三：规范化但不破坏结构

规范化可以统一换行、Unicode 形式和显然的断词，但不应把标题、列表、代码和表格都压成普通段落。表格要保留行列关系，代码要保留空白，标题路径会成为之后检索和引用的重要上下文。

结构切片按语义边界推进：优先完整标题节、段落、列表项、表格行组和代码块；超过预算时再在内部切分。每个 Chunk 记录父子关系、相邻关系、页码范围、标题路径、字符位置、内容摘要和切片器版本。稳定 ID 可以由来源版本、结构路径和内容摘要组合生成。

固定字符数切片实现简单，却容易把表头与数据、函数签名与函数体分开。滑动重叠可以缓解边界损失，但过大重叠会放大存储、召回重复和模型上下文成本。

## 步骤四：质量检查通过后才发布

质量门禁至少比较输入覆盖率、空块、异常短块、超长块、页码连续性、表格/代码保真和重复率。数字阈值来自文档类型与测试集，不应套用一个全行业常数。失败产物保留为候选，不进入在线查询。

候选索引构建完成后，再核对来源版本仍是当前版本。若更新的来源已经到达，晚完成的旧任务进入 `superseded`，不能覆盖新结果。发布使用一个原子指针切换，使单次查询只看到一个完整 Release，不会混合半新半旧的数据。

| 故障 | 系统行为 |
| --- | --- |
| 文件签名与声明类型不符 | 拒绝解析并记录格式错误 |
| 普通页文本质量合格 | 不调用 OCR |
| 扫描页且 OCR 关闭 | 失败关闭，指出需要 OCR |
| OCR 返回空文本 | 本页失败，不创建空 Chunk |
| 覆盖率低于门槛 | 候选不激活 |
| 旧版本任务晚完成 | 标记 superseded |
| 发布中断 | 在线指针仍指向上一完整版本 |

测试要准备文本 PDF、扫描 PDF、混合 PDF、表格、代码、损坏文件和压缩炸弹样本。除内容断言外，还要检查“哪些页调用了 OCR”、结构覆盖率、Chunk 定位、候选状态和发布指针。性能数据必须来自明确样本，不能凭文件页数虚构吞吐。

## 当前限制与下一步

不同格式需要不同解析适配器，复杂表格与版面还可能需要专门模型。流水线能保证产物可追踪和可重建，却不能保证所有版面都完美还原。下一篇进入 SQLAlchemy，学习一个候选版本的多次数据库写入怎样落在同一事务边界内。

## 用五种输入验收流水线

准备普通 PDF、扫描 PDF、含表格的 Office 文件、代码型 Markdown 和不支持格式各一份。先手工记录标题、页数、表头和关键段落，再运行格式识别、解析、条件 OCR、结构切片和候选发布。每一阶段都保存版本、状态、告警和可追踪身份。

| 输入 | 重点验证 |
| --- | --- |
| 普通 PDF | 文字与页码完整，不触发全页 OCR |
| 扫描 PDF | 缺字页进入 OCR，失败不会静默成功 |
| Office 表格 | 表头、行列和上下文可恢复 |
| Markdown 代码 | 标题路径、语言和代码整体保留 |
| 未知格式 | 明确拒绝并记录稳定错误 |

任务重复提交时根据来源哈希和解析版本复用结果；解析器或嵌入模型更新则创建新候选，不覆盖在线版本。候选通过内容覆盖、结构完整、空片段和索引数量检查后才激活。旧任务迟到提交时比较代次并退出。

测试报告应让执行者从原文件追到解析单元、片段和最终证据，也能从引用反查原页。流水线的深度不在于支持格式数量，而在于任何丢失、失败和版本变化都能被看见并阻止残缺数据上线。
