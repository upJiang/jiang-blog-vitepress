# 研究综合怎样判断覆盖度与冲突

研究综合不是把检索摘要首尾相接。它需要回答：用户问题包含哪些维度，每个维度有多少直接证据，证据之间是否冲突，哪些内容目前仍不知道。

## 覆盖矩阵先于正文

把问题拆成可验证维度，例如定义、适用对象、时间、步骤和例外。每条 Evidence 标记支持哪些维度、来源类型和新鲜度。矩阵让“缺资料”成为显式状态。

| 维度 | 状态 | 证据 |
| --- | --- | --- |
| 适用对象 | 已覆盖 | e1 |
| 生效时间 | 冲突 | e2、e3 |
| 申请步骤 | 缺失 | 无 |

## 同源复述不增加独立覆盖

多个页面可能引用同一公告。系统通过 canonical URL、文档 ID 或引用关系合并来源族，避免把转载数量当成置信度。

项目文档、官方规范和二手解释的证明力度不同。综合结果要按结论所需证据选择来源，不能用概览文章证明精确接口行为。

## 冲突先比较范围和版本

两条结论不一致，先看它们是否讨论相同对象、地区、时间和版本。旧规则与新规则并不一定逻辑冲突，但必须告诉读者哪个适用于当前问题。

范围一致且仍冲突时保留双方 Claim 和 Evidence，标记待确认。综合器不凭措辞强弱选择赢家。

## 从 Evidence 生成受限结论

每条事实 Claim 绑定直接支持它的 Evidence ID。推断与事实分开写，推断说明前提。没有覆盖的维度不生成肯定句，可以明确说当前来源未提供。

答案顺序跟随问题维度，不跟随搜索完成顺序。这样即使分支并行返回，读者仍看到一条连续逻辑。

## 覆盖度用于停止，不用于粉饰

覆盖度可以是已覆盖维度占比，但不同维度权重未必相同。核心维度缺失时，即使总占比高也不能完成任务。

评估综合结果要检查引用直接性、冲突保留、缺口披露和范围一致，不能只比较文字相似度。
