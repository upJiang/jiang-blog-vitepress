# 用 Python 调用一次 Responses API

第一次模型请求能打印出一句回答，只证明网络、凭证和某个模型在当时连通。应用接入还要回答几个更具体的问题：请求到底提交了什么，响应为什么停止，实际消耗了多少 Token，超时后能不能重试，流式连接断开时任务是否已经完成。

本文只处理一次 **Responses API** 文本调用。工具执行、会话记忆和 Agent 循环暂不加入，避免把模型协议错误和应用控制流错误混在一起。接口字段会继续演进，完整定义应以 [Responses API 官方参考](https://developers.openai.com/api/docs/api-reference/responses) 为准。

## 环境先做到可复现

示例需要 Python 3.11 或更高版本，并通过虚拟环境安装官方 SDK。依赖版本应写入项目锁文件，团队排查时才能知道序列化与异常类型来自哪个版本。

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade openai
```

API Key 放在环境变量或密钥管理服务中，不写进脚本、配置模板、日志和异常上报。

```bash
export OPENAI_API_KEY="replace-with-your-own-key"
```

代码只读取变量，不打印值。缺少凭证时应在发请求前失败，这样可以把本地配置错误和远端认证错误分开。

```python
import os

api_key = os.getenv("OPENAI_API_KEY")
if not api_key:
    raise RuntimeError("OPENAI_API_KEY is not configured")
```

仓库、聊天截图和终端历史都可能泄漏 Key。若凭证曾经进入 Git，即使后来删除文件，也应该立即撤销并重新签发，因为历史提交仍保留原值。

## 一次请求有哪些承重字段

最小文本请求通常包含模型、应用指令和用户输入：

```python
response = client.responses.create(
    model="your-model-id",
    instructions="只根据给定材料回答；材料不足时说明缺口。",
    input="已确认制度：远程访问需要设备合规并通过审批。\n问题：申请条件是什么？",
    max_output_tokens=300,
)
```

`model` 应来自受控配置，便于灰度与回滚。`instructions` 保存应用行为规则，`input` 承载本轮任务及允许使用的材料。把用户文本直接拼进规则字符串，会模糊来源，也增加提示注入的影响。

`max_output_tokens` 是上限，不是目标长度。设得太小会产生不完整响应，设得很大也不保证模型长篇输出，只会扩大最坏成本和延迟范围。

生产适配器还应设置总 Deadline。SDK 的网络超时只覆盖一次 HTTP 尝试，重试、排队和流式消费都要计入应用的总时限。请求超时后，服务端是否完成可能暂时未知；带副作用的调用不能凭一个超时异常就盲目重放。

应用层最好不要到处直接操作 SDK 对象。适配器把供应商响应转换为自己的数据结构，至少保留这些信息：

| 字段 | 用途 |
| --- | --- |
| 响应 ID | 查询、追踪和供应商支持定位 |
| 应用请求 ID | 关联同一次业务请求和重试 |
| 状态 | 区分完成、不完整、失败与取消 |
| 输出项目 | 保留文本、工具调用等不同类型 |
| 纯文本视图 | 只作为便捷读取，不替代完整输出 |
| usage | 记账、预算校准和容量分析 |
| 错误与不完整原因 | 决定重试、降级或终止 |

`output_text` 很方便，但它只是 SDK 汇总后的文本视图。响应加入工具调用、结构化内容或多个输出项后，只读这一个属性会丢失协议信息。适配器可以提供文本视图，同时把原始输出类型完整映射到领域对象。

## usage 怎样进入应用账本

Token 统计通常分为输入、输出和总量，部分模型或服务还会给出缓存、推理等细项。字段缺失时记录未知，不能自行用字符数冒充供应商账单。

usage 有三种常见用途：

- 和请求前估算比较，校准上下文装配器。
- 累加到单次 Turn、用户或租户预算。
- 按模型、路由和任务阶段分析容量与成本。

金额计算需要绑定当时生效的价格版本。今天的价格表不能回算旧调用并声称得到原始账单，除非明确标注为按当前价格估算。缓存命中、批处理和不同输入类型的计价也要按供应商口径处理。

## 流式响应是一串事件

流式调用不会一次返回完整字符串。客户端接收响应创建、内容增量、内容完成、响应完成或错误等事件。事件类型和载荷应按 SDK 的类型处理，不要靠字符串包含关系猜测。

```python
with client.responses.stream(
    model="your-model-id",
    input="解释远程访问的申请条件。",
) as stream:
    for event in stream:
        handle_event(event)
    final_response = stream.get_final_response()
```

UI 可以边收到边显示，但数据库终态应等到完成事件或最终响应确认。若第 20 个文本增量后连接断开，已经显示的字符属于暂存内容；应用需要查询服务端记录或读取自身持久化状态，不能直接把部分文本标成完成。

流式处理还要考虑背压。浏览器消费慢、代理缓冲或移动网络重连时，服务端不能无限积累事件。常见做法是把核心状态和递增事件序号持久化，客户端按游标续读；无法恢复流时，退回终态查询。

## 错误分类决定下一步动作

把所有异常统一显示为“模型不可用”，排查时几乎没有信息。应用至少要分开本地配置、认证、限流、服务端错误、网络超时、用户取消、内容拒绝、长度截断和响应解析错误。

| 错误 | 通常处理方式 |
| --- | --- |
| 缺少 Key、模型配置为空 | 请求前拒绝，不重试 |
| 认证或权限失败 | 停止并修配置，不自动换 Key |
| 限流 | 读取服务端提示，在总 Deadline 内退避 |
| 短暂服务端错误 | 有上限地重试，记录每次尝试 |
| 网络超时 | 判断结果是否未知，再决定查询或重试 |
| 内容拒绝 | 保存可公开的拒绝原因，走产品拒答路径 |
| 输出截断 | 保留诊断信息，缩小输入或调整输出预算 |
| 本地解析错误 | 保存响应类型和适配器版本，不能伪造文本 |

重试只适合有机会恢复的错误。认证错误重试十次仍是认证错误；输出被长度限制截断时原样重试也大概率得到相同结果。退避时间要计入总 Deadline，并设置最大次数。

## Fake 能证明什么

测试替身可以固定返回完成、截断、限流和空输出，验证应用的分支、调用次数和日志脱敏。它无法验证 TLS、SDK 序列化、模型名称、服务端事件顺序和真实 usage。

因此测试分两层：单元测试大量使用 Fake，保持快速稳定；少量集成测试用真实服务和最小请求，记录模型、SDK 版本、时间及配置条件。线上请求日志只保留必要的 ID、状态、耗时和用量，原始提示与回答要按数据分级另行保存。

完成一次调用的标准也随之清楚：请求构造可追踪，响应终态可分类，usage 可记账，错误有明确责任层。拿到一段非空文本，只完成了其中很小的一部分。
