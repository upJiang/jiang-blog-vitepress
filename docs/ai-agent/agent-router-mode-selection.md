# Router 怎样选择执行模式和模型

Router 位于任务入口。它先判断任务需要固定回答、一次检索还是多步研究，再为该模式选择满足能力和时限的模型。把“模式选择”和“模型选择”混成一次自由生成，容易让简单问题进入昂贵循环。

## 先从任务信号选择执行模式

输入信号包括意图、是否需要当前事实、指定范围、风险等级、Deadline 和期望输出。健康检查可以走固定代码；单一事实查询走一次检索；跨多个来源且需要补缺的问题才进入研究模式。

Router 输出结构化 `mode`、理由码和预算，不直接生成最终答案。高风险动作由策略覆盖模型判断，例如任何权限修改都进入固定审批流。

## 模式决定后再匹配模型能力

模型路由考虑是否支持结构化输出、工具调用、上下文长度和所需模态。成本只是约束之一，不能把不支持目标能力的模型放在首选位。

同一任务的规划、抽取和最终生成可以使用不同模型，但每次切换都要记录模型 ID、策略版本和输入输出预算。

## 一次路由轨迹

问题“远程访问规则是什么”需要当前知识但只有一个目标，Router 选择 `fast_retrieval`，预算一次检索和一次生成。问题“比较三个地区规则并列出冲突”包含多目标与冲突处理，才选择 `deep_research`。

若用户指定的知识范围为空，路由应直接进入澄清或拒答，不能为了“完成任务”放宽到全库。

## 降级要保持语义和安全边界

首选模型不可用时，可以切换兼容模型、缩短非关键上下文或从研究模式降为只返回已找到证据。降级不能删除权限过滤，也不能把结构化命令改成未经校验的自由文本。

路由失败要有明确终态：不支持的模态、预算不足、所有模型不可用。悄悄换模型而不记录，会让质量回归无法定位。

## 用真实任务集评估 Router

评测集标注期望模式、风险和最低能力，检查过度路由与不足路由。简单问题频繁进入深度研究是成本问题，复杂问题被压成一次回答则是质量问题。

阈值调整要经过回归，不能针对某一句测试问题加关键词特判。Router 需要覆盖同类意图的不同说法。
