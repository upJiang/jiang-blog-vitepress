# Swarm 模式怎样在局部协作中保持全局约束

Swarm 允许多个 Agent 根据局部状态选择下一位协作者，控制权不总是回到同一个中央 Planner。它适合任务边界难以预先画成 DAG 的协作，但也更容易重复工作和失去停止条件。

## 局部路由是 Swarm 的核心

每个 Agent 处理自己擅长的状态，并根据结果返回下一角色或终态。共享的是受控工作区和任务元数据，不是所有角色的完整对话。

例如入口角色识别问题后交给检索角色；检索发现证据冲突，再移交审查角色；审查完成后交给回答角色。

## 移交候选仍由运行时校验

Agent 可以提议 `next_agent`，编排器检查角色是否存在、调用关系是否允许、预算是否足够。禁止的角色跳转、重复循环和越权工具不能因为“去中心化”而放行。

全局状态保存访问范围、总步数、已访问角色和 Deadline，每次移交都扣减同一预算。

## 工作区要能发现重复和冲突

角色把结果写成带来源的条目，使用稳定任务 ID 和 Evidence ID。新角色先读取与自己任务相关的摘要，避免再次执行相同检索。两个角色给出冲突结论时，工作区保留两者和证据，不做最后写入者覆盖。

消息广播会放大上下文，按任务订阅或窄移交更可控。

## 终止条件必须是全局的

达到最大移交次数、角色路径重复、没有新增证据、Deadline 到达或回答通过验证时停止。单个角色说“我已完成”只结束自己的步骤，编排器决定任务是否完成。

父任务取消要阻止新的移交，并使在途角色的迟到结果只能进入审计记录。

## Swarm 的适用范围

探索式研究、开放式协作且角色可以独立贡献时可以考虑 Swarm。审批、交易和依赖固定的批处理更适合工作流或 DAG。

评测要统计角色访问图、重复调用、无效移交和最终覆盖。只看答案，会忽略 Swarm 是否在不可控地消耗资源。
