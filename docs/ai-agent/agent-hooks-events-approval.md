# Hook、事件与人工审批怎样约束工具执行

Agent 循环发生了什么，需要事件记录；某个动作能不能继续，需要 Hook 和策略判断；高风险动作是否得到人类同意，需要审批状态。三者用途不同，混在一个回调里会让控制流难以恢复。

## 事件先描述已经发生的事实

事件可以记录模型调用开始、工具候选产生、校验失败、工具完成和 Turn 终止。它们应带递增序号、时间、关联 ID 和脱敏载荷，供界面、重放和审计读取。

事件不是新的执行命令。消费方重复收到 `tool.completed`，不应再次执行工具。

## Hook 在生命周期节点观察或拦截

前置 Hook 可以补充 Trace、检查参数或拒绝动作；后置 Hook 可以记录结果和指标。Hook 应有明确超时与失败策略，观测 Hook 失败通常不能破坏主业务，安全 Hook 失败则应默认拒绝。

业务权限不应只写在 Hook 中。核心授权留在命令处理和数据访问层，Hook 负责横切规则，避免绕过某条调用路径后权限消失。

## 审批是一段可持久化的暂停

发送邮件、修改权限或运行写命令前，运行时生成审批请求，保存动作摘要、参数、风险、过期时间和当前策略版本。Turn 进入 `waiting_approval`，Worker 可以释放，不需要一直占着线程。

审批通过后还要重新检查用户身份、Deadline 和目标状态。批准的是一份具体动作快照，不是允许模型在恢复后随意改参数。

## 一次受控写操作的轨迹

轨迹是：模型提出 `update_access`，前置 Hook 记录候选，策略判断需要审批，运行时持久化请求并暂停。用户批准后，运行时装载原动作快照，再次授权，执行工具，写入完成事件。

审批拒绝、审批过期、恢复时策略已变化，都进入不同终态。界面可以解释原因，Agent 不应把它们统一改写成“工具调用失败”。

## 哪些动作不该交给审批兜底

审批不能替代沙箱和最小权限。若工具本身能访问整个生产网络，即使每次弹窗确认，错误参数仍可能造成无法恢复的后果。高危能力应先缩小作用域，再考虑是否允许人工放行。

低风险、可撤销、频繁的动作可以预授权；高风险、不可逆或跨租户的动作需要审批或直接禁用。判断依据是副作用，而不是工具名字是否熟悉。
