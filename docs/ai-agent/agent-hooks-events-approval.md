# Hook、事件与人工审批怎样约束执行

模型提出发布知识版本 `r-7`，运行时不能立刻调用发布工具。它要核对身份和版本，计算风险，必要时等待人工决定，并把候选、审批和执行回执保存下来。Hook、事件、策略与审批都出现在这条路径上，职责不能混用。

## 四个对象各自做什么

**Hook** 是运行时在稳定生命周期边界调用的扩展点。它可以记录、补充上下文，或按合同返回阻断结果。

**Event** 是已经发生的事实，例如动作已提出、审批已创建、工具已完成。事件供 UI、审计和恢复读取，本身不作业务决定。

**Policy** 根据可信身份、动作、资源和风险，确定允许、拒绝或需要审批。策略结果应可重复，并绑定版本。

**Approval** 是人对一份冻结动作作出的有期限决定。审批人确认具体工具、参数、对象版本和风险摘要，不能批准一个尚未补全的意图。
## 稳定边界形成执行骨架

```text
before_decision
  → decision_proposed
  → before_tool
  → policy_evaluated
  → approval_requested / tool_started
  → tool_completed / tool_failed / tool_unknown
  → after_tool
  → turn_finished
```

Hook 名称和载荷要版本化。`before_tool` 可以拒绝候选，却不能悄悄把 `release_id=r-7` 改成 `r-8` 后继续执行。若允许变更参数，应产生新的候选与审批链。

同步 Hook 位于关键路径，适合权限阻断、参数规范化和必要上下文注入。异步订阅适合指标、通知和离线审计。把网络上报放进同步 Hook，会让监控服务故障拖死业务请求。
## 事件合同要支持顺序与重放

一个事件至少包含：

```json
{
  "event_id": 41,
  "run_id": "run-9",
  "type": "approval_requested",
  "state_version": 6,
  "occurred_at": "2026-08-18T09:00:00Z",
  "payload": {"action_hash": "sha256:...", "expires_at": "..."}
}
```

`event_id` 在同一执行内递增，客户端重连按游标续读。事件先持久化再广播，才能避免界面看见了“执行完成”，数据库却没有终态。敏感参数使用摘要或受控引用，不复制凭证和原始文档。

进度类事件可以丢弃或合并，状态转换、审批、工具回执和终态必须持久化。高频 Token 增量不适合全部作为永久事件，通常只在实时通道发送，最终文本另行保存。
## 审批对象必须冻结

审批请求包含工具稳定 ID、规范化参数、目标版本、风险说明、请求人和过期时间。对这些字段计算 `action_hash`：

```text
hash(tool_id, canonical_args, target_version, policy_version)
```

批准时重新计算并比较。任何字段变化都使原审批失效。这样可以防止先展示低风险摘要，批准后再替换目标。

审批只授权一次受控动作，不授予整个 Agent 永久权限。执行器使用幂等键，保存下游回执。审批超时、拒绝和用户取消都进入不同终态，不应让模型反复换一种说法继续申请。
## 暂停与恢复要重新核对现实

等待审批期间，任务状态是 `waiting_approval`，Worker 释放执行资源，但检查点保留候选和版本。恢复时先确认审批未过期、用户仍有权限、对象版本未变化、Deadline 还有余量，再取得执行租约。

如果 `r-7` 已经被其他流程发布或废弃，旧审批不再适用。运行时返回冲突，必要时创建新候选，不能沿用旧快照强行执行。

取消与批准并发时，状态版本和单调迁移决定结果。取消先提交，迟到批准只留事件；批准先提交并进入执行，取消能否中断取决于工具能力，已发生副作用还要处理回执。

## 三类故障的根因不同

**界面一直等待审批**，先查审批事件是否持久化、订阅游标是否推进、审批状态是否已过期。重复创建审批通常来自重连后没有按 `action_hash` 去重。

**外部动作执行两次**，检查幂等键、状态版本和超时后的 unknown 分支。Hook 重试不能重新调用副作用函数。

**客户端缺少完成事件**，检查事务顺序和广播失败。核心终态已写入时，客户端应通过重放或轮询恢复，不能重跑任务来补一个事件。
## Hook 不能成为隐藏控制流

Hook 过多时，主流程看起来只有一行 `execute()`，真实授权、参数修改和重试散落在插件中。关键状态转换应留在运行时，Hook 只通过窄接口返回明确结果。每个 Hook 有时限、失败策略和顺序，不允许循环触发自身事件。

事件订阅者默认不能修改业务状态。需要触发新动作时，通过正式命令入口并重新鉴权，避免监听日志的组件获得旁路写权限。
## 测试审批链需要覆盖竞态

测试不仅检查“批准后成功”，还要注入参数篡改、审批过期、拒绝、重复点击、用户取消、Worker 重启、工具超时和迟到回执。断言每种情况的动作次数、状态版本、事件序号和最终资源状态。

性质测试可以随机排列批准、取消和工具完成事件，验证终态不倒退，同一 `action_hash` 最多产生一次副作用，旧策略版本不能授权新候选。

短请求只需要在函数前后记录耗时，可以用普通回调。任务会等待人工、跨进程恢复或要求事件重放时，Hook 已经依赖持久化 Runtime；继续把状态藏在回调闭包里，只会让恢复行为不可预测。
