# 上下文污染与间接提示注入

追踪恶意内容怎样从文件、网页、记忆和工具结果进入输入，并在装配前标记和隔离。**Prompt Injection**、**Trust Boundary**、**Context** 分别指向同一条执行链上的不同对象：稳定规则、当前问题、短期历史、长期记忆候选、检索证据和工具结果进入系统，内容来源、信任标签、净化结果、触发规则、工具权限和审计证据保存处理中间状态，最终得到可追踪的上下文清单、裁剪记录、摘要引用和最终模型输入。

上下文污染与间接提示注入位于模型调用之前的输入编译层与调用之外的状态存储层。它的主要机制是所有外部文本进入上下文前标记来源与信任级别，指令和数据分通道；工具动作只接受运行时策略，不能接受文档内嵌命令。网页文字伪装系统指令、OCR 隐藏文本、记忆持久化恶意要求、工具结果要求外传和净化器删除正常证据会让链路在不同位置停止，错误记录必须保留发生阶段、当时的状态和终止原因。

::: info 贯穿示例

上下文污染与间接提示注入场景：多轮对话已经积累大量历史，用户切换到新的文档范围后继续追问“它什么时候生效”。身份、权限、版本和业务事实由应用提供，模型与外部内容只产生需要检查的候选。

:::

这次推演用装配清单、Token 估算、裁剪原因、摘要版本和记忆来源把请求和终态关联起来。与直接 Prompt Injection、内容净化、沙箱和数据权限比较时，重点看输入来源、状态所有者、下一步的决策者和失败终点。

一次上下文污染与间接提示注入执行可以画成“收集材料 → 标记来源 → 计算预算 → 裁剪或检索 → 编译上下文”。稳定规则在入口出现，内容来源记录进度，可追踪的上下文清单只有通过当前主题的校验条件后才会成为可交付结果。

网页文字伪装系统指令与 OCR 隐藏文本会产生不同证据。前者先检查内容来源和输入来源，后者沿调用记录定位依赖或状态冲突；不区分发生位置，重试会掩盖原始原因。

上下文污染与间接提示注入与直接 Prompt Injection 的共同点不代表它们可以互换。当前主题拥有信任标签，相邻组件只通过契约读取或提交候选，不能直接修改这个状态。

诊断上下文污染与间接提示注入从现象时间线开始：固定最后一次正常状态，收集装配清单、Token 估算、裁剪原因、摘要版本和记忆来源，复现网页文字伪装系统指令，修复后再用相同输入确认可追踪的上下文清单和终止原因同时恢复。

## 上下文问题发生在模型调用之前

追踪恶意内容怎样从文件、网页、记忆和工具结果进入输入，并在装配前标记和隔离。在“上下文污染与间接提示注入场景：多轮对话已经积累大量历史，用户切换到新的文档范围后继续追问“它什么时候生效””这类任务里，上下文污染与间接提示注入负责把稳定规则带入处理链，并明确可追踪的上下文清单可以交付的条件。

可观察现象包括网页文字伪装系统指令、OCR 隐藏文本、记忆持久化恶意要求。排查从出现时间、影响范围和最近一次正常状态开始，先固定证据，再讨论根因和修复。

上下文污染与间接提示注入位于模型调用之前的输入编译层与调用之外的状态存储层。它处理所有外部文本进入上下文前标记来源与信任级别，指令和数据分通道；工具动作只接受运行时策略，不能接受文档内嵌命令，身份认证、授权结果和最终业务状态仍由应用中的确定性组件负责。

稳定规则是这条链路的起点。来源缺失时，程序只能拒绝请求或采用明确记录的默认值；模型补出的字段没有可信来源，不能继续驱动标记来源。

网页文字伪装系统指令会直接破坏内容来源与可追踪的上下文清单之间的对应关系。排查时先保留原始输入摘要和发生阶段，再判断是否允许重试。

OCR 隐藏文本属于另一类风险，它影响的是信任标签或下游解释。两类错误不能共用“重新调用一次模型”这样的处理方式。

上下文污染与间接提示注入的完成条件至少包含内容来源、信任标签、可追踪的上下文清单和检查结论。只有最终文字，没有这些中间记录，无法证明结果来自本次请求。

单进程 Demo 可以把状态放在内存中，但仍要保留输入、状态转移和停止原因。跨进程、带权限或有副作用的任务再把这些字段持久化，不能依赖 Prompt 代替状态。

上下文污染与间接提示注入还要把业务条件写成状态条件：短期历史何时就绪，可追踪的上下文清单何时允许交付，网页文字伪装系统指令发生后是否还能继续。

上下文污染与间接提示注入对外区分完成、部分完成和无法确认。三个状态如果都包装成一段顺畅文字，上层界面无法采用不同处理方式。

## 上下文污染与间接提示注入保存什么，不保存什么

上下文污染与间接提示注入接收稳定规则、当前问题、短期历史、长期记忆候选、检索证据和工具结果，向下游交付可追踪的上下文清单、裁剪记录、摘要引用和最终模型输入。输入与输出之间采用明确契约，避免调用方把一句含糊目标直接交给底层适配器。

上下文编译器决定本次输入，外部存储保存跨调用状态，模型不负责长期保存。因此内容来源与信任标签要有唯一写入方，其他组件只能通过版本化命令申请修改。

直接 Prompt Injection 与上下文污染与间接提示注入解决的问题相邻，但控制权不同。比较两者时要看谁选择计算预算、谁保存内容来源、谁确认可追踪的上下文清单。

内容净化可以参与同一请求，却不能替代上下文污染与间接提示注入的职责。组合之后，当前问题的可信来源和网页文字伪装系统指令的终止规则仍需单独检查。

净化结果若只保存在 SDK 对象里，重试或进程退出后就失去解释依据。需要恢复或审计的字段进入持久层，体积较大的结果只保存稳定引用。

上下文污染与间接提示注入使用的身份、范围和版本来自可信运行时。用户消息、检索文本和模型候选可以表达意图，不能提升权限或改写活动 Release。

OCR 隐藏文本发生时，错误应回到拥有该状态的组件处理。上游缺输入、当前组件违反不变量、下游不可用分别形成不同终态。

上下文污染与间接提示注入的确定性边界位于内容来源写入之前。模型可以建议值，应用核对来源和当前版本；涉及权限、金额、发布或不可逆动作时，再进入策略或人工批准。

上下文污染与间接提示注入内部可以使用更细的临时对象，跨边界只暴露稳定协议。替换直接 Prompt Injection 时，调用方不需要理解内部缓存和 SDK 响应。

## 材料来源、优先级与预算

上下文污染与间接提示注入的输入合同至少列出稳定规则、当前问题和短期历史。每项都注明来源、是否必需、允许的缺省值，以及缺失后是在入口拒绝还是进入降级路径。

状态合同中的内容来源表示当前进度，信任标签保存本次执行依赖的快照，净化结果负责关联前后动作。三个字段用途不同，不能合并成一段自由文本。

并发分支按稳定身份合并净化结果。完成顺序只反映耗时，不能决定结果属于哪个请求，也不能让后返回的旧状态覆盖新修订。

输出合同同时描述可追踪的上下文清单和裁剪记录，并为拒绝、取消、部分完成和未知状态提供固定形状。调用方据此分支，不解析错误文案猜测结果。

信任标签参与乐观并发检查。处理开始时读取的版本已经变化，旧候选保留为审计材料，但不能继续写入当前状态。

稳定规则里若包含模型可填写的同名字段，应用会丢弃它，再从认证、配置或活动版本中补入可信值。结构校验通过不等于授权或业务校验通过。

装配清单、Token 估算、裁剪原因、摘要版本和记忆来源组成上下文污染与间接提示注入的最小追踪材料。日志保存稳定 ID、版本和错误类，完整 Prompt、文档正文与凭证不进入指标标签。

撤回或删除当前问题时，依赖它的缓存、候选和未完成任务要按版本失效。稳定 ID 可以保留审计关系，已撤回内容不能继续进入可追踪的上下文清单。

契约还需要描述新鲜度。信任标签对应的数据发生变化后，旧缓存、旧候选和未完成任务怎样失效，应由版本或时间规则直接判断，不能依赖模型注意到矛盾。

删除和撤回也属于数据生命周期。上下文污染与间接提示注入引用的原始对象被移除时，稳定 ID 可以保留审计关系，正文与派生结果则按策略失效，避免继续向用户展示过期内容。

::: warning 上下文污染与间接提示注入的可信边界

可追踪的上下文清单通过结构校验后仍是候选。身份、权限、知识版本与业务事实由应用从可信服务读取，核对完成后才能执行或交付。

:::

## 装配、裁剪和召回的处理顺序

上下文污染与间接提示注入的处理机制是：所有外部文本进入上下文前标记来源与信任级别，指令和数据分通道；工具动作只接受运行时策略，不能接受文档内嵌命令。这条描述要落成可检查的状态变化，不能只停在框架节点名称上。

收集材料接收稳定规则并建立内容来源。入口校验未通过时就地结束，后续模型、检索器或工具调用次数保持为零。

标记来源固定身份、范围、配置版本和绝对 Deadline。子步骤只继承剩余时间，不能各自重新获得完整超时。

计算预算读取信任标签并执行主题逻辑。调用参数由应用组装，外部返回先保存为候选，尚未获得修改领域状态的资格。

裁剪或检索检查候选的结构、范围、版本和主题不变量。可追踪的上下文清单缺少来源、落在旧版本或越过权限时，当前状态停在 rejected 或 failed。

编译上下文先保存可追踪的上下文清单与终止原因，再产生事件或通知。交付失败可以重放，核心状态写入失败则不能对外宣称完成。

计算预算出现部分结果时，由任务合同决定保留、补偿还是整体丢弃。可重建制品可以重新生成，外部副作用需要查询回执或执行补偿。

实现可以使用函数、Graph、Middleware 或 Workflow，内容来源的所有权和网页文字伪装系统指令的停止规则不会随框架改变。

部分成功需要在步骤边界处理。计算预算已经产生一部分可追踪的上下文清单时，程序按任务合同决定保留、补偿或整体丢弃，并记录未完成项，不能默认为全部成功。

每个步骤都应有逆向动作或明确的不可逆说明。可重建制品可以删除后重算，已发送的外部命令只能查询回执或补偿；两类失败不能共用同一重试函数。

## 多轮追问怎样改变输入

用“上下文污染与间接提示注入场景：多轮对话已经积累大量历史，用户切换到新的文档范围后继续追问“它什么时候生效””推演一次上下文污染与间接提示注入。入口创建 request_id，读取可信身份，把稳定规则和当前版本写入初始状态。

收集材料阶段生成内容来源与输入摘要。若当前问题缺失，请求返回 rejected，并指出缺少哪项材料，不继续消耗模型或外部服务配额。

标记来源阶段冻结 scope、release、policy 和 deadline_at。用户或模型在正文中提供的同名值只作为普通内容，不覆盖运行时快照。

计算预算按“所有外部文本进入上下文前标记来源与信任级别，指令和数据分通道；工具动作只接受运行时策略，不能接受文档内嵌命令”推进。每次依赖调用保存 call_id、参数摘要、开始时间与状态版本，后续才能判断超时前是否已经产生结果。

候选结果对应可追踪的上下文清单、裁剪记录、摘要引用和最终模型输入。裁剪或检索逐项检查权限、版本与领域约束，问题列表为空才允许形成下一状态。

编译上下文写入终态。客户端断开只影响交付通道，不触发核心逻辑重跑；重新连接时读取已经保存的状态或事件游标。

故障注入选择记忆持久化恶意要求。程序保留原候选和错误位置，只重做失败边界，不能从入口复制整个任务并产生第二份状态。

推演结束后用 request_id 关联内容来源、可追踪的上下文清单与终止原因。测试据此排除并发请求串线，也能确认失败路径没有遗留未关闭资源。

上下文污染与间接提示注入在输入拒绝时不调用依赖，正常路径按 5 个阶段推进，有限修复只重做失败边界。调用次数是控制流断言，不是性能宣传。

上下文污染与间接提示注入的最终记录用 request_id 关联内容来源、可追踪的上下文清单和失败问题，测试据此证明结果来自本次执行，没有混入并发请求。

## 可观察的正常结果

上下文污染与间接提示注入正常完成时，内容来源、信任标签和可追踪的上下文清单指向同一次执行。重复读取返回同一终态，未完成分支已经取消或有明确所有者。

装配清单、Token 估算、裁剪原因、摘要版本和记忆来源用于还原处理过程。它们可以按阶段和版本聚合，敏感正文留在受控存储中，不复制到日志与指标。

裁剪记录可能是合法的空结果。空结果要带范围、版本和原因；如果任务要求必须找到材料，则同一个空结果应进入拒答而非成功。

依赖返回成功状态只证明传输完成。上下文污染与间接提示注入还要检查可追踪的上下文清单是否满足业务范围、质量阈值和当前版本，明确拒绝也可能是正确终态。

并发完成时，每个分支保留自己的身份和局部预算。汇合节点按任务合同接纳可用结果，慢分支不能抹掉已经确认的记录。

内容来源的状态迁移必须单调：完成不能退回运行中，取消不能被迟到结果覆盖，失败重试也不能绕过入口已经固定的权限。

上下文污染与间接提示注入的成功证据最终要同时回答输入是什么、执行了哪些步骤、交付了什么以及为什么停止；任一项缺失都应留在未确认状态。

上下文污染与间接提示注入把业务验收与服务健康分开。依赖返回 200 只说明传输成功，可追踪的上下文清单仍要满足当前范围和质量要求；明确拒答也可能是正确终态。

上下文污染与间接提示注入的观测指标按阶段和版本聚合。错误率、空结果率、拒绝率、恢复次数与资源消耗回答不同问题，不能压成一个成功率。

## 污染、过期与信息损失

上下文污染与间接提示注入按输入、状态、依赖、结果和交付五个位置分类错误。分类决定恢复动作，不能用同一个重试循环处理全部失败。

遇到网页文字伪装系统指令时，系统要返回稳定的错误类型、发生阶段和可重试标记。上下文污染与间接提示注入保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

遇到 OCR 隐藏文本时，系统要返回稳定的错误类型、发生阶段和可重试标记。上下文污染与间接提示注入保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

遇到记忆持久化恶意要求时，系统要返回稳定的错误类型、发生阶段和可重试标记。上下文污染与间接提示注入保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

遇到工具结果要求外传时，系统要返回稳定的错误类型、发生阶段和可重试标记。上下文污染与间接提示注入保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

遇到净化器删除正常证据时，系统要返回稳定的错误类型、发生阶段和可重试标记。上下文污染与间接提示注入保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

上下文污染与间接提示注入结束错误处理时保存终态、可重试性和资源清理结果。后台扫描器依靠这些字段区分仍在运行、等待恢复和已经失败的任务。

上下文污染与间接提示注入在执行前写入绝对 Deadline、最大动作数、重复签名、无进展阈值、预算和人工取消信号。任一条件触发后都不再创建新工作。

上下文污染与间接提示注入把重试时间和次数计入总预算。依赖连续失败会减少后续额度，达到上限后保留原始错误，不再用模型重新措辞掩盖失败。

上下文污染与间接提示注入的清理动作可以重复执行。临时对象、文件句柄、子进程、连接或 Lease 仍被活动任务引用时，清理器必须拒绝删除。

## 怎样验证承重信息仍然存在

构造超限输入并断言承重信息仍在，检查每段来源，验证过期、撤回、权限变化和缓存失效。测试需要显式给出稳定规则、初始内容来源、预期可追踪的上下文清单和终止原因，不能只断言返回值非空。

上下文污染与间接提示注入的单元测试用 Fake Adapter 固定可追踪的上下文清单与错误，断言参数、调用顺序、状态修订和清理动作。它只证明本地控制逻辑。

契约测试围绕稳定规则、内容来源和裁剪记录构造合法与非法样本。Schema 解析成功后继续检查权限、版本与领域不变量。

故障测试注入网页文字伪装系统指令和 OCR 隐藏文本，记录依赖是否被调用、状态是否改变、资源是否释放，以及同一身份重试会不会重复执行。

在计算预算前后终止执行进程，可以检查恢复边界。调用前退出允许重新领取；外部动作后退出先查回执；终态写入后只重放交付。

集成测试连接真实协议与隔离存储，检查序列化、约束、并发和超时。需要在线服务时单独记录服务版本、时间、配置与是否具备凭证。

上下文污染与间接提示注入的回归报告要保留失败类型分布。明确拒绝变成超时、权限错误变成普通空结果，都属于行为回归，即使总通过数没有变化。

性质测试可以补足固定样本。随机改变消息顺序、重复提交、完成顺序或状态版本，断言权限不扩大、终态不倒退、同一身份不产生两次副作用。

离线评测关注固定输入下的质量变化，运行时测试关注控制和恢复。上下文污染与间接提示注入只有两类证据都存在，才能同时回答“结果是否合格”和“系统是否安全完成”。

## 缓存、容量与数据保留

上下文污染与间接提示注入长期运行后，输入 Schema、内容来源结构和依赖配置可能独立升级。每次执行固定一组版本，旧记录才能被正确读取或迁移。

上下文污染与间接提示注入的容量主要受窗口上限、工具结果大小、历史长度、缓存前缀和记忆召回量影响。并发可能缩短单次等待，也会同时占用连接、配额、内存和下游吞吐，容量要沿调用链逐层核算。

候选版本在固定样本上比较正确性、错误类型、延迟和资源消耗。网页文字伪装系统指令等安全红线回归时直接停止发布，不能用平均质量抵消。

网页文字伪装系统指令的降级路径在发布前写好：减少非关键增强、返回已经确认的结果，或明确暂时无法确认。缺失事实不能交给模型补写。

上下文污染与间接提示注入的运行手册从 request_id 定位装配清单、Token 估算、裁剪原因、摘要版本和记忆来源，再决定重试、补偿、取消或回滚，无需先展开完整敏感内容。

数据保留按证据用途分级。聚合字段可以保留更久，原始输入和大结果设置短期限、访问控制与删除通道。

上下文污染与间接提示注入先在单进程实现状态、超时、错误和测试；只有恢复与容量证据提出要求时，再增加队列、Lease、分布式缓存或工作流引擎。

上下文污染与间接提示注入的监控阈值要对应可执行动作。窗口上限、工具结果大小、历史长度、缓存前缀和记忆召回量中的某项接近上限时，系统可以限流、排队、缩小候选或切换保守路径；只发送告警不会保护正在运行的任务。

回滚要覆盖代码之外的状态。上下文污染与间接提示注入若改变 Schema、缓存键或持久化记录，旧版本是否还能读取新写入数据必须提前验证；无法双向兼容时采用候选版本隔离。

## 与聊天记录、RAG 和长期记忆的边界

采用上下文污染与间接提示注入前先画最小控制图。固定函数已经能完成任务时，新增模型决策和跨进程状态只会扩大测试与运维范围。

上下文污染与间接提示注入与直接 Prompt Injection 的差别落在控制权：谁选择下一步，谁保存内容来源，谁确认可追踪的上下文清单可信。

内容净化可以与上下文污染与间接提示注入组合。组合之后，外部知识仍需授权，工具调用仍需校验，模型输出仍停留在候选状态。

上下文污染与间接提示注入适合价值足够、失败可观察、动作可约束且预算可接受的任务。高风险且不可逆的决定需要确定性规则或人工批准。

格式正确但事实错误的可追踪的上下文清单是必要反例。系统若直接进入成功，说明业务验证缺失；保留候选并给出证据问题，才符合边界。

执行期间修改信任标签可以检验并发设计。旧动作仍能覆盖新状态，说明版本或 Lease 有缺口，增加 Prompt 规则无法修复竞态。

上下文污染与间接提示注入增加了状态、调用、恢复责任和故障面。设计记录应明确获得的能力，也列出新增的退出、降级与回滚路径。

演进可以从最小闭环开始：一个调用、一个状态对象、一组明确错误和几条确定性测试。真实 Trace 证明瓶颈后，再加入并发、缓存、队列或更复杂策略。

相邻文章提供的能力只按依赖引入。直接 Prompt Injection 解决不了当前失败时，不应为了目录完整强行组合；设计保持可替换，后续需求出现再扩展。
