# RAG 数据处理流水线

把 PDF 上传到向量数据库就算完成 RAG 吗？如果解析漏了一页、表格失去表头，或更新时新旧片段混在一起，后面的模型再强也只能基于残缺知识回答。

RAG 数据链负责把来源变成可检索、可追踪、可重建的知识版本。本篇建立全流程地图，解析、切片和版本实现细节分别在实践 03–05 展开。

## RAG 解决什么问题

Retrieval-Augmented Generation 的基本思路是先从外部知识召回证据，再让模型基于证据回答。它减少模型只依赖训练记忆的情况，但不自动保证召回完整、来源正确或回答忠实。

```mermaid
flowchart LR
  A[原始来源] --> B[解析与 OCR]
  B --> C[结构化切片]
  C --> D[质量检查]
  D --> E[嵌入与索引]
  E --> F[候选版本]
  F -->|验证通过| G[在线知识版本]
```

## 第一步：保存原始来源和解析版本

文件、网页和外部系统数据都要有稳定来源身份、内容哈希和更新时间。解析器输出正文、标题、表格、页码、告警和版本。

原始来源与结构化文本需要保留，向量模型变化时才能重新构建。只保存向量会失去可解释和重建能力。

## 第二步：按语义结构切片

标题路径、段落、列表、代码和表格采用不同策略。片段保存来源版本、章节和稳定 ID，必要时连接父级和相邻内容。

片段过小会失去语境，过大又降低召回精度和浪费 Token。阈值由实际文档与 Eval 调整，没有通用最佳数字。

## 第三步：嵌入只是检索投影

Embedding 把文本转成向量，便于寻找语义相近内容。业务编号、精确名称和表格字段仍需要全文或结构化通道配合。

记录嵌入模型、维度和索引参数。模型升级时创建新投影，用固定评测集比较后再发布。

## 第四步：候选版本验证后激活

构建期间在线检索继续使用旧版本。候选检查内容覆盖、重复、孤立关系和索引完整性，通过后在数据库事务中激活。

旧任务晚完成时要检测过期，不能覆盖更新版本。Agent 回合钉住创建时知识版本，保证一次执行前后一致。

## 正常结果和失败结果

正常导入对混合 PDF 只 OCR 缺字页，保留表格和标题路径，候选全部通过后激活。

失败导入即使 OCR 返回空内容仍标记成功，随后把空片段发布；或者更新时直接删除旧向量，导致构建失败期间知识不可用。

## 怎样验证数据链

用小型代表文件覆盖文本、扫描页、表格、代码、超长段落和不支持格式。检查原文单元是否能定位到片段，重复处理是否幂等，过期任务是否被拒绝，失败候选是否不会进入在线版本。

## 用一个小样本验收整条数据链

不要一开始导入几万份相似文件。先建立一个能够人工核对的样本包：一页普通文本、一页扫描 PDF、一张带合并单元格的表格、一段代码和两个标题相同但路径不同的章节。为每个样本写下预期结构，再运行导入。

| 阶段 | 初学者应看到的产物 | 最小检查 |
| --- | --- | --- |
| 来源登记 | 来源 ID、内容哈希、格式、更新时间 | 同一文件重复提交能识别 |
| 解析 | 文字块、页码、标题、表格、告警 | 扫描页不会静默变成空白 |
| 切片 | 片段 ID、标题路径、父子与相邻关系 | 表头和单元格语境仍在 |
| 投影 | 模型版本、维度、索引状态 | 失败投影不会标记完成 |
| 发布 | 候选版本和激活指针 | 在线查询只看到一个完整版本 |

随后做两次变化实验。第一次只修改一个段落，确认稳定片段身份没有全部重排；第二次让嵌入步骤主动失败，确认旧版本仍可查询、候选不会被激活。这个实验能同时检验幂等、版本隔离和故障边界。

数据链的工作产物应包含一份导入报告：处理了多少结构单元、哪些页进入 OCR、哪些内容被跳过、质量门禁为何通过。数字来自本次样本运行，不使用固定“最佳阈值”。只有当样本能从来源追到片段、再从片段返回来源，后续检索评测才有可靠基础。
