# RAG 策略怎样从固定检索升级到研究循环

RAG 的共同目标是把外部证据带进生成，但控制方式可以很不同。先根据问题复杂度和失败代价选择最小策略，再决定是否需要改写、纠错或 Agent 循环。

## 2-Step RAG 是可解释基线

固定流程先检索一次，再用选出的 Evidence 生成答案。查询、Top-K 和过滤都由程序设置，适合单一问题和稳定知识库。它也是评估其他策略的基线。

无结果时明确停止，不能让模型依靠参数知识补齐私有或实时事实。

## 混合 RAG 解决不同召回缺口

精确匹配擅长 ID 和术语，全文检索擅长关键词，向量检索擅长语义相近。多路候选经过 ACL 和版本过滤，再融合、重排。

混合检索增加的是召回通道，不等于 Agent。控制图仍可完全固定。

## 纠正式 RAG 在证据不足时补搜

系统先评估证据覆盖和冲突，再对缺口改写查询。补搜轮数有限，且始终继承原实体、时间和权限范围。

评估信号来自 Evidence，而不是模型对自己答案的主观满意度。

## Agentic RAG 动态选择检索动作

当下一步取决于当前结果，Agent 可以选择结构化查询、全文、向量或图谱通道，并决定是否分解问题。运行时限制动作、预算和停止条件。

动态选择提高适应性，也增加状态、延迟和恢复成本。简单 FAQ 使用它通常得不偿失。

## 用失败模式选择策略

先用查询集观察基线：术语匹配差就加全文或别名，语义表达差就加向量，复合问题漏维度再引入分解，证据冲突需要研究循环。

策略升级要由评测证明修复了对应缺口，同时没有破坏 ACL、新鲜度和延迟边界。
