# 延迟工具加载与 Tool Search

Agent 接入几十个工具后，每次请求携带全部名称、描述、Schema 和枚举，会挤占业务上下文，也会增加相似工具之间的选择错误。延迟加载把选择拆成两步：先从短目录发现候选，再把少量完整 Schema 放进本轮工作集。

## 目录、Schema 与授权分三层

工具目录只保存稳定 ID、短描述、标签、风险级别和 Schema 指纹。完整 Schema 描述参数与返回形状。执行授权根据当前身份、范围、策略和动作参数判断。

发现命中不会授予权限。目录即使来自缓存，运行时仍要在执行前重新授权；模型也不能通过搜索到一个隐藏工具来扩大能力。
## 哪些工具应该常驻

常驻集合适合体积小、几乎每个任务都需要、并且用于继续发现能力的工具，例如 `tool_search`、读取当前任务状态和提交最终回答。高风险写工具、大型 Schema 和领域专用工具延迟加载。

常驻太少会增加一次发现往返，常驻太多又失去节省。可以按使用频率、Schema Token、选择混淆和首轮必需性评估，不要固定追求某个数量。
## 一次发现到执行的链路

用户问“列出这个客户未完成的订单”：

1. Host 先按身份与租户过滤目录。
2. 模型或确定性路由生成工具搜索条件。
3. 目录返回 `orders.list_open` 等候选及指纹。
4. Host 加载当前版本的完整 Schema。
5. 模型提出参数，运行时重新授权并执行。

发现阶段只需知道能力可能相关，不需要加载每个枚举。Schema 加载后若版本指纹变化，旧候选失效并重新规划。
## 工作集要绑定指纹

```json
{
  "tool_id": "orders.list_open",
  "schema_hash": "sha256:...",
  "catalog_version": "catalog-12"
}
```

模型生成调用时带上或由运行时绑定这些值。执行器发现目录已经更新，就拒绝旧参数，避免同名工具的新版本改变语义。

工具目录缓存键包含目录版本、租户、权限策略和语言。权限撤回立即失效；缓存命中只复用元数据，不复用授权结果。

## Hosted 与客户端执行的取舍

Hosted Tool Search 由模型服务托管发现与加载，集成更短，但可观测字段、授权点和缓存语义受服务能力限制。客户端执行让应用完全控制目录、权限和版本，代价是多一次本地或远程调用。

无论哪种方式，可信范围都不能放进模型搜索条件后直接采用。Host 先过滤可见目录，最终工具参数再经过应用授权。
## 发现失败有几种形态

零命中可能是任务确实没有工具，也可能是目录索引过期、描述太窄或权限过滤。应用记录查询、目录版本、候选数和过滤原因，不能让模型在零命中后猜一个工具名。

多命中需要按意图、风险和 Schema 区分。两个工具描述高度相似时，优先修目录与命名，不要无限增加模型推理。高风险工具出现时可以要求显式用户意图或确定性路由。

加载失败和执行失败分开。目录命中但 Schema 不存在属于发布一致性问题；Schema 成功但参数非法属于模型候选问题；授权拒绝属于当前身份边界。
## 容量收益要计算完整链路

延迟加载节省了常驻 Schema Token，却增加发现调用、目录索引和一次模型决策。评测应统计总输入 Token、调用次数、首 Token 延迟、错误工具率与任务通过率。

工具只有五个且每个 Schema 很短时，全量加载通常更直接。工具几十个、多个业务域独立、Schema 很大且单次只用少量时，延迟加载才容易产生收益。
## 安全测试从隐藏工具开始

构造当前用户不可见的工具，确认它不会出现在目录、缓存和模型工作集中。再测试模型直接编造隐藏 ID、使用旧指纹、把只读候选换成写工具，执行器都应拒绝。

发布测试同时部署目录和 Schema，验证切换期间不会出现目录已指向新版本、Schema 仍是旧版本。失败时回滚整个能力包，不单独修缓存。

延迟加载优化的是工具定义何时进入上下文。它不能减少工具本身的权限风险，也不能替代稳定的调用契约。目录短、工作集有版本、授权始终在执行入口，三项同时成立才可控。
