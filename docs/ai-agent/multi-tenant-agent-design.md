# 多租户 Agent 的身份、状态与证据隔离

两个租户都问“远程访问审批多久生效”，查询文字完全相同。租户 A 的检索结果先进入共享缓存，租户 B 随后命中同一个 Key。系统如果只按查询和模型版本缓存，B 会拿到 A 的文档片段。即使生成答案时做了引用检查，越权内容已经进入上下文、模型服务和 Trace。

多租户隔离不能只在 API 查询里补一个 `tenant_id` 条件。一次 Agent 请求会经过会话、检索、向量库、缓存、计划分支、异步 Worker、工具、事件流、记忆和审计。租户范围在任何一步丢失，后面的组件就无法恢复原始边界。

安全的数据流从认证层生成 **TenantContext**，而不是让客户端、Prompt 或模型填写租户。Turn 固定用户、租户、权限修订、知识 Release 与策略版本。所有派生对象都带上这个范围；字段缺失时失败关闭，不能退回“查询全部”。

::: info 租户隔离和对象 ACL 是两层约束

租户边界先排除其他组织的数据，对象 ACL 再判断当前用户能否看到本租户内的文档、会话或工具。通过租户过滤不代表拥有全部对象权限，管理员身份也不能绕过审计。

:::

## 多租户架构先选择数据隔离策略

多租户系统的目标包括数据保密、状态不串线、资源可计量、故障影响可限制，以及操作能够审计。不同租户共享一套应用并不要求共享所有存储。数据敏感度、规模、合规和运维能力决定物理隔离强度。

常见实现可以分成三类。共享数据库与共享表在每行保存 `tenant_id`，成本低、跨租户运维简单，但任何漏过滤都可能泄露。共享数据库、独立 Schema 提供更明显的命名空间，迁移和连接管理更复杂。独立数据库隔离最强，适合高价值或合规租户，部署、备份和版本管理的成本也最高。

| 策略 | 优点 | 主要风险与代价 |
| --- | --- | --- |
| 共享表 | 资源利用高，统一迁移与查询 | 每条数据路径都要带租户条件，热点租户会互相影响 |
| 独立 Schema | 命名空间清楚，可按租户迁移 | Schema 数量、连接池和发布复杂度上升 |
| 独立数据库 | 故障与权限边界更强 | 成本高，跨库运维、备份和升级更重 |

应用可以分层组合：普通租户使用共享表，受监管租户进入独立数据库，向量索引和对象存储也按相同级别隔离。路由结果由可信租户目录提供，不能让请求参数选择数据库。数据迁移时保留旧新位置、版本和双写状态，避免一半请求读旧库、一半写新库。

共享表必须在主键、唯一约束和索引中考虑租户。业务编号只在租户内唯一时，约束应是 `(tenant_id, external_id)`；只给 `external_id` 加全局唯一，会造成租户互相占用编号。反过来，索引没有 `tenant_id` 前缀可能让查询扫描其他租户行，带来性能侧信道和热点干扰。

数据库行级安全（RLS）可以作为第二道保护。连接在事务开始时绑定可信租户上下文，策略限制读取和写入。应用查询仍要显式带 `tenant_id`，RLS 用于拦截遗漏，不能成为开发者不写范围条件的理由。连接池归还前必须清理会话变量，否则下一个请求会继承上一租户。
## 认证层创建唯一可信的 TenantContext

外部请求可能带 Cookie、JWT 或 API Key。认证中间件验证签名、有效期、撤销状态和目标服务，再从身份目录读取 `tenant_id`、`user_id`、角色、Subject 列表和权限修订。客户端提交的 `X-Tenant-ID` 最多用于选择候选，最终值必须与凭证绑定关系一致。

```text
TenantContext
├── tenant_id
├── user_id
├── roles
├── subject_ids
├── permission_revision
├── authentication_method
└── request_id
```

HTTP 中间件把上下文放进请求作用域，路由只接收已经验证的对象。gRPC 拦截器做同样工作，把可信字段放入 Server Context。内部服务调用不能只转发几个可伪造 Header，使用服务身份和签名 Token，并限定允许代表的用户与租户。异步任务则把最小身份信封持久化，Worker 消费时重新验证当前权限。

认证失败、凭证过期和权限服务不可用要分开。身份无法确认时不创建 Turn，也不查询缓存。权限服务暂时不可用，高风险请求失败关闭；公开只读能力能否降级由策略决定，不能把空 Subject 当成全局可见。

### API Key 只保存不可逆摘要

API Key 创建时生成足够随机的秘密，完整值只显示一次。数据库保存可识别前缀、盐化哈希或适合当前方案的安全摘要、所属租户和用户、Scope、创建时间、过期时间与撤销状态。日志只出现 Key ID 或前缀，不能记录原值。

验证流程先按公开前缀找到候选，再进行恒定时间摘要比较，检查撤销、过期、租户状态和允许 Scope。Key 轮换时新旧 Key 可以在受控窗口并存，使用记录帮助确认旧 Key 已停止；窗口结束后撤销旧 Key 并清理缓存。

一个 Key 不应同时拥有查询、写入、管理和跨环境能力。按用途创建最小 Scope，生产与测试分开，工具调用再叠加业务授权。Key 泄露后，撤销事件要使网关、策略缓存和长任务恢复检查立即失效。
## 会话与 Turn 把身份范围固定下来

Conversation 属于一个租户和所有者，协作会话另有明确成员 ACL。读取不存在的会话和读取其他租户会话都对普通调用方返回 NotFound，避免通过错误类型枚举对象。受控审计可以记录真实拒绝原因，运维人员在自己的权限内查看。

Turn 创建时保存 Tenant ID、User ID、Conversation ID、Release ID、Policy ID、ACL 快照引用和幂等键。后续模型输出不能修改这些字段。用户在问题里写“切换到租户 B”，只能作为待解释文字，不能改变运行范围。

多轮对话的焦点对象也要重新授权。上一轮引用的文档后来撤权，本轮“它什么时候生效”不能继续沿用旧焦点。运行时用当前 TenantContext 检查 Focus 引用，失败后清除或返回安全说明，不把旧标题和摘要喂给模型。

长期记忆至少绑定用户和租户，组织级记忆还要绑定知识范围与可见 Subject。用户离开租户后，旧身份不能继续读取记忆；迁移到新组织也不能自动携带企业事实。偏好类记忆是否跨租户复用需要明确产品规则，默认隔离更容易解释。

```mermaid
flowchart LR
    A[验证凭证] --> B[TenantContext]
    B --> C[创建 Conversation / Turn]
    C --> D[固定 Release、Policy 与 ACL 修订]
    D --> E[上下文与记忆装配]
    E --> F[检索和工具]
    F --> G[Claim / Evidence 验证]
    G --> H[租户事件流]
    H --> I[审计与计量]
```
## 工作流与异步任务不能依赖进程上下文

同步请求中的 ContextVar、线程本地变量或框架 Request 对象不会自动进入队列。任务信封要显式保存 `task_id`、`turn_id`、`tenant_id`、`user_id`、权限修订、Policy ID、Release ID 和 Deadline。缺少租户字段的旧任务不能按默认租户执行。

Worker 收到任务后，先加载 Turn 并比较信封范围，再检查租户是否停用、权限修订是否仍有效、策略是否允许恢复。通过后才读取文档、缓存和凭证。信封中的 Scope 是任务创建时的证据，当前授权仍由服务端读取；攻击者不能直接向队列提交一个高权限信封。

Temporal 等持久工作流系统允许在 Search Attribute、Memo 或 Workflow 输入中保存检索信息。租户 ID 必须进入不可变 Workflow 输入和可查询属性，Activity 输入继续携带范围。只在启动 HTTP 请求里有租户，重放或迁移 Worker 后就会丢失。Memo 适合查询元数据，不应存完整凭证和敏感正文。

重试、取消和补偿都沿用原租户。任务因为权限不足失败，重试不会换成 Worker 服务账号读取全局数据。补偿操作也使用当时的租户和动作身份，审计记录“代表谁撤销了什么”。

队列可以按风险或租户等级分池，避免一个大租户耗尽全部 Worker。分池不替代任务级校验，消息路由错误时 Worker 仍会拒绝范围不匹配。租户配额在入队前预留，执行完成后按真实消耗结算，重复投递用租户与请求幂等身份去重。
## 向量检索必须在召回前限定租户和权限

把所有租户向量放在一个集合中，召回后再删其他租户结果，会让无权向量参与 Top K。合法结果可能被挤出，时延和相似度分布也泄露其他数据存在。租户和 Release 过滤应进入向量查询本身，再叠加对象 ACL。

向量存储可以使用租户独立 Collection、分区或元数据过滤。无论形式如何，Chunk 都保存 Tenant ID、知识库、Release、来源对象和 ACL 信息。检索命令中的可信范围由应用注入，模型只提供查询文字和受限参数。`tenant_id`、`scope_ids` 与 Release 出现在模型 Tool Call 时应被拒绝或忽略，不能覆盖运行时值。

全文、精确、结构化和图谱检索也遵守相同边界。SQL 查询的每个分支都带租户和 Release，图遍历不跨命名空间，Alias 与 Wiki 路由先限制租户。Rerank 只接收已经过滤的候选；把全局候选交给外部 Rerank 服务后再删，数据已经离开边界。

Evidence 保存租户、对象、版本与可见性证明。生成完成前重新检查当前 ACL，处理运行期间的撤权。Citation 只展示最终授权的 Evidence，不能把过滤掉的文档标题作为“相关资料”附在末尾。

零结果也要保护边界。指定租户范围没有资料时，系统返回证据不足，不能回退全局索引找相近答案。范围放宽必须由用户在有权限的界面明确选择，并创建新的检索命令。
## 缓存键还不够，命中后仍要鉴权

多租户缓存键至少包含 Tenant ID、权限修订、知识 Release、Policy ID、查询摘要和影响结果的模式。用户级对象还要加入用户或 Subject 集摘要。只按自然语言问题、Embedding 或 URL 缓存会串线。

```text
retrieval:{tenant}:{acl_revision}:{release}:{policy}:{mode}:{query_digest}
```

缓存值保存 Candidate ID 与来源版本，命中后按当前 Context 再做 ACL 校验。原因有两点：撤权事件可能还没删完所有 Key，细粒度对象权限也未必适合全部编码进 Key。缓存候选而不是最终授权，可以在返回前再次确认。

Singleflight 合并并发请求时使用完整租户键。两个租户的问题文字相同，也不能共享正在运行的检索 Future；否则后到请求会直接等待并读取前一租户结果。Embedding 缓存若只保存纯查询向量，可以按模型与文本共享，因为它不含租户知识；派生 Candidate 和答案不能随之共享。

删除租户、撤销权限和激活新 Release 都会触发缓存失效。大规模失效可以依靠版本进入 Key，让旧项自然不可达，再异步清理。日志与指标不记录完整 Key 中的用户标识和查询正文，使用有界的租户级聚合与哈希。
## 工具和 MCP Server 重新校验可信范围

Agent 运行时把 Tool Call 分成模型参数和可信参数。模型可以提供 `query`、文件相对路径或业务字段，租户、用户、允许 Scope、凭证引用、Release 与审批由应用补入。Schema 明确拒绝模型提交这些保留字段，避免同名覆盖。

MCP Server 或远程工具不能因为调用来自“内部 Agent”就默认管理员权限。服务端验证调用方服务身份、代表用户的授权令牌、租户和动作 Scope，再按自己的数据层过滤。网关转发的 Header 需要签名或绑定到短期 Token，普通客户端不能伪造。

工具结果带 Tenant ID、Call ID 和来源对象返回。运行时检查响应范围与请求一致，范围缺失或不匹配直接丢弃并告警。第三方服务无法返回可信租户标签时，把结果限制为当前调用的数据对象，不允许写入共享缓存或组织记忆。

管理员工具走单独策略和审计。支持人员临时进入某租户时，采用明确的模拟身份、工单原因、时间上限与只读默认；界面持续显示当前租户。直接用全局管理员账号调用普通 Agent，容易让模型在多个租户之间混合证据。
## SSE 和事件订阅也要隔离

SSE 连接通常按 Turn ID 订阅事件。只验证“这个 Turn 存在”不够，查询必须同时匹配当前租户和会话权限。其他租户传入一个猜到的 ID，应得到 NotFound，不返回事件数量、状态或标题。

每条 Event 保存 Tenant ID、Turn ID、递增序号、类型和载荷引用。事件存储按租户与 Turn 查询，消息总线主题也带租户命名空间。网关不能订阅全局主题后只靠前端过滤，浏览器已经接收到的数据无法收回。

重连使用 `Last-Event-ID` 时，服务端在当前租户范围解释序号。客户端不能用另一个 Turn 的游标跳转。事件载荷中的 Evidence、工具结果和错误正文继续执行各自权限与脱敏规则，事件通道不是绕开答案门禁的调试接口。

轮询降级与 SSE 使用相同 Repository 方法和授权，不能出现流式接口安全、轮询接口按 ID 全局读取。WebSocket、Webhook 和通知队列也复用统一 TenantContext 与对象授权。
## 配额限制资源干扰，也要支持幂等

多租户隔离还包括资源。一个租户大量启动 Deep Research、Embedding 或代码执行，会占满模型配额、Worker、数据库连接和对象存储。按 Plan 配置并发 Turn、每分钟请求、Token、检索分支、工具执行、存储和后台任务上限。

配额检查在创建昂贵工作前执行，并预留估算额度。任务完成后按实际消耗结算，多退少补；取消和失败执行明确退款规则。预留使用 `(tenant_id, request_id)` 幂等，队列重复投递不能重复扣减。配额服务不可用时，高成本任务不应无上限进入系统。

Plan 只是默认上限，安全上限不能被高价套餐取消。租户管理员可以在产品范围内分配团队额度，不能修改平台全局资源和安全门禁。临时提升记录原因、批准人和到期时间。

公平调度可以使用每租户并发槽、加权队列或令牌桶。只做总量配额，某个租户仍能在短时间占满所有 Worker。队列等待、拒绝和执行消耗按租户聚合，监控不把用户 ID 放进高基数指标标签。
## 租户停用和删除要处理全部派生状态

租户生命周期从目录记录开始。创建租户时分配稳定 ID、数据位置、默认 Policy、密钥命名空间和配额，所有初始化在幂等事务或可补偿流程中完成。只建业务表而忘了向量分区、对象存储前缀或审计范围，第一批请求就会进入不完整环境。

暂停租户时，认证入口先拒绝新请求，发布取消信号给活动 Turn，停止新的队列预留并撤销 API Key。正在执行的只读任务可以按策略安全结束，高风险工具立即取消。暂停状态进入 Worker 恢复检查、策略决策和事件订阅，不能只在登录页面生效。

导出数据需要建立清单：会话、消息、Turn、Evidence、Claim、反馈、记忆、上传文件、向量、Wiki、图谱、事件、审计和配额记录分别由谁拥有。导出任务仍在租户范围内运行，产物加密并设置短有效期，下载动作独立授权。指标聚合和不可逆匿名数据是否纳入，按公开的数据政策执行。

删除采用标记、等待、物理清理和验证四个阶段。标记后旧 Key、缓存和恢复任务立即失效；等待期内允许受控撤销。物理清理按对象关系删除正文与派生索引，审计只保留法规或安全要求允许的最小记录。清理器输出每类对象的数量和失败项，不能仅返回“任务成功”。

向量和模型派生数据容易漏删。Chunk 删除后，对应 Embedding、索引节点、检索缓存、答案缓存和长期记忆引用都要失效。共享模型参数通常无法按租户删除单条训练数据，因此企业数据默认不直接进入通用训练；确有训练流程时，要在准入前定义删除能力与合同边界。

备份与灾难恢复也遵守租户策略。共享数据库备份可能无法立刻物理删除单租户历史，保留期和恢复后的二次删除要写进流程。恢复演练先验证数据库可用，再确认租户目录、RLS、向量分区、密钥和缓存版本相互一致。
## 开发和测试不能依赖默认租户

开发模式常用 `tenant=default` 跳过认证，这个分支一旦随配置进入生产，所有缺失范围的请求都会落到同一命名空间。默认租户只允许出现在明确的本地 Fixture 中，生产配置启动时检查禁用；Repository、Worker 和工具收到空租户仍然拒绝。

自动化测试至少创建两个租户和相同业务编号，能发现唯一约束、缓存 Key 与查询遗漏。测试同一问题、同一 Turn ID 候选、同名文档和交错事件，断言每个层只返回自己的对象。只使用一个租户的成功用例，无法证明隔离。

本地管理员账号也不应默认跨租户。调试需要模拟时，显式选择租户、记录原因和到期时间，并在界面和日志中标记代表访问。测试完成后撤销模拟会话，避免后续请求沿用全局 Scope。
## 一次请求怎样保持范围不丢失

租户 A 的编辑用户创建问题“远程访问审批多久生效”。认证中间件验证 API Key，生成 `tenant-a/user-7/acl-r4` 的 TenantContext。Turn Repository 在租户范围内创建 `turn-1`，同时固定 `release-9` 与 `policy-3`。

模式路由和查询改写只读取问题，不修改范围。检索计划的每个分支由运行时注入 Tenant ID、Subject 和 Release。向量与全文检索都在查询阶段过滤，融合器收到的 Candidate 已经属于当前范围。缓存 Key 包含 Tenant、权限修订和 Release。

模型生成一个 `search_policy` Tool Call，只提供查询和数量。运行时忽略任何模型生成的 Tenant 字段，使用 TenantContext 编译命令。工具返回 Evidence，答案 Claim 绑定 Evidence ID。交付前重新检查权限，确认 `acl-r4` 仍有效。

执行时间较长时，任务信封持久化租户和权限修订。Worker 开始与恢复时重新比较。答案事件只通过 `tenant-a/turn-1` 的订阅读取，最终审计用 Request ID 连接身份、检索、工具、Claim 与配额。

如果租户 B 使用同一问题查询，缓存 Key 不同，Singleflight 也不共享。B 猜到 `turn-1` 时得到 NotFound。即使向量相似度会召回 A 的文档，元数据过滤让它不进入 Top K。边界在每层重复出现，任何一层的缺陷仍有下一层阻断。

## 五类失败证据对应不同责任层

**入口范围错误**，认证记录显示凭证与租户不匹配，请求在创建 Turn 前结束。检查 Key 绑定、Token Audience、中间件与内部代理，不要重试 Agent。

**存储过滤遗漏**，Turn 带正确 Tenant ID，SQL 或向量查询却没有范围。Trace 中能看到命令参数缺失，责任在 Repository 或检索适配器。先阻断受影响入口，补跨租户回归，再清理可能污染的缓存和索引。

**派生状态串线**，检索命令正确，缓存、记忆、摘要或事件返回其他租户对象。检查 Key、Singleflight、派生对象字段与失效。内容已经进入模型时，相关 Turn 和 Trace 按数据事件处理，不能只删缓存。

**异步范围丢失**，API 正常，Worker 的任务信封缺少 Tenant 或恢复时未重新授权。队列消费者失败关闭，旧消息进入隔离队列；不要用服务账号默认 Scope 让任务继续。

**工具边界失效**，运行时提交正确范围，远程工具忽略或接受模型覆盖。保留调用 Token、请求摘要和响应来源，撤销工具凭证，修复 Server 端授权。调用方过滤结果只能作为临时保护，工具仍需独立修复。

::: danger 出现跨租户 Evidence 后不要继续生成

检测到范围不匹配时，立即停止答案、工具与记忆写入，撤销未完成事件，保留稳定 ID 和哈希作调查。让模型删掉敏感段落再交付，无法证明内容没有影响其余结论。

:::

告警包括跨租户过滤命中、响应范围不匹配、缺租户任务、回滚后旧权限缓存命中和配额账本冲突。合法 NotFound 和 ACL 拒绝属于安全结果，平台错误另算。审计正文放在受控存储，指标使用租户级有界标签。
## 隔离强度与运维成本怎样取舍

每层都保存租户字段会增加索引、缓存空间、消息大小和测试量，独立数据库或执行池还会增加连接、部署与容量成本。这些代价换来可解释的故障范围。只依赖入口过滤，代码看起来更少，一旦异步或缓存绕过就没有补救。

共享基础设施适合规模大、数据分类一致、团队具备严格 Repository 和测试门禁的场景。高价值租户、法规要求或噪声干扰明显时，提升到独立索引、数据库和 Worker。隔离层级可以不同，但目录服务要明确每个租户的数据位置和版本。

设计评审从一条请求反查：TenantContext 从哪里产生，Turn 固定了哪些版本，向量查询在何处过滤，缓存 Key 有哪些范围字段，Worker 怎样恢复身份，工具如何验证代表授权，SSE 如何隐藏其他 Turn，撤权如何清理派生状态。任何一步回答“上游已经检查过”，都说明边界还没有贯穿。

多租户 Agent 可交付的证据不只是“B 看不到 A 的页面”。系统还要证明 A 的 Candidate 没进入 B 的模型上下文、缓存、记忆、事件、工具和审计，并且高并发与权限变化时仍保持同样结果。

发布前还应抽查空租户、未知租户、已暂停租户和权限修订刚变化的请求，确认它们都在读取数据前停止，并留下可以定位到入口或恢复阶段的错误证据。
## 租户范围要贯穿每个投影

认证得到的 `tenant_id` 进入 Turn、队列消息、缓存键、向量过滤、数据库查询、事件读取和审计。任何一层从用户输入或模型输出重新解析租户，都是越权入口。

跨租户请求返回稳定的 NotFound 或空结果，不泄露资源存在性。配额、并发和数据删除也按租户隔离，测试要使用两个租户和相同的对象 ID。
