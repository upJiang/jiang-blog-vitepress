# Evidence 预算、缓存与 Singleflight

按问题覆盖选择证据，缓存键绑定查询、权限、知识版本和检索配置，命中后重新鉴权。**Evidence**、**Cache**、**Singleflight** 分别指向同一条执行链上的不同对象：文件或查询、知识范围、活动版本、解析配置、检索配置和用户权限进入系统，问题维度、候选覆盖、Evidence、预算、缓存键、命中状态、Singleflight owner 和等待者保存处理中间状态，最终得到可定位到来源版本的 Chunk、排序候选、Evidence 集合或安全的空结果。

Evidence 预算、缓存与 Singleflight 位于外部知识从原始文件进入可授权证据的离线与在线数据链路，主要机制是证据选择按问题维度、来源多样性和 Token 预算挑选 Chunk；缓存键绑定规范化查询、权限范围、Release、检索配置和模型版本，并在命中后再鉴权。相似 Chunk 挤满预算、缓存遗漏权限或版本、命中后不鉴权、Singleflight owner 失败悬挂和截断破坏引用会让链路在不同位置停止，错误记录必须保留发生阶段、当时的状态和终止原因。

::: info 贯穿示例

Evidence 预算、缓存与 Singleflight 场景：一份包含正文、表格和扫描页的制度文档发布新版本，用户随后按编号和语义分别查询同一条规定。Evidence 预算、缓存与 Singleflight 需要的身份、权限、版本和业务事实由应用提供，模型与外部内容只产生候选。

:::

这次推演用结构化查询、通道结果、候选 ID、融合分数、重排结果、权限裁决和证据集合把请求和终态关联起来。与 Context Budget、结果缓存、Singleflight、Evidence 和引用比较时，重点看输入来源、状态所有者、下一步的决策者和失败终点。

Evidence 预算、缓存与 Singleflight 的执行顺序是“理解查询并固定范围 → 并行取得候选 → 按稳定身份去重融合 → 重排并分配证据预算 → 验证可见性后返回”。文件或查询从入口进入，问题维度记录进度，可定位到来源版本的 Chunk 通过当前主题的校验条件后才会交付。

相似 Chunk 挤满预算与缓存遗漏权限或版本会产生不同证据。前者先检查问题维度和输入来源，后者沿调用记录定位依赖或状态冲突；不区分发生位置，重试会掩盖原始原因。

Evidence 预算、缓存与 Singleflight 与 Context Budget 的共同点不代表它们可以互换。当前主题拥有候选覆盖，相邻组件只通过契约读取或提交候选，不能直接修改这个状态。

Evidence 预算、缓存与 Singleflight 的架构图要标出组件职责、问题维度的唯一所有者、知识范围经过的接口，以及相似 Chunk 挤满预算怎样传播。架构取舍需要说明新增状态和恢复成本，只列组件名称无法用于故障定位。

## 候选很多时先解决证据选择问题

按问题覆盖选择证据，缓存键绑定查询、权限、知识版本和检索配置，命中后重新鉴权。在“Evidence 预算、缓存与 Singleflight 场景：一份包含正文、表格和扫描页的制度文档发布新版本，用户随后按编号和语义分别查询同一条规定”这类任务里，Evidence 预算、缓存与 Singleflight 负责把文件或查询带入处理链，并明确可定位到来源版本的 Chunk 可以交付的条件。

Evidence 预算、缓存与 Singleflight 位于外部知识从原始文件进入可授权证据的离线与在线数据链路。它处理证据选择按问题维度、来源多样性和 Token 预算挑选 Chunk；缓存键绑定规范化查询、权限范围、Release、检索配置和模型版本，并在命中后再鉴权，身份认证、授权结果和最终业务状态仍由应用中的确定性组件负责。

文件或查询是这条链路的起点；来源缺失时，程序只能拒绝请求或采用明确记录的默认值，模型补出的字段不能继续驱动并行取得候选。

相似 Chunk 挤满预算会破坏问题维度与可定位到来源版本的 Chunk 之间的对应关系，排查时先保留原始输入摘要和发生阶段，再判断是否允许重试。

缓存遗漏权限或版本影响候选覆盖或下游解释，不能和相似 Chunk 挤满预算共用“重新调用一次模型”的处理方式。

Evidence 预算、缓存与 Singleflight 完成时至少留下问题维度、候选覆盖、可定位到来源版本的 Chunk 和检查结论；只有最终文字，无法证明结果来自本次请求。

问题维度在单进程 Demo 中可以留在内存，跨进程、带权限或有副作用的任务则要持久化输入、状态转移和停止原因，不能依赖 Prompt 保存状态。

Evidence 预算、缓存与 Singleflight 还要把业务条件写成状态条件：活动版本何时就绪，可定位到来源版本的 Chunk 何时允许交付，相似 Chunk 挤满预算发生后是否还能继续。

Evidence 预算、缓存与 Singleflight 对外区分完成、部分完成和无法确认，三个状态若都包装成可定位到来源版本的 Chunk，上层界面无法采用不同处理方式。

## Evidence 预算怎样分配给问题维度

Evidence 预算、缓存与 Singleflight 接收文件或查询、知识范围、活动版本、解析配置、检索配置和用户权限，向下游交付可定位到来源版本的 Chunk、排序候选、Evidence 集合或安全的空结果，输入与输出之间用明确契约连接，调用方不能把一句含糊目标直接交给底层适配器。

查询理解器产生受约束计划，检索器返回候选，Evidence 选择器决定进入回答的材料。因此问题维度与候选覆盖要有唯一写入方，其他组件只能通过版本化命令申请修改。

Context Budget 与 Evidence 预算、缓存与 Singleflight 解决的问题相邻，但控制权不同，比较时要看谁选择按稳定身份去重融合、谁保存问题维度、谁确认可定位到来源版本的 Chunk。

结果缓存可以参与同一请求，却不能替代 Evidence 预算、缓存与 Singleflight；组合后仍要单独检查知识范围的可信来源和相似 Chunk 挤满预算的终止规则。

Evidence 若只保存在 SDK 对象里，重试或进程退出后就失去解释依据；需要恢复或审计的字段进入持久层，体积较大的可定位到来源版本的 Chunk 只保存稳定引用。

Evidence 预算、缓存与 Singleflight 使用的身份、范围和版本来自可信运行时，文件或查询可以表达意图，但不能提升权限或改写活动 Release。

缓存遗漏权限或版本发生时，错误回到候选覆盖的所有者处理，上游缺输入、当前组件违反不变量和下游不可用分别形成不同终态。

Evidence 预算、缓存与 Singleflight 的确定性边界位于问题维度写入之前。模型可以建议值，应用核对来源和当前版本；涉及权限、金额、发布或不可逆动作时，再进入策略或人工批准。

Evidence 预算、缓存与 Singleflight 内部可以使用更细的临时对象，跨边界只暴露稳定协议。替换 Context Budget 时，调用方不需要理解内部缓存和 SDK 响应。

## 覆盖度与来源多样性怎样平衡

Evidence 预算、缓存与 Singleflight 的输入合同至少列出文件或查询、知识范围和活动版本，每项都注明来源、是否必需、允许的缺省值，以及缺失后是在入口拒绝还是进入降级路径。

状态合同中的问题维度表示当前进度，候选覆盖保存本次执行依赖的快照，Evidence 关联前后动作，三者不能合并成一段自由文本。

并发分支按稳定身份合并 Evidence，完成顺序只反映耗时，不能决定结果属于哪个请求，更不能让迟到的旧状态覆盖新修订。

输出合同同时描述可定位到来源版本的 Chunk 和排序候选，并为拒绝、取消、部分完成和未知状态提供固定形状，调用方据此分支，无需解析错误文案猜测结果。

候选覆盖参与乐观并发检查；处理开始后若版本变化，旧候选只保留作审计，不能继续写入问题维度。

文件或查询里若包含模型填写的同名字段，应用会丢弃它，再从认证、配置或活动版本中补入可信值，因为结构校验通过不等于授权或业务校验通过。

结构化查询、通道结果、候选 ID、融合分数、重排结果、权限裁决和证据集合组成 Evidence 预算、缓存与 Singleflight 的最小追踪材料，日志只保存稳定 ID、版本和错误类，完整 Prompt、文档正文与凭证不进入指标标签。

撤回或删除知识范围时，相关缓存、候选和未完成任务按版本失效；稳定 ID 可以保留审计关系，已撤回内容不能继续进入可定位到来源版本的 Chunk。

契约还需要描述新鲜度。候选覆盖对应的数据发生变化后，旧缓存、旧候选和未完成任务怎样失效，应由版本或时间规则直接判断，不能依赖模型注意到矛盾。

删除和撤回也属于数据生命周期。Evidence 预算、缓存与 Singleflight 引用的原始对象被移除时，稳定 ID 可以保留审计关系，正文与派生结果则按策略失效，避免继续向用户展示过期内容。

::: warning Evidence 预算、缓存与 Singleflight 的可信边界

可定位到来源版本的 Chunk 通过结构校验后仍是候选。Evidence 预算、缓存与 Singleflight 使用的身份、权限、知识版本与业务事实由应用从可信服务读取，核对完成后才能执行或交付。

:::

## 缓存键为什么必须绑定权限和版本

Evidence 预算、缓存与 Singleflight 按“证据选择按问题维度、来源多样性和 Token 预算挑选 Chunk；缓存键绑定规范化查询、权限范围、Release、检索配置和模型版本，并在命中后再鉴权”推进，这段机制必须落成问题维度和候选覆盖的实际变化，不能只列框架节点名称。

理解查询并固定范围接收文件或查询并建立问题维度，入口校验未通过就地结束，后续模型、检索器或工具调用次数保持为零。

并行取得候选固定身份、范围、配置版本和绝对 Deadline，后续子步骤只继承剩余时间，不能各自重新获得完整超时。

按稳定身份去重融合读取候选覆盖并执行主题逻辑，参数由应用组装，外部返回先保存为排序候选，尚未获得修改领域状态的资格。

重排并分配证据预算检查结构、范围、版本和主题不变量；可定位到来源版本的 Chunk 缺少来源、落在旧版本或越过权限时，问题维度停在 rejected 或 failed。

验证可见性后返回先保存可定位到来源版本的 Chunk 与终止原因，再产生事件或通知，交付失败可以重放，核心状态写入失败则不能对外宣称完成。

按稳定身份去重融合出现部分结果时，由任务合同决定保留、补偿还是整体丢弃；可定位到来源版本的 Chunk 若可重建就重新生成，外部副作用则查询回执或执行补偿。

实现可以使用函数、Graph、Middleware 或 Workflow，问题维度的所有权和相似 Chunk 挤满预算的停止规则不会随框架改变。

部分成功需要在步骤边界处理。按稳定身份去重融合已经产生一部分可定位到来源版本的 Chunk 时，程序按任务合同决定保留、补偿或整体丢弃，并记录未完成项，不能默认为全部成功。

按稳定身份去重融合和重排并分配证据预算都要写明逆向动作或不可逆原因，可定位到来源版本的 Chunk 若可重建就删除后重算，已发送的外部命令只能查询回执或补偿。

## Singleflight 怎样合并相同检索

沿“Evidence 预算、缓存与 Singleflight 场景：一份包含正文、表格和扫描页的制度文档发布新版本，用户随后按编号和语义分别查询同一条规定”推演 Evidence 预算、缓存与 Singleflight：入口创建 request_id，读取可信身份，把文件或查询和当前版本写入初始状态。

理解查询并固定范围生成问题维度与输入摘要；若知识范围缺失，请求返回 rejected，并指出缺少哪项材料，不继续消耗模型或外部服务配额。

并行取得候选冻结 scope、release、policy 和 deadline_at，用户或模型在正文中提供的同名值只作为普通内容，不能覆盖这份运行时快照。

按稳定身份去重融合按“证据选择按问题维度、来源多样性和 Token 预算挑选 Chunk；缓存键绑定规范化查询、权限范围、Release、检索配置和模型版本，并在命中后再鉴权”推进，每次依赖调用保存 call_id、参数摘要、开始时间与状态版本，以便判断超时前是否已经产生结果。

候选结果对应可定位到来源版本的 Chunk、排序候选、Evidence 集合或安全的空结果，重排并分配证据预算逐项检查权限、版本与领域约束，问题列表为空才允许形成下一状态。

验证可见性后返回写入终态；客户端断开只影响交付通道，重新连接时读取已经保存的问题维度或事件游标，不重跑核心逻辑。

故障注入选择命中后不鉴权，程序保留原候选和错误位置，只重做失败边界，不能从入口复制整个任务并产生第二份状态。

推演结束后用 request_id 关联问题维度、可定位到来源版本的 Chunk 与终止原因，测试据此排除并发请求串线，并确认失败路径没有遗留未关闭资源。

Evidence 预算、缓存与 Singleflight 在输入拒绝时不调用依赖，正常路径按 5 个阶段推进，有限修复只重做失败边界。调用次数是控制流断言，不是性能宣传。

Evidence 预算、缓存与 Singleflight 的最终记录用 request_id 关联问题维度、可定位到来源版本的 Chunk 和失败问题，测试据此证明结果来自本次执行，没有混入并发请求。

## 一次命中缓存的证据装配

Evidence 预算、缓存与 Singleflight 正常完成时，问题维度、候选覆盖和可定位到来源版本的 Chunk 指向同一次执行，重复读取返回同一终态，未完成分支已经取消或有明确所有者。

结构化查询、通道结果、候选 ID、融合分数、重排结果、权限裁决和证据集合用于还原 Evidence 预算、缓存与 Singleflight 的处理过程，可以按阶段和版本聚合；敏感正文留在受控存储中，不复制到日志与指标。

排序候选可能是合法的空结果，但必须带范围、版本和原因；任务明确要求找到材料时，同一个空结果进入拒答而非成功。

依赖返回成功状态只证明传输完成。Evidence 预算、缓存与 Singleflight 还要检查可定位到来源版本的 Chunk 是否满足业务范围、质量阈值和当前版本，明确拒绝也可能是正确终态。

按稳定身份去重融合并发完成时，每个分支保留自己的身份和局部预算，重排并分配证据预算按任务合同接纳可用结果，慢分支不能抹掉已经确认的记录。

问题维度的状态迁移必须单调：完成不能退回运行中，取消不能被迟到结果覆盖，失败重试也不能绕过入口已经固定的权限。

Evidence 预算、缓存与 Singleflight 的成功证据最终要同时回答输入是什么、执行了哪些步骤、交付了什么以及为什么停止；任一项缺失都应留在未确认状态。

Evidence 预算、缓存与 Singleflight 把业务验收与服务健康分开。依赖返回 200 只说明传输成功，可定位到来源版本的 Chunk 仍要满足当前范围和质量要求；明确拒答也可能是正确终态。

Evidence 预算、缓存与 Singleflight 的观测指标按阶段和版本聚合。错误率、空结果率、拒绝率、恢复次数与资源消耗回答不同问题，不能压成一个成功率。

## 缓存命中后为什么还要重新鉴权

Evidence 预算、缓存与 Singleflight 按输入、状态、依赖、结果和交付五个位置分类错误，发生位置决定恢复动作，不能用同一个重试循环处理全部失败。

遇到相似 Chunk 挤满预算时，系统要返回稳定的错误类型、发生阶段和可重试标记。Evidence 预算、缓存与 Singleflight 保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

缓存遗漏权限或版本触及 Evidence 预算、缓存与 Singleflight 的安全边界，重试不会使它自动合法；执行路径保存拒绝规则和输入来源，清除未授权候选，并以稳定错误结束当前动作。

遇到命中后不鉴权时，系统要返回稳定的错误类型、发生阶段和可重试标记。Evidence 预算、缓存与 Singleflight 保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

遇到 Singleflight owner 失败悬挂时，系统要返回稳定的错误类型、发生阶段和可重试标记。Evidence 预算、缓存与 Singleflight 保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

遇到截断破坏引用时，系统要返回稳定的错误类型、发生阶段和可重试标记。Evidence 预算、缓存与 Singleflight 保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

## 用命中与未命中路径做一致性测试

Evidence 预算、缓存与 Singleflight 长期运行后，输入 Schema、问题维度结构和依赖配置可能独立升级，每次执行固定一组版本，旧记录才能被正确读取或迁移。

Evidence 预算、缓存与 Singleflight 的监控阈值要对应可执行动作。查询分支、各通道 Top K、重排候选、Evidence Token、缓存和端到端延迟中的某项接近上限时，系统可以限流、排队、缩小候选或切换保守路径；只发送告警不会保护正在运行的任务。

## Evidence 怎样进入答案生成

采用 Evidence 预算、缓存与 Singleflight 前先画出文件或查询到可定位到来源版本的 Chunk 的最小控制图；固定函数已经能完成任务时，新增模型决策和跨进程问题维度只会扩大测试与运维范围。

Evidence 预算、缓存与 Singleflight 与 Context Budget 的差别落在控制权：谁选择下一步，谁保存问题维度，谁确认可定位到来源版本的 Chunk 可信。

结果缓存可以与 Evidence 预算、缓存与 Singleflight 组合，但外部知识仍需授权，工具调用仍需校验，模型产生的可定位到来源版本的 Chunk 仍停留在候选状态。

Evidence 预算、缓存与 Singleflight 适合价值足够、相似 Chunk 挤满预算可观察且预算可接受的任务，高风险、不可逆的决定需要确定性规则或人工批准。

Evidence 预算、缓存与 Singleflight 从一个调用、一个问题维度、一组明确错误和几条确定性测试开始，真实 Trace 证明需要后再加入并发、缓存、队列或更复杂策略。
