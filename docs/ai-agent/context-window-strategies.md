# 上下文窗口怎样保留近期状态与关键事实

比较滑动窗口、优先级裁剪和外部状态引用，说明各自损失的信息。**Context Window**、**Trimming** 分别指向同一条执行链上的不同对象：稳定规则、当前问题、待完成动作、最近消息、固定事实和预留输出预算进入系统，message_id、priority、token estimate、pinned flag、omission reason、summary_ref 和 budget revision 保存处理中间状态，最终得到本次消息清单、Token 预算表、被省略内容的引用和无法满足预算的明确错误。

上下文窗口保留近期状态与关键事实位于模型调用之前的输入编译层与调用之外的状态存储层。它的主要机制是装配器先保留稳定规则、当前问题和未完成动作，再按相关性选择最近历史；较旧材料改用可回查摘要或稳定引用，超过硬上限时直接拒绝继续生成。机械保留最近 N 条、当前问题被旧历史挤出、工具调用与结果拆散、摘要覆盖否定约束、预留输出不足和按字符数当 Token 数会让链路在不同位置停止，错误记录必须保留发生阶段、当时的状态和终止原因。

::: info 贯穿示例

上下文窗口保留近期状态与关键事实场景：一段多轮排障会话已经接近窗口上限，用户补充新的错误日志并要求继续定位，应用必须保留当前问题和未完成工具调用。身份、权限、版本和业务事实由应用提供，模型与外部内容只产生需要检查的候选。

:::

这次推演用装配清单、Token 估算、裁剪原因、摘要版本和记忆来源把请求和终态关联起来。与滑动窗口、消息历史、摘要记忆、外部状态和模型上下文窗口比较时，重点看输入来源、状态所有者、下一步的决策者和失败终点。

一次上下文窗口保留近期状态与关键事实执行可以画成“收集材料 → 标记来源 → 计算预算 → 裁剪或检索 → 编译上下文”。稳定规则在入口出现，message_id 记录进度，本次消息清单只有通过当前主题的校验条件后才会成为可交付结果。

机械保留最近 N 条与当前问题被旧历史挤出会产生不同证据。前者先检查 message_id 和输入来源，后者沿调用记录定位依赖或状态冲突；不区分发生位置，重试会掩盖原始原因。

上下文窗口保留近期状态与关键事实与滑动窗口的共同点不代表它们可以互换。当前主题拥有 priority，相邻组件只通过契约读取或提交候选，不能直接修改这个状态。

实现上下文窗口保留近期状态与关键事实时，代码顺序应与状态顺序一致：入口拒绝不会调用依赖，正常分支保存 token estimate，错误分支返回稳定类型，测试分别断言调用次数、参数、输出和清理结果。

## 上下文问题发生在模型调用之前

比较滑动窗口、优先级裁剪和外部状态引用，说明各自损失的信息。在“上下文窗口保留近期状态与关键事实场景：一段多轮排障会话已经接近窗口上限，用户补充新的错误日志并要求继续定位，应用必须保留当前问题和未完成工具调用”这类任务里，上下文窗口保留近期状态与关键事实负责把稳定规则带入处理链，并明确本次消息清单可以交付的条件。

上下文窗口保留近期状态与关键事实位于模型调用之前的输入编译层与调用之外的状态存储层。它处理装配器先保留稳定规则、当前问题和未完成动作，再按相关性选择最近历史；较旧材料改用可回查摘要或稳定引用，超过硬上限时直接拒绝继续生成，身份认证、授权结果和最终业务状态仍由应用中的确定性组件负责。

稳定规则是这条链路的起点。来源缺失时，程序只能拒绝请求或采用明确记录的默认值；模型补出的字段没有可信来源，不能继续驱动标记来源。

机械保留最近 N 条会直接破坏 message_id 与本次消息清单之间的对应关系。排查时先保留原始输入摘要和发生阶段，再判断是否允许重试。

当前问题被旧历史挤出属于另一类风险，它影响的是 priority 或下游解释。两类错误不能共用“重新调用一次模型”这样的处理方式。

上下文窗口保留近期状态与关键事实的完成条件至少包含 message_id、priority、本次消息清单和检查结论。只有最终文字，没有这些中间记录，无法证明结果来自本次请求。

单进程 Demo 可以把状态放在内存中，但仍要保留输入、状态转移和停止原因。跨进程、带权限或有副作用的任务再把这些字段持久化，不能依赖 Prompt 代替状态。

上下文窗口保留近期状态与关键事实还要把业务条件写成状态条件：待完成动作何时就绪，本次消息清单何时允许交付，机械保留最近 N 条发生后是否还能继续。

上下文窗口保留近期状态与关键事实对外区分完成、部分完成和无法确认。三个状态如果都包装成一段顺畅文字，上层界面无法采用不同处理方式。

## 上下文窗口保留近期状态与关键事实保存什么，不保存什么

上下文窗口保留近期状态与关键事实接收稳定规则、当前问题、待完成动作、最近消息、固定事实和预留输出预算，向下游交付本次消息清单、Token 预算表、被省略内容的引用和无法满足预算的明确错误。输入与输出之间采用明确契约，避免调用方把一句含糊目标直接交给底层适配器。

上下文编译器决定本次输入，外部存储保存跨调用状态，模型不负责长期保存。因此 message_id 与 priority 要有唯一写入方，其他组件只能通过版本化命令申请修改。

滑动窗口与上下文窗口保留近期状态与关键事实解决的问题相邻，但控制权不同。比较两者时要看谁选择计算预算、谁保存 message_id、谁确认本次消息清单。

消息历史可以参与同一请求，却不能替代上下文窗口保留近期状态与关键事实的职责。组合之后，当前问题的可信来源和机械保留最近 N 条的终止规则仍需单独检查。

token estimate 若只保存在 SDK 对象里，重试或进程退出后就失去解释依据。需要恢复或审计的字段进入持久层，体积较大的结果只保存稳定引用。

上下文窗口保留近期状态与关键事实使用的身份、范围和版本来自可信运行时。用户消息、检索文本和模型候选可以表达意图，不能提升权限或改写活动 Release。

当前问题被旧历史挤出发生时，错误应回到拥有该状态的组件处理。上游缺输入、当前组件违反不变量、下游不可用分别形成不同终态。

上下文窗口保留近期状态与关键事实的确定性边界位于 message_id 写入之前。模型可以建议值，应用核对来源和当前版本；涉及权限、金额、发布或不可逆动作时，再进入策略或人工批准。

上下文窗口保留近期状态与关键事实内部可以使用更细的临时对象，跨边界只暴露稳定协议。替换滑动窗口时，调用方不需要理解内部缓存和 SDK 响应。

## 材料来源、优先级与预算

上下文窗口保留近期状态与关键事实的输入合同至少列出稳定规则、当前问题和待完成动作。每项都注明来源、是否必需、允许的缺省值，以及缺失后是在入口拒绝还是进入降级路径。

状态合同中的 message_id 表示当前进度，priority 保存本次执行依赖的快照，token estimate 负责关联前后动作。三个字段用途不同，不能合并成一段自由文本。

并发分支按稳定身份合并 token estimate。完成顺序只反映耗时，不能决定结果属于哪个请求，也不能让后返回的旧状态覆盖新修订。

输出合同同时描述本次消息清单和 Token 预算表，并为拒绝、取消、部分完成和未知状态提供固定形状。调用方据此分支，不解析错误文案猜测结果。

priority 参与乐观并发检查。处理开始时读取的版本已经变化，旧候选保留为审计材料，但不能继续写入当前状态。

稳定规则里若包含模型可填写的同名字段，应用会丢弃它，再从认证、配置或活动版本中补入可信值。结构校验通过不等于授权或业务校验通过。

装配清单、Token 估算、裁剪原因、摘要版本和记忆来源组成上下文窗口保留近期状态与关键事实的最小追踪材料。日志保存稳定 ID、版本和错误类，完整 Prompt、文档正文与凭证不进入指标标签。

撤回或删除当前问题时，依赖它的缓存、候选和未完成任务要按版本失效。稳定 ID 可以保留审计关系，已撤回内容不能继续进入本次消息清单。

契约还需要描述新鲜度。priority 对应的数据发生变化后，旧缓存、旧候选和未完成任务怎样失效，应由版本或时间规则直接判断，不能依赖模型注意到矛盾。

删除和撤回也属于数据生命周期。上下文窗口保留近期状态与关键事实引用的原始对象被移除时，稳定 ID 可以保留审计关系，正文与派生结果则按策略失效，避免继续向用户展示过期内容。

::: warning 上下文窗口保留近期状态与关键事实的可信边界

本次消息清单通过结构校验后仍是候选。身份、权限、知识版本与业务事实由应用从可信服务读取，核对完成后才能执行或交付。

:::

## 装配、裁剪和召回的处理顺序

上下文窗口保留近期状态与关键事实的处理机制是：装配器先保留稳定规则、当前问题和未完成动作，再按相关性选择最近历史；较旧材料改用可回查摘要或稳定引用，超过硬上限时直接拒绝继续生成。这条描述要落成可检查的状态变化，不能只停在框架节点名称上。

收集材料接收稳定规则并建立 message_id。入口校验未通过时就地结束，后续模型、检索器或工具调用次数保持为零。

标记来源固定身份、范围、配置版本和绝对 Deadline。子步骤只继承剩余时间，不能各自重新获得完整超时。

计算预算读取 priority 并执行主题逻辑。调用参数由应用组装，外部返回先保存为候选，尚未获得修改领域状态的资格。

裁剪或检索检查候选的结构、范围、版本和主题不变量。本次消息清单缺少来源、落在旧版本或越过权限时，当前状态停在 rejected 或 failed。

编译上下文先保存本次消息清单与终止原因，再产生事件或通知。交付失败可以重放，核心状态写入失败则不能对外宣称完成。

计算预算出现部分结果时，由任务合同决定保留、补偿还是整体丢弃。可重建制品可以重新生成，外部副作用需要查询回执或执行补偿。

实现可以使用函数、Graph、Middleware 或 Workflow，message_id 的所有权和机械保留最近 N 条的停止规则不会随框架改变。

部分成功需要在步骤边界处理。计算预算已经产生一部分本次消息清单时，程序按任务合同决定保留、补偿或整体丢弃，并记录未完成项，不能默认为全部成功。

每个步骤都应有逆向动作或明确的不可逆说明。可重建制品可以删除后重算，已发送的外部命令只能查询回执或补偿；两类失败不能共用同一重试函数。

## 多轮追问怎样改变输入

用“上下文窗口保留近期状态与关键事实场景：一段多轮排障会话已经接近窗口上限，用户补充新的错误日志并要求继续定位，应用必须保留当前问题和未完成工具调用”推演一次上下文窗口保留近期状态与关键事实。入口创建 request_id，读取可信身份，把稳定规则和当前版本写入初始状态。

收集材料阶段生成 message_id 与输入摘要。若当前问题缺失，请求返回 rejected，并指出缺少哪项材料，不继续消耗模型或外部服务配额。

标记来源阶段冻结 scope、release、policy 和 deadline_at。用户或模型在正文中提供的同名值只作为普通内容，不覆盖运行时快照。

计算预算按“装配器先保留稳定规则、当前问题和未完成动作，再按相关性选择最近历史；较旧材料改用可回查摘要或稳定引用，超过硬上限时直接拒绝继续生成”推进。每次依赖调用保存 call_id、参数摘要、开始时间与状态版本，后续才能判断超时前是否已经产生结果。

候选结果对应本次消息清单、Token 预算表、被省略内容的引用和无法满足预算的明确错误。裁剪或检索逐项检查权限、版本与领域约束，问题列表为空才允许形成下一状态。

编译上下文写入终态。客户端断开只影响交付通道，不触发核心逻辑重跑；重新连接时读取已经保存的状态或事件游标。

故障注入选择工具调用与结果拆散。程序保留原候选和错误位置，只重做失败边界，不能从入口复制整个任务并产生第二份状态。

推演结束后用 request_id 关联 message_id、本次消息清单与终止原因。测试据此排除并发请求串线，也能确认失败路径没有遗留未关闭资源。

上下文窗口保留近期状态与关键事实在输入拒绝时不调用依赖，正常路径按 5 个阶段推进，有限修复只重做失败边界。调用次数是控制流断言，不是性能宣传。

上下文窗口保留近期状态与关键事实的最终记录用 request_id 关联 message_id、本次消息清单和失败问题，测试据此证明结果来自本次执行，没有混入并发请求。

## 可观察的正常结果

上下文窗口保留近期状态与关键事实正常完成时，message_id、priority 和本次消息清单指向同一次执行。重复读取返回同一终态，未完成分支已经取消或有明确所有者。

装配清单、Token 估算、裁剪原因、摘要版本和记忆来源用于还原处理过程。它们可以按阶段和版本聚合，敏感正文留在受控存储中，不复制到日志与指标。

Token 预算表可能是合法的空结果。空结果要带范围、版本和原因；如果任务要求必须找到材料，则同一个空结果应进入拒答而非成功。

依赖返回成功状态只证明传输完成。上下文窗口保留近期状态与关键事实还要检查本次消息清单是否满足业务范围、质量阈值和当前版本，明确拒绝也可能是正确终态。

并发完成时，每个分支保留自己的身份和局部预算。汇合节点按任务合同接纳可用结果，慢分支不能抹掉已经确认的记录。

message_id 的状态迁移必须单调：完成不能退回运行中，取消不能被迟到结果覆盖，失败重试也不能绕过入口已经固定的权限。

上下文窗口保留近期状态与关键事实的成功证据最终要同时回答输入是什么、执行了哪些步骤、交付了什么以及为什么停止；任一项缺失都应留在未确认状态。

上下文窗口保留近期状态与关键事实把业务验收与服务健康分开。依赖返回 200 只说明传输成功，本次消息清单仍要满足当前范围和质量要求；明确拒答也可能是正确终态。

上下文窗口保留近期状态与关键事实的观测指标按阶段和版本聚合。错误率、空结果率、拒绝率、恢复次数与资源消耗回答不同问题，不能压成一个成功率。

## 污染、过期与信息损失

上下文窗口保留近期状态与关键事实按输入、状态、依赖、结果和交付五个位置分类错误。分类决定恢复动作，不能用同一个重试循环处理全部失败。

遇到机械保留最近 N 条时，系统要返回稳定的错误类型、发生阶段和可重试标记。上下文窗口保留近期状态与关键事实保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

当前问题被旧历史挤出要求重新读取权威状态。旧候选可以保留用于审计，却不能覆盖新版本；确认前后状态无法兼容时，当前尝试以 conflict 结束。
