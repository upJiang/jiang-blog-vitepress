# 上下文超限时怎样裁剪、滑窗和摘要

多轮对话不断增长，最终一定会超过可用窗口。解决方法不是随机删几条消息，而是先判断哪些信息可重建、哪些只能保留原文，再选择裁剪、滑窗或摘要。

## 先把信息分成四种

系统策略和当前权限属于硬约束；当前问题与关键证据属于本轮承重信息；近期消息用于指代；旧闲聊通常可丢。工具结果若能通过稳定 ID 重取，可以只保留摘要和引用。

分类发生在截断前。直接按字符从头删除，可能留下工具结果却删掉对应调用，或者删掉用户对数据范围的限定。

## 裁剪适合独立且低优先级的片段

优先级裁剪逐块选择材料，适合证据包、旧附件和互不依赖的历史段。它保留完整片段，缺点是被删内容完全不可见。

要记录每块成本与淘汰原因。若关键证据单块过大，应先做结构化压缩，不应因为它放不下就改选低价值闲聊。

## 滑动窗口保留最近的对话关系

滑窗从最近消息向前保留，适合短期对话。窗口边界要按完整消息或完整工具调用组移动，保证 assistant 的工具调用与 tool 结果成对出现。

它会遗忘较早承诺和实体。应用可以把当前主题、已确认范围和未完成事项单独保存为焦点状态，不能指望最近 N 条消息总能包含这些信息。

## 摘要压缩语义，也引入信息损失

滚动摘要把较早对话变成较短状态：已知事实、用户选择、未决问题和来源。摘要是派生数据，要保留覆盖到哪个消息序号，避免同一消息被重复总结。

模型摘要可能改写否定、数字和条件。身份、权限、金额、Deadline 等字段应由确定性状态保存；原始消息继续留在存储中，必要时可以回查。

## 超限处理要有可重复的顺序

一条稳定顺序是：保留硬约束和当前问题，装入焦点状态，选择关键证据，保留最近完整消息组，再用摘要补较早历史。仍超限时停止并提示缩小范围，而不是继续无声丢信息。

回归测试要覆盖长对话中的指代、工具消息配对、早期限制和摘要失败。摘要服务不可用时，可以退回确定性裁剪，但要标记本轮上下文质量下降。
