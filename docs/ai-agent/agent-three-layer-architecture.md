# 生产 Agent 的三层架构与调用边界

拆开 API 编排、Agent Runtime 和能力服务，明确状态、数据与失败各归谁处理。**Architecture**、**Agent**、**Layering** 分别指向同一条执行链上的不同对象：业务 SLO、风险等级、流量、模型能力、数据规模、成本预算和发布策略进入系统，请求上下文、Turn 状态、能力调用、Deadline、版本快照、结果和跨层错误保存处理中间状态，最终得到可定位、可降级、可回滚的请求结果，以及容量、质量和成本证据。

生产 Agent 的三层架构与调用边界位于把模型能力、运行时、数据服务和基础设施组合成可运维系统的架构层。它的主要机制是接口层负责协议、身份和请求形状，Runtime 层负责 Turn、控制流和终态，能力层负责模型、检索与工具；数据库和对象存储由其领域所有者访问。Controller 直接拼检索 SQL、模型适配器修改 Turn、能力服务自行决定权限、跨层共享事务和所有错误变成 500 会让链路在不同位置停止，错误记录必须保留发生阶段、当时的状态和终止原因。

生产 Agent 的三层架构与调用边界场景：知识助手流量升高，同时向量服务变慢和模型限流，系统需要保住已有会话并给出可解释降级。身份、权限、版本和业务事实由应用提供，模型与外部内容只产生需要检查的候选。

这次推演用跨层 Trace、阶段耗时、错误类型、质量信号、资源用量和发布版本把请求和终态关联起来。与 MVC、分层架构、微服务、Agent Runtime 和能力平台比较时，重点看输入来源、状态所有者、下一步的决策者和失败终点。

一次生产 Agent 的三层架构与调用边界执行可以画成“入口准入 → 运行时编排 → 调用能力服务 → 汇总观测 → 降级或交付”。业务 SLO 在入口出现，请求上下文记录进度，可定位只有通过当前主题的校验条件后才会成为可交付结果。

Controller 直接拼检索 SQL 与模型适配器修改 Turn 会产生不同证据。前者先检查请求上下文和输入来源，后者沿调用记录定位依赖或状态冲突；不区分发生位置，重试会掩盖原始原因。

生产 Agent 的三层架构与调用边界与 MVC 的共同点不代表它们可以互换。当前主题拥有 Turn 状态，相邻组件只通过契约读取或提交候选，不能直接修改这个状态。

生产 Agent 的三层架构与调用边界的架构图要标出组件职责、请求上下文的唯一所有者、风险等级经过的接口，以及 Controller 直接拼检索 SQL 怎样传播。架构取舍需要说明新增状态和恢复成本，只列组件名称无法用于故障定位。

## 生产问题怎样穿过多层组件

拆开 API 编排、Agent Runtime 和能力服务，明确状态、数据与失败各归谁处理。在“生产 Agent 的三层架构与调用边界场景：知识助手流量升高，同时向量服务变慢和模型限流，系统需要保住已有会话并给出可解释降级”这类任务里，生产 Agent 的三层架构与调用边界负责把业务 SLO 带入处理链，并明确可定位可以交付的条件。

生产 Agent 的三层架构与调用边界位于把模型能力、运行时、数据服务和基础设施组合成可运维系统的架构层。它处理接口层负责协议、身份和请求形状，Runtime 层负责 Turn、控制流和终态，能力层负责模型、检索与工具；数据库和对象存储由其领域所有者访问，身份认证、授权结果和最终业务状态仍由应用中的确定性组件负责。

业务 SLO 是这条链路的起点。来源缺失时，程序只能拒绝请求或采用明确记录的默认值；模型补出的字段没有可信来源，不能继续驱动运行时编排。

Controller 直接拼检索 SQL 会直接破坏请求上下文与可定位之间的对应关系。排查时先保留原始输入摘要和发生阶段，再判断是否允许重试。

模型适配器修改 Turn 属于另一类风险，它影响的是 Turn 状态或下游解释。两类错误不能共用“重新调用一次模型”这样的处理方式。

生产 Agent 的三层架构与调用边界的完成条件至少包含请求上下文、Turn 状态、可定位和检查结论。只有最终文字，没有这些中间记录，无法证明结果来自本次请求。

单进程 Demo 可以把状态放在内存中，但仍要保留输入、状态转移和停止原因。跨进程、带权限或有副作用的任务再把这些字段持久化，不能依赖 Prompt 代替状态。

生产 Agent 的三层架构与调用边界还要把业务条件写成状态条件：流量何时就绪，可定位何时允许交付，Controller 直接拼检索 SQL 发生后是否还能继续。

生产 Agent 的三层架构与调用边界对外区分完成、部分完成和无法确认。三个状态如果都包装成一段顺畅文字，上层界面无法采用不同处理方式。

## 生产 Agent 的三层架构与调用边界负责哪一层

生产 Agent 的三层架构与调用边界接收业务 SLO、风险等级、流量、模型能力、数据规模、成本预算和发布策略，向下游交付可定位、可降级、可回滚的请求结果，以及容量、质量和成本证据。输入与输出之间采用明确契约，避免调用方把一句含糊目标直接交给底层适配器。

入口拥有协议与身份，Runtime 拥有控制状态，能力服务拥有模型、检索和工具适配。因此请求上下文与 Turn 状态要有唯一写入方，其他组件只能通过版本化命令申请修改。

MVC 与生产 Agent 的三层架构与调用边界解决的问题相邻，但控制权不同。比较两者时要看谁选择调用能力服务、谁保存请求上下文、谁确认可定位。

分层架构可以参与同一请求，却不能替代生产 Agent 的三层架构与调用边界的职责。组合之后，风险等级的可信来源和 Controller 直接拼检索 SQL 的终止规则仍需单独检查。

能力调用若只保存在 SDK 对象里，重试或进程退出后就失去解释依据。需要恢复或审计的字段进入持久层，体积较大的结果只保存稳定引用。

生产 Agent 的三层架构与调用边界使用的身份、范围和版本来自可信运行时。用户消息、检索文本和模型候选可以表达意图，不能提升权限或改写活动 Release。

模型适配器修改 Turn 发生时，错误应回到拥有该状态的组件处理。上游缺输入、当前组件违反不变量、下游不可用分别形成不同终态。

生产 Agent 的三层架构与调用边界的确定性边界位于请求上下文写入之前。模型可以建议值，应用核对来源和当前版本；涉及权限、金额、发布或不可逆动作时，再进入策略或人工批准。

生产 Agent 的三层架构与调用边界内部可以使用更细的临时对象，跨边界只暴露稳定协议。替换 MVC 时，调用方不需要理解内部缓存和 SDK 响应。

## 组件职责、状态和数据归属

生产 Agent 的三层架构与调用边界的输入合同至少列出业务 SLO、风险等级和流量。每项都注明来源、是否必需、允许的缺省值，以及缺失后是在入口拒绝还是进入降级路径。

状态合同中的请求上下文表示当前进度，Turn 状态保存本次执行依赖的快照，能力调用负责关联前后动作。三个字段用途不同，不能合并成一段自由文本。

并发分支按稳定身份合并能力调用。完成顺序只反映耗时，不能决定结果属于哪个请求，也不能让后返回的旧状态覆盖新修订。

输出合同同时描述可定位和可降级，并为拒绝、取消、部分完成和未知状态提供固定形状。调用方据此分支，不解析错误文案猜测结果。

Turn 状态参与乐观并发检查。处理开始时读取的版本已经变化，旧候选保留为审计材料，但不能继续写入当前状态。

业务 SLO 里若包含模型可填写的同名字段，应用会丢弃它，再从认证、配置或活动版本中补入可信值。结构校验通过不等于授权或业务校验通过。

跨层 Trace、阶段耗时、错误类型、质量信号、资源用量和发布版本组成生产 Agent 的三层架构与调用边界的最小追踪材料。日志保存稳定 ID、版本和错误类，完整 Prompt、文档正文与凭证不进入指标标签。

撤回或删除风险等级时，依赖它的缓存、候选和未完成任务要按版本失效。稳定 ID 可以保留审计关系，已撤回内容不能继续进入可定位。

契约还需要描述新鲜度。Turn 状态对应的数据发生变化后，旧缓存、旧候选和未完成任务怎样失效，应由版本或时间规则直接判断，不能依赖模型注意到矛盾。

删除和撤回也属于数据生命周期。生产 Agent 的三层架构与调用边界引用的原始对象被移除时，稳定 ID 可以保留审计关系，正文与派生结果则按策略失效，避免继续向用户展示过期内容。

可定位通过结构校验后仍是候选。身份、权限、知识版本与业务事实由应用从可信服务读取，核对完成后才能执行或交付。

:::

## 调用链、Deadline 与失败传播

生产 Agent 的三层架构与调用边界的处理机制是：接口层负责协议、身份和请求形状，Runtime 层负责 Turn、控制流和终态，能力层负责模型、检索与工具；数据库和对象存储由其领域所有者访问。这条描述要落成可检查的状态变化，不能只停在框架节点名称上。

入口准入接收业务 SLO 并建立请求上下文。入口校验未通过时就地结束，后续模型、检索器或工具调用次数保持为零。

运行时编排固定身份、范围、配置版本和绝对 Deadline。子步骤只继承剩余时间，不能各自重新获得完整超时。

调用能力服务读取 Turn 状态并执行主题逻辑。调用参数由应用组装，外部返回先保存为候选，尚未获得修改领域状态的资格。

汇总观测检查候选的结构、范围、版本和主题不变量。可定位缺少来源、落在旧版本或越过权限时，当前状态停在 rejected 或 failed。

降级或交付先保存可定位与终止原因，再产生事件或通知。交付失败可以重放，核心状态写入失败则不能对外宣称完成。

调用能力服务出现部分结果时，由任务合同决定保留、补偿还是整体丢弃。可重建制品可以重新生成，外部副作用需要查询回执或执行补偿。

实现可以使用函数、Graph、Middleware 或 Workflow，请求上下文的所有权和 Controller 直接拼检索 SQL 的停止规则不会随框架改变。

部分成功需要在步骤边界处理。调用能力服务已经产生一部分可定位时，程序按任务合同决定保留、补偿或整体丢弃，并记录未完成项，不能默认为全部成功。

每个步骤都应有逆向动作或明确的不可逆说明。可重建制品可以删除后重算，已发送的外部命令只能查询回执或补偿；两类失败不能共用同一重试函数。

## 沿一次过载请求推演

用“生产 Agent 的三层架构与调用边界场景：知识助手流量升高，同时向量服务变慢和模型限流，系统需要保住已有会话并给出可解释降级”推演一次生产 Agent 的三层架构与调用边界。入口创建 request_id，读取可信身份，把业务 SLO 和当前版本写入初始状态。

入口准入阶段生成请求上下文与输入摘要。若风险等级缺失，请求返回 rejected，并指出缺少哪项材料，不继续消耗模型或外部服务配额。

运行时编排阶段冻结 scope、release、policy 和 deadline_at。用户或模型在正文中提供的同名值只作为普通内容，不覆盖运行时快照。

调用能力服务按“接口层负责协议、身份和请求形状，Runtime 层负责 Turn、控制流和终态，能力层负责模型、检索与工具；数据库和对象存储由其领域所有者访问”推进。每次依赖调用保存 call_id、参数摘要、开始时间与状态版本，后续才能判断超时前是否已经产生结果。

候选结果对应可定位、可降级、可回滚的请求结果，以及容量、质量和成本证据。汇总观测逐项检查权限、版本与领域约束，问题列表为空才允许形成下一状态。

降级或交付写入终态。客户端断开只影响交付通道，不触发核心逻辑重跑；重新连接时读取已经保存的状态或事件游标。

故障注入选择能力服务自行决定权限。程序保留原候选和错误位置，只重做失败边界，不能从入口复制整个任务并产生第二份状态。

推演结束后用 request_id 关联请求上下文、可定位与终止原因。测试据此排除并发请求串线，也能确认失败路径没有遗留未关闭资源。

生产 Agent 的三层架构与调用边界在输入拒绝时不调用依赖，正常路径按 5 个阶段推进，有限修复只重做失败边界。调用次数是控制流断言，不是性能宣传。

生产 Agent 的三层架构与调用边界的最终记录用 request_id 关联请求上下文、可定位和失败问题，测试据此证明结果来自本次执行，没有混入并发请求。

## 正常服务的观测证据

生产 Agent 的三层架构与调用边界正常完成时，请求上下文、Turn 状态和可定位指向同一次执行。重复读取返回同一终态，未完成分支已经取消或有明确所有者。

跨层 Trace、阶段耗时、错误类型、质量信号、资源用量和发布版本用于还原处理过程。它们可以按阶段和版本聚合，敏感正文留在受控存储中，不复制到日志与指标。

可降级可能是合法的空结果。空结果要带范围、版本和原因；如果任务要求必须找到材料，则同一个空结果应进入拒答而非成功。

依赖返回成功状态只证明传输完成。生产 Agent 的三层架构与调用边界还要检查可定位是否满足业务范围、质量阈值和当前版本，明确拒绝也可能是正确终态。

并发完成时，每个分支保留自己的身份和局部预算。汇合节点按任务合同接纳可用结果，慢分支不能抹掉已经确认的记录。

请求上下文的状态迁移必须单调：完成不能退回运行中，取消不能被迟到结果覆盖，失败重试也不能绕过入口已经固定的权限。

生产 Agent 的三层架构与调用边界的成功证据最终要同时回答输入是什么、执行了哪些步骤、交付了什么以及为什么停止；任一项缺失都应留在未确认状态。

生产 Agent 的三层架构与调用边界把业务验收与服务健康分开。依赖返回 200 只说明传输成功，可定位仍要满足当前范围和质量要求；明确拒答也可能是正确终态。

生产 Agent 的三层架构与调用边界的观测指标按阶段和版本聚合。错误率、空结果率、拒绝率、恢复次数与资源消耗回答不同问题，不能压成一个成功率。

## 降级、隔离与恢复

生产 Agent 的三层架构与调用边界按输入、状态、依赖、结果和交付五个位置分类错误。分类决定恢复动作，不能用同一个重试循环处理全部失败。

遇到 Controller 直接拼检索 SQL 时，系统要返回稳定的错误类型、发生阶段和可重试标记。生产 Agent 的三层架构与调用边界保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

遇到模型适配器修改 Turn 时，系统要返回稳定的错误类型、发生阶段和可重试标记。生产 Agent 的三层架构与调用边界保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

能力服务自行决定权限属于安全边界，重试不会使它自动合法。执行路径应保存拒绝规则和输入来源，清除未授权候选，并以稳定错误结束当前动作。

遇到跨层共享事务时，系统要返回稳定的错误类型、发生阶段和可重试标记。生产 Agent 的三层架构与调用边界保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

遇到所有错误变成 500 时，系统要返回稳定的错误类型、发生阶段和可重试标记。生产 Agent 的三层架构与调用边界保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

生产 Agent 的三层架构与调用边界结束错误处理时保存终态、可重试性和资源清理结果。后台扫描器依靠这些字段区分仍在运行、等待恢复和已经失败的任务。

生产 Agent 的三层架构与调用边界在执行前写入绝对 Deadline、最大动作数、重复签名、无进展阈值、预算和人工取消信号。任一条件触发后都不再创建新工作。

生产 Agent 的三层架构与调用边界把重试时间和次数计入总预算。依赖连续失败会减少后续额度，达到上限后保留原始错误，不再用模型重新措辞掩盖失败。

生产 Agent 的三层架构与调用边界的清理动作可以重复执行。临时对象、文件句柄、子进程、连接或 Lease 仍被活动任务引用时，清理器必须拒绝删除。

## 故障演练和发布验证

沿正常、过载、依赖失败和回滚四条路径演练，核对状态所有者、传播边界与可观测字段。测试需要显式给出业务 SLO、初始请求上下文、预期可定位和终止原因，不能只断言返回值非空。

生产 Agent 的三层架构与调用边界的单元测试用 Fake Adapter 固定可定位与错误，断言参数、调用顺序、状态修订和清理动作。它只证明本地控制逻辑。

契约测试围绕业务 SLO、请求上下文和可降级构造合法与非法样本。Schema 解析成功后继续检查权限、版本与领域不变量。

故障测试注入 Controller 直接拼检索 SQL 和模型适配器修改 Turn，记录依赖是否被调用、状态是否改变、资源是否释放，以及同一身份重试会不会重复执行。

在调用能力服务前后终止执行进程，可以检查恢复边界。调用前退出允许重新领取；外部动作后退出先查回执；终态写入后只重放交付。

集成测试连接真实协议与隔离存储，检查序列化、约束、并发和超时。需要在线服务时单独记录服务版本、时间、配置与是否具备凭证。

生产 Agent 的三层架构与调用边界的回归报告要保留失败类型分布。明确拒绝变成超时、权限错误变成普通空结果，都属于行为回归，即使总通过数没有变化。

性质测试可以补足固定样本。随机改变消息顺序、重复提交、完成顺序或状态版本，断言权限不扩大、终态不倒退、同一身份不产生两次副作用。

离线评测关注固定输入下的质量变化，运行时测试关注控制和恢复。生产 Agent 的三层架构与调用边界只有两类证据都存在，才能同时回答“结果是否合格”和“系统是否安全完成”。

## 容量、成本与版本治理

生产 Agent 的三层架构与调用边界长期运行后，输入 Schema、请求上下文结构和依赖配置可能独立升级。每次执行固定一组版本，旧记录才能被正确读取或迁移。

生产 Agent 的三层架构与调用边界的容量主要受到达率、并发、队列、模型配额、数据库连接和成本预算影响。并发可能缩短单次等待，也会同时占用连接、配额、内存和下游吞吐，容量要沿调用链逐层核算。

候选版本在固定样本上比较正确性、错误类型、延迟和资源消耗。Controller 直接拼检索 SQL 等安全红线回归时直接停止发布，不能用平均质量抵消。

Controller 直接拼检索 SQL 的降级路径在发布前写好：减少非关键增强、返回已经确认的结果，或明确暂时无法确认。缺失事实不能交给模型补写。

生产 Agent 的三层架构与调用边界的运行手册从 request_id 定位跨层 Trace、阶段耗时、错误类型、质量信号、资源用量和发布版本，再决定重试、补偿、取消或回滚，无需先展开完整敏感内容。

数据保留按证据用途分级。聚合字段可以保留更久，原始输入和大结果设置短期限、访问控制与删除通道。

生产 Agent 的三层架构与调用边界先在单进程实现状态、超时、错误和测试；只有恢复与容量证据提出要求时，再增加队列、Lease、分布式缓存或工作流引擎。

生产 Agent 的三层架构与调用边界的监控阈值要对应可执行动作。到达率、并发、队列、模型配额、数据库连接和成本预算中的某项接近上限时，系统可以限流、排队、缩小候选或切换保守路径；只发送告警不会保护正在运行的任务。

回滚要覆盖代码之外的状态。生产 Agent 的三层架构与调用边界若改变 Schema、缓存键或持久化记录，旧版本是否还能读取新写入数据必须提前验证；无法双向兼容时采用候选版本隔离。

## 架构复杂度的适用边界

采用生产 Agent 的三层架构与调用边界前先画最小控制图。固定函数已经能完成任务时，新增模型决策和跨进程状态只会扩大测试与运维范围。

生产 Agent 的三层架构与调用边界与 MVC 的差别落在控制权：谁选择下一步，谁保存请求上下文，谁确认可定位可信。

分层架构可以与生产 Agent 的三层架构与调用边界组合。组合之后，外部知识仍需授权，工具调用仍需校验，模型输出仍停留在候选状态。

生产 Agent 的三层架构与调用边界适合价值足够、失败可观察、动作可约束且预算可接受的任务。高风险且不可逆的决定需要确定性规则或人工批准。
