# 图谱辅助检索的路由、扩展与回退

用 Alias 和 Wiki 路由实体，受限扩展子图并把关系绑定到来源，图谱失败时退回普通检索。**Knowledge Graph**、**Retrieval**、**Fallback** 分别指向同一条执行链上的不同对象：文件或查询、知识范围、活动版本、解析配置、检索配置和用户权限进入系统，起点实体、扩展规则、访问节点、边证据、深度、预算、权限过滤和回退原因保存处理中间状态，最终得到可定位到来源版本的 Chunk、排序候选、Evidence 集合或安全的空结果。

图谱辅助检索位于外部知识从原始文件进入可授权证据的离线与在线数据链路。它的主要机制是查询先借助 Alias 和 Wiki 解析实体，再按关系类型、深度、方向和权限受限扩展子图；每条关系必须回到文档证据，失败时退回普通检索。热门节点爆炸、无证据边进入回答、跨 Release 扩展、图失败导致整个检索失败和图上下文挤掉原文会让链路在不同位置停止，错误记录必须保留发生阶段、当时的状态和终止原因。

::: info 贯穿示例

图谱辅助检索场景：一份包含正文、表格和扫描页的制度文档发布新版本，用户随后按编号和语义分别查询同一条规定。身份、权限、版本和业务事实由应用提供，模型与外部内容只产生需要检查的候选。

:::

这次推演用结构化查询、通道结果、候选 ID、融合分数、重排结果、权限裁决和证据集合把请求和终态关联起来。与 Knowledge Graph、GraphRAG、邻接查询、Wiki 路由和混合检索比较时，重点看输入来源、状态所有者、下一步的决策者和失败终点。

一次图谱辅助检索执行可以画成“理解查询并固定范围 → 并行取得候选 → 按稳定身份去重融合 → 重排并分配证据预算 → 验证可见性后返回”。文件或查询在入口出现，起点实体记录进度，可定位到来源版本的 Chunk 只有通过当前主题的校验条件后才会成为可交付结果。

热门节点爆炸与无证据边进入回答会产生不同证据。前者先检查起点实体和输入来源，后者沿调用记录定位依赖或状态冲突；不区分发生位置，重试会掩盖原始原因。

图谱辅助检索与 Knowledge Graph 的共同点不代表它们可以互换。当前主题拥有扩展规则，相邻组件只通过契约读取或提交候选，不能直接修改这个状态。

实现图谱辅助检索时，代码顺序应与状态顺序一致：入口拒绝不会调用依赖，正常分支保存访问节点，错误分支返回稳定类型，测试分别断言调用次数、参数、输出和清理结果。

## 图谱辅助检索补的是关系发现

用 Alias 和 Wiki 路由实体，受限扩展子图并把关系绑定到来源，图谱失败时退回普通检索。在“图谱辅助检索场景：一份包含正文、表格和扫描页的制度文档发布新版本，用户随后按编号和语义分别查询同一条规定”这类任务里，图谱辅助检索负责把文件或查询带入处理链，并明确可定位到来源版本的 Chunk 可以交付的条件。

图谱辅助检索位于外部知识从原始文件进入可授权证据的离线与在线数据链路。它处理查询先借助 Alias 和 Wiki 解析实体，再按关系类型、深度、方向和权限受限扩展子图；每条关系必须回到文档证据，失败时退回普通检索，身份认证、授权结果和最终业务状态仍由应用中的确定性组件负责。

文件或查询是这条链路的起点。来源缺失时，程序只能拒绝请求或采用明确记录的默认值；模型补出的字段没有可信来源，不能继续驱动并行取得候选。

热门节点爆炸会直接破坏起点实体与可定位到来源版本的 Chunk 之间的对应关系。排查时先保留原始输入摘要和发生阶段，再判断是否允许重试。

无证据边进入回答属于另一类风险，它影响的是扩展规则或下游解释。两类错误不能共用“重新调用一次模型”这样的处理方式。

图谱辅助检索的完成条件至少包含起点实体、扩展规则、可定位到来源版本的 Chunk 和检查结论。只有最终文字，没有这些中间记录，无法证明结果来自本次请求。

单进程 Demo 可以把状态放在内存中，但仍要保留输入、状态转移和停止原因。跨进程、带权限或有副作用的任务再把这些字段持久化，不能依赖 Prompt 代替状态。

图谱辅助检索还要把业务条件写成状态条件：活动版本何时就绪，可定位到来源版本的 Chunk 何时允许交付，热门节点爆炸发生后是否还能继续。

图谱辅助检索对外区分完成、部分完成和无法确认。三个状态如果都包装成一段顺畅文字，上层界面无法采用不同处理方式。

## Alias 与 Wiki 怎样找到种子对象

图谱辅助检索接收文件或查询、知识范围、活动版本、解析配置、检索配置和用户权限，向下游交付可定位到来源版本的 Chunk、排序候选、Evidence 集合或安全的空结果。输入与输出之间采用明确契约，避免调用方把一句含糊目标直接交给底层适配器。

查询理解器产生受约束计划，检索器返回候选，Evidence 选择器决定进入回答的材料。因此起点实体与扩展规则要有唯一写入方，其他组件只能通过版本化命令申请修改。

Knowledge Graph 与图谱辅助检索解决的问题相邻，但控制权不同。比较两者时要看谁选择按稳定身份去重融合、谁保存起点实体、谁确认可定位到来源版本的 Chunk。

GraphRAG 可以参与同一请求，却不能替代图谱辅助检索的职责。组合之后，知识范围的可信来源和热门节点爆炸的终止规则仍需单独检查。

访问节点若只保存在 SDK 对象里，重试或进程退出后就失去解释依据。需要恢复或审计的字段进入持久层，体积较大的结果只保存稳定引用。

图谱辅助检索使用的身份、范围和版本来自可信运行时。用户消息、检索文本和模型候选可以表达意图，不能提升权限或改写活动 Release。

无证据边进入回答发生时，错误应回到拥有该状态的组件处理。上游缺输入、当前组件违反不变量、下游不可用分别形成不同终态。

图谱辅助检索的确定性边界位于起点实体写入之前。模型可以建议值，应用核对来源和当前版本；涉及权限、金额、发布或不可逆动作时，再进入策略或人工批准。

图谱辅助检索内部可以使用更细的临时对象，跨边界只暴露稳定协议。替换 Knowledge Graph 时，调用方不需要理解内部缓存和 SDK 响应。

## 子图扩展为何要限制关系和深度

图谱辅助检索的输入合同至少列出文件或查询、知识范围和活动版本。每项都注明来源、是否必需、允许的缺省值，以及缺失后是在入口拒绝还是进入降级路径。

状态合同中的起点实体表示当前进度，扩展规则保存本次执行依赖的快照，访问节点负责关联前后动作。三个字段用途不同，不能合并成一段自由文本。

并发分支按稳定身份合并访问节点。完成顺序只反映耗时，不能决定结果属于哪个请求，也不能让后返回的旧状态覆盖新修订。

输出合同同时描述可定位到来源版本的 Chunk 和排序候选，并为拒绝、取消、部分完成和未知状态提供固定形状。调用方据此分支，不解析错误文案猜测结果。

扩展规则参与乐观并发检查。处理开始时读取的版本已经变化，旧候选保留为审计材料，但不能继续写入当前状态。

文件或查询里若包含模型可填写的同名字段，应用会丢弃它，再从认证、配置或活动版本中补入可信值。结构校验通过不等于授权或业务校验通过。

结构化查询、通道结果、候选 ID、融合分数、重排结果、权限裁决和证据集合组成图谱辅助检索的最小追踪材料。日志保存稳定 ID、版本和错误类，完整 Prompt、文档正文与凭证不进入指标标签。

撤回或删除知识范围时，依赖它的缓存、候选和未完成任务要按版本失效。稳定 ID 可以保留审计关系，已撤回内容不能继续进入可定位到来源版本的 Chunk。

契约还需要描述新鲜度。扩展规则对应的数据发生变化后，旧缓存、旧候选和未完成任务怎样失效，应由版本或时间规则直接判断，不能依赖模型注意到矛盾。

删除和撤回也属于数据生命周期。图谱辅助检索引用的原始对象被移除时，稳定 ID 可以保留审计关系，正文与派生结果则按策略失效，避免继续向用户展示过期内容。

::: warning 图谱辅助检索的可信边界

可定位到来源版本的 Chunk 通过结构校验后仍是候选。身份、权限、知识版本与业务事实由应用从可信服务读取，核对完成后才能执行或交付。

:::

## 关系路径怎样绑定原文证据

图谱辅助检索不是用图遍历替代全文和向量检索。查询理解先识别实体或 Alias，得到经过 ACL 和 Release 过滤的种子对象；图服务在限定关系类型、深度和节点预算内扩展子图，再把关系上下文转换为带来源的候选。文本检索仍负责找到能直接支持答案的 Chunk。

扩展结果要保留 seed_object_id、关系路径、每条边的证据和可见性。路径越长，语义漂移和权限组合越复杂，因此默认使用小深度，并为每类关系设白名单。图谱上下文可以帮助发现相关对象或补全查询词，不能在没有原文 Evidence 时直接支撑事实回答。

失败回退是明确路径：Alias 无匹配时回到普通查询理解；图服务超时时继续文本检索；子图为空时返回原检索结果；图谱候选与文本证据冲突时保留冲突并交给验证器，不能让图关系覆盖当前 Release 的原文。

图谱辅助检索的处理机制是：查询先借助 Alias 和 Wiki 解析实体，再按关系类型、深度、方向和权限受限扩展子图；每条关系必须回到文档证据，失败时退回普通检索。这条描述要落成可检查的状态变化，不能只停在框架节点名称上。

理解查询并固定范围接收文件或查询并建立起点实体。入口校验未通过时就地结束，后续模型、检索器或工具调用次数保持为零。

并行取得候选固定身份、范围、配置版本和绝对 Deadline。子步骤只继承剩余时间，不能各自重新获得完整超时。

按稳定身份去重融合读取扩展规则并执行主题逻辑。调用参数由应用组装，外部返回先保存为候选，尚未获得修改领域状态的资格。

重排并分配证据预算检查候选的结构、范围、版本和主题不变量。可定位到来源版本的 Chunk 缺少来源、落在旧版本或越过权限时，当前状态停在 rejected 或 failed。

验证可见性后返回先保存可定位到来源版本的 Chunk 与终止原因，再产生事件或通知。交付失败可以重放，核心状态写入失败则不能对外宣称完成。

按稳定身份去重融合出现部分结果时，由任务合同决定保留、补偿还是整体丢弃。可重建制品可以重新生成，外部副作用需要查询回执或执行补偿。

实现可以使用函数、Graph、Middleware 或 Workflow，起点实体的所有权和热门节点爆炸的停止规则不会随框架改变。

部分成功需要在步骤边界处理。按稳定身份去重融合已经产生一部分可定位到来源版本的 Chunk 时，程序按任务合同决定保留、补偿或整体丢弃，并记录未完成项，不能默认为全部成功。

每个步骤都应有逆向动作或明确的不可逆说明。可重建制品可以删除后重算，已发送的外部命令只能查询回执或补偿；两类失败不能共用同一重试函数。

## 图谱上下文怎样转成检索候选

用户问“设备合规和远程访问有什么关系”。Alias 解析出两个可见主题，图服务找到 has_topic 或 requires 候选，并返回关系 quote。检索器用两个规范名和原问题分别执行精确、全文或向量查询，最终 Evidence 仍来自当前 Release 的制度 Chunk。

如果图谱只找到旧版本关系，版本过滤会将其排除，文本检索仍可回答当前制度；若图服务超时，Trace 记录 graph_degraded，系统不重试到耗尽总 Deadline。若关系指向用户不可见文档，该节点和由它产生的查询扩展都被删除，避免通过图路径泄露名称。

评测需要成对样本：一个图谱确实能补召回的多跳问题，一个普通文本检索已经足够的问题，一个 Alias 歧义问题，以及图服务故障用例。比较的是最终 Evidence 覆盖、错误率和额外延迟，不是图谱返回了多少节点。

用“图谱辅助检索场景：一份包含正文、表格和扫描页的制度文档发布新版本，用户随后按编号和语义分别查询同一条规定”推演一次图谱辅助检索。入口创建 request_id，读取可信身份，把文件或查询和当前版本写入初始状态。

理解查询并固定范围阶段生成起点实体与输入摘要。若知识范围缺失，请求返回 rejected，并指出缺少哪项材料，不继续消耗模型或外部服务配额。

并行取得候选阶段冻结 scope、release、policy 和 deadline_at。用户或模型在正文中提供的同名值只作为普通内容，不覆盖运行时快照。

按稳定身份去重融合按“查询先借助 Alias 和 Wiki 解析实体，再按关系类型、深度、方向和权限受限扩展子图；每条关系必须回到文档证据，失败时退回普通检索”推进。每次依赖调用保存 call_id、参数摘要、开始时间与状态版本，后续才能判断超时前是否已经产生结果。

候选结果对应可定位到来源版本的 Chunk、排序候选、Evidence 集合或安全的空结果。重排并分配证据预算逐项检查权限、版本与领域约束，问题列表为空才允许形成下一状态。

验证可见性后返回写入终态。客户端断开只影响交付通道，不触发核心逻辑重跑；重新连接时读取已经保存的状态或事件游标。

故障注入选择跨 Release 扩展。程序保留原候选和错误位置，只重做失败边界，不能从入口复制整个任务并产生第二份状态。

推演结束后用 request_id 关联起点实体、可定位到来源版本的 Chunk 与终止原因。测试据此排除并发请求串线，也能确认失败路径没有遗留未关闭资源。

图谱辅助检索在输入拒绝时不调用依赖，正常路径按 5 个阶段推进，有限修复只重做失败边界。调用次数是控制流断言，不是性能宣传。

图谱辅助检索的最终记录用 request_id 关联起点实体、可定位到来源版本的 Chunk 和失败问题，测试据此证明结果来自本次执行，没有混入并发请求。

## 一次多跳问题的图文联合检索

图谱辅助检索正常完成时，起点实体、扩展规则和可定位到来源版本的 Chunk 指向同一次执行。重复读取返回同一终态，未完成分支已经取消或有明确所有者。

结构化查询、通道结果、候选 ID、融合分数、重排结果、权限裁决和证据集合用于还原处理过程。它们可以按阶段和版本聚合，敏感正文留在受控存储中，不复制到日志与指标。

排序候选可能是合法的空结果。空结果要带范围、版本和原因；如果任务要求必须找到材料，则同一个空结果应进入拒答而非成功。

依赖返回成功状态只证明传输完成。图谱辅助检索还要检查可定位到来源版本的 Chunk 是否满足业务范围、质量阈值和当前版本，明确拒绝也可能是正确终态。

并发完成时，每个分支保留自己的身份和局部预算。汇合节点按任务合同接纳可用结果，慢分支不能抹掉已经确认的记录。

起点实体的状态迁移必须单调：完成不能退回运行中，取消不能被迟到结果覆盖，失败重试也不能绕过入口已经固定的权限。

图谱辅助检索的成功证据最终要同时回答输入是什么、执行了哪些步骤、交付了什么以及为什么停止；任一项缺失都应留在未确认状态。

图谱辅助检索把业务验收与服务健康分开。依赖返回 200 只说明传输成功，可定位到来源版本的 Chunk 仍要满足当前范围和质量要求；明确拒答也可能是正确终态。

图谱辅助检索的观测指标按阶段和版本聚合。错误率、空结果率、拒绝率、恢复次数与资源消耗回答不同问题，不能压成一个成功率。

## 旧关系、越权节点与冲突证据

图谱辅助检索按输入、状态、依赖、结果和交付五个位置分类错误。分类决定恢复动作，不能用同一个重试循环处理全部失败。

热门节点爆炸通常会留下动作签名重复、状态无变化或预算持续下降的迹象。控制器据此写入停止原因，取消未开始分支，并把现有证据交给人工或保守路径。

遇到无证据边进入回答时，系统要返回稳定的错误类型、发生阶段和可重试标记。图谱辅助检索保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

遇到跨 Release 扩展时，系统要返回稳定的错误类型、发生阶段和可重试标记。图谱辅助检索保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

图谱辅助检索结束错误处理时保存终态、可重试性和资源清理结果。后台扫描器依靠这些字段区分仍在运行、等待恢复和已经失败的任务。

图谱辅助检索在执行前写入绝对 Deadline、最大动作数、重复签名、无进展阈值、预算和人工取消信号。任一条件触发后都不再创建新工作。

图谱辅助检索把重试时间和次数计入总预算。依赖连续失败会减少后续额度，达到上限后保留原始错误，不再用模型重新措辞掩盖失败。

图谱辅助检索的清理动作可以重复执行。临时对象、文件句柄、子进程、连接或 Lease 仍被活动任务引用时，清理器必须拒绝删除。

## 图服务超时后的文本检索回退

使用带标注的小语料验证内容保留、稳定 ID、权限过滤、版本切换、召回指标和失败回退。测试需要显式给出文件或查询、初始起点实体、预期可定位到来源版本的 Chunk 和终止原因，不能只断言返回值非空。

图谱辅助检索的单元测试用 Fake Adapter 固定可定位到来源版本的 Chunk 与错误，断言参数、调用顺序、状态修订和清理动作。它只证明本地控制逻辑。

契约测试围绕文件或查询、起点实体和排序候选构造合法与非法样本。Schema 解析成功后继续检查权限、版本与领域不变量。

故障测试注入热门节点爆炸和无证据边进入回答，记录依赖是否被调用、状态是否改变、资源是否释放，以及同一身份重试会不会重复执行。

在按稳定身份去重融合前后终止执行进程，可以检查恢复边界。调用前退出允许重新领取；外部动作后退出先查回执；终态写入后只重放交付。

集成测试连接真实协议与隔离存储，检查序列化、约束、并发和超时。需要在线服务时单独记录服务版本、时间、配置与是否具备凭证。

图谱辅助检索的回归报告要保留失败类型分布。明确拒绝变成超时、权限错误变成普通空结果，都属于行为回归，即使总通过数没有变化。

性质测试可以补足固定样本。随机改变消息顺序、重复提交、完成顺序或状态版本，断言权限不扩大、终态不倒退、同一身份不产生两次副作用。

离线评测关注固定输入下的质量变化，运行时测试关注控制和恢复。图谱辅助检索只有两类证据都存在，才能同时回答“结果是否合格”和“系统是否安全完成”。

## 用成对样本测量图谱增益

图谱辅助检索长期运行后，输入 Schema、起点实体结构和依赖配置可能独立升级。每次执行固定一组版本，旧记录才能被正确读取或迁移。

图谱辅助检索的容量主要受查询分支、各通道 Top K、重排候选、Evidence Token、缓存和端到端延迟影响。并发可能缩短单次等待，也会同时占用连接、配额、内存和下游吞吐，容量要沿调用链逐层核算。

候选版本在固定样本上比较正确性、错误类型、延迟和资源消耗。热门节点爆炸等安全红线回归时直接停止发布，不能用平均质量抵消。

热门节点爆炸的降级路径在发布前写好：减少非关键增强、返回已经确认的结果，或明确暂时无法确认。缺失事实不能交给模型补写。

图谱辅助检索的运行手册从 request_id 定位结构化查询、通道结果、候选 ID、融合分数、重排结果、权限裁决和证据集合，再决定重试、补偿、取消或回滚，无需先展开完整敏感内容。

数据保留按证据用途分级。聚合字段可以保留更久，原始输入和大结果设置短期限、访问控制与删除通道。

图谱辅助检索先在单进程实现状态、超时、错误和测试；只有恢复与容量证据提出要求时，再增加队列、Lease、分布式缓存或工作流引擎。

图谱辅助检索的监控阈值要对应可执行动作。查询分支、各通道 Top K、重排候选、Evidence Token、缓存和端到端延迟中的某项接近上限时，系统可以限流、排队、缩小候选或切换保守路径；只发送告警不会保护正在运行的任务。

回滚要覆盖代码之外的状态。图谱辅助检索若改变 Schema、缓存键或持久化记录，旧版本是否还能读取新写入数据必须提前验证；无法双向兼容时采用候选版本隔离。

## 什么时候普通文本检索已经足够

采用图谱辅助检索前先画最小控制图。固定函数已经能完成任务时，新增模型决策和跨进程状态只会扩大测试与运维范围。

图谱辅助检索与 Knowledge Graph 的差别落在控制权：谁选择下一步，谁保存起点实体，谁确认可定位到来源版本的 Chunk 可信。

GraphRAG 可以与图谱辅助检索组合。组合之后，外部知识仍需授权，工具调用仍需校验，模型输出仍停留在候选状态。

图谱辅助检索适合价值足够、失败可观察、动作可约束且预算可接受的任务。高风险且不可逆的决定需要确定性规则或人工批准。

格式正确但事实错误的可定位到来源版本的 Chunk 是必要反例。系统若直接进入成功，说明业务验证缺失；保留候选并给出证据问题，才符合边界。

执行期间修改扩展规则可以检验并发设计。旧动作仍能覆盖新状态，说明版本或 Lease 有缺口，增加 Prompt 规则无法修复竞态。

图谱辅助检索增加了状态、调用、恢复责任和故障面。设计记录应明确获得的能力，也列出新增的退出、降级与回滚路径。

演进可以从最小闭环开始：一个调用、一个状态对象、一组明确错误和几条确定性测试。真实 Trace 证明瓶颈后，再加入并发、缓存、队列或更复杂策略。

相邻文章提供的能力只按依赖引入。Knowledge Graph 解决不了当前失败时，不应为了目录完整强行组合；设计保持可替换，后续需求出现再扩展。
