# 多格式文档解析与 OCR

同一份制度可以是 Markdown、网页、PDF、Word，也可能是扫描件。读取字节后调用 `extract_text()`，通常能得到一段字符串，却可能丢掉标题层级、表头、页码、列表顺序和图片文字。后续 Chunk 再规整，也无法恢复已经消失的结构。

**Document Parsing（文档解析）** 把已准入的原始对象转换成带结构、来源和警告的中间表示。**OCR（Optical Character Recognition，光学字符识别）** 处理没有文本层的图片页面。解析目标是可追溯地保留知识单元，不只是让输出非空。

## ParsedContent 要表达正文之外的信息

统一解析结果可以包含：

```text
ParsedContent {
  content
  display_content
  structured_content
  warnings
  parser_version
}
```

`content` 用于后续结构识别与检索，`display_content` 用于引用预览。两者初期可以相同，职责仍要分开。检索文本可能加入标题或规范化空白，展示文本要尽量保持用户可读布局。

`structured_content` 保存格式相关事实，例如页数、Sheet 名、表格数、图片数和需要 OCR 的页面。`warnings` 表示解析已完成但存在信息损失。`parser_version` 让重建和回归能够定位行为变化。

空输出、格式不支持、容器损坏和必需 OCR 失败通常是 Error，不能只放一条 Warning 后继续索引。若系统无法区分两者，线上会出现“入库成功但永远搜不到”的静默失败。
## 格式路由不能只信扩展名

文件在准入阶段已经检查扩展名、MIME 和 Magic。解析器根据检测后的类型选择适配器，仍要验证内部结构。

```text
Markdown / Text -> 文本解码器
HTML            -> DOM 结构解析器
PDF             -> 页面与布局解析器
DOCX            -> OOXML 段落和表格
XLSX            -> Workbook / Sheet / Cell
PPTX            -> Slide / Shape / Table
Image-only PDF  -> PDF 解析 + 按页 OCR
```

旧 Office 二进制格式若没有可靠解析器，明确拒绝并要求转换。把未知二进制按 UTF-8 `errors=replace` 解码，会产生大量替换字符，还可能被误认为有效正文。

解析器选择与解析器版本一起写入 Source。将来替换库或算法后，新候选版本可以和旧活动版本并存验证，不能直接覆盖线上 Chunk。
## 纯文本也存在编码和边界

Markdown、TXT、LOG、CSV 看似简单，至少要处理 BOM、UTF-8、常见本地编码、CRLF 和最大输出长度。

解码顺序需要固定。全部候选编码失败时，可以用替换模式生成诊断预览，但是否允许入库要看替换比例。大量 `�` 表明字符已经损失，继续切块只会索引乱码。

Markdown 不能先渲染为纯文本再切块，否则标题、列表、代码围栏、链接和表格结构都会丢失。解析中间层保留这些 Block 类型，最终检索文本再按用途规范化。

CSV 若只是普通文本，表头与行关系会消失。能够识别列结构时，应走表格解析；分隔符、引用和换行遵循 CSV 解析器，不能手工 `split(',')`。
## HTML 解析要区分内容与页面噪声

HTML 中的 `script`、`style`、`noscript` 和模板内容通常不进入知识正文。标题、段落、列表、代码和表格按 DOM 顺序提取，嵌套表格内部节点避免重复。

链接需要同时保留锚文本和规范化 URL，后续引用或抓取才能回到来源。隐藏元素、导航、页脚和 Cookie 文案是否去除，取决于抓取器是否提供正文定位；通用解析器不要凭少数 class 名硬编码所有站点。

HTML 里的文字仍是不可信数据。删除脚本标签不能消除正文提示注入，风险标签继续进入 Source。远程页面的 Final URL、抓取时间和内容哈希也要保存。

将表格直接 `get_text(' ')` 会把行列压成一句话。解析器要输出矩形行数组或标准 Markdown 表格，同时记录表格数量和原 DOM 位置。
## PDF 的文本层为什么最难

PDF 描述页面上的绘制指令，不天然包含“段落”与“阅读顺序”。常见问题包括：

```text
双栏文本交错
页眉页脚重复进入每页
连字符断词
字体编码导致乱码
标题只通过字号表现
表格只有坐标，没有单元格语义
扫描页完全没有文本层
```

解析器逐页保留 Page Marker，再提取文本 Block 与坐标。标题识别可以参考字号相对正文的比例，并限制标题长度；它是启发式结果，出现异常层级时记录 Warning。

表格检测失败不一定使整页失败。正文可用时记录 `table_detection_failed:page`，让质量门禁判断该文档是否允许激活。用户查询高度依赖表格时，这类 Warning 可以升级为阻断。

页眉页脚去重需要比较跨页重复位置和文本，不能简单删除每页第一行。合同编号或章节标题也可能位于页眉，删除策略要通过保留率测试。
## 怎样识别真正需要 OCR 的页面

页面无文本不一定需要 OCR。纯空白页可以忽略，有图片且文本层为空更像扫描页。可以使用这些信号：

```text
extracted_text_is_empty
page_has_images
text_character_count_below_threshold
rendered_page_ink_ratio
```

初始版本使用“无文本且含图片”作为保守条件，误报容易解释。阈值算法需要在扫描件、图表页、签章页和空白页样本上评测。

解析结果先写 `ocr_required_pages=[2, 5]`，不在普通解析器内部静默调用远程视觉模型。上层 Parser Service 根据配置、页面数上限和预算决定是否执行 OCR。
## OCR 应按页执行并保持位置

OCR 流程如下：

```mermaid
flowchart LR
    A[检测需 OCR 页面] --> B[按受限 DPI 渲染]
    B --> C[逐页 OCR]
    C --> D[空结果与页数门禁]
    D --> E[插回对应 Page Marker]
    E --> F[更新警告与解析器版本]
```

渲染 DPI 过低会损失小字，过高会增加像素、内存、延迟和费用。服务设置最低与最高范围，并在入库策略中版本化。页面数超过上限时失败关闭或转人工，不能只 OCR 前几页后宣称文档完整。

每页 OCR 返回空文本时，该页仍然缺失。系统应产生明确错误，不能删除 `ocr_required_pages` 警告后继续。OCR 成功后把文本插入原页标题下，保留页码用于 Citation。

`parser_version` 增加 OCR 适配器与版本，例如 `structured-v2+ocr-v3`。重建时可以判断内容差异来自基础解析器还是 OCR 模型。

真实 OCR 客户端可能限流、超时或返回内容安全错误。重试受总 Deadline 和页面幂等身份限制，已经成功页面可以缓存，但缓存键要绑定图片哈希、DPI、模型和 OCR Prompt 版本。
## 为什么 OCR 不可用时要失败关闭

一份十页 PDF 有九页文本层，关键审批表在扫描的第十页。忽略 OCR 警告继续入库，检索会稳定返回一个不完整版本，用户很难知道缺的正是关键页。

**Fail Closed（失败关闭）** 表示必需页面没有获得文本时，候选版本不激活。旧活动版本继续服务，新版本状态记录 `ocr_required` 或 `ocr_failed`。

并非所有图片都必须 OCR。装饰图、Logo 和无文字截图可以作为 Warning。判断标准与知识库用途相关，政策要能按文件类型和范围配置。

关闭 OCR 功能时，接口应明确列出需要处理的页码，而不是返回通用“解析失败”。用户可以启用 OCR、替换可搜索 PDF 或删除扫描页后重试。
## Word 解析要保留样式语义

DOCX 段落的 Heading 样式可以映射为标题层级，List 样式映射为列表，普通段落保留顺序。表格按文档内部出现位置输出，不能先提取所有段落再把表格统一放到末尾。

文本框、页眉页脚、批注、修订、脚注和嵌入对象需要明确支持矩阵。未支持的元素记录 Warning，不能让用户误以为完整保留。

嵌入图片没有 OCR 时记录数量与未处理状态。Word 中大量知识可能在截图或流程图里，这项 Warning 对质量评估很重要。

重复合并单元格会让表格行出现相同文本，结构化表格模型要保存原始坐标或合并信息，后续再决定去重。
## Spreadsheet 需要决定公式与显示值

XLSX 的单元格可能包含公式、缓存结果、日期、错误和空值。`data_only=false` 读取公式，`data_only=true` 读取保存时缓存的计算值，两者解决不同问题。

用于知识检索时，可以保存结构化字段：

```text
sheet_name
row_index
column_name
formula
cached_value
display_value
```

若解析器只选一种表示，必须写入版本和文档说明。缓存值可能过期，服务端也未必具备 Excel 公式计算引擎。

每个 Sheet 作为独立章节，首个有效行可作为表头。超大工作簿设置行列上限并记录具体 Sheet 的截断 Warning。截断发生时，候选版本是否激活由质量政策决定。

空尾列可以裁掉，内部空列不能删除，否则字段位置会错位。行宽标准化到最大列数，重复表头和多级表头交给后续表格 Block 处理。
## PPTX 的阅读顺序来自布局

幻灯片中的 Shape 顺序不一定等于视觉顺序。可以按 `top, left` 坐标排序，先保存 Slide Marker 和标题，再处理正文、表格和图片。

这种排序对多栏布局仍可能错误。复杂页面记录布局 Warning，必要时使用视觉模型生成辅助描述，但视觉描述属于派生内容，不能覆盖原始文本。

演讲者备注、隐藏页和母版文字是否解析，要按产品场景选择。默认策略应明确，避免同一文件在不同版本中无故增减内容。

图片计数和未 OCR 状态写入结构化元数据。流程图里的箭头关系无法靠普通 OCR 完整还原，需要后续多模态解析与人工核验。
## 解析上限与截断必须可见

为了保护服务，解析器通常限制最大输出字符、Sheet 行列、PDF 页数、OCR 页数和嵌入对象。达到上限时不能只做字符串截断。

字符串截断可能切断代码围栏、表格行或多字节字符的语义单元。更稳妥的方式是按 Block 边界停止，保存 `truncated_at`、已处理数量和总量估计。

解析警告进入候选版本 Coverage Manifest。关键单位保留率不足时，不生成 Embedding 或不激活 Release。这样服务保护和知识完整性同时可见。
## Parser 测试要以结构保真为目标

测试夹具应覆盖：

| 格式 | 关键断言 |
| --- | --- |
| Markdown | 标题、列表、代码、链接和表格顺序 |
| HTML | 噪声标签移除，嵌套表格不重复 |
| PDF | 页码、标题、双栏、表格与扫描页标记 |
| DOCX | Heading、段落与表格交错顺序 |
| XLSX | Sheet、空列、公式、日期和截断 |
| PPTX | Slide、Shape 顺序、表格和图片警告 |
| OCR | 指定页插回原位置，空结果失败 |
| 损坏容器 | 明确 Error，不产生候选内容 |

单元测试使用固定小文件和 Fake OCR 验证路由、页码与错误处理。Fake 返回脚本文字，只能证明本地合并逻辑，不能证明真实视觉模型识别率、限流或隐私政策。

真实集成测试记录解析库、OCR 模型、DPI 和时间，使用隔离凭证与无敏感样本。Parser 升级时对黄金文件生成 Block 与 Coverage Diff，检查内容保留、顺序、警告和引用位置。

可用的解析结果应回答：哪些内容被识别，来自原文件哪个位置，哪些结构被保留，哪些部分仍然缺失。下一步 Block 文档模型正是把这些差异固定成统一结构，让 Chunker 不再面对一段失去来源的长字符串。
