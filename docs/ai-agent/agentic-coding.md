# 编码 Agent 怎样从仓库证据走到验证结果

编码 Agent 的任务不是生成一段看起来合理的代码，而是在真实仓库约束下定位问题、修改最小范围、运行验证并交付可审查差异。仓库文件和命令输出是它的主要证据。

## 先读取约束和当前状态

Agent 识别仓库规则、语言、构建命令、目标文件和未提交差异。现有变更默认属于用户，不能为了让补丁干净而重置。

问题描述与代码现状不一致时，以可复现行为和源码为依据，记录假设。

## 定位从调用链和测试开始

使用搜索找到符号、消费者和已有测试，沿输入、状态、输出定位责任层。避免针对错误消息加局部关键词特判。

修复计划说明修改边界和验证方式，不把大范围重构伪装成必要步骤。

## 执行工具受工作区权限限制

文件写入只发生在目标仓库，命令使用允许的工作目录，网络和秘密按需开放。删除、迁移和生产操作需要额外授权。

命令输出视为证据，但只有真实执行成功才能写“测试通过”。

## 验证与风险相匹配

先跑相关测试，再按影响面运行类型检查、构建或集成测试。失败区分代码回归、环境缺失和已有基线问题，不能未验证就归因。

前端交互还需要浏览器检查，截图放临时目录并清理。

## 交付包含差异与剩余风险

最终说明改了什么、验证了什么、哪些检查无法运行。提交、推送和部署是独立权限，不由“实现完成”自动授权。

优秀 Harness 让 Agent 能读取证据和运行测试，同时阻止它越过仓库与生产边界。
