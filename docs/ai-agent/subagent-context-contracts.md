# SubAgent 的上下文隔离与任务契约

父 Agent 正在修改一个仓库，同时需要一个子 Agent 只核对测试失败。若把完整 Prompt、所有文件和全部工具都复制过去，子 Agent 可能改动无关文件，也可能把父任务中的旧假设当成当前事实。**SubAgent** 的关键不是“再开一个模型”，而是把一个窄目标、窄上下文、窄工具集和明确输出合同交给独立执行单元，并在合并前重新检查父快照。

上下文隔离的边界必须可执行：允许哪些 `context_refs`，能读哪些文件，能调用哪些工具，结果要返回哪些 Evidence，父任务取消时怎样收尾。子 Agent 可以提出结论和改动候选，但身份、权限、活动版本、Deadline 和文件所有权由 Runtime 注入并校验。这样既减少无关 Token，也避免把父任务的控制权隐式传给子任务。

::: info 贯穿示例

父 Agent 把“确认 `test_agent_runtime.py` 中的权限回归，不能修改生产代码”交给子 Agent。契约只包含相关测试文件、失败日志引用、只读搜索工具、活动代码版本和 90 秒 Deadline。子 Agent 返回四项：结论、Evidence ID、建议改动（本例应为空）和未完成项。父 Agent 合并前检查这些字段是否仍对应同一个版本。

:::

实现 子任务隔离时，代码顺序应与状态顺序一致：入口拒绝不会调用依赖，正常分支保存文件所有权，错误分支返回稳定类型，测试分别断言调用次数、参数、输出和清理结果。

## 为什么要隔离子任务上下文

在 SubAgent 流程中，入口先固定可信范围；缺少来源时直接结束当前路径，不能让模型补字段继续推进。

子任务重叠会破坏子任务 ID 与带来源的子结果之间的对应关系，排查时先保留原始输入摘要和发生阶段，再判断是否允许重试。

上下文过宽影响上下文清单或下游解释，不能和子任务重叠共用“重新调用一次模型”的处理方式。

## SubAgent 与 Handoff、DAG 和普通线程的边界

在 SubAgent 中，运行时持有全局预算和依赖状态，局部执行单元只能修改合同允许的那部分。因此子任务 ID 与上下文清单要有唯一写入方，其他组件只能通过版本化命令申请修改。

线程与 子任务隔离解决的问题相邻，但控制权不同，比较时要看谁选择并行取证、谁保存子任务 ID、谁确认带来源的子结果。

进程可以参与同一请求，却不能替代 子任务隔离；组合后仍要单独检查子任务契约的可信来源和子任务重叠的终止规则。

子任务隔离使用的身份、范围和版本来自可信运行时，父目标可以表达意图，但不能提升权限或改写活动 Release。

上下文过宽发生时，错误回到上下文清单的所有者处理，上游缺输入、当前组件违反不变量和下游不可用分别形成不同终态。

子任务隔离的确定性边界位于子任务 ID 写入之前。模型在 SubAgent 中只提交候选值，程序仍要从认证、版本和策略快照补入可信字段。

子任务隔离内部可以使用更细的临时对象，跨边界只暴露稳定协议。替换线程时，调用方不需要理解内部缓存和 SDK 响应。

## 任务契约怎样限制输入和输出

子任务隔离的输入合同至少列出父目标、子任务契约和依赖图，每项都注明来源、是否必需、允许的缺省值，以及缺失后是在入口拒绝还是进入降级路径。

SubAgent 契约要分别描述子任务身份、上下文清单、文件所有权和父任务版本。上下文清单限定它能读什么，所有权限定它能写什么，父版本用于合并前检查冲突；缺少任何一项，隔离就只停留在 Prompt 约定。

并发分支按稳定身份合并文件所有权，完成顺序只反映耗时，不能决定结果属于哪个请求，更不能让迟到的旧状态覆盖新修订。

SubAgent 对外结果要分别表达可交付内容、缺口、取消和未知状态，调用方不必解析错误文案。

上下文清单参与乐观并发检查；处理开始后若版本变化，旧候选只保留作审计，不能继续写入子任务 ID。

若 SubAgent 收到模型代填的身份、范围或版本，应用会丢弃这些值并从可信上下文重新装配。

子任务身份、来源、工作区版本、覆盖缺口、冲突和合并裁决组成 子任务隔离的最小追踪材料，日志只保存稳定 ID、版本和错误类，完整 Prompt、文档正文与凭证不进入指标标签。

撤回 SubAgent 的来源或任务时，相关候选按版本失效，稳定 ID 只保留审计关系。

契约还需要描述新鲜度。上下文清单对应的数据发生变化后，旧缓存、旧候选和未完成任务怎样失效，应由版本或时间规则直接判断，不能依赖模型注意到矛盾。

删除和撤回也属于数据生命周期。子任务隔离引用的原始对象被移除时，稳定 ID 可以保留审计关系，正文与派生结果则按策略失效，避免继续向用户展示过期内容。

::: warning 子任务隔离的可信边界

带来源的子结果通过结构校验后仍是候选。子任务隔离使用的身份、权限、知识版本与业务事实由应用从可信服务读取，核对完成后才能执行或交付。

:::

## 从父快照到可合并结果

子任务隔离要用一个越权样本验证：父 Agent 只提供目标文件和必要资料，子任务尝试读取范围外内容时被拒绝，返回结果带结论、证据、改动和未完成项。父任务合并前再次检查上下文清单与工作区版本。

一个可审查的子任务合同可以写成下面的结构：

```json
{
  "task_id": "test-review:17",
  "parent_snapshot": "turn:42@revision:8",
  "context_refs": ["file:test_agent_runtime.py", "log:run-17"],
  "allowed_tools": ["read_file", "run_test"],
  "write_scope": [],
  "deadline_at": "2026-08-17T12:00:00Z",
  "return_when": "每个失败都绑定日志位置，无法判断时返回 unknown"
}
```

`context_refs` 是引用，不是把父上下文全文复制一份。装配器读取引用时重新检查权限和版本，超过预算时优先保留失败日志和测试配置，丢弃无关聊天历史。`write_scope` 为空意味着本任务只能观察；如果允许修改，应该列出精确文件或命名空间，而不是给一个宽泛的仓库写权限。

输出也要固定形状：`conclusion` 说明判断，`evidence_ids` 指向日志或代码位置，`changes` 列出实际差异，`unresolved` 列出没有完成的项。父 Agent 只合并通过版本检查的字段，不能把子 Agent 的自然语言摘要直接当成新的系统指令。

拆分问题接收父目标并建立子任务 ID，入口校验未通过就地结束，后续模型、检索器或工具调用次数保持为零。

分派 SubAgent 的子任务时，身份、范围、配置版本和绝对 Deadline 一次冻结，后续只继承剩余时间。

并行取证读取上下文清单并执行主题逻辑，参数由应用组装，外部返回先保存为缺口清单，尚未获得修改领域状态的资格。

处理冲突检查结构、范围、版本和主题不变量；带来源的子结果缺少来源、落在旧版本或越过权限时，子任务 ID 停在 rejected 或 failed。

汇合 SubAgent 结果时先保存来源和终止原因，再发送事件；核心状态未写入就不能宣称完成。

并行 SubAgent 分支只完成一部分时，程序按任务合同选择保留、补偿或整体丢弃，并列出未完成项。

实现可以使用函数、Graph、Middleware 或 Workflow，子任务 ID 的所有权和子任务重叠的停止规则不会随框架改变。

部分成功需要在步骤边界处理。当 SubAgent 已经产生部分候选，先记录哪些可重建、哪些有外部副作用，再决定重试或补偿。

SubAgent 的并行和冲突处理都要记录逆向动作；可重建结果可以重算，已发送命令只能查回执或补偿。

## 用父状态变化推演一次子任务

沿“子任务隔离场景：研究任务需要同时核对协议规范、实现约束和测试证据，三个分支完成时间不同且可能给出冲突结论”推演 子任务隔离：入口创建 request_id，读取可信身份，把父目标和当前版本写入初始状态。

拆分问题生成子任务 ID 与输入摘要；若子任务契约缺失，请求返回 rejected，并指出缺少哪项材料，不继续消耗模型或外部服务配额。

启动 SubAgent 分支前冻结 Scope、Release、Policy 和 Deadline，正文中的同名字段不能覆盖运行时快照。

并行取证按“父 Agent 按文件或问题边界下发窄契约，只提供必要上下文和只需的工具；子结果包含结论、证据、改动和未完成项”推进，每次依赖调用保存 call_id、参数摘要、开始时间与状态版本，以便判断超时前是否已经产生结果。

SubAgent 的候选必须带来源、范围和版本，校验通过后才进入下一状态。

汇合结果写入终态；客户端断开只影响交付通道，重新连接时读取已经保存的子任务 ID 或事件游标，不重跑核心逻辑。

故障注入选择两个分支修改同一文件，程序保留原候选和错误位置，只重做冲突边界，不能从入口复制整个任务并产生第二份状态。另一个故障是父 Agent 在子任务完成后发布了新版本：子结果仍可作为审计证据保存，但合并器必须返回 `stale_parent_snapshot`，要求重新读取父快照。

推演结束后用 request_id 关联子任务 ID、带来源的子结果与终止原因，测试据此排除并发请求串线，并确认失败路径没有遗留未关闭资源。

子任务隔离在输入拒绝时不调用依赖，正常路径按 5 个阶段推进，有限修复只重做失败边界。调用次数是控制流断言，不是性能宣传。

子任务隔离的最终记录用 request_id 关联子任务 ID、带来源的子结果和失败问题，测试据此证明结果来自本次执行，没有混入并发请求。

## 合并前怎样确认结果仍然有效

子任务隔离正常完成时，子任务 ID、上下文清单和带来源的子结果指向同一次执行，重复读取返回同一终态，未完成分支已经取消或有明确所有者。

子任务身份、来源、工作区版本、覆盖缺口、冲突和合并裁决用于还原 子任务隔离的处理过程，可以按阶段和版本聚合；敏感正文留在受控存储中，不复制到日志与指标。

SubAgent 可以返回空结果，但必须同时说明范围、版本和原因；要求命中材料时，空结果应进入拒答。

依赖返回成功状态只证明传输完成。子任务隔离还要检查带来源的子结果是否满足业务范围、质量阈值和当前版本，明确拒绝也可能是正确终态。

SubAgent 的分支按稳定身份合并，完成顺序只代表耗时，迟到结果不能覆盖新修订。

子任务 ID 的状态迁移必须单调：完成不能退回运行中，取消不能被迟到结果覆盖，失败重试也不能绕过入口已经固定的权限。

子任务隔离的成功证据最终要同时回答输入是什么、执行了哪些步骤、交付了什么以及为什么停止；任一项缺失都应留在未确认状态。

子任务隔离把业务验收与服务健康分开。依赖对 SubAgent 返回 200 只说明传输完成，内容仍要满足当前范围和质量条件。

子任务隔离的观测指标按阶段和版本聚合。评估 SubAgent 时，把错误、空结果、拒绝、恢复和资源消耗分开统计，避免一个成功率掩盖不同故障。

## 上下文过宽、冲突和取消

子任务失败需要由父任务按证据处理：输入范围不合法时拒绝创建，读取依赖超时时缩小任务或回退，文件冲突时暂停合并，结果缺少必需字段时要求补交。父任务不能把子任务的权限扩大后再次运行。

遇到子任务重叠时，先记录发生阶段、错误类别和责任对象。子任务隔离保留输入摘要和状态版本，由对应组件决定重试、降级或终止。

遇到上下文过宽时，先记录发生阶段、错误类别和责任对象。子任务隔离保留输入摘要和状态版本，由对应组件决定重试、降级或终止。

遇到两个分支修改同一文件时，先记录发生阶段、错误类别和责任对象。子任务隔离保留输入摘要和状态版本，由对应组件决定重试、降级或终止。

遇到结果没有证据时，先记录发生阶段、错误类别和责任对象。子任务隔离保留输入摘要和状态版本，由对应组件决定重试、降级或终止。

遇到子任务完成后父状态已变化时，先记录发生阶段、错误类别和责任对象。子任务隔离保留输入摘要和状态版本，由对应组件决定重试、降级或终止。

子任务隔离将终态、可重试性和资源清理结果写入记录；后台扫描器根据子任务 ID 判断任务是在运行、等待恢复还是已失败。

子任务隔离执行前固定 Deadline、动作上限、重复签名、无进展阈值、预算和取消信号；任一条件触发，并行取证停止创建新工作。

子任务隔离把重试时间和次数计入总预算。SubAgent 每次重试先扣减剩余额度，达到上限就保留原始错误。

子任务隔离的清理动作设计成幂等操作；仍被活动任务或 Lease 引用的资源拒绝删除。

## 用测试验证隔离边界

用可重复的依赖图模拟完成、超时与取消，核对每份结果的任务 ID、来源、预算和合并裁决；测试显式给出父目标、初始子任务 ID、预期带来源的子结果和终止原因，不能只断言返回值非空。

子任务隔离的单元测试用 Fake Adapter 固定带来源的子结果与错误，断言参数、调用顺序、状态修订和清理动作，这些结果只证明本地控制逻辑。

契约测试围绕父目标、子任务 ID 和缺口清单构造合法与非法样本，Schema 解析成功后继续检查权限、版本与领域不变量。

故障测试注入子任务重叠和上下文过宽，记录并行取证是否被调用、子任务 ID 是否改变、资源是否释放，以及同一身份重试会不会重复执行。

在 SubAgent 的外部调用前后终止进程，可以区分重新领取、查询回执和只重放交付三种恢复边界。

子任务隔离的集成测试连接真实协议与隔离存储，检查序列化、约束、并发和超时；需要在线服务时另行记录服务版本、时间、配置与凭证条件。

子任务隔离的回归报告要保留失败类型分布。在 SubAgent 的回归中，拒绝、超时、权限错误和空结果必须保持各自类型，状态变化本身就是行为契约。

子任务隔离的性质测试随机改变子任务 ID 顺序、重复提交、完成顺序或状态版本，断言权限不扩大、终态不倒退、同一身份不产生两次副作用。

SubAgent 的离线评测关注质量变化，运行时测试关注控制和恢复，两类证据都齐全才可交付。SubAgent 只有两类证据都存在，才能同时回答“结果是否合格”和“系统是否安全完成”。

## 并发、预算与恢复取舍

子任务合同把父快照、允许读取的来源、可写范围和返回 Schema 绑定为一个版本。合同升级时，已运行的子任务沿旧版本完成，新任务才获得新的字段和权限。

子任务隔离的容量主要受分支数量、来源抓取、共享工作区冲突、综合调用和截止时间影响，并发可能缩短单次等待，也会占用连接、配额、内存和下游吞吐，必须沿拆分问题、分派窄任务、并行取证、处理冲突、汇合结果逐层核算。

子任务隔离的候选版本在固定样本上比较正确性、错误类型、延迟和资源消耗，子任务重叠等安全红线回归时直接停止发布，不能用平均质量抵消。

子任务重叠的降级路径在发布前写好，可以减少非关键增强、返回已经确认的带来源的子结果，或明确暂时无法确认，缺失事实不能交给模型补写。

排查隔离问题时，先用 `request_id` 找子任务身份、父快照、工作区版本、读取来源、差异和合并裁决，再决定撤销写入还是重新派发。没有父快照就不能判断差异是否越界。

子任务隔离的数据按证据用途分级保留，聚合字段可以留得更久，父目标和大体积带来源的子结果设置短期限、访问控制与删除通道。

子任务隔离先在单进程实现子任务 ID、超时、错误和测试，只有恢复与容量证据提出要求时，再增加队列、Lease、分布式缓存或工作流引擎。

子任务隔离的监控阈值要对应可执行动作。SubAgent 的分支、依赖、上下文和预算接近上限时，应限流或缩小候选；告警本身不会停止正在运行的任务。

回滚要覆盖代码之外的状态。子任务隔离若改变 Schema、缓存键或持久化记录，旧版本是否还能读取新写入数据必须提前验证；无法双向兼容时采用候选版本隔离。

## 什么时候退回单 Agent

采用 子任务隔离前先画出父目标到带来源的子结果的最小控制图；固定函数已经能完成任务时，新增模型决策和跨进程子任务 ID 只会扩大测试与运维范围。

线程主要保持对话连续性，子任务隔离还要限制可见上下文和写入范围。父任务决定下一步和是否合并，子任务只对自己的结果与来源负责。

进程可以与 子任务隔离组合，但外部知识仍需授权，工具调用仍需校验，模型产生的带来源的子结果仍停留在候选状态。

子任务隔离适合价值足够、子任务重叠可观察且预算可接受的任务，高风险、不可逆的决定需要确定性规则或人工批准。

执行期间修改上下文清单可以检验并发设计，旧动作若仍能覆盖子任务 ID，说明版本或 Lease 有缺口，增加 Prompt 规则无法修复这类竞态。

子任务隔离增加了子任务 ID、依赖调用、恢复责任和故障面，设计记录既要说明获得的能力，也要列出新增的退出、降级与回滚路径。

## 子任务合并的并发自测

用“父任务拆出一个只读调查子任务”做自测时，入口先记录输入摘要、身份和执行版本。父快照、引用范围、写入范围和合并修订由唯一组件写入，其他组件只能提交带修订号的候选。在“父任务拆出一个只读调查子任务”里，读者可以从任务 ID 找到它经过的节点，不必靠最终文案猜过程。

针对“父任务拆出一个只读调查子任务”，正常路径从准入开始，先检查范围和资源，再创建一次调用。调用结果带稳定 ID、来源和终止原因，父任务先修改同一文件或子任务越界读取分别记录。针对“父快照、引用范围、写入范围和合并修订”，输出进入下一节点前还要确认版本和权限，空结果也要说明范围。

在“父任务拆出一个只读调查子任务”的故障测试中，依赖调用前和结果已经产生但状态尚未提交时各切断一次。前者应没有外部调用，后者要留下可重放的未知状态。恢复使用同一幂等键，先查询外部回执，再决定补偿。

“父任务拆出一个只读调查子任务”的验证命令检查输入、状态变化、调用顺序、输出摘要、失败证据和资源清理。迟到结果进入冲突，不直接覆盖父状态。

“父任务拆出一个只读调查子任务”的取舍需要写在结果里：扩大缓存、并行或自动修复可能缩短等待，也会增加状态、成本和失败组合；保持较小能力面则更容易做权限隔离和人工接管。

回放“父任务拆出一个只读调查子任务”时改变输入顺序、重复提交、缩短 Deadline 或撤回权限，确认状态单调、范围不扩大、资源按时释放。指标用于定位变化，不替代事实核验。

## 父任务拆出一个只读调查子任务的边界案例

在“父任务拆出一个只读调查子任务”中，入口收到的资料可能不完整，程序先保存缺口和当前版本，不能让模型用常识填入 父快照、引用范围、写入范围和合并修订。“父任务拆出一个只读调查子任务”的输入后来补齐时，新的执行沿同一个任务 ID 继续；已经结束的失败记录不被覆盖。

父任务先修改同一文件时保留两个快照的共同祖先，越界读取时记录被拒绝的来源和规则。未派发、执行失败、执行完成但没有差异、结果尚未合并分别进入不同状态，迟到结果不能覆盖新的父修订。

“父任务拆出一个只读调查子任务”的正常输出先经过范围、版本和权限检查，再进入交付或下一个节点。迟到结果进入冲突，不直接覆盖父状态。“父任务拆出一个只读调查子任务”的输出只满足结构而没有可验证来源时，状态保持为候选，前端应显示缺口而不是成功标记。

用重复提交、并发完成、取消和进程退出四个样本回归。回归“父任务拆出一个只读调查子任务”时，检查同一幂等键是否只产生一个有效终态，迟到事件是否被拒绝，临时资源是否释放，重新连接是否能读到同一份事件。

“父任务拆出一个只读调查子任务”这组检查的结果应带命令、解释器或服务版本、输入摘要和退出码。“父任务拆出一个只读调查子任务”没有运行证据时，只能写“待验证”；离线替身通过也不能推导真实模型、网络服务或生产权限已经通过。
