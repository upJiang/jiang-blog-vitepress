# Agent Eval 怎样覆盖检索、回答与运行时

用固定用例同时检查范围、召回、引用、拒答、终态、恢复和语义判定不可用。**Agent Eval**、**Regression**、**Quality Gate** 分别指向同一条执行链上的不同对象：Claim、Evidence、引用位置、身份范围、策略版本、工具动作和验证报告进入系统，suite、case、fixture version、trace、deterministic assertions、semantic score 和 regression result 保存处理中间状态，最终得到可交付答案、带原因的拒答、待审批动作、违规记录或回滚决定。

Agent Eval 覆盖检索、回答与运行时位于候选答案与外部动作进入可信业务结果之前的证据、安全和治理层，主要机制是评测用例固定输入、身份、知识 Release 和 Policy，分别断言路由、检索、引用、答案、拒答、终态、恢复和成本；语义评分不能替代确定性不变量。只测最终文本、评测数据随生产变化、Judge 偏差、权限用例缺失、失败无法重放和平均分掩盖红线会让链路在不同位置停止，错误记录必须保留发生阶段、当时的状态和终止原因。

::: info 贯穿示例

Agent Eval 覆盖检索、回答与运行时场景：模型生成了看似完整的权限解释，但其中一条结论只引用了当前用户不可见的内部记录。Agent Eval 覆盖检索、回答与运行时需要的身份、权限、版本和业务事实由应用提供，模型与外部内容只产生候选。

:::

这次推演用 Claim、Evidence、引用坐标、策略版本、验证问题和拒答原因把请求和终态关联起来。与单元测试、RAG Eval、LLM Judge、回归门禁和在线监控比较时，重点看输入来源、状态所有者、下一步的决策者和失败终点。

Agent Eval 覆盖检索、回答与运行时的执行顺序是“拆分主张 → 绑定证据 → 执行规则检查 → 有限修复 → 交付或拒绝”。Claim 从入口进入，suite 记录进度，可交付答案通过当前主题的校验条件后才会交付。

只测最终文本与评测数据随生产变化会产生不同证据。前者先检查 suite 和输入来源，后者沿调用记录定位依赖或状态冲突；不区分发生位置，重试会掩盖原始原因。

Agent Eval 覆盖检索、回答与运行时与单元测试的共同点不代表它们可以互换。当前主题拥有 case，相邻组件只通过契约读取或提交候选，不能直接修改这个状态。

实现 Agent Eval 覆盖检索、回答与运行时时，代码顺序应与状态顺序一致：入口拒绝不会调用依赖，正常分支保存 fixture version，错误分支返回稳定类型，测试分别断言调用次数、参数、输出和清理结果。

## 可信问题从哪一条候选开始

用固定用例同时检查范围、召回、引用、拒答、终态、恢复和语义判定不可用。在“Agent Eval 覆盖检索、回答与运行时场景：模型生成了看似完整的权限解释，但其中一条结论只引用了当前用户不可见的内部记录”这类任务里，Agent Eval 覆盖检索、回答与运行时负责把 Claim 带入处理链，并明确可交付答案可以交付的条件。

Agent Eval 覆盖检索、回答与运行时位于候选答案与外部动作进入可信业务结果之前的证据、安全和治理层。它处理评测用例固定输入、身份、知识 Release 和 Policy，分别断言路由、检索、引用、答案、拒答、终态、恢复和成本；语义评分不能替代确定性不变量，身份认证、授权结果和最终业务状态仍由应用中的确定性组件负责。

Claim 是这条链路的起点；来源缺失时，程序只能拒绝请求或采用明确记录的默认值，模型补出的字段不能继续驱动绑定证据。

只测最终文本会破坏 suite 与可交付答案之间的对应关系，排查时先保留原始输入摘要和发生阶段，再判断是否允许重试。

评测数据随生产变化影响 case 或下游解释，不能和只测最终文本共用“重新调用一次模型”的处理方式。

Agent Eval 覆盖检索、回答与运行时完成时至少留下 suite、case、可交付答案和检查结论；只有最终文字，无法证明结果来自本次请求。

suite 在单进程 Demo 中可以留在内存，跨进程、带权限或有副作用的任务则要持久化输入、状态转移和停止原因，不能依赖 Prompt 保存状态。

Agent Eval 覆盖检索、回答与运行时还要把业务条件写成状态条件：引用位置何时就绪，可交付答案何时允许交付，只测最终文本发生后是否还能继续。

Agent Eval 覆盖检索、回答与运行时对外区分完成、部分完成和无法确认，三个状态若都包装成可交付答案，上层界面无法采用不同处理方式。

## Agent Eval 覆盖检索、回答与运行时的责任边界

Agent Eval 覆盖检索、回答与运行时接收 Claim、Evidence、引用位置、身份范围、策略版本、工具动作和验证报告，向下游交付可交付答案、带原因的拒答、待审批动作、违规记录或回滚决定，输入与输出之间用明确契约连接，调用方不能把一句含糊目标直接交给底层适配器。

策略与授权层处理确定性边界，验证器判断证据覆盖，模型只能修复候选文本。因此 suite 与 case 要有唯一写入方，其他组件只能通过版本化命令申请修改。

单元测试与 Agent Eval 覆盖检索、回答与运行时解决的问题相邻，但控制权不同，比较时要看谁选择执行规则检查、谁保存 suite、谁确认可交付答案。

RAG Eval 可以参与同一请求，却不能替代 Agent Eval 覆盖检索、回答与运行时；组合后仍要单独检查 Evidence 的可信来源和只测最终文本的终止规则。

fixture version 若只保存在 SDK 对象里，重试或进程退出后就失去解释依据；需要恢复或审计的字段进入持久层，体积较大的可交付答案只保存稳定引用。

Agent Eval 覆盖检索、回答与运行时使用的身份、范围和版本来自可信运行时，Claim 可以表达意图，但不能提升权限或改写活动 Release。

评测数据随生产变化发生时，错误回到 case 的所有者处理，上游缺输入、当前组件违反不变量和下游不可用分别形成不同终态。

Agent Eval 覆盖检索、回答与运行时的确定性边界位于 suite 写入之前。模型可以建议值，应用核对来源和当前版本；涉及权限、金额、发布或不可逆动作时，再进入策略或人工批准。

Agent Eval 覆盖检索、回答与运行时内部可以使用更细的临时对象，跨边界只暴露稳定协议。替换单元测试时，调用方不需要理解内部缓存和 SDK 响应。

## 主张、证据、策略与状态

Agent Eval 覆盖检索、回答与运行时的输入合同至少列出 Claim、Evidence 和引用位置，每项都注明来源、是否必需、允许的缺省值，以及缺失后是在入口拒绝还是进入降级路径。

状态合同中的 suite 表示当前进度，case 保存本次执行依赖的快照，fixture version 关联前后动作，三者不能合并成一段自由文本。

并发分支按稳定身份合并 fixture version，完成顺序只反映耗时，不能决定结果属于哪个请求，更不能让迟到的旧状态覆盖新修订。

输出合同同时描述可交付答案和带原因的拒答，并为拒绝、取消、部分完成和未知状态提供固定形状，调用方据此分支，无需解析错误文案猜测结果。

case 参与乐观并发检查；处理开始后若版本变化，旧候选只保留作审计，不能继续写入 suite。

Claim 里若包含模型填写的同名字段，应用会丢弃它，再从认证、配置或活动版本中补入可信值，因为结构校验通过不等于授权或业务校验通过。

Claim、Evidence、引用坐标、策略版本、验证问题和拒答原因组成 Agent Eval 覆盖检索、回答与运行时的最小追踪材料，日志只保存稳定 ID、版本和错误类，完整 Prompt、文档正文与凭证不进入指标标签。

撤回或删除 Evidence 时，相关缓存、候选和未完成任务按版本失效；稳定 ID 可以保留审计关系，已撤回内容不能继续进入可交付答案。

契约还需要描述新鲜度。case 对应的数据发生变化后，旧缓存、旧候选和未完成任务怎样失效，应由版本或时间规则直接判断，不能依赖模型注意到矛盾。

删除和撤回也属于数据生命周期。Agent Eval 覆盖检索、回答与运行时引用的原始对象被移除时，稳定 ID 可以保留审计关系，正文与派生结果则按策略失效，避免继续向用户展示过期内容。

::: warning Agent Eval 覆盖检索、回答与运行时的可信边界

可交付答案通过结构校验后仍是候选。Agent Eval 覆盖检索、回答与运行时使用的身份、权限、知识版本与业务事实由应用从可信服务读取，核对完成后才能执行或交付。

:::

## 确定性规则和模型判断怎样配合

Agent Eval 覆盖检索、回答与运行时按“评测用例固定输入、身份、知识 Release 和 Policy，分别断言路由、检索、引用、答案、拒答、终态、恢复和成本；语义评分不能替代确定性不变量”推进，这段机制必须落成 suite 和 case 的实际变化，不能只列框架节点名称。

拆分主张接收 Claim 并建立 suite，入口校验未通过就地结束，后续模型、检索器或工具调用次数保持为零。

绑定证据固定身份、范围、配置版本和绝对 Deadline，后续子步骤只继承剩余时间，不能各自重新获得完整超时。

执行规则检查读取 case 并执行主题逻辑，参数由应用组装，外部返回先保存为带原因的拒答，尚未获得修改领域状态的资格。

有限修复检查结构、范围、版本和主题不变量；可交付答案缺少来源、落在旧版本或越过权限时，suite 停在 rejected 或 failed。

交付或拒绝先保存可交付答案与终止原因，再产生事件或通知，交付失败可以重放，核心状态写入失败则不能对外宣称完成。

执行规则检查出现部分结果时，由任务合同决定保留、补偿还是整体丢弃；可交付答案若可重建就重新生成，外部副作用则查询回执或执行补偿。

实现可以使用函数、Graph、Middleware 或 Workflow，suite 的所有权和只测最终文本的停止规则不会随框架改变。

部分成功需要在步骤边界处理。执行规则检查已经产生一部分可交付答案时，程序按任务合同决定保留、补偿或整体丢弃，并记录未完成项，不能默认为全部成功。

执行规则检查和有限修复都要写明逆向动作或不可逆原因，可交付答案若可重建就删除后重算，已发送的外部命令只能查询回执或补偿。

## 沿一条越权结论推演

沿“Agent Eval 覆盖检索、回答与运行时场景：模型生成了看似完整的权限解释，但其中一条结论只引用了当前用户不可见的内部记录”推演 Agent Eval 覆盖检索、回答与运行时：入口创建 request_id，读取可信身份，把 Claim 和当前版本写入初始状态。

拆分主张生成 suite 与输入摘要；若 Evidence 缺失，请求返回 rejected，并指出缺少哪项材料，不继续消耗模型或外部服务配额。

绑定证据冻结 scope、release、policy 和 deadline_at，用户或模型在正文中提供的同名值只作为普通内容，不能覆盖这份运行时快照。

执行规则检查按“评测用例固定输入、身份、知识 Release 和 Policy，分别断言路由、检索、引用、答案、拒答、终态、恢复和成本；语义评分不能替代确定性不变量”推进，每次依赖调用保存 call_id、参数摘要、开始时间与状态版本，以便判断超时前是否已经产生结果。

候选结果对应可交付答案、带原因的拒答、待审批动作、违规记录或回滚决定，有限修复逐项检查权限、版本与领域约束，问题列表为空才允许形成下一状态。

交付或拒绝写入终态；客户端断开只影响交付通道，重新连接时读取已经保存的 suite 或事件游标，不重跑核心逻辑。

故障注入选择 Judge 偏差，程序保留原候选和错误位置，只重做失败边界，不能从入口复制整个任务并产生第二份状态。

推演结束后用 request_id 关联 suite、可交付答案与终止原因，测试据此排除并发请求串线，并确认失败路径没有遗留未关闭资源。

Agent Eval 覆盖检索、回答与运行时在输入拒绝时不调用依赖，正常路径按 5 个阶段推进，有限修复只重做失败边界。调用次数是控制流断言，不是性能宣传。

Agent Eval 覆盖检索、回答与运行时的最终记录用 request_id 关联 suite、可交付答案和失败问题，测试据此证明结果来自本次执行，没有混入并发请求。

## 可交付结果要满足什么

Agent Eval 覆盖检索、回答与运行时正常完成时，suite、case 和可交付答案指向同一次执行，重复读取返回同一终态，未完成分支已经取消或有明确所有者。

Claim、Evidence、引用坐标、策略版本、验证问题和拒答原因用于还原 Agent Eval 覆盖检索、回答与运行时的处理过程，可以按阶段和版本聚合；敏感正文留在受控存储中，不复制到日志与指标。

带原因的拒答可能是合法的空结果，但必须带范围、版本和原因；任务明确要求找到材料时，同一个空结果进入拒答而非成功。

依赖返回成功状态只证明传输完成。Agent Eval 覆盖检索、回答与运行时还要检查可交付答案是否满足业务范围、质量阈值和当前版本，明确拒绝也可能是正确终态。

执行规则检查并发完成时，每个分支保留自己的身份和局部预算，有限修复按任务合同接纳可用结果，慢分支不能抹掉已经确认的记录。

suite 的状态迁移必须单调：完成不能退回运行中，取消不能被迟到结果覆盖，失败重试也不能绕过入口已经固定的权限。

Agent Eval 覆盖检索、回答与运行时的成功证据最终要同时回答输入是什么、执行了哪些步骤、交付了什么以及为什么停止；任一项缺失都应留在未确认状态。

Agent Eval 覆盖检索、回答与运行时把业务验收与服务健康分开。依赖返回 200 只说明传输成功，可交付答案仍要满足当前范围和质量要求；明确拒答也可能是正确终态。

Agent Eval 覆盖检索、回答与运行时的观测指标按阶段和版本聚合。错误率、空结果率、拒绝率、恢复次数与资源消耗回答不同问题，不能压成一个成功率。

## 修复上限、拒答与安全终止

Agent Eval 覆盖检索、回答与运行时按输入、状态、依赖、结果和交付五个位置分类错误，发生位置决定恢复动作，不能用同一个重试循环处理全部失败。

遇到只测最终文本时，系统要返回稳定的错误类型、发生阶段和可重试标记。Agent Eval 覆盖检索、回答与运行时保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

遇到评测数据随生产变化时，系统要返回稳定的错误类型、发生阶段和可重试标记。Agent Eval 覆盖检索、回答与运行时保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

遇到 Judge 偏差时，系统要返回稳定的错误类型、发生阶段和可重试标记。Agent Eval 覆盖检索、回答与运行时保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

权限用例缺失触及 Agent Eval 覆盖检索、回答与运行时的安全边界，重试不会使它自动合法；执行路径保存拒绝规则和输入来源，清除未授权候选，并以稳定错误结束当前动作。

Agent Eval 覆盖检索、回答与运行时处理失败无法重放时需要稳定身份和结果回执，再次收到同一请求先读取旧结果；外部结果未知就停在 unknown，不能猜测失败后重新执行。

遇到平均分掩盖红线时，系统要返回稳定的错误类型、发生阶段和可重试标记。Agent Eval 覆盖检索、回答与运行时保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

Agent Eval 覆盖检索、回答与运行时结束错误处理时保存终态、可重试性和资源清理结果，后台扫描器依靠 suite 和这些字段区分仍在运行、等待恢复和已经失败的任务。

Agent Eval 覆盖检索、回答与运行时在执行前写入绝对 Deadline、最大动作数、重复签名、无进展阈值、预算和人工取消信号，任一条件触发后执行规则检查都不再创建新工作。

Agent Eval 覆盖检索、回答与运行时把重试时间和次数计入总预算。依赖连续失败会减少后续额度，达到上限后保留原始错误，不再用模型重新措辞掩盖失败。

Agent Eval 覆盖检索、回答与运行时的清理动作可以重复执行。临时对象、文件句柄、子进程、连接或 Lease 仍被活动任务引用时，清理器必须拒绝删除。

## 红线用例和回归门禁

用可见与不可见证据成对测试，覆盖越权、注入、修复上限、策略回滚和多租户缓存隔离；测试显式给出 Claim、初始 suite、预期可交付答案和终止原因，不能只断言返回值非空。

Agent Eval 覆盖检索、回答与运行时的单元测试用 Fake Adapter 固定可交付答案与错误，断言参数、调用顺序、状态修订和清理动作，这些结果只证明本地控制逻辑。

契约测试围绕 Claim、suite 和带原因的拒答构造合法与非法样本，Schema 解析成功后继续检查权限、版本与领域不变量。

故障测试注入只测最终文本和评测数据随生产变化，记录执行规则检查是否被调用、suite 是否改变、资源是否释放，以及同一身份重试会不会重复执行。

在执行规则检查前后终止进程可以检查恢复边界：调用前退出允许重新领取，外部动作后退出先查回执，交付或拒绝完成后只重放交付。

Agent Eval 覆盖检索、回答与运行时的集成测试连接真实协议与隔离存储，检查序列化、约束、并发和超时；需要在线服务时另行记录服务版本、时间、配置与凭证条件。

Agent Eval 覆盖检索、回答与运行时的回归报告要保留失败类型分布。明确拒绝变成超时、权限错误变成普通空结果，都属于行为回归，即使总通过数没有变化。

Agent Eval 覆盖检索、回答与运行时的性质测试随机改变 suite 顺序、重复提交、完成顺序或状态版本，断言权限不扩大、终态不倒退、同一身份不产生两次副作用。

离线评测关注固定输入下的质量变化，运行时测试关注控制和恢复。Agent Eval 覆盖检索、回答与运行时只有两类证据都存在，才能同时回答“结果是否合格”和“系统是否安全完成”。

## 策略版本、审计与回滚

Agent Eval 覆盖检索、回答与运行时长期运行后，输入 Schema、suite 结构和依赖配置可能独立升级，每次执行固定一组版本，旧记录才能被正确读取或迁移。

Agent Eval 覆盖检索、回答与运行时的容量主要受主张数量、验证调用、修复轮次、审批等待和审计保留期影响，并发可能缩短单次等待，也会占用连接、配额、内存和下游吞吐，必须沿拆分主张、绑定证据、执行规则检查、有限修复、交付或拒绝逐层核算。

Agent Eval 覆盖检索、回答与运行时的候选版本在固定样本上比较正确性、错误类型、延迟和资源消耗，只测最终文本等安全红线回归时直接停止发布，不能用平均质量抵消。

只测最终文本的降级路径在发布前写好，可以减少非关键增强、返回已经确认的可交付答案，或明确暂时无法确认，缺失事实不能交给模型补写。

Agent Eval 覆盖检索、回答与运行时的运行手册从 request_id 定位 Claim、Evidence、引用坐标、策略版本、验证问题和拒答原因，再决定重试、补偿、取消或回滚，无需先展开完整的 Claim。

Agent Eval 覆盖检索、回答与运行时的数据按证据用途分级保留，聚合字段可以留得更久，Claim 和大体积可交付答案设置短期限、访问控制与删除通道。

Agent Eval 覆盖检索、回答与运行时先在单进程实现 suite、超时、错误和测试，只有恢复与容量证据提出要求时，再增加队列、Lease、分布式缓存或工作流引擎。

Agent Eval 覆盖检索、回答与运行时的监控阈值要对应可执行动作。主张数量、验证调用、修复轮次、审批等待和审计保留期中的某项接近上限时，系统可以限流、排队、缩小候选或切换保守路径；只发送告警不会保护正在运行的任务。

回滚要覆盖代码之外的状态。Agent Eval 覆盖检索、回答与运行时若改变 Schema、缓存键或持久化记录，旧版本是否还能读取新写入数据必须提前验证；无法双向兼容时采用候选版本隔离。

## 功能收益不能覆盖哪些风险

采用 Agent Eval 覆盖检索、回答与运行时前先画出 Claim 到可交付答案的最小控制图；固定函数已经能完成任务时，新增模型决策和跨进程 suite 只会扩大测试与运维范围。

Agent Eval 覆盖检索、回答与运行时与单元测试的差别落在控制权：谁选择下一步，谁保存 suite，谁确认可交付答案可信。

RAG Eval 可以与 Agent Eval 覆盖检索、回答与运行时组合，但外部知识仍需授权，工具调用仍需校验，模型产生的可交付答案仍停留在候选状态。

Agent Eval 覆盖检索、回答与运行时适合价值足够、只测最终文本可观察且预算可接受的任务，高风险、不可逆的决定需要确定性规则或人工批准。

格式正确但事实错误的可交付答案是必要反例；若它直接进入成功，说明有限修复缺少业务验证，应保留候选并给出证据问题。

执行期间修改 case 可以检验并发设计，旧动作若仍能覆盖 suite，说明版本或 Lease 有缺口，增加 Prompt 规则无法修复这类竞态。

Agent Eval 覆盖检索、回答与运行时增加了 suite、依赖调用、恢复责任和故障面，设计记录既要说明获得的能力，也要列出新增的退出、降级与回滚路径。

Agent Eval 覆盖检索、回答与运行时从一个调用、一个 suite、一组明确错误和几条确定性测试开始，真实 Trace 证明需要后再加入并发、缓存、队列或更复杂策略。

单元测试只在能处理只测最终文本时引入，不为目录完整强行组合；接口保持可替换，后续需求出现再扩展。
