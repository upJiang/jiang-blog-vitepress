# Debate 模式怎样处理有证据的分歧

Debate 让多个角色对同一问题提出观点并互相质询。它适合证据存在冲突、需要比较解释的任务，不适合用“多说几遍”代替事实查询。

## 先把分歧拆成 Claim 和 Evidence

每个角色输出原子 Claim、支持证据、适用范围和已知反例。若两个角色引用同一段材料，只是换了措辞，并没有形成独立观点。

角色分工可以按来源或审查责任，例如一方检查规则正文，一方检查发布日期，一方检查例外条件，不要只给“支持者”“反对者”的人格提示。

## 质询阶段查漏洞，不增加权限

角色可以指出对方证据不直接、范围不一致或遗漏反例，并申请在原 ACL 内补充检索。它不能读取对方无权访问的隐藏资料，也不能通过辩论扩大知识范围。

质询应返回问题类型和目标 Claim，避免生成大段重复评论。

## 裁决不能只按多数票

多个角色可能由同一模型生成，错误高度相关。裁决器先执行硬规则：证据可见、引用直接、版本一致、没有安全问题；再比较覆盖与冲突。票数只能作为弱信号。

三名角色都支持一个没有证据的结论，结果仍然是不支持。

## 一次冲突处理轨迹

角色 A 从现行规则读到“需要登记”，角色 B 从旧文档读到“无需登记”。裁决器发现 Release 不同，按 Turn 固定版本排除旧证据，并在结果中说明版本差异。

如果两条现行证据确实冲突，系统保留冲突状态并请求人工确认，不让模型选一个听起来更合理的答案。

## 何时停止 Debate

达到轮数、没有新证据、问题集合不再变化或 Deadline 到达时停止。适合 Debate 的是可比较且失败代价允许的分析；确定性权限判断、简单抽取和实时状态查询不需要多角色讨论。

评估 Debate 要看是否发现真实冲突、是否减少不受支持 Claim，以及额外成本是否可接受。
