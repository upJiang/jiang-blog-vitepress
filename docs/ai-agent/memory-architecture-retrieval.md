# Agent 记忆怎样写入、检索和遗忘

长期记忆让以后的一次调用重新获得过去的信息。它不是把聊天记录永久拼进 Prompt，而是一套带来源、范围、有效期和撤回规则的写入与检索系统。

## 先区分短期状态和长期记忆

短期状态服务当前 Turn 或 Conversation，例如当前实体、已执行步骤和未决问题。长期记忆跨会话存在，适合稳定偏好、明确事实和经过确认的工作约定。原始消息是记录，不等于每句话都应该成为记忆。

“这次先看后端日志”属于当前任务状态；“回答默认使用中文”可能是长期偏好；模型猜测的职位或习惯不应写入。

## 写入前需要候选、校验和归属

模型可以抽取记忆候选，程序要检查类型、来源消息、用户范围、敏感级别和是否需要确认。写入时保存稳定 ID、创建时间、有效期与替代关系，不能只保存一句脱离上下文的文本。

冲突记忆不应静默覆盖。新事实可以标记旧记录失效，同时保留变更轨迹；用户撤回后，检索层必须立即排除。

## 检索按当前任务选择少量记忆

检索条件至少包含用户或租户范围、记忆类型和有效状态，再做关键词或向量匹配。候选经过相关性与新鲜度排序，最终只装入能帮助当前问题的部分。

一次轨迹可以是：当前问题识别为“输出偏好” -> 只查偏好类型 -> 找到已确认的中文偏好 -> 装入上下文。若查询的是权限问题，偏好记忆不应参与事实判断。

## 遗忘是产品能力，不是后台清理

记忆需要 TTL、手动删除、来源删除联动和合规清理。删除后还要处理向量索引、结果缓存和派生摘要，避免主表消失而检索仍能召回。

重要业务事实通常应从权威系统实时查询，不靠记忆长期保存副本。账号状态、余额和权限随时会变，记忆只能保存如何查询，不能替代源系统。

## 怎样评估记忆质量

评测集同时包含应该记住、应该忽略、已经过期和需要撤回的样例。检查写入准确率、检索命中、错误注入、跨用户泄漏和删除生效。只测“能不能召回”会鼓励系统保存过多内容。

记忆带来的价值要在具体任务中验证：是否减少重复确认，同时没有增加错误事实和隐私暴露。
