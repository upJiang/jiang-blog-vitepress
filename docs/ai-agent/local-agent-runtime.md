# 本地 Agent 的 Daemon、渠道与人工介入

本地 Agent 的关键不是“常驻”两个字，而是常驻进程怎样管理连接、任务和人工控制。Daemon 保存命名 Agent 与渠道会话，MCP 连接提供能力，Watcher 观察进度，Heartbeat 只证明进程还活着，不能证明任务有进展。人工接管必须成为状态机中的明确转换，而不是在 UI 上加一个停止按钮。

本文沿 `agent_id`、`channel session`、`schedule`、`watcher`、`heartbeat` 和 `takeover` 说明状态归属。多个渠道串上下文、Daemon 重启丢任务、双向能力形成权限环，以及接管后自动继续，都是需要单独验证的失败路径。

::: info 贯穿示例

贯穿示例是一个需要人工接管的本地任务：从聊天渠道收到“整理工作区报告”，Daemon 读取文件并运行脚本，发现脚本要访问未授权目录后暂停，人工确认范围后才继续。

:::

## Daemon 为什么是连接与执行的中间层

多个渠道串上下文会破坏 agent_id 与受控动作之间的对应关系，排查时先保留原始输入摘要和发生阶段，再判断是否允许重试。

Daemon 重启丢任务影响 daemon status 或下游解释，不能和多个渠道串上下文共用“重新调用一次模型”的处理方式。

## 渠道、身份和权限如何进入一次任务

Local Agent 的 Harness 持有工作区、工具和权限，模型只能根据观察提出动作候选。因此 agent_id 与 daemon status 要有唯一写入方，其他组件只能通过版本化命令申请修改。

后台 Agent 与本地 Agent解决的问题相邻，但控制权不同，比较时要看谁选择检查权限、谁保存 agent_id、谁确认受控动作。

MCP 可以参与同一请求，却不能替代本地 Agent；组合后仍要单独检查环境观察的可信来源和多个渠道串上下文的终止规则。

本地 Agent使用的身份、范围和版本来自可信运行时，用户目标可以表达意图，但不能提升权限或改写活动 Release。

Daemon 重启丢任务发生时，错误回到 daemon status 的所有者处理，上游缺输入、当前组件违反不变量和下游不可用分别形成不同终态。

本地 Agent 的确定性边界位于 agent_id 写入之前。模型在 Local Agent 中只提交候选值，程序仍要从认证、版本和策略快照补入可信字段。

本地 Agent内部可以使用更细的临时对象，跨边界只暴露稳定协议。替换后台 Agent 时，调用方不需要理解内部缓存和 SDK 响应。

## 会话、任务和工作区状态怎样分离

本地 Agent 的输入合同至少列出用户目标、环境观察和能力目录，每项都注明来源、是否必需、允许的缺省值，以及缺失后是在入口拒绝还是进入降级路径。

本地 Agent Runtime 要分开管理 `agent_id`、Daemon 状态、渠道会话和工作区版本。身份决定归属，Daemon 状态说明进程是否可接管，渠道会话承载用户交互；任何一项变化都不能靠修改最终摘要来代替。

并发分支按稳定身份合并 channel session，完成顺序只反映耗时，不能决定结果属于哪个请求，更不能让迟到的旧状态覆盖新修订。

Local Agent 的对外结果要分别表达可交付内容、缺口、取消和未知状态，调用方不必解析错误文案。

daemon status 参与乐观并发检查；处理开始后若版本变化，旧候选只保留作审计，不能继续写入 agent_id。

观察版本、动作参数、审批、文件差异、进程结果、截图和测试输出组成本地 Agent 的最小追踪材料，日志只保存稳定 ID、版本和错误类，完整 Prompt、文档正文与凭证不进入指标标签。

契约还需要描述新鲜度。daemon status 对应的数据发生变化后，旧缓存、旧候选和未完成任务怎样失效，应由版本或时间规则直接判断，不能依赖模型注意到矛盾。

删除和撤回也属于数据生命周期。本地 Agent引用的原始对象被移除时，稳定 ID 可以保留审计关系，正文与派生结果则按策略失效，避免继续向用户展示过期内容。

::: warning 本地 Agent 的可信边界

受控动作通过结构校验后仍是候选。本地 Agent使用的身份、权限、知识版本与业务事实由应用从可信服务读取，核对完成后才能执行或交付。

:::

## 断线时任务如何继续或停止

本地 Agent Runtime 的自测应包含一次人工接管：Daemon 创建命名 Agent，渠道产生会话，Heartbeat 证明仍在运行，人工暂停后新工具调用被拒绝，接管者读取同一状态继续处理。恢复不能创建第二个 Agent 身份。

观察环境接收用户目标并建立 agent_id，入口校验未通过就地结束，后续模型、检索器或工具调用次数保持为零。

检查权限读取 daemon status 并执行主题逻辑，参数由应用组装，外部返回先保存为可审查差异，尚未获得修改领域状态的资格。

执行并重新观察检查结构、范围、版本和主题不变量；受控动作缺少来源、落在旧版本或越过权限时，agent_id 停在 rejected 或 failed。

实现可以使用函数、Graph、Middleware 或 Workflow，agent_id 的所有权和多个渠道串上下文的停止规则不会随框架改变。

部分成功需要在步骤边界处理。

## 沿一次文件与终端任务推演

沿“本地 Agent场景：编码助手需要读取仓库、修改一个文件并运行测试，但不能访问工作区之外的路径，也不能在测试失败时宣称完成”推演本地 Agent：入口创建 request_id，读取可信身份，把用户目标和当前版本写入初始状态。

观察环境生成 agent_id 与输入摘要；若环境观察缺失，请求返回 rejected，并指出缺少哪项材料，不继续消耗模型或外部服务配额。

检查权限按“Daemon 管理命名 Agent、渠道会话和本地资源，双向 MCP 提供受控能力；Watcher 与 Heartbeat 观察任务，人工介入可以暂停并接管”推进，每次依赖调用保存 call_id、参数摘要、开始时间与状态版本，以便判断超时前是否已经产生结果。

运行确定性验证写入终态；客户端断开只影响交付通道，重新连接时读取已经保存的 agent_id 或事件游标，不重跑核心逻辑。

故障注入选择双向能力形成权限环，程序保留原候选和错误位置，只重做失败边界，不能从入口复制整个任务并产生第二份状态。

推演结束后用 request_id 关联 agent_id、受控动作与终止原因，测试据此排除并发请求串线，并确认失败路径没有遗留未关闭资源。

本地 Agent在输入拒绝时不调用依赖，正常路径按 5 个阶段推进，有限修复只重做失败边界。调用次数是控制流断言，不是性能宣传。

本地 Agent 的最终记录用 request_id 关联 agent_id、受控动作和失败问题，测试据此证明结果来自本次执行，没有混入并发请求。

## 人工接管前要留下哪些证据

本地 Agent正常完成时，agent_id、daemon status 和受控动作指向同一次执行，重复读取返回同一终态，未完成分支已经取消或有明确所有者。

观察版本、动作参数、审批、文件差异、进程结果、截图和测试输出用于还原本地 Agent 的处理过程，可以按阶段和版本聚合；敏感正文留在受控存储中，不复制到日志与指标。

依赖返回成功状态只证明传输完成。本地 Agent还要检查受控动作是否满足业务范围、质量阈值和当前版本，明确拒绝也可能是正确终态。

agent_id 的状态迁移必须单调：完成不能退回运行中，取消不能被迟到结果覆盖，失败重试也不能绕过入口已经固定的权限。

本地 Agent 的成功证据最终要同时回答输入是什么、执行了哪些步骤、交付了什么以及为什么停止；任一项缺失都应留在未确认状态。

本地 Agent把业务验收与服务健康分开。依赖对 Local Agent 返回 200 只说明传输完成，内容仍要满足当前范围和质量条件。

本地 Agent 的观测指标按阶段和版本聚合。评估 Local Agent 时，把错误、空结果、拒绝、恢复和资源消耗分开统计，避免一个成功率掩盖不同故障。

## 心跳丢失、重复消息与人工介入

本地 Agent 的故障处理要分别看进程、渠道和动作：Heartbeat 消失需要接管或暂停，渠道断开只影响交付，工具回执未知则先查询副作用。把三种情况都重启 Daemon，可能重复执行已经提交的动作。

遇到多个渠道串上下文时，先记录发生阶段、错误类别和责任对象。本地 Agent保留输入摘要和状态版本，由对应组件决定重试、降级或终止。

遇到 Daemon 重启丢任务时，先记录发生阶段、错误类别和责任对象。本地 Agent保留输入摘要和状态版本，由对应组件决定重试、降级或终止。

双向能力形成权限环触及本地 Agent 的安全边界，重试不会使它自动合法；执行路径保存拒绝规则和输入来源，清除未授权候选，并以稳定错误结束当前动作。

遇到 Heartbeat 正常但任务无进展时，先记录发生阶段、错误类别和责任对象。本地 Agent保留输入摘要和状态版本，由对应组件决定重试、降级或终止。

遇到人工接管后自动继续时，先记录发生阶段、错误类别和责任对象。本地 Agent保留输入摘要和状态版本，由对应组件决定重试、降级或终止。

本地 Agent将终态、可重试性和资源清理结果写入记录；后台扫描器根据 agent_id 判断任务是在运行、等待恢复还是已失败。

本地 Agent执行前固定 Deadline、动作上限、重复签名、无进展阈值、预算和取消信号；任一条件触发，检查权限停止创建新工作。

本地 Agent把重试时间和次数计入总预算。Local Agent 每次重试先扣减剩余额度，达到上限就保留原始错误。

本地 Agent 的清理动作设计成幂等操作；仍被活动任务或 Lease 引用的资源拒绝删除。

## 用断线和恢复样本做回放测试

使用隔离工作区和假环境重放观察动作循环，断言越界动作被拒绝、写操作需要审批、验证失败不会标记完成；测试显式给出用户目标、初始 agent_id、预期受控动作和终止原因，不能只断言返回值非空。

本地 Agent 的单元测试用 Fake Adapter 固定受控动作与错误，断言参数、调用顺序、状态修订和清理动作，这些结果只证明本地控制逻辑。

契约测试围绕用户目标、agent_id 和可审查差异构造合法与非法样本，Schema 解析成功后继续检查权限、版本与领域不变量。

故障测试注入多个渠道串上下文和 Daemon 重启丢任务，记录检查权限是否被调用、agent_id 是否改变、资源是否释放，以及同一身份重试会不会重复执行。

本地 Agent 的集成测试连接真实协议与隔离存储，检查序列化、约束、并发和超时；需要在线服务时另行记录服务版本、时间、配置与凭证条件。

本地 Agent 的回归报告要保留失败类型分布。在 Local Agent 的回归中，拒绝、超时、权限错误和空结果必须保持各自类型，状态变化本身就是行为契约。

本地 Agent 的性质测试随机改变 agent_id 顺序、重复提交、完成顺序或状态版本，断言权限不扩大、终态不倒退、同一身份不产生两次副作用。

Local Agent 的离线评测关注质量变化，运行时测试关注控制和恢复，两类证据都齐全才可交付。本地 Agent只有两类证据都存在，才能同时回答“结果是否合格”和“系统是否安全完成”。

## Daemon 的生命周期与容量边界

本地 Runtime 要把 `agent_id`、渠道游标、Lease、工作区策略和事件 Schema 固定到一次执行。Daemon 升级时先验证旧事件能否读取，再允许新进程领取任务，不能让内存结构变化直接丢失恢复点。

本地 Agent 的容量主要受观察体积、工具调用、后台进程、浏览器会话、文件差异和循环步数影响，并发可能缩短单次等待，也会占用连接、配额、内存和下游吞吐，必须沿观察环境、提出动作、检查权限、执行并重新观察、运行确定性验证逐层核算。

本地 Agent 的候选版本在固定样本上比较正确性、错误类型、延迟和资源消耗，多个渠道串上下文等安全红线回归时直接停止发布，不能用平均质量抵消。

多个渠道串上下文的降级路径在发布前写好，可以减少非关键增强、返回已经确认的受控动作，或明确暂时无法确认，缺失事实不能交给模型补写。

进程重启或重复送达时，先用 `request_id` 定位 Turn、事件游标、Lease、动作回执和渠道消息 ID，再判断是否继续、查询外部状态还是交给人工。确认副作用前不重跑同一动作。

本地 Agent 的数据按证据用途分级保留，聚合字段可以留得更久，用户目标和大体积受控动作设置短期限、访问控制与删除通道。

容量检查还要看本地设备的边界。磁盘空间、文件句柄、后台进程和渠道连接任一项接近上限时，Runtime 先暂停领取新 Turn，再保留 Checkpoint 和清理结果；只降低模型温度不能解决资源耗尽。

本地 Agent先在单进程实现 agent_id、超时、错误和测试，只有恢复与容量证据提出要求时，再增加队列、Lease、分布式缓存或工作流引擎。

本地 Agent 的监控阈值要对应可执行动作。Local Agent 的分支、依赖、上下文和预算接近上限时，应限流或缩小候选；告警本身不会停止正在运行的任务。

回滚要覆盖代码之外的状态。本地 Agent若改变 Schema、缓存键或持久化记录，旧版本是否还能读取新写入数据必须提前验证；无法双向兼容时采用候选版本隔离。

## 本地 Runtime 与 Harness、MCP 的边界

采用本地 Agent前先画出用户目标到受控动作的最小控制图；固定函数已经能完成任务时，新增模型决策和跨进程 agent_id 只会扩大测试与运维范围。

本地 Agent 受设备、工作区和渠道状态约束，后台 Agent 更依赖队列与租约。两者都由模型提出候选，但本地策略、Worker 和业务回执分别确认动作是否能继续。

MCP 可以与本地 Agent组合，但外部知识仍需授权，工具调用仍需校验，模型产生的受控动作仍停留在候选状态。

本地 Agent适合价值足够、多个渠道串上下文可观察且预算可接受的任务，高风险、不可逆的决定需要确定性规则或人工批准。

执行期间修改 daemon status 可以检验并发设计，旧动作若仍能覆盖 agent_id，说明版本或 Lease 有缺口，增加 Prompt 规则无法修复这类竞态。

本地 Agent增加了 agent_id、依赖调用、恢复责任和故障面，设计记录既要说明获得的能力，也要列出新增的退出、降级与回滚路径。

## Daemon 负责什么，不能负责什么

本地 Daemon 适合持有连接、调度短任务和转发事件，不适合把所有业务状态放在进程内存。启动时读取配置版本并注册能力，收到渠道消息后创建 Turn，状态写入本地数据库或受控存储，Worker 通过 Lease 执行。Daemon 重启后从未完成 Turn 和事件游标恢复，不能因为内存清空就重新发送消息。

渠道适配器只处理认证、消息格式和重连。它把聊天消息转换为统一输入，把事件转换为渠道允许的文本、卡片或附件。权限、工具参数和用户身份由 Runtime 重新确认，不能信任渠道传来的昵称或会话字段。多渠道重复送达用消息 ID 去重，无法确认的外部发送保留 `unknown`。

本地运行常见的失败是网络断开、凭证过期、锁文件残留和前台进程被终止。每类失败都需要稳定错误和恢复动作，重连不能创建第二个 Turn，凭证刷新不能把新 Scope 注入旧任务。测试用假渠道模拟断线、重复事件、取消和重启，检查事件顺序、状态单调和临时资源释放。

升级 Daemon 前先停止领取新任务，等待活动动作到 Checkpoint，再替换二进制并恢复。若旧版本无法读取新事件或配置，升级程序应在切换前失败，保留原进程和数据。

本地缓存也要有容量和过期策略。删除缓存不能删除仍被活动 Turn 引用的文件，清理失败应进入可重试队列并留下路径摘要。

## 本地 Runtime 的断线自测

用“Daemon 执行一个需要文件和终端的任务”回放时，Harness 先固定观察版本、工作区和执行预算。执行 ID、工作区策略、渠道游标、Lease 和人工接管由事件和 Checkpoint 保存，模型只能提出动作候选，策略层决定候选能否进入执行器。

正常路径是观察、候选、授权、动作、再观察和确定性验证。每次动作都带 `attempt_id`，输出包含退出码、差异或截图摘要。进程重启、渠道重复送达或外部动作未知要保留原始回执，不能让模型用一句“已完成”覆盖。
