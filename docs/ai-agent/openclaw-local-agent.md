# OpenClaw 时代的本地工具与权限引擎

本地 Agent 把文件、进程、窗口和网络能力带到用户设备上，权限问题因此比普通聊天更具体。可访问性树适合按语义定位控件，坐标控制适合树不可用的画布，两者都必须经过能力等级和 Hook 检查。循环检测负责发现重复动作，不能用一次“看起来成功”的截图代替业务回执。

本文沿 `observation`、`action history`、`hook decision`、`workspace` 和 `stall signal` 说明状态归属。设备状态不可重放、辅助功能权限过大、Hook 可绕过和动作历史无限增长，分别对应不同责任层。

::: info 贯穿示例

贯穿示例是本地文件任务：读取工作区内的配置，修改一个允许的文件并运行测试。工作区之外的路径、网络出口和删除动作默认拒绝，模型只能提出候选。

:::

## 本地 Agent 为什么需要常驻进程

坐标控制越界会破坏 local agent 与受控动作之间的对应关系，排查时先保留原始输入摘要和发生阶段，再判断是否允许重试。

辅助功能权限过大影响 capability level 或下游解释，不能和坐标控制越界共用“重新调用一次模型”的处理方式。

常驻进程还要处理设备睡眠、网络切换和用户注销。Heartbeat 只能说明 Daemon 仍能发出心跳，恢复后必须重新读取工作区版本、窗口身份和工具目录；睡眠期间产生的旧观察不能直接驱动写动作。对于删除文件、发送消息和修改系统设置等不可逆能力，恢复时应重新请求审批，避免把“任务仍在运行”误认为“原授权仍然有效”。

## Daemon、渠道与工具权限如何连接

OpenClaw 的 Harness 持有工作区、工具和权限，模型只能根据观察提出动作候选。因此 local agent 与 capability level 要有唯一写入方，其他组件只能通过版本化命令申请修改。

Computer Use 与 本地工具运行时解决的问题相邻，但控制权不同，比较时要看谁选择检查权限、谁保存 local agent、谁确认受控动作。

桌面自动化可以参与同一请求，却不能替代 本地工具运行时；组合后仍要单独检查环境观察的可信来源和坐标控制越界的终止规则。

本地工具运行时使用的身份、范围和版本来自可信运行时，用户目标可以表达意图，但不能提升权限或改写活动 Release。

辅助功能权限过大发生时，错误回到 capability level 的所有者处理，上游缺输入、当前组件违反不变量和下游不可用分别形成不同终态。

本地工具运行时的确定性边界位于 local agent 写入之前。模型在 OpenClaw 中只提交候选值，程序仍要从认证、版本和策略快照补入可信字段。

本地工具运行时内部可以使用更细的临时对象，跨边界只暴露稳定协议。替换 Computer Use 时，调用方不需要理解内部缓存和 SDK 响应。

## 本地工作区和会话状态怎样保存

本地工具运行时的输入合同至少列出用户目标、环境观察和能力目录，每项都注明来源、是否必需、允许的缺省值，以及缺失后是在入口拒绝还是进入降级路径。

本地 Agent 需要把 `agent_id`、能力等级和观察版本分开保存。能力等级决定哪些工具可以出现，观察记录说明 Agent 依据哪一版本地环境提出动作；身份、能力和观察混在一起时，降权或重启后仍可能沿用旧权限。

并发分支按稳定身份合并 observation，完成顺序只反映耗时，不能决定结果属于哪个请求，更不能让迟到的旧状态覆盖新修订。

OpenClaw 的对外结果要分别表达可交付内容、缺口、取消和未知状态，调用方不必解析错误文案。

capability level 参与乐观并发检查；处理开始后若版本变化，旧候选只保留作审计，不能继续写入 local agent。

观察版本、动作参数、审批、文件差异、进程结果、截图和测试输出组成 本地工具运行时的最小追踪材料，日志只保存稳定 ID、版本和错误类，完整 Prompt、文档正文与凭证不进入指标标签。

契约还需要描述新鲜度。capability level 对应的数据发生变化后，旧缓存、旧候选和未完成任务怎样失效，应由版本或时间规则直接判断，不能依赖模型注意到矛盾。

删除和撤回也属于数据生命周期。本地工具运行时引用的原始对象被移除时，稳定 ID 可以保留审计关系，正文与派生结果则按策略失效，避免继续向用户展示过期内容。

::: warning 本地工具运行时的可信边界

受控动作通过结构校验后仍是候选。本地工具运行时使用的身份、权限、知识版本与业务事实由应用从可信服务读取，核对完成后才能执行或交付。

:::

## 从消息到本地动作的执行链

本地工具运行时的推演要观察权限如何变化：同一个 Agent 先获得只读文件能力，再申请进程能力，Hook 在申请边界记录批准或拒绝，重复动作由循环检测停止。这样才能证明能力等级真的约束了动作，而不是只画出权限层级。

观察环境接收用户目标并建立 local agent，入口校验未通过就地结束，后续模型、检索器或工具调用次数保持为零。

检查权限读取 capability level 并执行主题逻辑，参数由应用组装，外部返回先保存为可审查差异，尚未获得修改领域状态的资格。

执行并重新观察检查结构、范围、版本和主题不变量；受控动作缺少来源、落在旧版本或越过权限时，local agent 停在 rejected 或 failed。

实现可以使用函数、Graph、Middleware 或 Workflow，local agent 的所有权和坐标控制越界的停止规则不会随框架改变。

## 沿一次本地文件任务推演

沿“本地工具运行时场景：编码助手需要读取仓库、修改一个文件并运行测试，但不能访问工作区之外的路径，也不能在测试失败时宣称完成”推演 本地工具运行时：入口创建 request_id，读取可信身份，把用户目标和当前版本写入初始状态。

观察环境生成 local agent 与输入摘要；若环境观察缺失，请求返回 rejected，并指出缺少哪项材料，不继续消耗模型或外部服务配额。

检查权限按“本地权限引擎把可访问性树、坐标控制、文件、进程和网络能力分级，Hook 在动作边界执行策略，循环检测阻止重复行为”推进，每次依赖调用保存 call_id、参数摘要、开始时间与状态版本，以便判断超时前是否已经产生结果。

运行确定性验证写入终态；客户端断开只影响交付通道，重新连接时读取已经保存的 local agent 或事件游标，不重跑核心逻辑。

故障注入选择 Hook 可被绕过，程序保留原候选和错误位置，只重做失败边界，不能从入口复制整个任务并产生第二份状态。

推演结束后用 request_id 关联 local agent、受控动作与终止原因，测试据此排除并发请求串线，并确认失败路径没有遗留未关闭资源。

本地工具运行时在输入拒绝时不调用依赖，正常路径按 5 个阶段推进，有限修复只重做失败边界。调用次数是控制流断言，不是性能宣传。

本地工具运行时的最终记录用 request_id 关联 local agent、受控动作和失败问题，测试据此证明结果来自本次执行，没有混入并发请求。

## 本地动作怎样返回可审查结果

本地工具运行时正常完成时，local agent、capability level 和受控动作指向同一次执行，重复读取返回同一终态，未完成分支已经取消或有明确所有者。

观察版本、动作参数、审批、文件差异、进程结果、截图和测试输出用于还原 本地工具运行时的处理过程，可以按阶段和版本聚合；敏感正文留在受控存储中，不复制到日志与指标。

依赖返回成功状态只证明传输完成。本地工具运行时还要检查受控动作是否满足业务范围、质量阈值和当前版本，明确拒绝也可能是正确终态。

local agent 的状态迁移必须单调：完成不能退回运行中，取消不能被迟到结果覆盖，失败重试也不能绕过入口已经固定的权限。

本地工具运行时的成功证据最终要同时回答输入是什么、执行了哪些步骤、交付了什么以及为什么停止；任一项缺失都应留在未确认状态。

本地工具运行时把业务验收与服务健康分开。依赖对 OpenClaw 返回 200 只说明传输完成，内容仍要满足当前范围和质量条件。

本地工具运行时的观测指标按阶段和版本聚合。评估 OpenClaw 时，把错误、空结果、拒绝、恢复和资源消耗分开统计，避免一个成功率掩盖不同故障。

## 断线、越权和重复执行

本地运行时的排障要先看权限与环境，再看工具回执：Daemon 未启动是生命周期故障，能力被拒绝是策略故障，命令返回非零是执行故障，结果无法确认则属于交付故障。不同故障不能共享一个无限重试计数器。

遇到坐标控制越界时，先记录发生阶段、错误类别和责任对象。本地工具运行时保留输入摘要和状态版本，由对应组件决定重试、降级或终止。

辅助功能权限过大触及 本地工具运行时的安全边界，重试不会使它自动合法；执行路径保存拒绝规则和输入来源，清除未授权候选，并以稳定错误结束当前动作。

遇到 Hook 可被绕过时，先记录发生阶段、错误类别和责任对象。本地工具运行时保留输入摘要和状态版本，由对应组件决定重试、降级或终止。

动作历史无限增长会在 本地工具运行时的记录中留下动作签名重复、状态无变化或预算持续下降的迹象，控制器据此写入停止原因，取消未开始分支，并转交现有证据。

本地工具运行时处理本地优先造成设备状态不可重放时需要稳定身份和结果回执，再次收到同一请求先读取旧结果；外部结果未知就停在 unknown，不能猜测失败后重新执行。

本地工具运行时将终态、可重试性和资源清理结果写入记录；后台扫描器根据 local agent 判断任务是在运行、等待恢复还是已失败。

本地工具运行时执行前固定 Deadline、动作上限、重复签名、无进展阈值、预算和取消信号；任一条件触发，检查权限停止创建新工作。

本地工具运行时把重试时间和次数计入总预算。OpenClaw 每次重试先扣减剩余额度，达到上限就保留原始错误。

本地工具运行时的清理动作设计成幂等操作；仍被活动任务或 Lease 引用的资源拒绝删除。

## 用 Fake Channel 测试本地运行时

使用隔离工作区和假环境重放观察动作循环，断言越界动作被拒绝、写操作需要审批、验证失败不会标记完成；测试显式给出用户目标、初始 local agent、预期受控动作和终止原因，不能只断言返回值非空。

本地工具运行时的单元测试用 Fake Adapter 固定受控动作与错误，断言参数、调用顺序、状态修订和清理动作，这些结果只证明本地控制逻辑。

契约测试围绕用户目标、local agent 和可审查差异构造合法与非法样本，Schema 解析成功后继续检查权限、版本与领域不变量。

故障测试注入坐标控制越界和辅助功能权限过大，记录检查权限是否被调用、local agent 是否改变、资源是否释放，以及同一身份重试会不会重复执行。

本地工具运行时的集成测试连接真实协议与隔离存储，检查序列化、约束、并发和超时；需要在线服务时另行记录服务版本、时间、配置与凭证条件。

本地工具运行时的回归报告要保留失败类型分布。在 OpenClaw 的回归中，拒绝、超时、权限错误和空结果必须保持各自类型，状态变化本身就是行为契约。

本地工具运行时的性质测试随机改变 local agent 顺序、重复提交、完成顺序或状态版本，断言权限不扩大、终态不倒退、同一身份不产生两次副作用。

OpenClaw 的离线评测关注质量变化，运行时测试关注控制和恢复，两类证据都齐全才可交付。本地工具运行时只有两类证据都存在，才能同时回答“结果是否合格”和“系统是否安全完成”。

## 心跳、后台进程和资源治理

本地工具运行时要把工作区策略、命令白名单、观察版本和渠道协议一起写入执行记录。升级任一合同后，旧执行仍按原版本恢复，不能让新的权限字段改变已经产生的动作。

本地工具运行时的容量主要受观察体积、工具调用、后台进程、浏览器会话、文件差异和循环步数影响，并发可能缩短单次等待，也会占用连接、配额、内存和下游吞吐，必须沿观察环境、提出动作、检查权限、执行并重新观察、运行确定性验证逐层核算。

本地工具运行时的候选版本在固定样本上比较正确性、错误类型、延迟和资源消耗，坐标控制越界等安全红线回归时直接停止发布，不能用平均质量抵消。

坐标控制越界的降级路径在发布前写好，可以减少非关键增强、返回已经确认的受控动作，或明确暂时无法确认，缺失事实不能交给模型补写。

发生越界或动作未知时，先用 `request_id` 找到观察版本、动作参数、审批事件、进程回执和截图摘要，再判断是策略拒绝、执行失败还是渠道断开。重试前必须确认原动作是否已经产生副作用。

本地工具运行时的数据按证据用途分级保留，聚合字段可以留得更久，用户目标和大体积受控动作设置短期限、访问控制与删除通道。

本地工具运行时先在单进程实现 local agent、超时、错误和测试，只有恢复与容量证据提出要求时，再增加队列、Lease、分布式缓存或工作流引擎。

本地工具运行时的监控阈值要对应可执行动作。OpenClaw 的分支、依赖、上下文和预算接近上限时，应限流或缩小候选；告警本身不会停止正在运行的任务。

回滚要覆盖代码之外的状态。本地工具运行时若改变 Schema、缓存键或持久化记录，旧版本是否还能读取新写入数据必须提前验证；无法双向兼容时采用候选版本隔离。

## 本地 Agent 与 MCP、远程 Agent 的边界

采用 本地工具运行时前先画出用户目标到受控动作的最小控制图；固定函数已经能完成任务时，新增模型决策和跨进程 local agent 只会扩大测试与运维范围。

本地 Agent 面向文件、进程和网络等设备能力，Computer Use 面向屏幕观察与交互动作。两者都让模型提出候选，但工作区策略、浏览器审批和确定性回执分别由对应的执行器确认。

桌面自动化可以与 本地工具运行时组合，但外部知识仍需授权，工具调用仍需校验，模型产生的受控动作仍停留在候选状态。

本地工具运行时适合价值足够、坐标控制越界可观察且预算可接受的任务，高风险、不可逆的决定需要确定性规则或人工批准。

执行期间修改 capability level 可以检验并发设计，旧动作若仍能覆盖 local agent，说明版本或 Lease 有缺口，增加 Prompt 规则无法修复这类竞态。

本地工具运行时增加了 local agent、依赖调用、恢复责任和故障面，设计记录既要说明获得的能力，也要列出新增的退出、降级与回滚路径。

## 本地工具代理的权限执行边界

本地 Agent 往往同时接触文件系统、终端、浏览器和用户凭证。它的配置输入必须明确工作目录、可读写路径、允许的命令、网络范围、超时和人工审批规则。模型可以提出“读取配置”或“运行测试”，但运行时先把路径解析为绝对路径并检查是否位于允许根目录，再调用工具。路径穿越、符号链接跳出工作区和隐藏文件访问都应在确定性层拒绝。

工具执行返回退出码、标准输出摘要、错误摘要、耗时和副作用标记。非零退出码不一定表示整个任务失败，例如格式检查可能返回可修复诊断；删除、发送或发布等不可逆动作则需要 Action ID 和审批事件。Agent 失联后，恢复器先查询 Action 回执，再决定重试或标记未知，不能仅根据进程退出猜测。

本地渠道还会带来上下文串线。来自聊天、桌面通知和命令行的消息必须转换为统一 Turn，并保留来源、用户和会话 ID。一个渠道的取消不能误伤另一个会话，跨渠道共享记忆要经过权限和来源过滤。测试使用临时目录和假的外部工具，验证越界路径、命令注入、重复动作和会话隔离。

## 本地工具权限的回放自测

用“Agent 读取工作区、修改一个文件并运行测试”回放时，Harness 先固定观察版本、工作区和执行预算。工作区根、命令白名单、网络策略、审批和回执由事件和 Checkpoint 保存，模型只能提出动作候选，策略层决定候选能否进入执行器。

正常路径是观察、候选、授权、动作、再观察和确定性验证。每次动作都带 `attempt_id`，输出包含退出码、差异或截图摘要。符号链接越界、命令超时或渠道断开要保留原始回执，不能让模型用一句“已完成”覆盖。

测试故意让观察过期、工具未知、命令超时和渠道断开。在“Agent 读取工作区、修改一个文件并运行测试”中，前两种在执行前拒绝，后两种要根据是否产生副作用决定重试或进入未知状态。恢复从最后一个 Checkpoint 开始，不重放已经确认的写动作。

“Agent 读取工作区、修改一个文件并运行测试”的离线 Fake Adapter 只验证接口和状态迁移，真实浏览器、终端或供应商还要做权限、资源和网络测试。没有可信回执就不宣称完成。

“Agent 读取工作区、修改一个文件并运行测试”的取舍要写清：更大的观察窗口能减少重新读取，却会增加 Token 和敏感内容暴露；更长的自动循环能覆盖更多步骤，却提高失控和回滚成本。

“Agent 读取工作区、修改一个文件并运行测试”的回放报告保存策略版本、动作数量、失败阶段和清理结果，平台升级后再用同一组事件比较，才能判断变化来自实现还是环境。
