# Deep Research Agent 怎样组织多轮检索

从问题分解、并行搜索、来源审查到补缺，建立有预算的研究循环。**Deep Research**、**Search**、**Agent** 分别指向同一条执行链上的不同对象：父目标、子任务契约、依赖图、可见资料、工具权限、截止时间和合并规则进入系统，研究问题、子问题、查询、来源质量、Evidence、覆盖矩阵、冲突、预算和停止原因保存处理中间状态，最终得到带来源的子结果、缺口清单、冲突记录、综合结论或明确的未完成状态。

Deep Research Agent 组织多轮检索位于多个执行单元之间的任务编排、共享状态和结果综合层，主要机制是研究循环先分解问题维度，再并行搜索与审查来源；综合器根据覆盖缺口发起补搜，并在边际收益不足或预算到期时停止。查询不断改写却无新增证据、来源互相转载、时间范围混乱、引用和结论错位以及截止时间后仍继续会让链路在不同位置停止，错误记录必须保留发生阶段、当时的状态和终止原因。

::: info 贯穿示例

Deep Research Agent 组织多轮检索场景：研究任务需要同时核对协议规范、实现约束和测试证据，三个分支完成时间不同且可能给出冲突结论。Deep Research Agent 组织多轮检索需要的身份、权限、版本和业务事实由应用提供，模型与外部内容只产生候选。

:::

这次推演用子任务身份、来源、工作区版本、覆盖缺口、冲突和合并裁决把请求和终态关联起来。与普通搜索、RAG、Planner、多 Agent 和研究报告比较时，重点看输入来源、状态所有者、下一步的决策者和失败终点。

Deep Research Agent 组织多轮检索的执行顺序是“拆分问题 → 分派窄任务 → 并行取证 → 处理冲突 → 汇合结果”。父目标从入口进入，研究问题记录进度，带来源的子结果通过当前主题的校验条件后才会交付。

查询不断改写却无新增证据与来源互相转载会产生不同证据。前者先检查研究问题和输入来源，后者沿调用记录定位依赖或状态冲突；不区分发生位置，重试会掩盖原始原因。

Deep Research Agent 组织多轮检索与普通搜索的共同点不代表它们可以互换。当前主题拥有子问题，相邻组件只通过契约读取或提交候选，不能直接修改这个状态。

Deep Research Agent 组织多轮检索的架构图要标出组件职责、研究问题的唯一所有者、子任务契约经过的接口，以及查询不断改写却无新增证据怎样传播。架构取舍需要说明新增状态和恢复成本，只列组件名称无法用于故障定位。

## 一个执行单元为什么不够

从问题分解、并行搜索、来源审查到补缺，建立有预算的研究循环。在“Deep Research Agent 组织多轮检索场景：研究任务需要同时核对协议规范、实现约束和测试证据，三个分支完成时间不同且可能给出冲突结论”这类任务里，Deep Research Agent 组织多轮检索负责把父目标带入处理链，并明确带来源的子结果可以交付的条件。

Deep Research Agent 组织多轮检索位于多个执行单元之间的任务编排、共享状态和结果综合层。它处理研究循环先分解问题维度，再并行搜索与审查来源；综合器根据覆盖缺口发起补搜，并在边际收益不足或预算到期时停止，身份认证、授权结果和最终业务状态仍由应用中的确定性组件负责。

父目标是这条链路的起点；来源缺失时，程序只能拒绝请求或采用明确记录的默认值，模型补出的字段不能继续驱动分派窄任务。

查询不断改写却无新增证据会破坏研究问题与带来源的子结果之间的对应关系，排查时先保留原始输入摘要和发生阶段，再判断是否允许重试。

来源互相转载影响子问题或下游解释，不能和查询不断改写却无新增证据共用“重新调用一次模型”的处理方式。

Deep Research Agent 组织多轮检索完成时至少留下研究问题、子问题、带来源的子结果和检查结论；只有最终文字，无法证明结果来自本次请求。

研究问题在单进程 Demo 中可以留在内存，跨进程、带权限或有副作用的任务则要持久化输入、状态转移和停止原因，不能依赖 Prompt 保存状态。

Deep Research Agent 组织多轮检索还要把业务条件写成状态条件：依赖图何时就绪，带来源的子结果何时允许交付，查询不断改写却无新增证据发生后是否还能继续。

Deep Research Agent 组织多轮检索对外区分完成、部分完成和无法确认，三个状态若都包装成带来源的子结果，上层界面无法采用不同处理方式。

## Deep Research Agent 组织多轮检索的协作边界

Deep Research Agent 组织多轮检索接收父目标、子任务契约、依赖图、可见资料、工具权限、截止时间和合并规则，向下游交付带来源的子结果、缺口清单、冲突记录、综合结论或明确的未完成状态，输入与输出之间用明确契约连接，调用方不能把一句含糊目标直接交给底层适配器。

编排器拥有依赖图与总预算，子任务只拥有契约内的局部状态。因此研究问题与子问题要有唯一写入方，其他组件只能通过版本化命令申请修改。

普通搜索与 Deep Research Agent 组织多轮检索解决的问题相邻，但控制权不同，比较时要看谁选择并行取证、谁保存研究问题、谁确认带来源的子结果。

RAG 可以参与同一请求，却不能替代 Deep Research Agent 组织多轮检索；组合后仍要单独检查子任务契约的可信来源和查询不断改写却无新增证据的终止规则。

查询若只保存在 SDK 对象里，重试或进程退出后就失去解释依据；需要恢复或审计的字段进入持久层，体积较大的带来源的子结果只保存稳定引用。

Deep Research Agent 组织多轮检索使用的身份、范围和版本来自可信运行时，父目标可以表达意图，但不能提升权限或改写活动 Release。

来源互相转载发生时，错误回到子问题的所有者处理，上游缺输入、当前组件违反不变量和下游不可用分别形成不同终态。

Deep Research Agent 组织多轮检索的确定性边界位于研究问题写入之前。模型可以建议值，应用核对来源和当前版本；涉及权限、金额、发布或不可逆动作时，再进入策略或人工批准。

Deep Research Agent 组织多轮检索内部可以使用更细的临时对象，跨边界只暴露稳定协议。替换普通搜索时，调用方不需要理解内部缓存和 SDK 响应。

## 任务契约、依赖与工作区状态

Deep Research Agent 组织多轮检索的输入合同至少列出父目标、子任务契约和依赖图，每项都注明来源、是否必需、允许的缺省值，以及缺失后是在入口拒绝还是进入降级路径。

状态合同中的研究问题表示当前进度，子问题保存本次执行依赖的快照，查询关联前后动作，三者不能合并成一段自由文本。

并发分支按稳定身份合并查询，完成顺序只反映耗时，不能决定结果属于哪个请求，更不能让迟到的旧状态覆盖新修订。

输出合同同时描述带来源的子结果和缺口清单，并为拒绝、取消、部分完成和未知状态提供固定形状，调用方据此分支，无需解析错误文案猜测结果。

子问题参与乐观并发检查；处理开始后若版本变化，旧候选只保留作审计，不能继续写入研究问题。

父目标里若包含模型填写的同名字段，应用会丢弃它，再从认证、配置或活动版本中补入可信值，因为结构校验通过不等于授权或业务校验通过。

子任务身份、来源、工作区版本、覆盖缺口、冲突和合并裁决组成 Deep Research Agent 组织多轮检索的最小追踪材料，日志只保存稳定 ID、版本和错误类，完整 Prompt、文档正文与凭证不进入指标标签。

撤回或删除子任务契约时，相关缓存、候选和未完成任务按版本失效；稳定 ID 可以保留审计关系，已撤回内容不能继续进入带来源的子结果。

契约还需要描述新鲜度。子问题对应的数据发生变化后，旧缓存、旧候选和未完成任务怎样失效，应由版本或时间规则直接判断，不能依赖模型注意到矛盾。

删除和撤回也属于数据生命周期。Deep Research Agent 组织多轮检索引用的原始对象被移除时，稳定 ID 可以保留审计关系，正文与派生结果则按策略失效，避免继续向用户展示过期内容。

::: warning Deep Research Agent 组织多轮检索的可信边界

带来源的子结果通过结构校验后仍是候选。Deep Research Agent 组织多轮检索使用的身份、权限、知识版本与业务事实由应用从可信服务读取，核对完成后才能执行或交付。

:::

## 分派、执行和汇合机制

Deep Research Agent 组织多轮检索按“研究循环先分解问题维度，再并行搜索与审查来源；综合器根据覆盖缺口发起补搜，并在边际收益不足或预算到期时停止”推进，这段机制必须落成研究问题和子问题的实际变化，不能只列框架节点名称。

拆分问题接收父目标并建立研究问题，入口校验未通过就地结束，后续模型、检索器或工具调用次数保持为零。

分派窄任务固定身份、范围、配置版本和绝对 Deadline，后续子步骤只继承剩余时间，不能各自重新获得完整超时。

并行取证读取子问题并执行主题逻辑，参数由应用组装，外部返回先保存为缺口清单，尚未获得修改领域状态的资格。

处理冲突检查结构、范围、版本和主题不变量；带来源的子结果缺少来源、落在旧版本或越过权限时，研究问题停在 rejected 或 failed。

汇合结果先保存带来源的子结果与终止原因，再产生事件或通知，交付失败可以重放，核心状态写入失败则不能对外宣称完成。

并行取证出现部分结果时，由任务合同决定保留、补偿还是整体丢弃；带来源的子结果若可重建就重新生成，外部副作用则查询回执或执行补偿。

实现可以使用函数、Graph、Middleware 或 Workflow，研究问题的所有权和查询不断改写却无新增证据的停止规则不会随框架改变。

部分成功需要在步骤边界处理。并行取证已经产生一部分带来源的子结果时，程序按任务合同决定保留、补偿或整体丢弃，并记录未完成项，不能默认为全部成功。

并行取证和处理冲突都要写明逆向动作或不可逆原因，带来源的子结果若可重建就删除后重算，已发送的外部命令只能查询回执或补偿。

## 用冲突来源推演一次研究

沿“Deep Research Agent 组织多轮检索场景：研究任务需要同时核对协议规范、实现约束和测试证据，三个分支完成时间不同且可能给出冲突结论”推演 Deep Research Agent 组织多轮检索：入口创建 request_id，读取可信身份，把父目标和当前版本写入初始状态。

拆分问题生成研究问题与输入摘要；若子任务契约缺失，请求返回 rejected，并指出缺少哪项材料，不继续消耗模型或外部服务配额。

分派窄任务冻结 scope、release、policy 和 deadline_at，用户或模型在正文中提供的同名值只作为普通内容，不能覆盖这份运行时快照。

并行取证按“研究循环先分解问题维度，再并行搜索与审查来源；综合器根据覆盖缺口发起补搜，并在边际收益不足或预算到期时停止”推进，每次依赖调用保存 call_id、参数摘要、开始时间与状态版本，以便判断超时前是否已经产生结果。

候选结果对应带来源的子结果、缺口清单、冲突记录、综合结论或明确的未完成状态，处理冲突逐项检查权限、版本与领域约束，问题列表为空才允许形成下一状态。

汇合结果写入终态；客户端断开只影响交付通道，重新连接时读取已经保存的研究问题或事件游标，不重跑核心逻辑。

故障注入选择时间范围混乱，程序保留原候选和错误位置，只重做失败边界，不能从入口复制整个任务并产生第二份状态。

推演结束后用 request_id 关联研究问题、带来源的子结果与终止原因，测试据此排除并发请求串线，并确认失败路径没有遗留未关闭资源。

Deep Research Agent 组织多轮检索在输入拒绝时不调用依赖，正常路径按 5 个阶段推进，有限修复只重做失败边界。调用次数是控制流断言，不是性能宣传。

Deep Research Agent 组织多轮检索的最终记录用 request_id 关联研究问题、带来源的子结果和失败问题，测试据此证明结果来自本次执行，没有混入并发请求。

## 正常汇合怎样证明覆盖

Deep Research Agent 组织多轮检索正常完成时，研究问题、子问题和带来源的子结果指向同一次执行，重复读取返回同一终态，未完成分支已经取消或有明确所有者。

子任务身份、来源、工作区版本、覆盖缺口、冲突和合并裁决用于还原 Deep Research Agent 组织多轮检索的处理过程，可以按阶段和版本聚合；敏感正文留在受控存储中，不复制到日志与指标。

缺口清单可能是合法的空结果，但必须带范围、版本和原因；任务明确要求找到材料时，同一个空结果进入拒答而非成功。

依赖返回成功状态只证明传输完成。Deep Research Agent 组织多轮检索还要检查带来源的子结果是否满足业务范围、质量阈值和当前版本，明确拒绝也可能是正确终态。

并行取证并发完成时，每个分支保留自己的身份和局部预算，处理冲突按任务合同接纳可用结果，慢分支不能抹掉已经确认的记录。

研究问题的状态迁移必须单调：完成不能退回运行中，取消不能被迟到结果覆盖，失败重试也不能绕过入口已经固定的权限。

Deep Research Agent 组织多轮检索的成功证据最终要同时回答输入是什么、执行了哪些步骤、交付了什么以及为什么停止；任一项缺失都应留在未确认状态。

Deep Research Agent 组织多轮检索把业务验收与服务健康分开。依赖返回 200 只说明传输成功，带来源的子结果仍要满足当前范围和质量要求；明确拒答也可能是正确终态。

Deep Research Agent 组织多轮检索的观测指标按阶段和版本聚合。错误率、空结果率、拒绝率、恢复次数与资源消耗回答不同问题，不能压成一个成功率。

## 重复研究、冲突与取消传播

Deep Research Agent 组织多轮检索按输入、状态、依赖、结果和交付五个位置分类错误，发生位置决定恢复动作，不能用同一个重试循环处理全部失败。

遇到查询不断改写却无新增证据时，系统要返回稳定的错误类型、发生阶段和可重试标记。Deep Research Agent 组织多轮检索保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

遇到来源互相转载时，系统要返回稳定的错误类型、发生阶段和可重试标记。Deep Research Agent 组织多轮检索保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

时间范围混乱触及 Deep Research Agent 组织多轮检索的安全边界，重试不会使它自动合法；执行路径保存拒绝规则和输入来源，清除未授权候选，并以稳定错误结束当前动作。

遇到引用时，系统要返回稳定的错误类型、发生阶段和可重试标记。Deep Research Agent 组织多轮检索保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

遇到结论错位时，系统要返回稳定的错误类型、发生阶段和可重试标记。Deep Research Agent 组织多轮检索保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

遇到截止时间后仍继续时，系统要返回稳定的错误类型、发生阶段和可重试标记。Deep Research Agent 组织多轮检索保存当时的输入摘要与状态版本，再由拥有该依赖的组件决定重试、降级或终止。

Deep Research Agent 组织多轮检索结束错误处理时保存终态、可重试性和资源清理结果，后台扫描器依靠研究问题和这些字段区分仍在运行、等待恢复和已经失败的任务。

Deep Research Agent 组织多轮检索在执行前写入绝对 Deadline、最大动作数、重复签名、无进展阈值、预算和人工取消信号，任一条件触发后并行取证都不再创建新工作。

Deep Research Agent 组织多轮检索把重试时间和次数计入总预算。依赖连续失败会减少后续额度，达到上限后保留原始错误，不再用模型重新措辞掩盖失败。

Deep Research Agent 组织多轮检索的清理动作可以重复执行。临时对象、文件句柄、子进程、连接或 Lease 仍被活动任务引用时，清理器必须拒绝删除。

## 编排测试与来源核对

用可重复的依赖图模拟完成、超时与取消，核对每份结果的任务 ID、来源、预算和合并裁决；测试显式给出父目标、初始研究问题、预期带来源的子结果和终止原因，不能只断言返回值非空。

Deep Research Agent 组织多轮检索的单元测试用 Fake Adapter 固定带来源的子结果与错误，断言参数、调用顺序、状态修订和清理动作，这些结果只证明本地控制逻辑。

契约测试围绕父目标、研究问题和缺口清单构造合法与非法样本，Schema 解析成功后继续检查权限、版本与领域不变量。

故障测试注入查询不断改写却无新增证据和来源互相转载，记录并行取证是否被调用、研究问题是否改变、资源是否释放，以及同一身份重试会不会重复执行。

在并行取证前后终止进程可以检查恢复边界：调用前退出允许重新领取，外部动作后退出先查回执，汇合结果完成后只重放交付。

Deep Research Agent 组织多轮检索的集成测试连接真实协议与隔离存储，检查序列化、约束、并发和超时；需要在线服务时另行记录服务版本、时间、配置与凭证条件。

Deep Research Agent 组织多轮检索的回归报告要保留失败类型分布。明确拒绝变成超时、权限错误变成普通空结果，都属于行为回归，即使总通过数没有变化。

Deep Research Agent 组织多轮检索的性质测试随机改变研究问题顺序、重复提交、完成顺序或状态版本，断言权限不扩大、终态不倒退、同一身份不产生两次副作用。

离线评测关注固定输入下的质量变化，运行时测试关注控制和恢复。Deep Research Agent 组织多轮检索只有两类证据都存在，才能同时回答“结果是否合格”和“系统是否安全完成”。

## 并发、预算和交付策略

Deep Research Agent 组织多轮检索长期运行后，输入 Schema、研究问题结构和依赖配置可能独立升级，每次执行固定一组版本，旧记录才能被正确读取或迁移。

Deep Research Agent 组织多轮检索的容量主要受分支数量、来源抓取、共享工作区冲突、综合调用和截止时间影响，并发可能缩短单次等待，也会占用连接、配额、内存和下游吞吐，必须沿拆分问题、分派窄任务、并行取证、处理冲突、汇合结果逐层核算。

Deep Research Agent 组织多轮检索的候选版本在固定样本上比较正确性、错误类型、延迟和资源消耗，查询不断改写却无新增证据等安全红线回归时直接停止发布，不能用平均质量抵消。

查询不断改写却无新增证据的降级路径在发布前写好，可以减少非关键增强、返回已经确认的带来源的子结果，或明确暂时无法确认，缺失事实不能交给模型补写。

Deep Research Agent 组织多轮检索的运行手册从 request_id 定位子任务身份、来源、工作区版本、覆盖缺口、冲突和合并裁决，再决定重试、补偿、取消或回滚，无需先展开完整的父目标。

Deep Research Agent 组织多轮检索的数据按证据用途分级保留，聚合字段可以留得更久，父目标和大体积带来源的子结果设置短期限、访问控制与删除通道。

Deep Research Agent 组织多轮检索先在单进程实现研究问题、超时、错误和测试，只有恢复与容量证据提出要求时，再增加队列、Lease、分布式缓存或工作流引擎。

Deep Research Agent 组织多轮检索的监控阈值要对应可执行动作。分支数量、来源抓取、共享工作区冲突、综合调用和截止时间中的某项接近上限时，系统可以限流、排队、缩小候选或切换保守路径；只发送告警不会保护正在运行的任务。

回滚要覆盖代码之外的状态。Deep Research Agent 组织多轮检索若改变 Schema、缓存键或持久化记录，旧版本是否还能读取新写入数据必须提前验证；无法双向兼容时采用候选版本隔离。

## 何时退回单 Agent

采用 Deep Research Agent 组织多轮检索前先画出父目标到带来源的子结果的最小控制图；固定函数已经能完成任务时，新增模型决策和跨进程研究问题只会扩大测试与运维范围。

Deep Research Agent 组织多轮检索与普通搜索的差别落在控制权：谁选择下一步，谁保存研究问题，谁确认带来源的子结果可信。

RAG 可以与 Deep Research Agent 组织多轮检索组合，但外部知识仍需授权，工具调用仍需校验，模型产生的带来源的子结果仍停留在候选状态。

Deep Research Agent 组织多轮检索适合价值足够、查询不断改写却无新增证据可观察且预算可接受的任务，高风险、不可逆的决定需要确定性规则或人工批准。

格式正确但事实错误的带来源的子结果是必要反例；若它直接进入成功，说明处理冲突缺少业务验证，应保留候选并给出证据问题。

执行期间修改子问题可以检验并发设计，旧动作若仍能覆盖研究问题，说明版本或 Lease 有缺口，增加 Prompt 规则无法修复这类竞态。

Deep Research Agent 组织多轮检索增加了研究问题、依赖调用、恢复责任和故障面，设计记录既要说明获得的能力，也要列出新增的退出、降级与回滚路径。

Deep Research Agent 组织多轮检索从一个调用、一个研究问题、一组明确错误和几条确定性测试开始，真实 Trace 证明需要后再加入并发、缓存、队列或更复杂策略。

普通搜索只在能处理查询不断改写却无新增证据时引入，不为目录完整强行组合；接口保持可替换，后续需求出现再扩展。
