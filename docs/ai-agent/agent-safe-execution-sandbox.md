# 安全执行怎样限制文件、网络与进程

当 Agent 能运行代码、操作文件或访问浏览器时，参数校验还不够。执行环境需要在操作系统和网络层限制可见范围，即使模型或工具代码出错，也不能触碰边界外资源。

## 先按任务创建最小执行身份

每次任务使用短期身份、独立工作目录和最少凭证。只读分析挂载只读仓库，写操作限制到明确目录，任务结束撤销令牌。

不要让所有 Agent 共用具有管理员权限的长期进程。逻辑上的工具白名单无法阻止底层库读取环境变量。

## 文件、网络和进程分别限制

文件系统使用允许目录与只读挂载；网络使用域名或目标服务允许列表并阻止内网元数据地址；进程限制可执行文件、系统调用、CPU、内存和运行时间。

容器是隔离手段之一，不是默认安全证明。挂载、用户、Capabilities 和宿主 Socket 配置错误仍会穿透边界。

## 副作用执行前生成可审查命令

模型提出动作后，程序解析成窄 Command，展示目标、参数和预期变化。审批通过的快照与实际执行命令做哈希绑定，恢复后不能替换目标。

删除、付款和权限修改等不可逆动作还需要业务层授权与幂等，沙箱不能提供事务语义。

## 执行结果按不可信数据处理

命令 stdout、网页 DOM 和文件内容都可能包含提示注入或秘密。截断大输出，脱敏凭证，保存原始结果引用，再以低信任标签进入上下文。

退出码、超时、资源耗尽和策略拒绝分别映射，模型不能把超时解释成命令成功。

## 用逃逸与资源攻击验证边界

测试访问父目录、连接未允许地址、启动子进程风暴、读取环境变量和超时后继续写入。预期是底层控制拒绝，并产生可审计事件。

人工确认是最后一道业务判断，不是沙箱替代品。用户可能批准了目标，却无法识别隐藏在脚本中的越界操作。
