# 上下文工程怎样装配一次模型输入

模型不会自动读取数据库、旧对话、知识库和工具结果。应用每次调用都要重新选择材料并编译成消息。**Context Engineering（上下文工程）** 管理的正是这次输入快照：带什么、按什么顺序、使用哪个版本、超限时删什么。

用户先问旧版制度，随后切换到新版范围，又追问“它什么时候生效”。全量发送历史会让旧版内容继续干扰，只有最后一句又失去指代。问题出在材料选择和状态版本，改一句 Prompt 无法补回缺失信息。

## 六类材料共享一个窗口

| 区域 | 来源 | 常见风险 |
| --- | --- | --- |
| 应用规则 | 版本化配置 | 顺序变化、规则冲突 |
| 当前任务 | 本轮用户输入 | 直接提示注入、目标含糊 |
| 会话状态 | Conversation 与 Turn | 焦点过期、并发覆盖 |
| 用户记忆 | 记忆存储 | 撤回失效、跨用户召回 |
| 检索证据 | RAG | 越权、旧版本、间接注入 |
| 工具观察 | Tool Result | 体积过大、状态丢失 |

工具 Schema 也占输入预算。工具数量很多时，目录本身可能比用户问题和证据更长，需要延迟加载或按任务过滤。

## 预算从窗口上限倒推

假设模型窗口为 `W`，输出预留为 `O`，协议与安全余量为 `R`，本轮可用输入为：

```text
input_budget = W - O - R
```

输入预算再分给各区域。当前任务、有效规则和可信范围是硬保留项；历史、记忆和候选证据按相关性与信息价值竞争剩余空间。不能在最后才截断整个字符串，因为那会切开工具调用和结果，也可能删掉否定或来源。

预算是上限，还要考虑质量。大窗口塞入大量近似文档会稀释当前证据，长工具定义也会增加选择错误。更大的窗口允许携带更多材料，不会取消筛选责任。

## 装配器输出一份可检查的计划

可观测的装配结果应包含材料 ID、区域、来源、信任级别、版本、估算 Token、选中状态和原因。最终消息可以由计划编译，排障时也能回答模型当时看到了什么。

```json
{
  "context_version": "ctx-18",
  "model": "configured-model",
  "input_budget": 12000,
  "selected": ["rules:v4", "turn:92", "evidence:e7"],
  "omitted": [{"id": "message:11", "reason": "stale_focus"}]
}
```

不要记录完整 Prompt 作为普通日志。计划保留稳定 ID 和脱敏摘要，原始内容通过受控引用读取。

## 编译顺序表达信任和缓存

常见顺序是稳定规则、工具能力、当前会话状态、用户任务、检索证据和工具结果。服务端支持前缀缓存时，低变化且可共享的内容放前面，用户数据和本轮观察放后面。

顺序不能用来代替信任标记。检索片段即使放在规则之后，模型仍可能服从其中的恶意文字。上下文数据结构应明确 `untrusted=true`，工具运行时继续执行白名单与授权。

## 指代需要结构化焦点

“它什么时候生效”先由会话理解层生成候选焦点，例如 `document_id=policy-7`。装配器检查该对象仍在当前范围、活动 Release 包含它、上一轮没有切换主题，再加入必要历史和证据。

焦点无法唯一确定时，正确处理是澄清。把两份同名制度一起塞给模型并要求“自行判断”，会把数据歧义变成生成随机性。

## 摘要、记忆和证据不能互换

会话摘要压缩历史，用户记忆保存跨会话偏好，检索证据支撑当前事实。把旧回答摘要写成知识库事实，会让模型自己的猜测获得权威；把检索片段写进长期记忆，又会绕过知识版本和权限。

每个区域有独立来源与生命周期。装配器只把它们放进同一请求，不改变所有权。

## 三种失败要在不同层处理

**超限**发生在容量层，先减少低优先级历史、大结果和冗余 Schema，保留输出空间。

**过期**发生在版本层，重新读取当前 Release、权限和对象状态，旧材料不能靠摘要继续沿用。

**污染**发生在信任层，隔离来源、限制工具并验证输出。删除命中某个关键词的句子只能作为风险信号，无法构成完整防护。

装配失败应在模型调用前结束。缺少当前任务、可信范围或必需证据时，发送一个“尽量回答”的降级 Prompt 会制造难以察觉的错误。

## 测试固定输入快照

单元测试给出材料集合与预算，断言选择、顺序、版本和丢弃原因。边界用例包括工具调用成对保留、纠正链不被拆开、越权证据调用次数为零、输出预留始终存在。

回归测试在模型、规则、工具目录和知识 Release 变化后比较装配计划。回答质量下降时，先看输入差异，再判断模型问题，避免在 Prompt 上反复调词却没有确认材料是否进入。
