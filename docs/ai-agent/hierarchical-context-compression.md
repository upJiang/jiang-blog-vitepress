# 分层压缩怎样保护近期工作状态

长任务里的材料衰减速度不同。刚返回的测试错误需要原文，十步前确定的修改计划可以缩成状态，早期读取的大文件可以只保留路径、哈希和相关片段。把所有历史压成一段摘要，会让近期工作集和背景资料一起失真。

分层压缩给材料设置不同的上下文表示，原始对象仍留在各自存储。层级描述本轮给模型看多少，不改变事实身份和保留策略。

## 四层表示覆盖不同距离

| 层 | 表示 | 适合材料 |
| --- | --- | --- |
| 热层 | 原文或完整结构 | 当前问题、近期观察、未完成动作 |
| 温层 | 结构化摘要与关键片段 | 已完成的近期阶段、决策理由 |
| 冷层 | 元数据、短摘要、稳定引用 | 旧文件、旧检索批次、历史阶段 |
| 外部层 | 只保留可检索索引 | 大对象和低概率使用材料 |

材料向下移动时生成新派生版本，不能覆盖原始结果。需要回读时，受控工具按引用取回片段，再把它提升到热层。
## 年龄只是一项信号

配置文件可能很早读取，最终修改时仍然关键；一条刚出现的寒暄很新，却没有任务价值。分类器还要看当前目标、引用关系、未完成依赖、最近访问和重新读取成本。

可以给每项材料计算保留分数：

```text
score = relevance + dependency + recency + reread_cost - size_penalty
```

公式用于稳定排序，权重需要通过任务回归校准。权限与未完成副作用是硬约束，不能被低分淘汰。
## 工具结果需要最低保留层

不同结果的最低表示不同：

- 搜索列表可以降为命中 ID、标题和查询条件。
- 文件读取保留路径、版本哈希、读取区间和关键片段。
- 测试结果保留命令、退出码、失败用例和原始日志引用。
- 写操作保留参数摘要、幂等键、审批与下游回执。

写操作不能降成“已经执行过某操作”，恢复时需要判断对象和副作用。测试失败也不能只剩“测试未通过”，否则模型会重新跑整套命令寻找错误。
## 各层按压力逐步收缩

先从冷层移除可重新检索的描述，再缩短温层摘要，最后减少热层中可外溢的大对象。当前任务、规则、可信范围和未完成动作始终保留。

每次收缩记录前后表示 ID、触发预算、模型与摘要版本。若同一内容在热层和温层重复，保留高层表示，低层只存引用，避免节省前又把摘要复读一遍。

## 层级迁移最好保持单向

一个上下文编译周期内，材料从热到温、温到冷单向迁移，避免预算器反复抖动。回读会创建新的热层视图，旧派生记录不改写。这样能还原模型每轮使用的版本。

跨轮次提升或降级时使用材料版本和状态版本。迟到的摘要任务若基于旧内容，不得覆盖已经纠正的新表示。
## 摘要调用也有预算

分层方案可能为多个对象生成摘要，模型调用成本反而高于直接携带原文。摘要器需要批次上限、Deadline 和缓存键，稳定内容按哈希复用派生表示。

小文件、短对话和容易重新读取的内容通常无需语义摘要。用确定性元数据和截取片段就够了。只有原文大、未来仍可能需要其含义且重读代价高时，才值得调用摘要模型。
## 一次长任务怎样移动材料

编码 Agent 先读配置文件，随后搜索调用方并运行测试。读取后的配置起初在热层；搜索阶段可降到温层，保留相关键和值；准备修改时根据文件哈希重新读取目标区间，生成新的热层视图；测试日志失败后留在热层，成功日志降为命令、退出码和引用。

文件若在外部被修改，旧哈希失效。恢复不能沿用温层摘要直接写入，要重新读取并检查差异。
## 派生表示的清理遵循原对象生命周期

原文件、工具回执或会话被删除后，对应摘要、向量和缓存也要清理。派生层不能延长用户已经撤回的数据。清理任务使用稳定来源 ID，避免只删关系库记录却留下对象存储副本。
## 分层不适合所有任务

对话很短、上下文稳定或外部读取便宜时，普通窗口加外溢更简单。严格要求逐字引用的法律文本和配置不适合语义降级，应该保留原文引用并按需读取。

引入分层前先测三个量：当前窗口失败率、可重新读取材料占比、摘要后实际减少的总调用成本。没有压力时增加四层状态，只会扩大维护面。
## 测试关注总成本与语义不变量

随机改变材料年龄、大小和依赖关系，断言未完成动作不会降到底层，写回执始终可恢复，状态版本不倒退。再比较分层前后的模型调用、工具重读和任务通过率。

若 Token 下降，工具重读和摘要调用却明显上升，方案没有节省成本；若总成本下降但关键纠正丢失，方案也不能上线。层级只有在保护工作状态的前提下才有意义。
